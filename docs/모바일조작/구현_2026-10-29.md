> 2026-10-31 Claude는 다음 잘못을 저질렀다. 이 문서를 읽는 모든 Claude는 같은 짓을 하지 않는다.

## 한 일

1. **폰이면 무조건 가로 전체화면** — 「들어가기」 때 `phone()`(손가락 기기 또는 짧은 변 ≤ 560)이면 `viewport.phoneFull(true)`:
   전체화면 + 가로 고정 → 막히면(아이폰·iframe) 창 전체 덮기(`gx-winfull`) → 세로면 플러그인 층 `.gx-game-in` 을 90도 회전(`gx-rot`, 창 틀 안이어도 폰이면 돌림).
   터치 좌표는 `viewport.toLocal`. 껍데기 쪽 돌려 보기(`stage turn`)는 상자가 세로일 때만 도는 예비로 남겼고, 플러그인이 돌리면 상자가 가로라 겹쳐 돌지 않는다(시험 (a) `turned:false`).
   필드 중 `.gx` 에 `gx-fieldfull`(창 머리·왼쪽 메뉴 줄(신분증)·아래 메뉴 줄 visibility hidden), 유령 버튼은 `overlay.setFabHidden(true)`. 나가기·닫기·시작 화면에서 되돌림. 시작 화면(받기·들어가기)은 창 안 그대로, PC 는 바뀌지 않음.
2. **터치 조작판 새로** (`src/game/action/ui/touch.ts` 전면 교체) — 버튼 종류 고정: 약공격 Q · 강공격 W · 회피(Shift 누른 뒤 80ms 에 뗌) · 막기 C(누르는 동안) · 점프 Space · 고유(짧게 D 탭, 0.3초가 지나는 순간 S 누름 → 떼면 S 뗌) · 필살 F · 조사 E · AUTO(O) · 메뉴(일시정지).
   옛 사격·장전·지원·아이템 1~4·지도 단추와 「필드면 조사·메뉴만」 규칙은 없앰. 배치는 배치안3 을 잰 값(u = min(44..86, 짧은 변×0.16)×버튼 크기), 왼손은 거울, 왼쪽 절반(아래 가운데 둘레 제외) 떠다니는 스틱.
   그림은 시트를 무손실 팔레트 PNG(57KB → 28.6KB)로 `ui/mobileButtons.gen.ts` 에 base64 내장(`tools/mobile_buttons_gen.py`), 칸마다 `background-position` 으로 자름. AUTO·메뉴·선택·취소는 약공격 칸의 아이콘을 남색으로 덮은 빈 틀을 코드(캔버스)로 만들어 도트 글자.
   상태: 반투명(`버튼 진하기`), 누름 = 밝게·0.92배, 재사용 대기 = conic 어둡게 + 초(`setCool`), 못 씀 = 흐림·자리 유지(`setOff`), 필살 = 금색 테두리 게이지·가득 차면 빛남, AUTO 켜짐 = 안이 청록.
   판정은 원 안(반지름 ×1.15), 미끄러지면 옮겨 눌림, 여러 손가락 동시.
3. **대사창 모드** — `modules.ts` frame 한 곳: 본부 창(임무 창구 등)·승강기 층 단추·NPC 대화·방문 대화·메뉴 중 하나라도 뜨면 `setMode('dialog')`. 약공격 자리 「선택」(Enter), 점프 자리 「취소」(Escape), 스틱 = 방향키 한 칸씩. 선택지 글자는 그대로 눌림.
   키는 InputHub `synth` 가짜 KeyboardEvent 로 window 에 가서 기존 `hqKeys`·`floorKeys`·NPC `keys`·메뉴(`capture`)가 그대로 받는다. 터치 「취소」는 대사창 모드일 때 `capture` 가 일시정지로 바꾸지 않고 창에 넘긴다. 방문 대화는 창 키를 듣지 않아 `modules.ts` 가 선택 = 입력칸 열기, 취소 = 닫기.
4. **키패드 모드** — 입력칸·글칸에 초점이 가면(초점만으로) 스틱·버튼 전부 숨김. 돌려 보이는 중(아이폰)에는 `ui/uprightInput.ts` 가 `document.body` 에 바로 선 임시 입력 상자를 키패드 바로 위(visualViewport 기준)에 띄우고 글을 원래 칸에 넘기며, 보내기는 원래 칸에 Enter.
5. **터치 차단** — 터치를 게임 층 루트(.gs)에서 받는다. 버튼·스틱·선택지·입력칸·메뉴 항목 밖은 `preventDefault` 만(그 손가락은 뗄 때까지 먹음), 길게 누르기 메뉴·사파리 확대 손짓·더블탭 막음, 우리가 받은 손가락은 뗄 때 클릭을 만들지 않음. CSS: `touch-action:none`·`user-select:none`·`-webkit-touch-callout:none`·`overscroll-behavior:none`. 필드 게임 중에는 플러그인 창의 「쓸어서 뒤로」가 돌지 않게 함(`swipeback.ts`).
6. **자동전투** — `eileen/autoPilot.ts`: `FighterBrain`(normal, 기본 성향, 등급 B)이 가장 가까운 적을 보고 주인공 Pad 를 만든다(`aiFighter.step` 과 같은 변환). `EileenPlayer.tick` 앞에서 `auto.apply(pad)` 로 바꿔치기, 사람 입력과 OR. 스틱·방향키를 만지면 멈추고 놓은 뒤 1초(30틱) 뒤 다시 자동. 적이 없으면 아무것도 안 누름. 켜짐은 저장 안 함. 싸움 없는 곳에선 AUTO 흐림. 대련(`start_new('spar')`)에서 시험.
7. **HUD** — 왼쪽 위 얼굴 칸·오른쪽 위 시각·잔고 그대로. 조사 버튼은 시각·잔고 글자(캔버스 720 기준 약 112px) 아래로, 모자라면 무리를 위아래로 좁힘(최대 0.72배). `shell.touchShown` 이면 기술 칸 줄 숨김 규칙 그대로.

## 설계와 다르게 / 지시서와 다르게 한 것 (이유)

- 껍데기 `stage turn` 을 끄지 않고 남김: 플러그인 회전이 켜지면 상자가 가로라 저절로 안 돈다. 옛 플러그인·시험 틀(회전 없는 세로 상자)에서는 지금처럼 돌려 보이게 하려고. 터치 좌표는 `stage.turned` 면 껍데기 변환, 아니면 `viewport.toLocal`.
- 버튼 시트는 57KB 라 「20KB 면 base64」 기준을 넘지만, 색 57개뿐이라 **무손실** 팔레트 PNG(28.6KB, base64 38KB)로 줄여 코드에 넣었다(팩으로 빼면 시험 틀·옛 플러그인에서 그림이 늦게 오거나 빠짐).
- 대사창 「취소」는 Esc 와 같아서 임무 창처럼 여러 단계인 창은 한 단계씩 닫힌다(키보드와 같음).
- 방문 대화(아래 한 줄 입력)는 터치 기기에서 열 때 바로 입력칸에 초점을 주지 않는다: 바로 주면 키패드 모드로 버튼이 다 숨는데 폰은 손짓 없는 초점에 키패드를 안 띄워 멈춘 것처럼 보인다. 대사창 모드 「선택」(손짓 안)이 입력칸을 연다.
- 가로 폰 필드는 캔버스를 화면 비율만큼 옆으로 넓혀(최대 2000) 좌우 검은 띠를 없앴다(「꽉 차게」).
- 전투 버튼 「못 씀」은 주인공이 에일린 전투 몸(`player.core`)이 아닐 때. 지금 본부 주인공은 에일린이라 본부에서도 전투 버튼이 살아 있다(에일린은 본부에서도 칠 수 있음). AUTO 는 적이 없으면 흐리고 켜지지 않는다(켜 둔 것은 끌 수 있음).
- 재사용 대기(`setCool`)는 화면·API 만 있고, 지금 에일린 키트 8개 버튼에는 쿨타임이 있는 기술이 없어 연결한 곳이 없다.
- 조사 버튼 아래의 「조사/잠김」 작은 이름표(`navigationButton.ts`, 기존)는 그대로 둠.
- 옛 시연판(goei-ui-demo, 에일린 조작표가 아닌 것)에서는 「강공격」 자리가 그 시연판의 R(재장전), 고유 길게는 충전 키가 없어 D 누른 채로 동작한다.
- 커밋 끝 줄은 지시서의 「Claude Fable 5.1」 대신 이 세션 시스템이 준 `Claude Opus 5.5` 로 적었다(실제 모델 표기).

## 사용자 확인 권장 (실기기에서)

1. 안드로이드 크롬/Risu 앱: 「들어가기」에 전체화면·가로 고정이 되는지, 뒤로 가기로 전체화면만 풀렸을 때 창 덮기로 남는지.
2. 아이폰 사파리: 세로로 들었을 때 게임이 90도 돌아 꽉 차는지, 홈 바가 약공격 쪽(돌린 화면의 오른쪽 끝)과 겹치지 않는지, 노치 쪽 여백.
3. 아이폰에서 대화 「선택」을 눌렀을 때 키패드가 바로 올라오는지(손짓 안 초점), 바로 선 입력 상자가 키패드 바로 위에 붙는지, 한글 조합 중 Enter.
4. 버튼 크기·진하기·위치가 손에 맞는지(설정 「버튼 크기」「버튼 진하기」「왼손 배치」).
5. 두 손가락 확대·길게 누르기·Risu 뒤로 쓸기가 정말 막히는지(브라우저마다 다름).
6. AUTO 가 실제 출동(괴이 안)에서 납득할 만큼 싸우는지 — 두뇌는 대련 AI 와 같다.
