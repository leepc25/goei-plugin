# 전투 AI 설계 (1판, 2026-10-26)

> 상태: **제안. 사용자 확인 전.** 코드·그림 변경 없음.
> 목표(사용자 말): 적이 몰려와 주먹만 휘두르는 싸움이 아니다. 점프·점프 공격·돌진 공격·달리기·콤보·필살기·고유기술·충전기가 **유기적으로 이어지는**, 격투·액션 게임의 CPU 플레이어 같은 싸움.
> 사용자 결정(2026-10-26): 지금 NPC·적 AI 코드는 **처음부터 다시 짠다**(「전부 다시 짜야겠네」). 옛 코드는 헷갈림만 준다.
> 근거 문서: `docs/인계/쟈알디/쟈알디_동작_최종세트_2판.md`(아래 「2판」), `docs/게임_기본기획서.md` 부록 E·10.1, `docs/보스_선정안.md` 3장, `docs/요원_기술안.md` 0장·1.1·1.2·1.10, `docs/NPC_생성_AI_스탯_설계.md` 4·5·12장(아래 「NPC 설계」), `docs/동작표/00_베이스_및_쟈알디.md`.
> 근거 코드: `src/game/action/engine/`(contract·fighter·world·input·moves·player), `eileen/`, `enemy/`, `fx/fieldFx.ts`.

읽는 법
- 시간은 **틱**으로 적는다. 30Hz라 1틱 = 약 33ms, 30틱 = 1초.
- 거리는 **px**(논리 좌표)로 적고, 필요하면 m를 붙인다. 1m ≈ 142px(`요원_기술안.md` 0.2).
- 표의 상태 칸: **확정** = 사용자가 정함 · **안** = 문서 안이 있고 시험판에 들어갔지만 사용자가 따로 확정한 기록은 없음 · **제안** = 이 문서가 처음 내놓는 것.

### 1-3. 옮겨 심을 것 (로직은 살리고 모양을 바꿈)

- `eileen/core.ts`: 2판 버튼 규칙(약 연계, 강 마무리 3종, 달리다 슬라이딩, 점프·2단 점프·점프 공격, 회피 방향, 막기, 충전 단계, 기상 슈퍼아머 0.6초)이 이미 들어 있다. 다만 **초 단위·`performance.now()`·`Math.random()`**으로 돌아서(63·108줄 등) 같은 씨앗으로 같은 결과가 안 나온다. 이 규칙을 틱 단위 `Actor`로 옮긴다. 연출 난수(불꽃 흩어짐)는 그대로 둬도 되지만 판정·시간은 `world.rand`와 틱만 쓴다.

## 2. 전체 구조

```
 [사람]  키·터치·패드 ─▶ Input.sample() ─▶ Pad ─▶ padToCmd() ─┐
                                                              ├─▶ Cmd(이번 틱 가상 버튼)
 [AI]    Perception ─▶ Strategy ─▶ Tactic ─▶ Executor ────────┘          │
         (매 틱)       (2~4초)     (0.2~0.5초)  (매 틱)                    ▼
            ▲              ▲           ▲                         Actor (몸 하나)
            │              │           │                          · 동작 실행(4장 MoveData)
         HabitTracker   SquadDirector(0.5초): 역할·표적·공격권     · 버퍼·캔슬·충전·회피/막기 판정
         (상대 버릇)     세력 관계표                                · Fighter 반응 규칙(부록 E)
                                                                     │
                                                                     ▼
                                                    World.step: 판정(resolveHits) → 히트스톱 → fieldFx
```

- **몸은 하나.** 플레이어, 동행, 이름 NPC, 몹, 사람 모양 보스가 모두 `Actor`다. 다른 것은 「누가 Cmd를 쓰나」뿐이다.
- **AI 몫은 Cmd를 쓰는 것까지.** 동작이 나가는지, 캔슬이 되는지, 충전이 몇 단인지는 `Actor`가 사람과 똑같이 판정한다. 그래서 AI가 반칙을 할 수 없다.
- 큰 보스(L급·화면급, 부위로 움직임)는 버튼층 대신 **덱 실행기**를 쓰지만 Perception·Tactic 점수는 같이 쓴다(12-1).

## 3. 입력층 (명령)

### 3-1. Cmd 모양

```ts
/** 가상 버튼. 키 배치와 무관하다 (17장 ① 어느 쪽으로 정해도 이 이름은 그대로) */
export type Act = 'light' | 'heavy' | 'jump' | 'guard' | 'skill' | 'super' | 'shoot' | 'run';

/** 한 틱의 입력. 사람(padToCmd)과 AI(Executor)가 같은 모양을 만든다 */
export interface Cmd {
  mx: -1 | 0 | 1;      // 좌우
  my: -1 | 0 | 1;      // 깊이(위아래 줄)
  press: number;       // 이번 틱에 눌린 Act (비트)
  hold: number;        // 누르고 있는 Act
  release: number;     // 이번 틱에 뗀 Act
}
```

### 3-2. 버튼 해석 (사람·AI 공통, `Actor` 안)

| 입력 | 해석 | 상태 |
| --- | --- | --- |
| `light` 땅 | 약1 → (캔슬 구간 안에 또) 약2 → 약3 | 확정 |
| `light` + 달리는 중 | 돌진 공격 | 확정 |
| `light` 공중 | 점프 공격(점프 1번에 1회) | 확정 |
| `heavy` | 강. 직전 약 몇 타냐로 스턴 / 띄움 / 날림 | 안(0-4) |
| `jump` 땅 | 제자리·방향·달리다 점프(입력 방향·달리기로 갈림) | 확정 |
| `jump` 공중 | 2단 점프(1회) | 확정 |
| `guard` 5틱 안에 뗌 | 회피(가까운 적 반대쪽, 무적 짧게) | 확정 |
| `guard` 5틱 넘게 누름 | 막기 유지 | 확정 |
| `skill` 9틱 안에 뗌 | 고유기술 | 확정(틱 수는 `CHARGE_AFTER` 따름) |
| `skill` 누름 유지 | 9틱부터 충전 자세. 15틱(0.5초) = 1단, 36틱(1.2초) = 2단. 떼면 방출. 15틱 전에 떼면 고유기술로 나감 | 확정(단계 시간) · 제안(15틱 전 뗌 처리) |
| `super` | 필살기(게이지 100) | 확정 |
| `shoot` | 원거리(있는 캐릭터만) | 확정(2판 14장) |
| `run` | 달리기 유지(방향 두 번과 같음) | 확정 |

- **선입력 버퍼 8틱**: 동작 중에 누른 버튼은 8틱 동안 기억했다가 캔슬 구간이 열리면 나간다(`player.ts` `BUFFER`). AI도 같은 버퍼를 탄다. 그래서 AI 콤보도 「조금 일찍 눌러 둠」이 된다.
- **히트스톱 중 입력**: 사람과 같게 받아 두기만 한다(`world.ts`의 `p.listen(pad)`와 같은 규칙).

### 3-3. AI가 버튼을 누르는 법: 입력 대본

AI는 「이 동작을 써라」가 아니라 **버튼 대본**을 만든다. Executor가 한 틱에 한 줄씩 Cmd로 바꾼다.

```ts
interface Step {
  mx?: -1 | 0 | 1; my?: -1 | 0 | 1;
  press?: Act[]; hold?: Act[]; release?: Act[];
  ticks?: number;                 // 이 줄을 몇 틱 유지 (기본 1)
  until?: Cond;                   // 조건까지 유지 (예: 'inRange:L1', 'landed', 'chargeLv>=1')
  confirm?: 'hit' | 'any';        // 앞 공격이 맞아야(hit) 다음 줄로. 아니면 대본 끝
  maxTicks?: number;              // until 안전장치
}
type Script = Step[];
```

예: 달려 들어가 돌진 공격 → 맞으면 약1·약2·강(띄움)

```ts
[
  { hold: ['run'], mx: +1, until: 'inRange:DASH', maxTicks: 40 },
  { hold: ['run'], mx: +1, press: ['light'] },
  { press: ['light'], confirm: 'hit' },   // 돌진 공격 맞음 확인 뒤 약1
  { press: ['light'], confirm: 'hit' },
  { press: ['heavy'], confirm: 'hit' },   // 약2 뒤 강 = 띄움
]
```

### 3-4. 공정 규칙 (제안)

1. AI는 상대의 **입력**을 보지 않는다. 화면에 보이는 것(동작 이름·몇 번째 장·위치·체력·게이지)만 본다.
2. 보이는 것도 **반응 지연만큼 늦게** 본다(5-2).
3. AI도 쿨타임·게이지·띄움 제한·기상 무적을 똑같이 받는다.
4. 화면 밖 AI는 공격을 시작하지 않는다(벨트 스크롤 관례).

## 4. 동작·프레임 데이터 형식

### 4-1. 용어

| 말 | 뜻 |
| --- | --- |
| 시작(startup) | 버튼 뒤 첫 공격 장까지 틱 |

| 회복(recovery) | 유효가 끝나고 자유로워질 때까지 틱 |
| 캔슬 구간 | 다음 동작으로 끊어 넘어갈 수 있는 틱 범위. 맞힘 / 막힘 / 헛침마다 따로 |
| 맞힘 이득(hitAdv) | 맞힌 뒤 내가 상대보다 몇 틱 먼저 움직이나. + 면 이어 칠 수 있음 |
| 막힘 이득(blockAdv) | 막혔을 때 같은 값. − 면 반격당할 수 있음(「막히면 위험」) |

### 4-2. TS 모양

```ts
export type Slot =
  | 'L1' | 'L2' | 'L3' | 'H' | 'DASH' | 'JA'         // 약3·강·돌진 공격·점프 공격
  | 'SKILL' | 'CHG1' | 'CHG2' | 'SUPER' | 'SHOT'      // 고유기술·충전 1/2단·필살·원거리
  | 'DODGE' | 'BLOCK' | 'JUMP' | 'JUMP2' | 'GETUP';

export interface MoveHitData {
  frames: number[];               // 공격 상자가 켜지는 장
  box?: [number, number, number, number];   // [앞 시작, 앞 끝, 높이 아래, 위] 도트. 없으면 그림 reach
  dy: number;                     // 깊이 허용 폭 ±px
  dmg: number;
  react: React;                   // 부록 E.1
  stun?: number;                  // 스턴 틱 (강 단독·약1 뒤)
  push: number; lift?: number;    // 밀림·띄움 속도 px/틱
  stop: number;                   // 히트스톱 틱
  strength: 1 | 2 | 3;
  low?: boolean;                  // 누운 상대에게도 맞음
  armorBreak?: boolean;
  unblockable?: boolean;
  wallBounce?: boolean;           // 벽에 닿으면 벽 충돌(부록 E.1)
}

export interface MoveData {
  id: string;                     // 'jyaldi.L1'
  slot: Slot;
  clip: string;                   // 그림 클립 이름. 클립이 없으면 이 동작은 없음 (13장)
  ticks: number[];                // 장마다 머무는 틱
  hits: MoveHitData[];
  /** 캔슬: from 틱부터 into 슬롯으로. on = 언제 열리나 */
  cancels: { into: Slot[]; from: number; to?: number; on: ('hit' | 'block' | 'whiff')[] }[];
  armor?: [number, number, 1 | 2 | 3];   // 틱 범위, 등급(부록 E.2)
  invuln?: [number, number];
  motion?: { lunge?: [number, number]; adv?: number; air?: boolean };
  cost?: { cd?: number; meter?: number };          // 쿨타임 틱, 필살 게이지
  /** 만들 때 계산해 두는 값 (사람이 안 적음) */
  calc?: {
    startup: number; active: number; recovery: number; total: number;
    hitAdv: number; blockAdv: number;
    range: [number, number];      // 맞힐 수 있는 앞 거리 px (lunge 포함)
    reachZ: [number, number];     // 맞힐 수 있는 높이 → 대공 판단
  };
  /** AI 쪽 표시 (사람이 적음) */
  ai: {
    tags: ('poke' | 'gap' | 'launcher' | 'antiair' | 'finisher' | 'reversal' | 'meaty' | 'zoning' | 'otg' | 'armor')[];
    risk?: number;                // 0~1, 헛치면 얼마나 위험한가 (회복으로 자동 계산, 덮어쓰기 가능)
  };
}
```

### 4-3. 이득 계산 (자동)

- 막힘 경직(제안): 세기 1 = 6틱, 2 = 9틱, 3 = 12틱. 막은 쪽은 뒤로 `push × 0.6`.
- `hitAdv = 반응 틱 − (남은 유효 + 회복)` (첫 유효 틱에 맞았다고 봄. 히트스톱은 양쪽이 같이 멈추니 뺌)
- `blockAdv = 막힘 경직 − (남은 유효 + 회복)`
- 스턴·띄움·다운은 반응 틱이 크니 hitAdv가 크게 + 가 된다. 이 값으로 「이어 칠 수 있는 동작」 목록을 자동으로 만든다.
- 검수: 시험 돌리기(15장)로 실제 잰 값과 계산값이 2틱 넘게 다르면 경고.

## 5. 상황 읽기 (Perception)

### 5-1. 매 틱 만드는 상황표

```ts
interface Sense {
  // 나
  hp: number; meter: number; cds: Record<Slot, number>; armor: number;
  phase: Phase; moveSlot?: Slot; moveTick: number; canAct: boolean; airborne: boolean;
  // 표적 (반응 지연만큼 옛날 모습)
  tgt: {
    id: number; dx: number; ady: number;          // 가로 거리(부호 = 오른쪽 +), 깊이 차이
    facingMe: boolean; myBackToHim: boolean;
    state: OppState;                              // 아래 표
    stateLeft: number;                            // 그 상태가 끝날 때까지 남은 틱(보이는 장으로 추정)
    move?: { slot: Slot; startupLeft: number; recoveryLeft: number; threatens: boolean };
    hp: number; meter: number; guardMeter: number;
    vz: number; landsIn?: number; landX?: number; // 공중이면 착지 시점·자리
  };
  // 주변
  alliesNear: number; foesNear: number;           // 300px 안
  foeBehind: boolean;                             // 내 등 뒤 200px 안에 적
  wallAhead: number; wallBehind: number;          // 화면 잠금(bounds)·장면 끝까지 px
  laneTop: number; laneBottom: number;            // 깊이로 비킬 여유
  inRange: Partial<Record<Slot, boolean>>;        // 동작별 지금 닿나 (calc.range·dy로)
}

type OppState =
  | 'neutral' | 'walk' | 'run' | 'startup' | 'active' | 'recovery'
  | 'block' | 'blockstun' | 'hitstun' | 'stun' | 'air' | 'air-hurt'
  | 'down' | 'wakeup' | 'charging' | 'super' | 'dodge';
```

- `threatens` = 상대 동작의 사거리(calc.range)·깊이(dy) 안에 내가 있고, 아직 유효 전.
- 공중 상대의 착지 시점·자리는 `z, vz, vx`와 중력 2.6으로 바로 계산한다(정확해도 됨. 사람도 포물선은 눈으로 읽음).
- 벨트 스크롤 고유값: **깊이로 비키기**. 동작 `dy`가 20px이면 깊이 4.2px/틱으로 약 6틱이면 빠진다. 그래서 시작 6틱 넘는 공격은 깊이로도 피할 수 있다.

### 5-2. 반응 지연: 「옛 모습 고리」

- 몸마다 최근 32틱의 작은 모습(위치·상태·동작 장)을 고리에 쌓는다.
- AI는 `now − 반응 틱` 의 모습을 본다. 반응 틱은 등급·난이도로 정한다(9장, 예: B급 10틱).
- 그래서 「상대가 공격을 시작했다」를 B급은 10틱 뒤에 안다. 시작이 8틱인 공격은 못 막고, 14틱인 공격은 막는다. 따로 확률을 덧씌우지 않아도 사람처럼 된다.
- 지연에 ±2틱 흔들림을 준다(같은 상황에서 늘 같은 틱에 반응하지 않게).
- 비용: 몸 14개 × 32칸 × 작은 숫자 몇 개. 미리 잡은 배열을 돌려 써서 틱마다 새 물건을 안 만든다.

### 5-3. 자주 쓰는 판단 함수

| 함수 | 뜻 |
| --- | --- |
| `punishable(s)` | 상대 `recoveryLeft ≥ 내 가장 빠른 닿는 동작의 startup + 이동 틱` |
| `willHitMe(s)` | 상대 동작이 threatens이고 `startupLeft ≤ 내 회피 가능 틱` |
| `antiAirWindow(s)` | 상대가 내 쪽으로 떨어지고 `landsIn`이 내 대공 동작 startup + 0~3틱 |
| `meatyTiming(s, move)` | 상대 기상(wakeup) 끝 틱에 내 동작 유효 첫 틱이 겹치게 누를 틱 |
| `cornered(s)` | 등 뒤 벽까지 150px 안 |
| `safeSpace(s)` | 상대 모든 동작 사거리 + 20px 밖 |

| 물러나기 backoff | 상대 사거리 안, 내가 불리 | 15 | 벽까지 여유 있음 +10 | 0.5 / 1.3 / 1.5 |
| 기다리기 wait | 늘 | 10 | 지휘가 공격권을 안 줌 +50 | 0.5 / 1.0 / 1.0 |

위험 = `동작 risk × 30 × (1 − 모험 성향)`. 막히면 −8 이하인 동작은 신중 전략에서 크게 깎인다.

### 6-4. 실행

- 대본 한 줄씩 Cmd로. `until`이 안 풀리면 `maxTicks`에서 끊고 전술을 다시 고른다.
- **맞음 확인**: 콤보 다음 줄은 `confirm: 'hit'`. 맞힘이 안 되면 7장 콤보표의 「막힘」 갈래로.
- **콤보 끊김(사람다움)**: 이음 하나마다 등급별 확률로 일부러 놓친다(9장). 놓치면 버튼을 3~6틱 늦게 누르거나 안 누른다.
- **끊기 조건**: 내가 맞음, 표적 죽음·화면 밖, 전략 바뀜, 상대 필살 컷인 시작. 끊기면 바로 전술 다시 고름.
- **충전 유지**: `hold: ['skill']`를 목표 단계까지. 그 사이 상대가 220px 안으로 오면 지금 단계로 바로 뗀다(1단도 안 됐으면 고유기술로 나감).
- **깊이 맞추기**: 공격 전 상대와 깊이 차이가 동작 dy보다 크면 먼저 my로 맞춘다. 맞추는 동안은 「들어가는 중」으로 보여 상대가 읽을 수 있다.

### 6-5. 한 장면 예

쟈알디(AI, B급, 반응 10틱) vs 플레이어 에일린. 거리 260px, 같은 깊이.
1. 플레이어가 강(시작 7, 회복 14)을 헛친다.
2. AI는 10틱 늦게 본다. 그때 상대 회복은 7 + 3 + 14 − 10 = 14틱 남음.
3. 벌주기 후보: DASH(시작 5 + 260px을 lunge로 덮음) → `punishable` 참(14 ≥ 5 + 4). whiff_punish 점수 70 + (14−9)×2 = 80, 공세 가중 1.2 → 96.
4. 대본: `run + light` → 맞음 → 다운 → 기상 겹치기(oki)로 이어짐.
5. 같은 장면에서 F급(반응 20틱)은 남은 회복이 4틱이라 벌주기를 못 하고 approach를 고른다. 등급 차이가 코드 분기 없이 숫자로만 생긴다.

## 7. 콤보 경로표

### 7-1. 모양

```ts
interface ComboRoute {
  id: string;
  start: 'neutral' | 'hit' | 'counter' | 'air' | 'stun' | 'wall' | 'down' | 'block';
  need?: { meter?: number; ready?: Slot[]; wallWithin?: number; tgtAirborne?: boolean; tgtArmorMax?: number };
  steps: { slot: Slot; via: 'link' | 'cancel' | 'chase'; confirm: 'hit' | 'any'; delay?: number }[];
  onBlock: 'stop' | { safe: Slot } | 'continue';   // 막히면
  value: { dmg: number; end: 'down' | 'air' | 'stun' | 'neutral' | 'wall'; adv?: number };
  diff: 1 | 2 | 3 | 4 | 5;                          // 어려움. 등급이 낮으면 못 씀(9장)
}
```

- `link` = 앞 동작이 끝난 뒤 이어 누름(맞힘 이득이 + 여야 함). `cancel` = 캔슬 구간에 끊어 넣음. `chase` = 띄운 상대를 쫓아 이동(점프·달리기) 후 누름.
- 시작할 때 쓸 수 있는 경로만 남긴다: 클립이 다 있음(13장), 쿨·게이지 됨, 등급 diff 허용.
- 고를 때 `value.dmg × 끝 상태 덤(다운 1.2, 벽 1.3, 스턴 1.1) × 성향(과시면 긴 경로 ×1.3)`.
- 무한 방지(부록 E.1): 한 콤보에 띄움 2회, **스턴 1회**(제안), 15히트 넘으면 피해 보정 ×0.5.

## 8. 방어·반응

### 8-1. 반응 순서 (상대 공격이 보였을 때)

`willHitMe`가 참이 된 틱(반응 지연 뒤)에 아래 순서로 본다. 각 줄은 「등급의 방어 성공률」로 한 번 굴린다(9장). 실패하면 그냥 하던 것을 계속한다(사람이 못 본 것처럼).

1. **끼어들기**: 내 가장 빠른 닿는 동작 시작 < 상대 남은 시작 − 1 → 먼저 친다.
2. **아머로 받기**: 내 아머 동작이 상대 공격 반응 등급을 견디고 유효가 먼저 오면 → 받으며 친다(쟈알디 근접 폭파).
3. **회피**: 남은 시작 ≥ 1, 회피 무적(1~8틱)이 상대 유효를 덮으면 → 회피. 회피 뒤 반격 경로가 있으면 이어 붙임.
4. **깊이로 비키기**: 남은 시작 ≥ 6, 상대 동작 dy 작음 → 위나 아래 줄로.
5. **막기**: 막을 수 있는 공격(`unblockable` 아님)이면 → 막기.
6. 다 아니면 맞는다.

- 어떤 줄을 고를지는 성향이 바꾼다: 공격성 높으면 1·2 먼저, 참을성 높으면 5 먼저, 우회 성향은 4 먼저.
- **막기 오래 금지**: AI는 45틱 넘게 막고만 있지 않는다. 막기 게이지(에일린 시험판 `guard` 0~100)가 40% 아래면 회피·물러나기로 바꾼다.
- **저스트 회피**: 상대 유효 3틱 전 안에 회피하면 성공. 사람은 화면이 느려짐(0-7 안). AI 성공은 화면을 느리게 하지 않고 AI만 6틱 먼저 움직인다(제안).

### 8-2. 공중·기상·스턴

| 상황 | AI 선택지 |
| --- | --- |
| 내가 띄워짐 | 할 수 있는 것 없음(사람과 같음). 2단 점프·공중 회피 없음 |
| 내가 다운 | 기상 시점 고르기: 바로(0틱) / 늦게(+10~20틱) / 기상 직후 회피 / 기상 직후 막기 / 기상 직후 고유기(아머). 성향·버릇으로 섞음. 같은 것 3번 연속 금지 |
| 기상 직후 | 무적 12틱(`GETUP_INVULN`) + 에일린 시험판처럼 기상 아머 0.6초는 안(통일 필요, 17장 ⑤) |
| 내가 스턴 | 레버 연타로 줄임(시험판: 누를 때마다 0.18초). AI도 같은 버튼 연타. 등급 높을수록 빨리 누름 |
| 상대가 공중에서 다가옴 | 대공(antiair 동작) / 뒤로 빠져 착지 자리에서 기다리기 / 막기. 대공 동작이 없으면 뒤 두 개만 |
| 상대가 필살 컷인 | 컷인 동안 세계 정지. 끝난 뒤 반응 지연 없이(컷인이 예고라서) 회피 시도, 성공률은 등급 그대로 |

### 8-3. 몸 규칙 보강 (Fighter에 더함, 제안)

- 막기: 정면만. 막힘 경직 6/9/12틱, 피해 0(에일린 시험판은 1). 막기 게이지 깎임 = 피해 × 0.8.
- 강인(poise): NPC 설계 4-5 공식 그대로. 슈퍼아머와 따로 계산해 큰 쪽.
- 경직치(그로기): NPC 설계 4-5 그대로. 차면 스턴 45틱.

## 10. 습관 읽기 (HabitTracker)

### 10-1. 세는 것

상대(주로 플레이어)의 **보이는 행동**만 센다. 각 수는 반감기 600틱(20초)으로 줄어든다. 그래서 플레이어가 버릇을 바꾸면 AI도 따라 바뀐다.

### 10-2. 규칙

- 보정 상한 ×2. 버릇 하나로 AI가 한 가지만 하게 되지 않게.
- 세는 범위(제안): 몹은 장면 안에서만, 같은 세력 몹끼리 **나눠 씀**(「저놈 점프 많이 한다」). 이름 인물·보스는 한 출동 동안. 저장하지 않음.
- 등급별 읽기 속도(9-1): 「느림」 = 비율에 ×0.5, 「빠름」 = ×1.5. 성향 adapt를 또 곱함.
- 보스 덱 무게에도 같은 수를 쓴다(보스 선정안 3.2 「상황 반응」).

## 11. 집단 전투 지휘·표적 고르기

### 11-1. 지휘(SquadDirector)

장면 안 세력마다 하나. 15틱마다 돈다. 납작한 「공격 2체 제한」 대신 **역할**과 **공격권**을 나눈다.

| 역할 | 하는 일 | 몇 명 |
| --- | --- | --- |
| 주공 main | 표적 앞에서 정면 싸움. 전술 전부 | 표적당 공격권만큼 |
| 측면 flanker | 표적 등 뒤·다른 깊이로 돎. 표적이 주공에게 묶였을 때 침 | 표적당 0~1 |
| 원거리 ranged | 깊이 맞춰 사격·충전기. 주공과 같은 줄에 서지 않음 | 0~2 |
| 압박 대기 pressure | 바깥 원(표적에서 300~420px)에서 걸으며 기다림. 막기·회피만 | 나머지 |
| 숨 고르기 rest | 방금 큰 콤보를 끝냈거나 체력 낮음. 뒤로 빠짐 | 필요할 때 |

### 11-2. 공격권

- 표적마다 **공격 무게 상한**이 있다(보통 난이도: 근접 3점 + 원거리 1발 줄).
- 동작마다 무게: 약 1, 강·돌진·고유기 2, 충전·필살 3. 쓰기 전에 무게만큼 빌리고 동작이 끝나면 돌려준다.
- 무게가 모자라면 그 AI의 전술 점수에서 공격 전술이 0이 되고 wait·flank가 올라간다.
- 표적이 막 다운됐으면 겹치기는 한 명만(나머지는 둘러섬). 다운된 상대를 여럿이 패지 않게.
- 화면 밖 몸은 공격권을 받지 못한다.

### 11-3. 표적 점수

```
표적 점수 = 위협(최근 3초에 나를 때림 +50, 내 동료를 때림 +20)
          + 가까움(+40 − 거리/15)
          + 틈(표적이 회복·다운·스턴 +15)
          + 역할(원거리는 먼 표적 +10, 측면은 등 보이는 표적 +20)
          + 세력 미움(관계표 값)
          − 이미 이 표적을 노리는 같은 편 수 × 15
          + 지금 표적 유지 +20 (자꾸 안 바꾸게)
```

- 표적은 플레이어, 동행, 다른 세력 NPC 누구나 될 수 있다. 몹 대 몹(불량배 대 경찰)도 같은 엔진이다.
- **동행**은 주인공 쪽 지휘에 들어간다. 「주인공이 지금 때리는 표적 +30」, 「주인공을 때린 적 +30」을 더한다. 동행도 공격권을 쓴다(주인공 몫과 따로).

### 11-4. 세력 관계표 (제안)

`Body.team`(player/enemy/neutral) 대신 `faction`과 관계표를 본다. 옛 몸은 team으로 세력을 대신한다.

| 관계 | 값 | 뜻 |
| --- | --- | --- |
| 적대 | +30 | 보면 싸움 |
| 경계 | 0 | 맞으면 싸움, 소란도 2 이상이면 적대 |
| 중립 | 끔 | 서로 판정 없음 |
| 같은 편 | 끔 | 판정 없음 |

예: 관리국 ↔ 가짜 관리국 = 적대, 경찰 ↔ 불량배 = 경계(소란도 2부터 적대), 백일몽 ↔ 관리국 = 경계(먼저 맞으면 싸움, 기본기획서 10.2), 시민 ↔ 누구나 = 중립(맞으면 도망).
**중립 구역**(확정 0-18): 그 장면에서는 NPC끼리 관계를 「중립」으로 묶는다.

### 12-1. 보스 덱 실행기 (보스 선정안 3장)

- **덱**: 단계마다 기술 6~8개. 고를 때 같은 기술 연속 금지, 최근 3수 안 기술은 무게 절반(확정).
- **상황 반응**(확정 3.2): 거리 근·중·원, 상대 공중, 막기 오래(→ 잡기·막기 깨기), 원거리만(→ 돌진·당기기), 등 뒤(→ 뒤돌아 쓸기). 이 조건은 5장 상황표 + 10장 버릇 수로 판단한다.
- **연계 묶음**: 2~3개 이은 것. 예고 길이 2종(빠름·느림)으로 박자를 흔든다.
- **숨 고르기**: 큰 연계 뒤 30~60틱 빈틈(헐떡임·도발). 이때는 공격 전술 0.
- **단계 전환**: 70%·35%. 전환 중 무적 60~90틱 + 연출. 단계마다 체력 경계에서 필살 1회.
- **그로기**: 부록 E.2 수호자 규칙(차면 60틱 아머 없음).
- 사람 모양 보스(가짜 관리국 간부 등 이름 인물)는 이름 인물 키트 + 덱 무게를 덧씌운다. 큰 보스(L급·화면급)는 버튼층 없이 덱 실행기가 동작을 바로 고른다.

## 13. 그림이 없을 때

- **규칙(제안)**: 싸움 동작은 그 클립이 자산 팩 `frames.json`에 있을 때만 있다. 없으면 그 `MoveData`는 키트에서 빠진다.
- 빠진 동작을 쓰는 콤보 경로·전술은 자동으로 꺼진다. 예: 점프 클립 없음 → jump_in·J-띄워 쫓기·점프 대공 꺼짐 → 그 인물은 땅 싸움만. 그림이 들어오면 코드 변경 없이 강해진다.
- 싸우는 데 꼭 필요한 최소: 전투 대기 + 걷기 + 약 하나 + 맞기. 없으면 그 인물은 싸우지 않는다(도망·물러남만). NPC 설계 5-6의 「대체 사다리」(대기 그림 튀기기 등)는 생활 동작용이고, **싸움에는 쓰지 않는다**(가짜 공격이 보이면 판정과 그림이 어긋남).
- 판정 상자: 그림의 `reach`·`hurt`(art.ts `FrameInfo`)가 있으면 그것, 없으면 `MoveData.hits.box`.
- 개발 모드에서만 회색 상자 대역 허용(시험용, 「검수 전」 표시).
- 개발 창에 인물마다 「쓸 수 있는 동작 21/27, 빠진 것: JUMP, JA, CHG2 …」를 띄운다.

## 15. 개발 도구·자동 시험

NPC 설계 12장의 세계 관찰 창에 싸움 칸을 더한다(개발자 전용, 사용자 확정 「개발한다」).

### 15-1. 관찰 창

- 머리 위 한 줄: `공세 · whiff_punish · J-기본 3/5 · 반응 10`.
- 몸을 누르면: 전술 점수 상위 5개와 **점수 쪼갠 것**(기본·전략 가중·성향·버릇·덤·위험), 지금 상황표(지연된 상대 모습 포함), 버릇 수, 공격권 누가 쥐었나, 표적 줄(화살표).
- 판정 표시(지금 `H` 키 `showBoxes`) 위에 **프레임 막대**: 시작(노랑)·유효(빨강)·회복(파랑)·캔슬 구간(초록 테두리).
- 느리게(×0.25)·한 틱씩 진행.

### 15-2. 씨앗 재현

- 판정·시간에 쓰는 난수는 `world.rand`(mulberry32) 하나. `Math.random()`·`performance.now()`는 연출에만(1-3).
- 기록 = 씨앗 + 사람 Cmd(바뀐 틱만). 같은 기록이면 같은 싸움이 다시 나온다. 사용자가 본 이상한 장면을 번호로 받아 재현.

### 15-3. 머리 없는 시험 (화면 없이 node로)

`World`를 그림 없이 돌린다. `npm test`에 넣는다.

| 시험 | 내용 | 통과 기준 |
| --- | --- | --- |
| AI 대 AI | 쟈알디 대 쟈알디, 등급 조합, 씨앗 200개 | 90초 안에 끝남, 양쪽 다 피해 줌 |
| 등급 차이 | S 대 F, B 대 D | S가 95% 이상, B가 70% 이상 이김 |
| 집단 | 이름 인물 1 대 몹 4, 몹 대 몹(경찰 대 불량배) | 끝남, 화면 밖 공격 0, 공격권 상한 넘김 0 |

## 16. 구현 순서

각 단계는 단독 HTML 시연판 + 「검수 전」 표시로 전달한다.

| 단계 | 할 일 | 확인 |
| --- | --- | --- |
| 1 | `Cmd` 입력층 + `Actor` 몸(에일린 시험판 규칙을 틱 단위로 옮김). 사람은 `padToCmd`로 조작 | 플레이어 손맛이 시험판과 같음. 씨앗 재현됨 |
| 2 | `MoveData` 형식 + 쟈알디 자료 + calc 자동 계산 + 프레임 막대 + 머리 없는 시험 틀 | 프레임 검사 통과 |
| 3 | Perception(옛 모습 고리) + Executor(대본) + 콤보 경로표. 고정 대본만 도는 허수 AI | 콤보 검사 통과 |
| 4 | 전술·전략 점수 + 등급 수치. 쟈알디 대 쟈알디 AI 1:1 | AI 대 AI·등급 차이 통과 |
| 5 | 방어·반응·기상·대공 | 사용자 시연: 「CPU 같다」 확인 |
| 6 | 세력 관계표 + 지휘·공격권 + 몹 키트 + 몹 성향 뽑기 | 집단 시험 통과 |
| 7 | 습관 읽기 | 점프만 하면 대공이 늘어나는지 시연 |
| 8 | 보스 덱 실행기 | 보스 선정안 #1 경비원으로 시험 |
| 9 | 옛 AI 코드 삭제(1-2 표), 규칙 약점 설명은 문서로 | 빌드·시험 통과 |

- 그림이 없어도 1~4는 지금 있는 에일린·쟈알디 클립으로 된다. 다른 인물은 13장 규칙대로 그림이 오면 켜진다.
