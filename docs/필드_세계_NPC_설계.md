## 1. 목표와 범위

- 플레이어가 서 있어도 세계가 굴러간다. 요원은 출근해서 일하고 커피를 마시고 수다를 떨고 퇴근한다. 거리는 행인이 오가고, 가게는 문을 열고 닫고, 소란이 나면 경비·경찰이 온다.
- 적용 범위: `필드_거점_설계안.md`의 장면 전부(관리국 17, 백일몽 21, 가짜 관리국 19, 중림 11, 협회 10, 기독교 상점 3, 성원 5, 자택 17, 거리 17).
- 새 거점·도시·세력이 생겨도 **자료만 추가**하면 돌아가야 한다(2장).

## 2. 확장 원칙: 엔진은 특정 장소·인물을 모른다

| 자료 | 정의하는 것 | 늘릴 때 |
| --- | --- | --- |
| 장소 `Place` | 장면, 연결(문·끝·계단·엘리베이터·지하철), 꼬리표(종류·소속·시간대), 걷는 띠, 광고물 | 장면 자료 추가 |
| 광고물 `Affordance` | 「여기서 이걸 하면 이 욕구가 찬다」(책상·커피머신·소파·샌드백·벤치·계산대…) | 물건 한 줄 |
| 인물 `Character` | 이름 NPC: 스탯·성격·욕구 계수·취향·근무·사는 곳 | 파일 하나 |
| 원형 `Archetype` | 몹 종류: 몸·역할 범위·성향 뽑기 범위·스탯·반응·떨어뜨릴 것 | 한 줄 |
| 직무 `Post` | 근무형 몹: 자리·방식·근무시간·조건 | 한 줄 |
| 인구 규칙 `Population` | 장소 종류 × 시간대 → 몹 구성·목표 인원·흐름 | 표 하나 |
| 행동 부품 `Behavior` | 걷기·통행·순찰·순회·일하기·수다·반응·도망·따라가기·싸움(전투 AI로 넘김) | 부품 하나 등록 |
| 사건 `WorldEvent` | 세계 상태를 바꾸는 계기(본편 괴이 발생, 소란, 우발 사건) | 규칙 하나 |

- 자료는 게임 팩 안 JSON으로 싣는다. 저장소에서 내용을 받아 오는 데 의존하지 않는다(인계서 3장 규칙).
- 장소마다 손으로 짜지 않는다. **꼬리표만 붙이면** 그 종류의 인구·직무·흐름이 자동으로 깔린다. 특별한 장면만 예외를 적는다.

## 3. 3층 시뮬레이션

```
세계 World ─ 시계, 장소 그래프, 이름 NPC 위치 계산, 장면별 인구 통계, 소란도, 사건
  │            화면 밖은 숫자로만 (장소가 늘어도 비용 일정)
  ▼
장면 Scene ─ 지금 보이는 장면 하나만 실제 몸으로 (스포너·근무형·이름 NPC를 몸으로 만든다)
  │
  ▼
행위자 Actor ─ Body(엔진 몸) + Mind(관계·기분·태도) + Brain(할 일 고르기) + Motor(길찾기·클립·말풍선)
              싸움이 나면 Brain이 전투 AI(docs/전투_AI_설계.md)로 넘긴다
```

### 3-1. Risu 안에서 돌리는 조건

| 조건 | 대응 |
| --- | --- |
| 게임 창은 격리 iframe: localStorage 쓰면 오류, 외부 요청 막힘 | 저장은 저장 칸(pluginStorage, `bridge.ts`), 자료는 게임 팩 안 |
| 창이 숨거나 닫히면 화면 갱신(rAF)이 멈춤 | 화면 밖 세계는 실시간이 아니라 **따라잡기**: 다시 열 때 지난 게임 시간만큼 한 번에 계산 |
| 모바일 | 한 화면 몸 상한(이름 NPC 6 + 몹 8 + 전투 AI 상한은 전투 문서), 보이는 장면만 시뮬 |
| 모델 호출 | 대화할 때만, 한 번에 하나(지금과 같음). 행동에는 모델 호출 없음 |

계산량: 화면 속 몸 최대 14개 30Hz(지금 적 전투와 비슷), 할 일 고르기 몇 초마다 1번, 화면 밖 이름 NPC 55명 게임 1분마다 1번(1ms 미만), 화면 밖 몹은 계산 안 함.

## 4. 장소 자료

```ts
interface Place {
  id: string;                 // 'hq_2f_office', 'st_jongno_main'
  site: string;               // 'hq' | 'daydream' | 'fakehq' | 'jungrim' | 'sdra' | 'street' …
  kind: PlaceKind;            // 'office'|'lobby'|'corridor'|'lounge'|'clinic'|'street_downtown'|'market'|'residential'|'nightlife'|'park'|'school'|'subway'|'home' …
  faction: 'A00'|'B00'|'C00'|'neutral'|'public';
  length: number;             // 장면 가로(px)
  lane: [number, number];     // 걷는 띠 y (기본 420~669)
  links: Link[];              // 문·서쪽 끝·동쪽 끝·계단·엘리베이터·지하철 입구 → 다른 장면, 걸리는 시간
  gates: string[];            // 몹이 들어오고 나가는 곳 (links의 일부)
  affordances: Affordance[];  // 4-1
  population?: string;        // 인구 규칙 이름 (없으면 kind 기본)
  except?: Partial<…>;        // 이 장면만 다른 것
}
interface Affordance {
  id: string; x: number; y: number;
  act: string;                // 'type'|'drink_coffee'|'rest'|'shower'|'spar'|'sweep'|'sell'|'wait_bus' …
  fills: Partial<Record<Need, number>>;  // 1분당 차는 양
  slots: number;              // 동시에 쓰는 사람 수
  owner?: string;             // 주인 있는 자리(잼트리 책상)
  hours?: [string, string];   // 쓸 수 있는 시간(매점)
}
```

- 연결과 걸리는 시간은 `필드_거점_설계안.md` 11장 연결 그래프와 필드 설계 5-1(1m=142px, 걷기 1.3m/s, 문 3초, 계단 한 층 20초, 엘리베이터 30초)을 기계가 읽는 표로 옮긴다.
- 광고물 위치는 배경 그림이 완성되면 그림의 물건 자리에 맞춘다. 회색 장면은 임시 좌표.

## 5. 이름 NPC: 욕구 + 의무 AI [확정 원리]

### 5-1. 가진 것

| 칸 | 내용 |
| --- | --- |
| 욕구 `needs` | [안] 6종 0~100: 업무 `work`, 피로 `energy`, 카페인·허기 `fuel`, 사교 `social`, 휴식 `fun`, 위생 `hygiene`. 시간 따라 줄고 행동으로 참 |
| 욕구 계수 | 인물마다 줄어드는 속도와 중요도(큐라스 사교 ×1.5, 에일린 사교 ×0.4) |
| 취향 | 좋아하는 광고물·장소·사람(잼트리 커피, 고르고디오 샌드백, 큐라스 PC, 로제몬 휴게실 기둥·과자, 에일린 독서, 게슈간 문 쪽 자리 — `본부_설계_2판.md` 4장 근거) |
| 의무 | 근무시간·일과 블록. 근무 중엔 `work`에 큰 가중치 |
| 사는 곳 | 퇴근 후 가는 곳(숙소·자택·거점). 출퇴근 길에 거리를 지난다 |
| 본편 상태 | 가장 강함. 작전투입·외근·실종·사망 → 세계에서 빠짐, 부상 → 의무실 침대, 격리 → 격리실(기존 `stateOverride`) |

### 5-2. 고르기

```
후보 = 갈 수 있는 광고물 전부 + 사람(친한 인물 = 사교 광고물)
점수 = Σ(욕구 부족분 × 계수 × 그 광고물이 채우는 양) × 취향 × 의무 가중치 ÷ (1 + 가는 시간/60초)
     − 같은 활동 연속 감점 + 작은 무작위
→ 가장 높은 것
```

- 화면 속: 몇 초마다, 사건이 있으면 즉시. 화면 밖: 게임 1분마다(거친 계산, 걷는 시간은 거리로).
- 그래서 장면을 나갔다 오면 「잼트리가 이미 탕비실에 가 있다」처럼 앞뒤가 맞는다.

### 5-3. 이동과 행동

- 장면 사이: 장소 그래프 최단 경로(문·계단·엘리베이터·거리 끝).
- 장면 안: 걷는 띠를 따라 목표 x로, 깊이 y 보간. 막히면 옆걸음, 3번 실패하면 순간 이동(필드 설계 5-3).
- 도착하면 광고물의 동작(타자·마시기·샌드백)을 하고, 하는 동안 욕구가 참. 다 차면 다음 고르기.
- 주인 있는 자리에 플레이어가 서 있으면 잠깐 기다렸다 비켜 달라는 머리 아이콘.

### 5-4. 끼어들기

- 플레이어 접근(2m 안에서 멈추고 바라봄), 첫 만남 인사(목례·손 인사는 관계표), 아는 인물과 마주침(수다), 맞음·소란(반응·싸움·도망).
- 반응이 끝나면 원래 목표로 돌아간다.

### 5-5. 예: 잼트리의 하루

09:00 근무 시작 → 책상 타자 / 10:40 카페인 바닥 → 탕비실로, 복도에서 큐라스와 30초 수다 / 커피 → 책상 / 12:30 허기 → 구내 식당 또는 근처 거리 / 18:00 근무 끝 → 로비 → 종로 큰길 → 버스 정류장.

## 6. 몹

### 6-1. 네 층 분리 [확정]

| 층 | 정하는 것 | 고정 여부 |
| --- | --- | --- |
| 외형 | 그림(동작표 `docs/동작표/NPC/` 71명) | 고정 |
| 역할 | 직무·소속(청소부·경찰·백일몽 조원) | 그 판 동안 |
| 성향 | **나올 때마다 새로 뽑음**: 용기·친화·성급함·호기심·수다 (0~1 연속값). 역할은 범위만 좁힘(경찰 용기 0.5~1, 학생 0~0.6) | 개체마다 다름 |
| 상태 | 기분·공포·피로·소란도·주변 동료 수 | 계속 변함 |

- 그림에 붙는 것은 「어떻게 때리나」(동작 모양)뿐. 「때릴지 말지」는 성향과 상태가 정한다. 동작표의 「대부분 패닉」은 뽑는 범위의 참고.
- 상태가 성향을 덮는다: 겁 많은 개체도 동료가 여럿이면 덤비고, 용감한 개체도 혼자 다치면 도망.
- 개인 기록 없음(씨앗·장부·개인 호감 없음). 그 판 동안만 몸 번호.

### 6-2. 스포너 (계속 보충) [확정]

| 칸 | 뜻 | 예 (1F 로비 낮) |
| --- | --- | --- |
| `gates` | 들어오고 나가는 곳 | 현관, 엘리베이터 |
| `mix[시간대]` | 원형 비율 | 행정 직원 50%, 방문객 30%, 경비 20% |
| `target` | 목표 인원 | 낮 5, 밤 2 |
| `refill` | 모자랄 때 보충 간격 | 3~6초에 1명 |
| `cap` | 한 화면 몹 상한 | 8 |

- 모자라면 플레이어에서 먼 출입구로 **걸어 들어온다.** 남으면 할 일을 마친 몹이 걸어 나간다.
- 쓰러진 몹은 잠깐 누워 있다 사라지며 떨어뜨린 것(돈·소모품)을 남긴다.
- 장면에 처음 들어가면 그 시간대 `target`만큼 바로 깔고 시작.

### 6-3. 근무형 몹 [확정]

```ts
interface Post {
  archetype: string; bases: string[];
  how: 'fixed' | 'patrol' | 'roam';     // 자리 고정 / 장면 안 순찰 / 여러 장면 순회
  spot?: string; route?: string[];
  shifts: [string, string][]; count: number;
  cond?: Cond;                          // 소란도≥2, 비, 본편 사건 중 …
  relief?: number;                      // 쓰러지면 대체 근무자까지 초 (기본 60)
}
```

- 근무 시작에 출입구로 들어와 자리로, 끝나면 퇴근. 교대 직무는 다음 사람이 와야 퇴근(빈 데스크 없음). 근무 밖이면 그 자리 비움.
- 순회 위치는 `(시각 − 근무 시작) ÷ 장면당 머무는 시간`으로 계산(저장 없음).
- 근무형이 먼저 자리를 잡고, 남은 목표 인원만 스포너가 채운다.
- 관리국과 가짜 관리국은 같은 그림·배치 구분(확정)이므로 직무 표도 원형만 바꿔 끼운다.

### 6-5. 거리는 흐름

- 거리 장면은 양 끝이 다른 장면과 이어진다. 행인은 한쪽 끝·지하철 입구·건물 문으로 들어와 반대로 지나간다(통행 행동).
- 일부는 멈춘다: 가게 앞 구경, 통화, 벤치, 둘이 수다.
- 이름 NPC도 출퇴근·외근 길에 거리를 지난다 → 거리에서 아는 인물과 우연히 마주친다.

### 6-6. 소란도 (장면 단위) [확정]

| 단계 | 올리는 것 | 변화 |
| --- | --- | --- |
| 0 평온 | — | 평소 |
| 1 웅성 | 몹 때림, 물건 부숨 | 겁 많은 개체 도망, 구경꾼, 보충 느려짐 |
| 2 소동 | 몹 여럿 쓰러뜨림 | 싸우는 원형 섞여 들어옴, `cond` 직무 등장 |
| 3 진압 | 계속 싸움 | 진압 원형이 떼로: 본부 = 경비·관리국 요원, 거리 = 경찰, 가짜 관리국 구역 = 사원 |

- 싸움이 멎으면 초마다 식고, 장면을 나가면 빨리 식는다. 흔적은 소속 평판에 남는다(8-3).

## 7. 행위자 구조

### 7-1. 행동 부품

| 부품 | 쓰는 쪽 |
| --- | --- |
| `walk` 걷기·길찾기 | 모두 |
| `transit` 통행(한쪽 끝 → 반대쪽) | 행인 |
| `patrol` / `roam` | 경비 / 청소부·택배 |
| `work` 광고물 사용 | 이름 NPC·근무형 |
| `chat` 수다(말풍선 아이콘·미리 쓴 짝 대사) | 모두 |
| `react` 반응 13종(응대·손짓·끄덕·젓기·화내기·발견·놀라기·도망·뒷걸음·기기·주저앉기·웅크려 떨기 …) | 모두 |
| `flee` 도망 | 모두 |
| `follow` 따라가기(발자국 1.5초 뒤, 최대 4명 — 필드 설계 7장) | 이름 NPC |
| `fight` → 전투 AI | 싸우는 개체 |

- NPC 하나 = 부품 조합. 청소부 = roam + work + react + flee. 경찰 = patrol + react + fight. 새 행동 = 새 부품 등록.

### 7-2. 마음 (이름 NPC는 관계 포함, 몹은 상태만)

- 태도: friendly ⇄ neutral ⇄ wary ⇄ hostile → fight → (flee | down) (필드 설계 12장, `core/fieldrel.ts` 개념 재사용).
- 사건 입력: 봄·인사·맞음·동료가 맞음·물건 부서짐·고함·선물·괴이 근처·밤.
- 목격: 시야(앞 300px, 뒤 80px, 같은 장면) 안에서만.
- 이름 NPC의 호감·신뢰·기억은 호감도 시스템(다른 스레드)이 정한다. 여기서는 그 값을 읽어 인사·다가오기·피하기·동행 수락·정보 공개·편들기에 쓴다.

### 7-3. 클립이 없을 때 (대체 사다리)

```
원하는 클립 → 같은 계열 클립 → 대기 그림 + 코드 효과 → 머리 아이콘만
예) 놀라기 없음 → 대기 그림 위로 4px 튀기 + 「!」 / 걷기 없음 → 미끄러짐 + 그림자 흔들림
```

그림이 들어오면 클립 목록에 이름만 추가. AI 코드는 그대로.

## 8. 세계 사건·세력·소문 [안]

### 8-1. 사건 감독

가만히 둬도 일이 생긴다. 장소 종류·시간대·소란도에 따라 확률로:
소매치기, 취객 시비, 불량배 대 경찰, 길 잃은 사람, 가게 강도, 거리의 괴이 징후, 요원 호출(누군가 뛰어감).

### 8-2. 본편이 바꾸는 세계

| 본편 | 필드 |
| --- | --- |
| `[AG|…]` 요원 상태 | 세계에서 빠짐·의무실·격리실 |
| `[AN|지역|…|활성|등급]` 괴이 | 그 지역이 「괴이 상태」: 행인 감소, 경찰·관리국 증가, 일부 몹 오염 행동 |
| `[IN|…|진행]` 사건 | 관련 장소 통제·사람 몰림 |
| 상태줄 시각·날씨·동행 | 시계·비·밤, 동행 인물 |

### 8-3. 세력과 평판

- 몹끼리도 싸운다(불량배 대 경찰). 관리국 ↔ 가짜 관리국은 마주치면 싸울 수 있다(필드 설계 13장). 중립 구역에서는 NPC끼리 싸우지 않는다. **[확정]**
- 소속 평판 5단계(호의·중립·경계·적대·수배, `core/fieldstanding.ts` 개념). 한 장면의 일이 같은 소속·근처 장면으로 퍼지는 범위와 속도는 [안]: 같은 소속 즉시, 근처 장면 게임 1시간.

## 9. 스탯

`docs/NPC_생성_AI_스탯_설계.md` 4장 그대로 가져온다. 요점:

- 원작엔 숫자가 없으므로 **원작 글 평가 → 등급 → 숫자.** [안] 전투 등급 F~S(원작 괴이 등급 사다리 재사용) + 「—」(전투력 없음).
- 등급별 예산(— 2, F 4, E 6, D 8, C 10, B 12, A 14, S 18)을 체형 모양(돌격·중장·사격·암살·이능 원거리·불사·비전투)이 7칸(`hp`·`power`·`aim`·`defense`·`speed`·`poise`·`charge`, 기존 `AgentStats` 이름)에 나눈다.
- 강인(poise): `hit.strength − poise`로 반응 단계 낮춤. 경직치(그로기) 누적 → 스턴. 슈퍼아머는 동작 중에만 덧붙임.
- 상태 자원: 체력, 필살 게이지, 경직치, [안] 오염 0~100(30·60·90마다 최대 체력 −20%, 본편 → 게임 한 방향), 피로 0~3.
- 이름 NPC 기본 스탯은 거의 자라지 않음(기본기획서 16장).
- 몹은 원형 스탯 ±10%.
- 관계 스탯(옛 문서 4-7)은 호감도 시스템으로 넘긴다.

## 15. 개발 도구 [확정]

1. **세계 관찰 창**(단축키): 장면별 인물, 머리 위 할 일, NPC를 누르면 욕구 수치와 할 일 점수표, 화면 밖 이름 NPC 위치, 직무 상태, 소란도, 전투 AI의 전략·전술 점수(전투 문서).
2. **빨리 감기**: 게임 하루를 몇 초에.
3. **씨앗 재현**: 무작위 전부를 씨앗 하나로. 같은 번호 = 같은 하루.
4. **모바일 성능 측정**: 가상 브라우저 CPU 느리게 + 몸 14개 + 그림.
5. **자동 시험**: 하루 빨리 돌려 — 직무가 근무시간에 자리에 있음, 끼어 멈춘 몸 없음, 콘쥬스 목욕탕 일과 없음, 오류 없음.

## 16. 시간

### 16-1. 시계와 생활을 뗀다 [안, 사용자 이견 없음]

| | 정하는 것 | 흐르는 방식 |
| --- | --- | --- |
| 시계(몇 시) | 근무시간·출퇴근·낮밤·영업 | **플레이어 행동으로만**(16-2 표). 서 있으면 멈춤 |
| 생활(지금 뭘 하나) | 걷기·일하기·커피·수다·통행·몹 보충 | 실시간으로 계속. 단 **지금 시각에 할 법한 일 안에서만** |

- 실시간 시계를 쓰지 않는 이유: 본편은 한 턴에 몇 시간씩 뛰고 필드는 잠깐 들르는 곳. 대화창을 읽거나 모델 답을 기다리는 동안 시계가 가면 안 된다.
- 생활 욕구는 실시간으로 천천히 줄되, 한 시각 안에서 같은 일을 짧게 되풀이하지 않게 할 일이 고르게 돈다.

### 16-2. 행동별 흐르는 시간 [확정 2026-10-26]

자잘한 행동별 시간은 쓰지 않는다(사용자: 「자잘하게 복잡하게 할 이유가 없다」). 시계는 아래 다섯 가지로만 움직인다.

| 행동 | 시간 |
| --- | --- |
| 장면 넘어가기(문·계단·엘리베이터·거리 끝) | +10분 |
| 지역 이동(지하철·버스·택시) | +30분 |
| 대화: 이름 NPC와 모델을 불러 주고받는 대화, 창을 열고 닫을 때까지 한 번 | +10분 |
| 싸움: 한 장면에서 싸움이 일어나면 길이·횟수와 상관없이 **그 장면에서 한 번 +10분**. 다음 장면으로 넘어가 또 싸우면 다시 +10분 | +10분 |
| 시간 보내기 | 고른 만큼 |
| 그 밖의 모든 것(걷기·줍기·살펴보기·말풍선·몹 짧은 대답·메뉴) | 0 |

### 16-3. 본편과 맞추기 [확정]

- 필드에 들어갈 때 본편 상태줄 시각에서 시작한다.
- 돌아갈 때 필드에서 흐른 시간을 본편에 사실 문장으로 넘긴다(13장).
- 본편 시간이 크게 뛰었으면 다음 필드 입장 때 세계를 그 시각으로 다시 계산한다(따라잡기).

### 16-4. 한 방문 시간 상한 [보류]

16-2 표가 정해진 뒤 논한다(사용자 2026-10-26).

## 19. 구현 순서 [안]
