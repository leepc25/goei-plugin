# 눌러 보는 전수점검 (Claude가 쓰는 순서)

> **⚠ Claude 반성 · 2026-10-31 (사용자 지시로 문서마다 남김)**
> 2026-10-31 Claude는 다음 잘못을 저질렀다. 이 문서를 읽는 모든 Claude는 같은 짓을 하지 않는다.
> 1. **사용자 결정을 무시했다.** 콘쥬스는 사용자가 10-26에 20세로 정했고 인계서에도 적혀 있었는데, 옛 Claude 문장(teenage high school girl)을 근거로 화장실·샤워 그림을 거부하고, 사용자가 직접 뽑은 화장실 줄까지 팩에서 뺐다. 옷도 제복인데 교복이라고 단정했다.
> 2. **사용자 말에 토를 달고 같은 주장을 되풀이했다.** 사용자가 여러 번 지적했는데도 근거를 다시 확인하지 않아 몇 시간을 허비하게 했다.
> 3. **허락 없이 문서를 지웠다.** 「지침을 지우라」는 말만 듣고 목록을 보여 주지도 않고 96개를 지웠다가 되살렸다(결과물 삭제 금지 규칙 위반).
> 4. **문장을 덧대기만 하며 PixelLab을 낭비했다.** 이성해 점프 공격 5번 연속 실패, 이어폰 음악 120줄을 못 쓰게 만듦.
> 5. **답을 미루고 일을 멈춰 두었다.** 백그라운드로 돌릴 일을 돌리지 않고 대화만 했다.
>
> 지킬 것: 사용자 결정·위키가 근거다. 옛 Claude 자료는 근거가 아니다. 사용자 말에 토 달지 않는다. 무엇이든 지우기 전에 목록을 보여 주고 허락받는다. 실패하면 덧대지 말고 다시 쓰거나 바꾼다.

## 왜 (사용자 2026-11-08)

「전수점검을 수도 없이 시키는데 왜 못 잡냐.」 임무를 고르거나 풀 때 효과가 보이기 전에 창이 닫히는 것, 고른 카드에만 녹색 테두리가 생기는 것을 코드 읽기 점검이 하나도 못 잡았다. 코드를 읽으면 「효과 코드가 있다 → 됐다」로 넘어간다. 사람은 눌러 보면 바로 본다.

그래서 **전수점검 = 실제로 다 눌러 보고 화면을 보는 것**이다. 코드 읽기는 그다음, 원인을 찾을 때만.

## 순서

1. 빌드와 시험 카드: `npm run build`, 시험 카드가 없으면 `npm run test:browser -- --only install --no-build` (`.scratch/fixture/` 생김).
2. 돌리기 (오래 걸리니 **백그라운드로** 돌리고 사용자에게 바로 답한다):
   `npm run audit:click -- --vp pc,phone --start board,picker`
   - 상황판(채팅 시작 뒤, 괴이·사건·특수가 생긴 상태)과 시작 화면에서 출발해, 보이는 눌리는 것(data-action 전부 + 단추·체크·선택칸)을 **하나도 빼지 않고** 실제 마우스(폰은 손가락 탭)로 누른다. 누를 때마다 새 페이지에서 처음 상태로 다시 띄우고 눌러서 앞에서 누른 것이 섞이지 않는다.
   - 누르고 새로 열린 화면이 있으면 그 안의 것도 다 누른다(`--depth`).
   - 같은 단추가 값만 다르게 수백 개인 것(지역 250곳, 위키 항목 등)은 값 8개까지 누르고(`--per-action`), 눌러서 열린 화면이 이미 들어가 본 꼴(보이는 동작 이름 묶음이 같음)이면 다시 안 들어간다. 안 누른 값 수는 7절에 나온다. 특정 값이 의심되면 `--from` 으로 그 화면만 따로 돌린다.
   - 기록: `.scratch/click-audit/report.md`, `report.json`, `shots/` (단추마다 `_1앞`(누를 곳 빨간 테두리) · `_2직후`(0.14초) · `_3뒤`(1초)).
3. **report.md 1~7절을 처음부터 끝까지 다 본다.** 그리고 **캡처를 직접 연다.** 표에 이상 표시가 없다고 넘어가지 않는다. 도구는 사실만 적고, 판단은 점검하는 Claude가 한다.
   - 1절 이상 반응: 오류, 누르자 창이 닫힘, 누른 것이 바로 사라짐, 표시가 잠깐 바뀌었다 돌아감, 반응 없음, 가려져 못 누름, 재현 실패. 각각 세 캡처를 열어 사람이 봤을 때 어떤지 적는다.
   - 2절 선택 표시: 눌러서 「선택됨」이 된 것들의 테두리·바탕·그림자가 몇 가지인지. 같은 「고르기」인데 모양이 다르면 통일성 문제.
   - 3절 통일성: 같은 종류 단추·칸끼리 높이·글씨·색·테두리·모서리·여백이 갈리는 것.
   - 4절 이름: 같은 동작 다른 글자, 같은 글자 다른 동작.
   - 5절 화면마다 잰 것: 화면 밖으로 나감, 글자 잘림, 눌리는 것끼리 겹침.
   - 6절 폰 작은 누름 칸. (서랍 손잡이 18px처럼 사용자가 정한 크기는 결정이 우선.)
   - 7절 못 누른 것: 코드에 있는데 한 번도 화면에 안 나온 data-action. **이게 남으면 점검이 끝난 것이 아니다.** 그 화면이 나오는 상태(가게 열림, 소지품 있음, 괴담톡 방 있음 등)를 `scripts/click-audit.mjs`의 시작 상태에 더하고 다시 돌린다.
   - 화면마다 찍은 사진(`_3뒤`, `*_화면0.png`)도 훑어서, 표에 안 걸린 이상(색이 튐, 정렬 어긋남, 빈 화면, 이상한 글, PC·폰 어긋남)도 찾는다.
4. 맞춰 볼 근거: **사용자 결정만.** 프로젝트 메모리(MEMORY.md와 링크된 파일), `CLAUDE.md`, 사용자 결정이 적힌 문서. 옛 Claude 점검 문서·제안은 근거가 아니다.
5. 보고: 결정과 어긋난 것 **그리고** 결정에 없어도 이상한 것 전부(통일성 없는 것부터). 항목마다 캡처를 붙이고, 화면에서 보이는 말로 쓴다(클래스 이름 X). 고치기는 사용자가 「해」 한 뒤.

## 주의

- 이미 고친 것을 시험으로 박는 것은 이 점검의 목적이 아니다. 매번 처음부터 다 눌러 본다.
- 이 도구가 「이상 없음」이어도 점검이 끝난 게 아니다. 캡처를 안 보고 표만 보고 끝내지 않는다.
- 판(브랜치)이 바뀌면 `npm run build` 다시. 시험 카드 판이 옛것이면 `.scratch/fixture`를 새로 만든다.
- 돌리는 동안 사용자가 물으면 즉답: 어디까지 눌렀는지, 남은 수(로그 `[click-audit] … 번 누름, 남은 …`).
