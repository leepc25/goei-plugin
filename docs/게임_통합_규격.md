> **⚠ Claude 반성 · 2026-10-31 (사용자 지시로 문서마다 남김)**
> 2026-10-31 Claude는 다음 잘못을 저질렀다. 이 문서를 읽는 모든 Claude는 같은 짓을 하지 않는다.
> 1. **사용자 결정을 무시했다.** 콘쥬스는 사용자가 10-26에 20세로 정했고 인계서에도 적혀 있었는데, 옛 Claude 문장(teenage high school girl)을 근거로 화장실·샤워 그림을 거부하고, 사용자가 직접 뽑은 화장실 줄까지 팩에서 뺐다. 옷도 제복인데 교복이라고 단정했다.
> 2. **사용자 말에 토를 달고 같은 주장을 되풀이했다.** 사용자가 여러 번 지적했는데도 근거를 다시 확인하지 않아 몇 시간을 허비하게 했다.

> 4. **문장을 덧대기만 하며 PixelLab을 낭비했다.** 이성해 점프 공격 5번 연속 실패, 이어폰 음악 120줄을 못 쓰게 만듦.
> 5. **답을 미루고 일을 멈춰 두었다.** 백그라운드로 돌릴 일을 돌리지 않고 대화만 했다.

작성 2026-10-21 · 주인: 「게임 통합 검수」 스레드(지휘자). 이 문서가 모든 게임 스레드의 기준이다.
`docs/게임_모듈_연결.md`(API)·`src/game/action/engine/contract.ts`(타입)와 겹치면 둘 다 맞춰야 하고, 화면·시점·소유 문제는 이 문서가 이긴다.
여기 없는 것을 정하려면 지휘자에게 먼저 묻는다. 각 스레드는 사용자에게 시연 링크를 직접 올리지 않는다(아래 7장).

## 1. 게임은 하나다

- 실행되는 게임은 **`src/game/action/main.ts`의 `mountGame(box, bridge)` 하나**뿐이다. 그림·카메라·입력·HUD·주 루프는 엔진 것 하나만 쓴다.
- 모듈은 **자기 화면을 따로 만들지 않는다.** 자기 캔버스·자기 주인공·자기 HUD·자기 터치 버튼을 가진 별도 시연판은 금지(이미 있는 것은 7장대로 정리).
- 모듈 시연은 통합 빌드에 주소 꼬리표로 들어간다: `goei-action-game.html?start=<장면>` (예: `hq`, `stage=elevator`, `arena`, `items`, `story=첫출근`). 같은 엔진, 같은 화면, 같은 조작.

## 2. 시점: 벨트스크롤 (섀도우 오버 미스타라)

- 모든 걷는 장면(층, 정비 구역 가로 칸, 훈련장, **본부 포함**)은 **옆에서 비스듬히 내려다보는 벨트스크롤**이다. 좌우 + 앞뒤 깊이(↑↓)로 걷는다. 깊이 없는 순수 횡스크롤 장면은 없다.
  - 예외는 두 가지뿐: 정비 구역의 세로 칸(로프·사다리 오르내림)과 컷인·암전 연출.
- 바닥(걷는 띠): 기본 `lane = [440, 690]` (250 논리 px, 화면의 약 35%). 최소 220px. 앞뒤 3줄 이상이 눈에 보이게 바닥에 원근(타일 줄·그림자)을 그린다.
- 벽: 바닥 위 0~440. 문·소품은 바닥선에 붙는다. 몸은 발(y) 순서로 겹친다(앞이 위).
- 카메라: 가로로만 따라간다. 세로 고정. 싸움 구간에서 잠김(「GO →」). 확대·축소 없음.

## 3. 화면 크기와 채우기

| 항목 | 값 |
| --- | --- |
| 논리 화면 | **1280×720 고정** (16:9). 1600×720, 1057×720, 1280×400, 1280×560, 887×499 같은 다른 크기 금지 |
| 도트 | 도트 1px = 논리 2px. 요원 몸 128px 도트 = 화면에서 약 256px |
| 맞추기 | 비율 유지 꽉 채우기(contain). 남는 띠는 검정 |
| PC | 창 높이·너비 중 작은 쪽에 맞춰 최대. 1280×950 창에서 캔버스 1280×720 이상, 1920×1080 창에서 1920×1080 |
| 폰 가로 | 화면 높이 100%. 844×390이면 캔버스 693×390 이상. 좌우 남는 띠에 조이스틱·버튼을 먼저 둔다 |
| 폰 세로 | 「가로로 돌려 주세요」 + 90° 돌려 꽉 채우기. 세로 화면에 게임을 작게 넣지 않는다 |
| 플러그인 창 | 창 안에서도 같은 규칙. 게임 캔버스가 창 면적의 80% 이상. 시험용 버튼 줄·키 목록은 기본 숨김 |
| 스크롤 | 게임 화면에서 페이지 스크롤 0 |

## 4. 소유 (누가 무엇을 그리고 받는가)

| 것 | 주인 | 다른 모듈은 |
| --- | --- | --- |
| 주 루프·장면 전환·카메라·월드 그리기·판정 | 전투와 조작 (`engine/`) | 손대지 않음 |
| 키보드·터치·패드 입력 | 엔진 `InputHub` (터치 그림은 `ui/`) | 키를 직접 듣지 않음. 엔진이 넘겨주는 값만 씀 |
| HUD(체력·게이지·탄·아이템 칸·미니맵·보스 체력)·메뉴·화면 효과 | 화면 표시와 터치 조작 (`ui/`, `drawHud`) | 자기 HUD를 그리지 않음. 필요한 칸은 `HudState`에 필드 추가 요청 |
| 층 모양·소품 배치·싸움 구간·규칙 장치 | 층 생성 (`stage/`) | `FloorPlan`으로만 넘김. 그림은 `drawBackground/drawForeground` 안에서만 |
| 적 AI·판정 상자·반응 | 적과 수호자 (`enemy/`) | 엔진이 그림 |
| 아이템 수치·드랍·임시 무기 | 아이템 (`items/`) | 화면 칸은 HUD가, 손에 든 물건은 엔진이 앵커에 그림 |
| 본부 장소·임무·정산 수치 | 본부 (`hq/`) | 본부 걷는 화면은 엔진 벨트 장면으로 그림. 메뉴 창만 DOM 허용 |
| 대사 상자·말풍선·컷신 대본 | 대사와 컷신 (`story/`) | 캔버스 위 겹침만. 컷신의 배경·인물 움직임은 엔진 배우(`StoryHost.actor/camera`)로 |
| 소리 | 효과음 (`audio/`) | 엔진 `GameEvent`만 받음 |
| 플러그인 창·저장·본편 연동 | 리스 플러그인 탑재 | `mountGame`만 부름. 자기 게임 화면 없음 |

## 5. 그림 규칙

- 캐릭터 클립에는 캐릭터 몸만. 가구·문·사다리·무기·든 물건·빛줄기는 따로 그리고, 엔진이 클립의 장마다 앵커(`hand`, 앉는 높이 등)에 그린다(`게임_모듈_연결.md` 2-1).
- 플레이어는 쟈알디 클립. 회색 상자 대역은 적·소품에만 허용. 흰 네모·색 막대로 사람을 그리지 않는다(본부 동료 포함: 쟈알디 클립을 색만 바꾼 대역 또는 요원 사진 말풍선).
- 그림은 새로 만들지 않는다(PixelLab 금지).

## 6. 조작 (부록 A, 하나만)

방향키 이동(↑↓ 깊이) · Shift 짧게 회피 / 누른 채 달리기 · Space 점프 · A 근접 · S 권총 · D 고유 · Q 가드 · W 필살 · E 상호작용 · R 재장전 · 1~4 아이템 · C 지원 · Z 지도 · Esc 메뉴 · H 판정 보기.
터치는 `ui/` 배치 하나. 버튼 이름·개수는 모든 장면에서 같다. 폰 가로에서 버튼은 남는 좌우 띠와 아래쪽에 두고, 플레이어가 서는 바닥 띠 가운데를 가리지 않는다.

## 7. 시연판과 보고

- 사용자에게 보여 주는 게임 링크는 **통합본 하나**(`release/demo/goei-action-game.html`, 고정 커밋 rawcdn.githack). 지휘자만 합격 판정과 함께 올린다.
- 모듈 스레드는 진행을 지휘자와 「게임 전투와 조작」에 `message_thread`로 보고한다. 사용자에게 링크를 직접 올리지 않는다.
- 기존 모듈 단독 시연판(`goei-elevator-stage`, `goei-hq`, `goei-enemy-arena`, `goei-items-demo`, `goei-story`, `goei-ui-demo`, `goei-plugin-game`)은 통합본 `?start=` 꼬리표로 바꾸거나, 개발용으로만 두고 사용자에게 보내지 않는다. `goei-sound`(소리 목록판)은 도구로 남겨도 된다.

## 8. 합격 체크리스트 (지휘자가 스크린샷으로 확인)

1. 폰 가로 844×390, 폰 세로 390×844, PC 1280×950, PC 1920×1080에서 캔버스가 3장 표대로 찬다. 페이지 스크롤 없음.
2. 제목 → 본부(벨트 장면, 쟈알디가 걸어 다님) → 임무 → 출동 → 로비 층 → 싸움 구간 → 다음 층 → 귀환·정산 → 본부가 끊김 없이 이어진다.
3. 모든 걷는 장면에서 ↑↓로 깊이가 움직이고(바닥 띠 220px 이상), 발 순서로 겹친다.
4. HUD는 하나(`drawHud`). 다른 모양의 체력 막대·아이템 칸이 동시에 보이지 않는다.
5. 터치 버튼 배치가 모든 장면에서 같고, 플레이어 서는 자리를 가리지 않는다. 대사 자막이 버튼에 겹치지 않는다.
6. 적 실제 등장·타격(히트스톱·흔들림·넉백·다운)·아이템 사용·물건 들고 던지기·권총 탄 제한이 출동 안에서 된다.
7. 대사·컷신이 같은 화면 위에서 나오고 그동안 전투가 멈춘다.
8. 콘솔 오류 0 (소리 사용자 동작 전 경고 제외). `npm test`와 게임 브라우저 시험 전부 통과.
9. 플러그인 창(Risu 안)에서 같은 통합본이 뜨고 위 1~5를 만족한다.
