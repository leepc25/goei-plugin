# 게임 통합 현황

작성 2026-10-21 · 관리: 「게임 전투와 조작」 스레드 · 연결 약속은 `docs/게임_모듈_연결.md`

## 게임은 하나다

- 게임은 `release/demo/goei-action-game.html` 하나다. 진입점은 `src/game/action/main.ts`의 `mountGame(box, bridge)`이고, 모듈 연결은 `src/game/action/engine/modules.ts` 한 곳에서 한다.
- 플러그인 게임 창도 같은 `mountGame`을 부른다(`src/game/play.ts`).
- 각 모듈의 단독 시연판(`goei-hq`·`goei-elevator-stage`·`goei-enemy-arena`·`goei-items-demo`·`goei-story`·`goei-ui-demo`·`goei-sound`·`goei-graybox` 등)은 모듈 시험용이다. 사용자에게 게임으로 내보내지 않는다. 새 기능은 통합판에서 돌아야 끝난 것이다.

## 작업 규칙

1. 각 스레드는 자기 폴더만 고친다. 엔진(`engine/`)과 `main.ts`는 「전투와 조작」이 고친다.
   - 예외 1: `engine/itemsLink.ts`는 아이템 연결 전용이므로 「아이템과 무기」가 직접 고친다.
   - 예외 2: `engine/modules.ts`는 자기 모듈을 잇는 몇 줄까지만 고친다(소리가 한 것처럼). 그보다 크면 바꿀 줄을 보내 준다.
2. 올리기 전에 main을 합친다. 그다음 아래 셋이 통과해야 main에 올린다.
   - `npm run build`
   - `node tests/engine-browser.mjs`
   - `node tests/game-loop.mjs` (본부 → 출동 → 승강기 층 여러 개 → 철수 → 정산 한 바퀴)
3. `release/demo/goei-action-game.html`은 빌드가 만든다. 손으로 고치지 않는다.

## 모듈별 상태

| 모듈 | 폴더 | 통합판 연결 | 남은 일 |
| --- | --- | --- | --- |
| 전투와 조작 (엔진) | `engine/` | 됨: 조작·판정·경직·넉백·잡기·든 물건·장면 흐름 | 적 모듈의 적 잡기, 효과 중복 정리, 돌린 화면 좌표 |
| 화면 표시와 터치 | `ui/` | 됨: 껍데기·메뉴·HUD·터치·화면 효과·설정 | 채우기 모드(엔진 1280 고정이라 꺼 둠) |
| 효과음과 음악 | `audio/` | 됨: 사건 소리·메뉴 소리·음량 밀대·발소리 | 엔진이 걸음마다 `step` 사건을 내면 발소리 계산 삭제 |
| 본부와 임무 흐름 | `hq/` | 됨: 본부 → 임무 → 출동 → 정산 | 플러그인 저장 칸(`bridge.slot`), 요원 사진 |
| 차원 승강기 층 | `stage/` | 됨: 출동 = 승강기 층 | 승강기·승객 대사를 대사 모듈로 넘기기(hooks) |
| 적과 수호자 | `enemy/` | 됨: 도감에 있는 종류 | 없는 종류는 임시 적(Thug)으로 떨어짐 → 적 스레드가 채우는 중 |
| 아이템과 무기 | `items/` | 됨: 소모품·줍기·탄·들기·던지기·임시 무기 | 적 드랍 이중, 부서지는 물건, 층 물건 배치, 상인 |
| 대사와 컷신 | `story/` | 됨: 말풍선·층 안내 방송·대화창이 열리면 전투 멈춤 | 승강기·승객 대사 연결, 후송·귀환·첫 투입 컷신 |
| 리스 플러그인 탑재 | `src/game/play.ts`, `bridge.ts` | 됨: 플러그인이 `mountGame` 호출 | 저장 칸·사진·보고 문구(엔진 쪽에서 고침) |

## 겹치는 것과 정한 주인

| 겹침 | 지금 | 정한 것 |
| --- | --- | --- |
| 키 입력 | 엔진 `Input`(창 keydown)과 껍데기 `InputHub`가 둘 다 키를 듣는다. 터치·패드는 껍데기가 가짜 키로 엔진에 넘긴다 | 게임 조작은 엔진이 읽는다. 껍데기는 메뉴·Esc·터치·패드만 맡는다. 대화창이 열린 동안의 키는 `modules.ts`가 대사 모듈로 넘긴다 |
| HUD | 엔진 기본 HUD와 껍데기 HUD | 껍데기 HUD만 쓴다(엔진 `hud: false`). 엔진은 `hudState`로 값만 준다 |
| 맞을 때 효과 | 엔진의 불꽃·고리와 껍데기 `fx.onGameEvent('hit')`가 같이 그려진다 | 화면 효과는 껍데기가 맡는다. 껍데기가 있을 때 엔진의 불꽃·고리는 끈다 |
| 적 드랍 | 아이템 `dropFromKill`과 적 모듈 `setDropHook`가 둘 다 굴린다 | 적 모듈이 드랍을 정하고, 아이템이 바닥에 떨어뜨린다(`spawnEnemyDrops`). `itemsLink`의 enemyDie 드랍은 뺀다 |
| 층 물건 배치 | `itemsLink`가 층마다 임시로 물건 둘·무기 하나를 놓는다 | 아이템의 `furnishFloor`로 옮긴다. 층 모듈은 지형·장치만 놓는다 |
| 승강기 방송·승객 대사 | 층 모듈 기본 문장과 대사 모듈 `board`·`passenger_*`가 둘 다 있다. 엔진은 층에 내릴 때마다 `say('board')`를 부른다 | 대사 모듈이 맡는다. 층 모듈 `createElevatorStage(store, hooks)`의 `hooks.elevator`·`hooks.passenger`를 대사 모듈이 채운다. 엔진의 `say('board')` 호출은 그때 뺀다 |
| 탄약 | 엔진 권총의 탄창·예비탄과 아이템 `ItemRun`의 탄 | 권총 탄창은 엔진, 예비탄 수는 아이템이 정하고 `itemsLink`가 맞춘다. 임시 총의 탄은 아이템 |
| 잡기 | 엔진 잡기는 엔진 `Fighter`만 잡는다 | 적 모듈 `Enemy`의 `grabbable`·`state`도 엔진이 본다 |

## 각 스레드에 부탁한 것 (2026-10-21)

- 본부와 임무 흐름: `hq/`만 고쳐 통합판에서 돌게 한다. 정산 결과에 출동 id를 넣는다.
- 차원 승강기 층: 엔진 연결은 이미 되어 있다(`modules.ts`의 `createElevatorStage`). 할 일은 `stage/` 안에서 통합판 한 바퀴(`tests/game-loop.mjs`)가 막히지 않게 하는 것과, 대사 모듈과 hooks 모양을 맞추는 것이다.
- 적과 수호자: 층 모듈이 부르는 모든 kind를 도감에 넣는다. 잡기는 엔진이 `grabbable`·`state`를 보게 고친다. `drawBack`은 이미 몸보다 먼저 그린다.
- 아이템과 무기: `itemsLink.ts`를 직접 고쳐 위 세 가지(적 드랍·부서지는 물건·층 물건 배치)와 상인을 넣는다.
- 대사와 컷신: `stage`의 hooks를 채우는 함수를 내보낸다(예: `stageHooks(story)`). 후송·귀환 컷신은 엔진이 `run:end` 때 부른다.
- 화면 표시와 터치: 엔진이 돌린 화면 좌표를 `shell.stage.toGame`으로 읽게 고친다(엔진 쪽 일).
- 효과음과 음악: 그대로. 엔진이 `step`을 내면 알린다.
- 리스 플러그인 탑재: 저장 칸·사진·보고 문구는 엔진 쪽에서 고친다.
