# 게임 통합 현황

작성 2026-10-21 · 관리: 「게임 전투와 조작」 스레드 · 연결 약속은 `docs/게임_모듈_연결.md`

## 게임은 하나다

- 게임은 `release/demo/goei-action-game.html` 하나다. 진입점은 `src/game/action/main.ts`의 `mountGame(box, bridge)`이고, 모듈 연결은 `src/game/action/engine/modules.ts` 한 곳에서 한다.
- 플러그인 게임 창도 같은 `mountGame`을 부른다(`src/game/play.ts`).
- 각 모듈의 단독 시연판(`goei-hq`·`goei-elevator-stage`·`goei-enemy-arena`·`goei-items-demo`·`goei-story`·`goei-ui-demo`·`goei-sound`·`goei-graybox` 등)은 모듈 시험용이다. 사용자에게 게임으로 내보내지 않는다. 새 기능은 통합판에서 돌아야 끝난 것이다.

## 작업 규칙

1. 각 스레드는 자기 폴더만 고친다. 엔진(`engine/`)과 `main.ts`는 「전투와 조작」이 고친다.
   - 예외 1: `engine/itemsLink.ts`는 아이템 연결 전용이므로 「아이템과 무기」가 직접 고친다.
   - 예외 2: `engine/modules.ts`는 자기 모듈을 잇는 몇 줄까지만 고친다(소리가 한 것처럼). 그보다 크면 바꿀 줄을 보내 준다.
2. 올리기 전에 main을 합친다. 그다음 아래 셋이 통과해야 main에 올린다.
   - `npm run build`
   - `node tests/engine-browser.mjs`
   - `node tests/game-loop.mjs` (본부 → 출동 → 승강기 층 여러 개 → 철수 → 정산 한 바퀴)
3. `release/demo/goei-action-game.html`은 빌드가 만든다. 손으로 고치지 않는다.

## 정한 것 (겹침 정리, 끝남)

- 키 입력: 게임 조작은 엔진, 메뉴·Esc·터치·패드는 껍데기. 대화창이 열리면 `modules.ts`가 키를 대사 모듈로(Space·Enter·E·Z·A 넘기기, 1~9 선택, Esc 건너뛰기). 본부 메뉴 창이 열리면 Esc는 창 닫기.
- HUD: 껍데기 HUD 하나. 본부에서는 전투 HUD를 그리지 않는다.
- 맞을 때 효과: 껍데기 fx만(`world.hitFx = false`).
- 적 드랍: 적 모듈이 정하고 아이템이 떨어뜨린다. 층 물건 배치: 아이템 `furnishFloor`.
- 승강기 방송·승객 대사: 대사 모듈 `stageHooks()` → 층 모듈. 엔진은 따로 부르지 않는다.
- 저장: 이어하기는 본부 자동 저장이 있을 때만 보인다(`goei-game-saved`).

## 시험 (올리기 전에 전부)

`npm run build` → `npm test` → `node tests/engine-browser.mjs` → `node tests/game-loop.mjs` (+ 자기 모듈 브라우저 시험)
