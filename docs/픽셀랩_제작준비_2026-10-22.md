# PixelLab 제작 준비 · 2026-10-22

현재 작업은 조사와 요청서 준비다. **생성 호출 0회, 차감 0회, 새 그림 없음.** 캐릭터 동결을 유지한다. [별도 스레드 지시문](parallel/별도스레드_10개_지시문.md)의 9번(본부 출입구)·10번(빈 복도 환경 컷씬)은 사용자가 해당 제작 지시를 전달한 세션에서 실행한다. 이 문서는 생성 실행이나 시각 승인을 대신하지 않는다.

## 연결과 실행 가능 범위

- 현재 세션의 도구 목록에서 `PixelLab`, `pixellab`, `search_help`를 검색했으나 PixelLab MCP 도구는 없다. 공식 문서 조회와 로컬 요청서 작성만 수행했다.
- 현재 환경 상태 조회에는 설정된 비밀값·외부 인증 주입 항목이 없다. 과거 `game-src/action/jyaldi-v5/scripts/mcp.py`는 이전 실행 환경의 프록시 인증 주입과 CA 경로에 의존하므로 현 세션에서 바로 실행 가능한 연결로 취급하지 않는다. 인증값을 읽거나 출력하지 않았다.
- 실제 제작 세션은 PixelLab MCP 연결 후 도구 목록 및 무료 `search_help`를 확인해야 한다. API를 선택한다면 공식 v2 인증을 별도로 구성하고 현재 스키마를 읽는다. MCP 도구 이름을 임의 REST 경로로 바꾸어 호출하지 않는다.
- 비밀키를 채팅·문서·저장소에 붙이지 않는다. 도구 연결 없이 생성 완료, 잔액 조회 완료 또는 작업 ID 발급을 주장하지 않는다.

## 비용 근거와 견적 구분

2026-10-22 확인한 [공식 MCP 문서](https://api.pixellab.ai/mcp/docs)의 생성 차감 단위다. 실제 제작 세션에서 다시 확인한다.

| 도구 | 확인된 차감 | 적용 판단 |
| --- | --- | --- |
| `create_image_pixen` | 이미지당 1회 | 문 1종 또는 빈 복도 정지 시안에 적합. |
| `edit_image_pixen` | 이미지당 1회 | 제한적인 색·소품 수정. 큰 자세 변화 해결책으로 사용하지 않는다. |
| `animate_with_skeleton_v3` | 3장 2회 / 4~14장 3회 / 15장 4회 | 향후 캐릭터 작업에만 해당. 문은 사람 뼈대로 만들지 않는다. |
| `animate_image` | 픽셀 면적·장수에 비례. 공식 예: 64²×8장 1회, 128²×16장 4회 | 로컬 문 동작 견적은 아래처럼 계산하되 호출 전 도구 도움말과 대조. |
| `create_image_pro` | 10~25회 | 최소 시안용 기본 선택 아님. |

Pixen 캔버스는 가로·세로 4의 배수이고 총 면적 최대 512²다. 투명 배경은 총 면적 256²까지다. 따라서 640×360 정지 배경은 면적 조건에 들어가지만 투명 배경으로 만들 수는 없다. `animate_image`의 첫 장은 최대 256×256이므로 640×360 전체 컷을 그대로 입력하는 방식은 쓰지 않는다.

ProFlash는 저장소의 과거 “160px 6회”를 현행 확정 가격으로 제시하면 안 된다. [공식 API 명세](https://api.pixellab.ai/v2/openapi.json)는 최초 이미지 잠정 5회와 인증된 `GET /v2/pro-flash/cost` 조회를 안내한다. 조회 인수는 작업 종류·폭·높이·방향 수이며 실제 청구는 완료 결과에 기록된다. 이 세션에서는 인증 견적을 조회하지 않았다. 이전 잔액 역시 현재 잔액으로 인용하지 않는다.

## 9번: 본부 출입구 최소 제작 패키지

**첫 단계는 문 1종 정지 시안 1장, Pixen 1회다.** 닫힘·열림 세트나 여러 색상 문을 한꺼번에 만들지 않는다. 조사·프롬프트·검수판 준비는 생성 전 수행한다.

1. 첫 사무실 화면과 본부 도면에서 문 영역, 문턱 좌표, 사람 표시 높이, 시점, 벽·문틀 색을 기록한다. 미측정 상태에서 아래 예시 치수를 게임 확정 규격으로 간주하지 않는다.
2. 예시 작업 캔버스는 128×160 투명 PNG. 실제 측정 결과에 맞춰 확정하고, 닫힌 문 한 개를 문틀·문턱까지 포함한다. 출입 표식과 E 안내는 게임 UI가 읽을 수 있는 별도 요소로 유지한다.
3. 1× 원본과 게임 표시 배율로 비교한다. 캐릭터 없이 문틀·벽·바닥 접점만 검수하고 원본을 덮어쓰지 않는다.

도구 스키마 확인 후 적용할 요청 초안:

```json
{
  "description": "One closed office doorway for a pixel-art headquarters in a side-view belt-scrolling game. A clearly readable door opening, rigid rectangular frame, visible threshold and a small blank sign plate. Muted cool-gray office materials, consistent hard pixel edges. Isolated doorway only; no people, no text, no corridor background, no perspective drift. Final proportions and palette follow the measured headquarters reference.",
  "width": 128,
  "height": 160,
  "no_background": true,
  "view": "side",
  "seed": 20261022
}
```

문 구조·시점이 실패하면 프롬프트만 바꾸어 재호출하지 않는다. 실제 참조 선택, 시점 지정, 문짝과 문틀의 분리 필요성을 진단한다. 다음 단계 산출물은 승인된 시안, 문턱 앵커, 열림 방향, 원본 해시, 실제 표시 배율이다. 위치와 충돌은 코드팀이 연결하며 이미지 생성이 출입 버그 수정 자체는 아니다.

저장 위치: `game-src/art/hq-door-round2/`. 제작 담당은 이 디렉터리의 호출 원장을 유지하고, AGENTS.md의 요원별 `spend.log` 규칙과 달리 이번 자산은 환경 제작 건임을 명시한다.

## 10번: 빈 복도 환경 컷씬 최소 제작 패키지

**첫 단계는 빈 복도 정지 구도 1장, Pixen 1회다.** 캐릭터·이전 컷씬 프레임을 생성 입력으로 쓰지 않는다. 최종 재생 화면은 640×360이며 생성 해상도와 표시 해상도를 기록한다. 예시로 320×180 원본을 정수 2배 표시할 수 있지만 현재 게임 픽셀 밀도와 대조한 뒤 선택한다.

구도 요청 초안:

```text
Empty headquarters office corridor, pixel art for a side-view belt-scrolling game, locked camera, one closed office doorway as the focal point, muted cool-gray walls and readable floor plane, quiet first-day-at-work atmosphere. No people, no human silhouettes, no writing, no blur. Keep the doorway and floor geometry stable. Composition reviewed at 640 by 360 display resolution.
```

시안이 채택되면 배경은 고정하고 문 부분만 따로 제작한다. 계획은 닫힘 유지 → 손잡이/문짝의 움직임 시작 → 점진적으로 열림 → 열린 상태 유지다. 문틀과 바닥은 모든 장에서 같은 좌표여야 한다. 열린 끝 장과 닫힌 첫 장이 없는 상태로 전체 환경을 열린 생성에 맡기지 않는다.

| 단계 | 최소 작업량 | 차감 견적 |
| --- | --- | --- |
| 빈 복도 구도 | 정지 배경 1장 | Pixen 1회, 첫 실행 범위 |
| 문 동작 기준 | 닫힘·열림 각각 1장 | Pixen 계열 2회 예상. 동일 구조 유지 여부를 먼저 검수 |
| 문 열림 동작 | 128×160 영역, 8장, 시작·끝 고정 | 저장소 공식 조사식 `ceil(폭×높이×장수/65536)` 기준 3회 예상. 현행 도움말 재확인 필요 |
| 조립·검수 | 새 배경+새 문을 640×360 HTML에서 재생 | 생성 차감 없음 |

전체 예시 견적은 6회지만 **현재 허용된 실행을 뜻하지 않는다**. 9번의 새 문이 실제 채택되고 크기·조명까지 맞으면 기준 그림을 공유해 중복 생성을 줄일 수 있다. 자동 공유나 구 캐릭터 재활용으로 대체하지 않는다. ProFlash로 바꾸면 별도 견적이 필요하다.

프레임 수를 늘리거나 같은 프레임을 복사하는 것으로 부드러움을 판정하지 않는다. 실제 경첩 중심, 문짝 회전의 단계 차이, 팔레트 깜빡임, 문틀 흔들림, 재생 시간표를 검수한다. 닫힘·열림의 의도된 정지는 타이밍 데이터로 기록한다. 이미지 중간 보간을 쓴 경우 생성 원본과 구분하며 픽셀 경계와 잔상을 별도로 확인한다.

저장 위치: `game-src/art/cutscene-production-round2/`. 원본 컷씬·런타임 타이밍은 덮어쓰지 않는다. 생성 프레임, 원본 해시, 요청·응답 작업 ID, 타이밍 JSON, HTML 검수판을 전달한다. 기존 컷씬 재생 성능 수정은 통합/자산 담당의 별도 작업이다.

## 캐릭터 재개 시에만 사용하는 대기 목록

이번 문·복도 작업에 포함하지 않는다. 캐릭터 제작이 다시 지시되면 기준표와 몸 치수를 먼저 특정하고 무술 근거·지지 발·손 번갈이·도구 도움말을 확인한다. 측정하지 않은 관절 좌표를 준비 완료라고 기입하지 않는다.

- 기준 그림이 확정된 뒤 걷기 8장 + 달리기 8장: skeleton v3 합계 6회. 큰 이동은 핵심 자세와 접지를 먼저 설계한다.
- 시작 3장 + 정지 3장 추가: 합계 4회. 앞선 루프 검수 후 별도 실행한다.
- 모든 요원·방향·생활 동작을 동시에 생성하지 않는다. 같은 얼굴·복식·팔레트 검수와 실제 이동 거리/재생 타이밍 검사를 분리한다. 기술 테스트 통과를 사용자 시각 승인으로 기록하지 않는다.

## 실행 직전 인계 체크

1. 사용자가 지시한 대상이 9번 문인지 10번 환경 컷인지 기록한다. 문서 열람을 생성 지시로 간주하지 않는다.
2. 연결된 실제 PixelLab 도구 목록과 무료 도움말을 확인한다. 지원 크기·투명 여부·끝 장 입력·비용을 현재 값으로 채운다.
3. 원본별 승인 근거와 파일 해시, 문턱/경첩 좌표, 표시 배율을 기록하고 첫 호출의 차감 횟수를 미리 알린다.
4. 원장에 시각·담당자·도구·작업 ID·입력 해시·크기·장수·견적·실제 청구·결과 경로·검수 결과를 남긴다. 여러 작업자가 같은 계정을 쓰면 전체 잔액 차이만으로 개인 소비량을 산정하지 않는다.
5. 첫 결과를 1×/실제 화면에서 검수한다. 실패하면 원인을 보고하고 방식을 바꾼다. 기존 파일을 덮어쓰거나 몰래 재생성하지 않는다.

이 문서의 검증 범위는 저장소 인계·생산 상태·도구 목록·공식 공개 문서 대조다. 생성 결과, 새 문 치수 실측, PixelLab 인증 연결, 실제 계정 견적 및 사용자 시각 승인은 아직 없다.
