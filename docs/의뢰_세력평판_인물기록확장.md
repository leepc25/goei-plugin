# 의뢰서 · 인물 기록에 세력 평판 더하기 (2026-10-26)

> 의뢰: 필드 세계 설계 스레드 → **인물 기록 담당 작업자**
> 상태: **설계 의뢰. 사용자 확인 전 코드 시작 금지**(인계서 규칙 2). 설계안을 먼저 문서로 내고 사용자 결정을 받은 뒤 구현.
> 함께 볼 문서: `docs/인물기록_구현현황.md`, `docs/인물기록_호감_통합설계_3판.md`, `docs/인물기록_프롬프트_설계.md`, `docs/인물기록_규칙대조표.md`, `docs/필드_세계_NPC_설계.md`(6-6 소란도, 8장 세력·경찰·출입).

---

## 1. 왜 필요한가

- 인물 기록(v0.16.62)의 호감은 전부 **인물 한 명 단위**다. 「세력이 유저를 어떻게 보나」는 없다.
  - `Person.faction`은 소속 표시뿐, `relations-base.json`의 `orgs`(40칸)는 인물 호감 시작값으로 한 번 쓰이고 끝(`src/core/people/base.ts:22`), 세력 문서(`docs_faction`)는 세력 사이 변화를 적는 **글**이고 지침에 「한 구성원의 행동은 그 사람의 행적이지 세력 변화가 아니다」라고 돼 있다.
- 필드에는 이름 없는 몹(경비·조원·사원)이 많다. 몹은 개인 기록이 없으므로 **유저에 대한 기억은 세력 단위로만** 가질 수 있다.
- 필드 따로 평판을 만들면 본편과 필드가 또 갈라진다(사용자 판단: 인물 기록을 손보는 쪽).

## 2. 목표

세력을 **「인물처럼 장부를 가진 대상」** 으로 하나 더 둔다. 호감 엔진·살아 있음 판정·되감기·화면을 그대로 다시 쓴다. 본편과 필드가 같은 값을 읽는다.

## 3. 설계 요구 (의뢰 내용)

### 3-1. 저장
- `PeopleStore`에 세력 항목을 더한다. 열쇠는 조직 코드(`A00`·`B00`·`C00`·`D00`·`E00` 등, 사용자 추가 세력 포함).
- 시작값 = `relations-base.json` `orgs`의 「세력 > 유저 소속」(이미 있는 표). 유저 소속은 `store.identity`.
- 값은 저장하지 않고 변경 기록(`Change`)에서 매번 계산(인물 호감과 같은 원칙). `Change.who`에 `세력:B00` 같은 대상 표기를 쓰거나 별도 필드 — 작업자가 정함.
- **표적은 이 의뢰 범위에서 뺀다**(2026-10-26 사용자: 「필드에서 몹들이 적대하게 할 방법만 있으면 된다. 수배를 때리면 서사에서도 모든 게 수배로 귀결된다」). 표적은 필드 전용 게임 상태로 필드 저장 칸에 두고 필드 쪽에서 만든다(필드 세계 설계 8-6). 인물 기록·갱신기·본편 주입은 표적을 모른다

### 3-2. 값과 단계
- 인물 호감 단계(끌림·애정 등)는 세력에 맞지 않는다. **세력 전용 단계표** 제안: 적대 · 경계 · 중립 · 호의. 범위·경계값은 작업자 제안.
- 계기 이름은 기존 `CUES` 재사용 가능(도움·큰도움·실망·무시·배신·파탄·중대위반 …). 기준 메시지당 상한·예외 계기 규칙 동일.
- **개인 호감은 세력으로 번지지 않는다.** 쟈알디가 유저를 좋아해도 관리국 평판은 그대로.

### 3-3. 무엇이 바꾸나

| 출처 | 방법 | 비용 |
| --- | --- | --- |
| 필드 | 그 소속 사람(**몹 포함**)이 목격한 유저 행동 → 게임 코드가 세력 계기로 기록. `src/core/people/field.ts`에 세력 경로 추가. 필드 사건(`FieldEvent`)에 「목격한 소속」 정보가 필요하면 형식을 제안 | 모델 0 |
| 본편 | 갱신기 출력에 **세력 계기** 칸 하나. **세력이 집단으로 반응할 때만**(공식 감사·거래 성사·출입 금지 같은 집단 반응), 원문 인용 필수. | 추가 호출 없음, 출력 조금 늘어남 |

- 세력 문서(`docs_faction`)와 겹치지 않게 정리할 것: 문서 = 세력끼리의 일(글), 평판 = 세력 → 유저(값).

### 3-5. 쓰이는 곳
- **본편 주입**: 그 세력이 장면에 나올 때만 한 줄(영어 단계 문장, 인물 기록 블록과 같은 방식). 예: `Fake Bureau → {{user}}: hostile; marked as a target.` 장면 세력 판정은 장면 인물의 소속 + 상태창 장소로.
- **게임 다리**: `GameBridge.people`(`src/host/game/people.ts`)에 세력 평판 읽기 추가. 필드는 몹·경비의 첫 반응(무시·지켜봄·경고·쫓아냄·공격)을 이 값으로 정한다.
- **화면**: 위키 탭 「이 채팅의 인물」 옆에 세력 목록(단계·근거 기록·취소·고정).
- **설정**: 기능 켜기·끄기(`$pp_*` 방식), 주입 켜기·끄기.

## 5. 위험과 확인할 것

1. 갱신기 지침이 커지고 출력 칸이 늘어 **기존 인물 갱신 정확도가 떨어질 수 있다** → 기능 끔 상태에서 지침·출력이 지금과 같아야 함(절 표식으로 빼기). 켬 상태 정확도는 측정 세트로 확인.
2. 세력 계기 남발(구성원 한 명의 일을 세력 반응으로 착각) → 지침에 「집단 반응만」 + 인용 검사 + 기준 메시지당 상한.
3. 저장 구조 변경 → 옛 채팅은 세력 항목 없이 읽혀야 함(빈 값 = 시작값).
4. 필드 쪽 연결은 필드 세계 설계 구현과 겹친다 → 다리(읽기)와 `field.ts`(쓰기)까지만 이번 범위, 몹 반응 로직은 필드 쪽.
