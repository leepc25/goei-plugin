# QC 09 · 개선 제안 나1 (본체에서 세계 자료·설치 자료 떼어 내기) 구현 기록 — 2026-10-29

> **⚠ Claude 반성 · 2026-10-31 (사용자 지시로 문서마다 남김)**
> 2026-10-31 Claude는 다음 잘못을 저질렀다. 이 문서를 읽는 모든 Claude는 같은 짓을 하지 않는다.
> 1. **사용자 결정을 무시했다.** 콘쥬스는 사용자가 10-26에 20세로 정했고 인계서에도 적혀 있었는데, 옛 Claude 문장(teenage high school girl)을 근거로 화장실·샤워 그림을 거부하고, 사용자가 직접 뽑은 화장실 줄까지 팩에서 뺐다. 옷도 제복인데 교복이라고 단정했다.
> 2. **사용자 말에 토를 달고 같은 주장을 되풀이했다.** 사용자가 여러 번 지적했는데도 근거를 다시 확인하지 않아 몇 시간을 허비하게 했다.
> 3. **허락 없이 문서를 지웠다.** 「지침을 지우라」는 말만 듣고 목록을 보여 주지도 않고 96개를 지웠다가 되살렸다(결과물 삭제 금지 규칙 위반).
> 4. **문장을 덧대기만 하며 PixelLab을 낭비했다.** 이성해 점프 공격 5번 연속 실패, 이어폰 음악 120줄을 못 쓰게 만듦.
> 5. **답을 미루고 일을 멈춰 두었다.** 백그라운드로 돌릴 일을 돌리지 않고 대화만 했다.
>
> 지킬 것: 사용자 결정·위키가 근거다. 옛 Claude 자료는 근거가 아니다. 사용자 말에 토 달지 않는다. 무엇이든 지우기 전에 목록을 보여 주고 허락받는다. 실패하면 덧대지 말고 다시 쓰거나 바꾼다.

## 한 줄

본체(goei-body.js)에 번들하던 데이터 JSON 1.4MB 를 자료 팩 두 개(`goei-data-world.*`·`goei-data-install.*`)로 빼서 따로 받는다. 본체 **3.42MB·18조각 → 2.00MB·10조각 (−41.5%)**. 세계 자료는 본체가 처음 뜰 때 받아 pluginStorage 에 두고 그 뒤로는 저장소에서 읽는다. 설치 자료는 설치·점검 때만 받고 저장하지 않는다.

## 받기 흐름

### 세계 자료 (본체 부팅)

```
시작기(옛·새) ── 본체 조각 받기/저장소 ──▶ runBody ──▶ body.start()
  start():
    1. loadWorldData()   (src/host/datapack.ts)
       a. pluginStorage goei:data-world 읽기 → 길이·FNV 지문이 본체 지문과 같으면 applyWorldPack → 끝 (받기 없음, 수 ms)
       b. 없음·판 다름·깨짐 → goei-data-world.json 받기 → 목록 hash ≠ 본체 지문이면 「아직 이 판의 세계 자료가 올라오지 않았어요」
          → 조각 받기 → 길이 → sha256(crypto.subtle 있으면) 또는 hash 확인 → applyWorldPack → 저장(실패해도 이번엔 받은 자료로)
       c. 실패 → 전역 __goeiWorldFail(1분 재시도 억제) → 본체가 받기 창(src/host/datapanel.ts) 띄우고 throw
    2. (성공 뒤에만) loadPrefs → 위키·토크나이저 → 플로팅 버튼·감시 → 처리기 넘김
```

| 시작기 | 받기 실패 때 | 다시 받기 성공 뒤 |
|---|---|---|
| **옛 시작기** (`release/goei-plugin.js`, 기기에 깔린 것) | 시작 실패에 로그만 남기고 창을 안 띄운다 → **본체가 띄운 창**(까닭·다시 받기·닫기, 시작기 창과 같은 모양 `PANEL_CSS`)이 유일한 안내. 옛 시작기는 메시지 표시·요청마다 본체를 다시 실행하므로 실패 기록·창은 전역·DOM 으로 하나만 | 채팅을 그대로 다시 저장해 Risu 가 다시 그리게 → display 처리기 → 시작기가 본체를 다시 시작(저장소에서 읽음). 메시지 없는 채팅이면 다음 메시지·요청·카드 열기 때 |
| **새 시작기** (`src/main.ts`) | 본체 창이 떠 있으면(`__goeiBodyPanel`) 자기 창을 겹치지 않는다. 본체 코드 자체가 깨진 경우는 전처럼 시작기 창 | 본체가 고리 `__goeiRelaunch` 를 불러 시작기가 `ensure(true)` → 바로 다시 뜬다 |

규칙 확인: 어떤 기능도 저장소에서 영구히 받아 오는 데 의존하지 않는다 — 한 번 받은 자료는 pluginStorage 에 있고, 시작은 저장소에서 읽는다. 판이 바뀌면(플러그인 업데이트) 본체 지문이 달라져 한 번 다시 받는다.

### 설치 자료 (설치·점검)

`src/host/install.ts checkInstall()` 앞에서 `ensureInstallData(progress)` 가 팩을 받아 `setInstallData()`. 설치·점검 페이지는 받는 동안 「설치 자료 목록 받는 중…」「설치 자료 받는 중 n/3」 을, 실패하면 까닭과 **「다시 점검」** 단추를 보인다(`src/ui/editor/install.ts`). 같은 세션에서 두 번째 점검부터는 받지 않는다.

## 스스로 내린 결정

| 결정 | 근거 |
|---|---|
| 설치 자료는 pluginStorage 에 저장하지 않는다 | 설치·점검은 이미 네트워크 동작(사진·아이콘·위키·토크나이저를 받음)이고 자주 열지 않는다. 530KB 를 늘 저장소에 두면 본체 다이어트 이득의 1/3 이 사라진다. 실패하면 화면에 까닭과 「다시 점검」이 있고, 저장소에서 영구히 받아 오는 데 의존하는 기능도 없다(설치 자체가 저장소에서 사진을 받는 동작) |
| 세계 자료 지문은 길이 + FNV(부팅) · sha256/FNV(받기) | 부팅 때 880K 글의 FNV 는 수 ms(동기) 이고 crypto.subtle 이 없는 환경에서도 된다. 받기 뒤는 본체 받기와 같은 순서(sha256 있으면 sha256, 없으면 hash) |
| 받기 창은 본체가 띄운다 (시작기 창 재사용이 아니라 같은 모양) | 옛 시작기는 start() 실패에 창을 안 띄운다. 시작기 창의 「다시 받기」는 본체를 다시 받는 단추라 자료 받기에 맞지 않다. CSS 만 `loader/panel.ts PANEL_CSS` 로 공유 |
| 새 시작기에 고리 두 개(`__goeiBodyPanel`·`__goeiRelaunch`) | 창이 둘 겹치지 않게, 다시 받기 뒤 사용자가 아무것도 안 해도 뜨게. 옛 시작기에서는 없어도 동작(채팅 다시 저장) |
| 자료 없을 때 records.ts export 는 던진다 | 지시(조용히 빈 배열 금지). 부팅 순서상 실제로는 안 불리고, 불리면 부팅 순서가 깨진 것 |
| 저장소 사용량 표에 「세계 자료」 줄 추가(지우기 단추 없음) | 그 표는 저장소에 있는 것을 다 보여 주는 표라 870KB 항목을 빼면 표가 틀린다. 지우기는 본체가 뜰 때 바로 다시 받으므로 의미가 없어 두지 않음 |
| 시험 초기화는 `tests/data-init.mjs` 하나 | `dist-test/core.mjs` 는 빌드가 만드는 입구가 이 도우미로 자료를 넣고 `core.bundle.mjs` 를 그대로 내보내므로 `../dist-test/core.mjs` 를 쓰는 시험 50여 개는 손대지 않았다. 소스를 esbuild 로 바로 묶는 시험(people-*·visit) 은 `buildWithData()`(splitting 으로 records.ts 사본을 하나로) |
| 브라우저 틀은 가짜 저장소에 팩을 미리 둔다 | 본체를 미리 두는 틀(14벌)과 같은 뜻(저장소에 자료가 있는 보통 경우). 받기 자체는 qc-loader·browser 시작기 절·install 에서 본다 |
| 1분 재시도 억제를 전역(`globalThis.__goeiWorldFail`)에 둠 | 옛 시작기가 표시마다 본체를 다시 실행해 모듈 상태가 매번 새로 생기기 때문 |
