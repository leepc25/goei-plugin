## ④ 스스로 내린 결정

- 결정: 편집 창 본문이 600px 이하면(화면 폭과 무관) 760px 이하와 같은 한 열·드롭다운 배치를 쓴다(컨테이너 쿼리). 근거: 사용자 규격은 「760px 이하는 한 열」인데 폰 가로(844)와 창 폭 50~60% 는 화면이 760을 넘어도 본문 칸이 조작 폭(320)보다 좁아 실제로 넘쳤다. PC 1100×900 기본(90%)은 본문이 약 730px 이라 지금 배치 그대로다(사진 `ed-*-pc.jpg`). 사용자가 정한 수치(높이 34·이름 칸 200·입력칸 320)는 바꾸지 않았다.
- 결정: 기능 페이지의 고급 칸은 시작 전이든 뒤든 늘 이 채팅. 근거: 그 페이지는 범위 전환이 없고 이 채팅 값을 보여 준다(같은 페이지의 다른 값도 이 채팅). 고급 페이지(gen)만 범위를 따른다.
- 결정: 「저장」 단추로 같은 글을 다시 저장하면 채팅에 같은 값을 다시 쓰는 것은 그대로 둔다(사용자가 누른 저장이라 생략하지 않음). 시험은 범위가 맞는지만 본다.
- 결정: 폰 가로 844 에서 편집 창은 PC 처럼 창 폭 % 를 따르고, 쓸기 뒤로·하단 서랍은 760 이하에서만(기존 설계). 시험의 기대를 이것에 맞췄다.

## ⑤ 고치지 못했거나 확인이 필요한 것

- 폰 가로(844×390) 시작 화면은 세력 그림이 높이를 많이 먹어 「출발」 위로 한 줄 정도만 보인다(스크롤로 됨, 사진 `start-picker-land.jpg`). 넘침·잘림은 없어 고치지 않았다. 배치를 바꿀지는 사용자 판단.
- 폰 가로 세계 기록 페이지는 이제 드롭다운 한 줄 + 상세라 쓰기 편해졌지만, 상세가 390 높이라 짧다. 실제 Risu 폰에서 한 번 보기를 권한다.
- 시험의 「시작 전」 괴담넷 페이지는 기본이 켜짐이라 첫 조작(끄기) 뒤 나머지 줄이 숨어 시작 전엔 스위치 하나만 눌린다. 같은 조작은 「새 채팅 기본값」 바퀴(시작 뒤)에서 29개 다 눌렸다.
- `tests/browser.mjs`(패널 전체 시험)는 v0.17.8 기준에서도 시작 직후 설정 창 단언에서 실패한다(옛 트리·`.st-colsbox`를 찾음). 이 영역의 같은 내용은 `qc-settings-*` 시험이 덮으므로, 옛 시험 갱신은 담당 영역(패널 전체)에서 하기를 권한다.
- 실제 Risu iframe·실기기 터치는 Chromium 뷰포트·CDP 터치로만 재현했다.
