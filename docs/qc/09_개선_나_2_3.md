## 1. 나2 · 본체 조각 sha256 확인

| 항목 | 전 | 후 |
|---|---|---|
| `goei-body.json` (scripts/build.mjs) | `version` · `parts` · `length`(JS 글자 수) · `hash`(UTF-16 FNV-1a 32비트) | + `sha256`(이어 붙인 본체 **전체**의 UTF-8 바이트, 소문자 hex 64자) |
| 시작기 확인 순서 (src/loader/body.ts `fetchBody`) | 길이·판 → `hash`(있으면) | 길이·판 → **`crypto.subtle` 이 있으면 `sha256`**(목록에 있을 때) → 없으면(보안 컨텍스트 아님·digest 실패) `hash` → 둘 다 없는 옛 release 목록은 길이·판만 (호환) |
| 불일치 처리 | `받은 본체가 깨져 있어요. 다시 받아 주세요.` | 같은 경로(받기 창 「다시 받기」, 저장 안 함). 메시지에 어느 지문인지 표시: `…깨져 있어요(sha256)…` / `…깨져 있어요(hash)…` |
| 시작기 크기 (`dist/goei-plugin.js`, 같은 빌드) | 13,099 B | **13,948 B (+849 B)** — sha256 약 450 B + 나3 catch 약 400 B |

**조각마다 sha256 은 넣지 않았다.** 근거: 시작기는 조각 하나가 틀려도 전체를 다시 받을 뿐 조각 단위 재시도 경로가 없다. 조각별 지문을 쓰려면 받는 쪽에 「어느 조각이 틀렸는지 기억해 그 조각만 다시」 상태 관리가 들어가 시작기가 커진다(모든 봇에서 읽히는 파일). 본체 전체 3.4MB 를 17~18조각으로 받는 지금은 전체 하나로 충분하고, 1MB 프록시 제한 때문에 조각으로 나눈 것이지 재시도 단위가 필요해서가 아니다. 조각 단위 재시도가 필요해지면(받기 실패가 잦다는 보고가 오면) 그때 `parts` 를 `{name, sha256}` 로 바꾸면 된다 — 지금 목록 모양은 그대로 호환된다.

`crypto.subtle` 은 보안 컨텍스트(https·tauri·localhost)에서만 있다. 실제 Risu 플러그인 칸은 보안 컨텍스트라 sha256 경로가 돈다(사진 지문 sha1 과 같은 조건). FNV-1a 확인은 그대로 남겨 두어 보안 컨텍스트가 아닌 환경(시험의 about:blank srcdoc 등)에서도 글자 바뀜은 잡는다.

## 2. 나3 · 요청 조립이 실패할 때의 정책

**정책 (사용자 부재 중 정함 → 사용자 확인 필요): 요청은 막지 않는다. 대신 모델이 플러그인 표식을 보지 않게 한다.**

근거: 막으면 사용자는 「전송이 안 된다」만 보고 까닭을 알 수 없다(Risu 는 처리기 예외를 사용자에게 보여 주지 않는다). 표식이 남은 원문을 그대로 보내면 모델이 `%%SCENE_CARD:…%%` 같은 글자를 따라 쓰거나 되묻는다. 실패한 단계 하나를 건너뛰고 표식만 지워 보내면 그 턴은 조금 부족한 요청(예: 참고 기록 없음)이지만 롤플레이는 이어지고, 로그로 까닭을 남긴다.

### 2-1. 구현

| 곳 | 바뀐 것 |
|---|---|
| `src/body.ts onBeforeRequest` | 단계마다 `step(이름, 실행, 실패 때 값)` / `stepAsync` 로 감싼다. 던지면 이름·까닭을 모으고 그 단계 **이전** 모양으로 계속. 단계 밖에서 던진 것도 `catch` 로 모은다. 끝에서 **항상** `sanitize(messages)` 를 돌려 보낸다. 실패가 있으면 한 줄 로그 `[goei] 요청 조립 실패: 단계 A(까닭) · B(까닭) — 그 단계는 건너뛰고 표식만 지워 보냅니다`. 이 함수는 던지지 않는다 |

## 4. 스스로 내린 결정 (사용자 확인 항목은 ★)

1. ★ **정책: 요청을 막지 않고 표식만 지운다** (2절). 막는 쪽을 원하면 `onBeforeRequest` 끝의 `sanitize` 대신 던지면 되지만, Risu 가 예외를 사용자에게 어떻게 보여 주는지 실측이 없다.
2. 조각별 sha256 없음 (1절).
3. 상태창 줄·이미지 태그는 끝 정리에서 지우지 않음 (2-3절).
4. 정리 단계의 시드는 수명과 상관없이 본문을 남긴다(표식만 제거). 18이 실패한 턴에만 생기는 모양이고, 로어 글이 한 턴 더 가는 것이 로어가 빠지는 것보다 낫다.
5. 끝 정리는 다른 봇의 요청에도 돈다(본체가 떠 있으면 시작기가 모든 요청을 본체에 넘긴다). 우리 표식 문자열(`%%SCENE_CARD:` 등)만 보므로 다른 봇 글은 바뀌지 않고, 상황판 태그 제거는 괴이 카드(liteNow)일 때만.
