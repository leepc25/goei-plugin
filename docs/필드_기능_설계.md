# 필드 기능 설계 (그림 없이 먼저 짜는 구조)

> **⚠ Claude 반성 · 2026-10-31 (사용자 지시로 문서마다 남김)**
> 2026-10-31 Claude는 다음 잘못을 저질렀다. 이 문서를 읽는 모든 Claude는 같은 짓을 하지 않는다.
> 1. **사용자 결정을 무시했다.** 콘쥬스는 사용자가 10-26에 20세로 정했고 인계서에도 적혀 있었는데, 옛 Claude 문장(teenage high school girl)을 근거로 화장실·샤워 그림을 거부하고, 사용자가 직접 뽑은 화장실 줄까지 팩에서 뺐다. 옷도 제복인데 교복이라고 단정했다.
> 2. **사용자 말에 토를 달고 같은 주장을 되풀이했다.** 사용자가 여러 번 지적했는데도 근거를 다시 확인하지 않아 몇 시간을 허비하게 했다.
> 3. **허락 없이 문서를 지웠다.** 「지침을 지우라」는 말만 듣고 목록을 보여 주지도 않고 96개를 지웠다가 되살렸다(결과물 삭제 금지 규칙 위반).
> 4. **문장을 덧대기만 하며 PixelLab을 낭비했다.** 이성해 점프 공격 5번 연속 실패, 이어폰 음악 120줄을 못 쓰게 만듦.
> 5. **답을 미루고 일을 멈춰 두었다.** 백그라운드로 돌릴 일을 돌리지 않고 대화만 했다.
>
> 지킬 것: 사용자 결정·위키가 근거다. 옛 Claude 자료는 근거가 아니다. 사용자 말에 토 달지 않는다. 무엇이든 지우기 전에 목록을 보여 주고 허락받는다. 실패하면 덧대지 말고 다시 쓰거나 바꾼다.


2026-10-23. 그림·요원 배치는 나중에 들어오고, 이 문서는 필드가 **어떻게 작동하는지**만 정한다. 그림이 하나도 없어도 네모 임시 모양으로 전부 돌아가게 만든다.

## 0. 원칙

1. **게임 코드가 정한다. 모델은 대사만 쓴다.** 위치·이동·일과·동행 같은 행동은 코드가 판정하고, 모델은 대화를 누를 때만 부른다. 모델이 태그로 계기를 줘도 받을지는 코드가 정한다(지금 NPC 대화 방식 그대로).
2. **세계는 데이터다.** 지역·장면·이동수단·거점·일과를 표 하나씩으로 적고, 엔진은 표를 읽기만 한다. 그림 파일은 표의 이름만 가리킨다. 그림이 없거나 지침과 달라도 표와 충돌 상자는 그대로 돈다.
3. **본편이 먼저다.** 본편 상황판(요원 상태·괴이 위치·시각)과 필드가 어긋나면 본편을 따른다. 필드는 본편에 마음대로 쓰지 않고, 사용자가 버튼을 누를 때만 기록한다.
4. **보이는 곳만 진짜로 움직인다.** 화면 밖 NPC는 일과표로 위치만 계산한다(5장).

## 2. 소속(조직 코드)에 따라 들어가는 곳

본편 `faction`이 시작 코드를 정한다. 코드는 시작 화면에서 고른 세력이고 지금 다섯 개다(`scenarios.json`).

| 코드 | 세력 | 거점(필드 시작 지점) | 비고 |
| --- | --- | --- | --- |
| A00 | 관리국 | 관리국 본부 (지금 17장면) | 이미 있음 |
| B00 | 가짜 관리국 | 가짜 관리국 거점 | 이도형·곽성주 쪽, 새로 |
| C00 | 백일몽 주식회사 | 백일몽 본사 | 새로. 위장 제약사 모습 |
| D00 | 민간인 | 자택 | 거점 없음. 방문만 가능 |
| E00 | 프리랜서 | 협회 접수창구·알선소 | 의뢰 중심 |

**거점(Site)** = 장면 묶음 + 입장 가능 소속 + 시작 장면. 데이터:

```ts
interface SiteDef {
  id: string;                    // 'hq_a00', 'daydream', 'assoc', 'mid_arcade' …
  name: string;
  kind: 'faction' | 'neutral' | 'home' | 'outside';
  scenes: SceneId[];             // 이 거점에 속한 장면
  entry: SceneId;                // 들어오는 장면
  // 들어올 수 있는 조건. 못 들어오면 문 앞에서 이유를 한 줄 보여 준다
  access: { factions?: string[]; needs?: Cond[]; deny?: Cond[]; denyText?: string };
}
```

- 필드에 들어가는 순간 `faction`으로 **시작 거점**을 고른다(위 표). 한 코드의 시작 거점은 하나, 나머지는 이동으로 간다.
- 다른 소속이 남의 거점에 가는 것을 **규칙으로 막지 않는다.** 문은 열려 있고, 들어가면 그 거점 사람들이 평판·소속에 따라 반응한다(경계 → 경고 → 추방 → 공격, 13장). 물리적으로 잠긴 곳(보안 게이트 등)은 문 조건이 아니라 NPC·아이템(출입증)으로 풀거나 뚫는다. 들어가서 일으킨 일은 전부 장부에 남아 결과로 돌아온다.
- **새 소속(F00 이후)**은 코드를 더해도 `SiteDef` 한 줄 + 장면만 더하면 된다. 코드 확장은 [조직코드_확장_설계.md](조직코드_확장_설계.md) 3장과 같은 방향이다(소속 목록을 명부에서 읽는다).
- 같은 NPC 명단(`roster.ts`)의 `group`을 거점에 묶는다(예: 관리국 요원은 관리국 거점 소속). 거점이 달라도 NPC 대화 기술은 같다.

## 3. 처음 들어갈 때 위치 판정

필드를 열 때 **본편 스냅숏**으로 지금 어디에 있어야 하는지 정한다. 모델을 부르지 않고 코드 규칙으로만.

```
입력: faction, player(조작 요원), events[](loc,state), minute, 마지막 필드 위치(저장)
출력: { site, scene, x } 또는 { denied: '이유' }
```

| 본편 상황 | 판정 |
| --- | --- |
| 평소(진행 중 괴이 없음) | 마지막 필드 위치. 저장이 없으면 시작 거점 `entry` |
| 플레이어가 **괴이 안**(3-1 판정) | **지금은 입장 불가**(괴이 장면을 아직 안 만들었으므로). 안내 한 줄만. 괴이 장면이 생기면 괴이 속 필드에서 시작하고, 그 괴이가 허락하면 본부로 탈출, 아니면 전화만, 전화도 안 되면 아무것도 못 한다(3-2) |
| 플레이어가 부상·격리 | 의무실 또는 격리 구역 시작. 건물 밖으로 못 나감 |
| 본편 시각이 마지막 필드 시각보다 크게 지남 | 위치를 일과 기준으로 다시 정함(예: 밤이면 자택·숙소) |
| D00 민간인 | 자택 또는 길거리. 거점 문은 방문 규칙을 따름 |

- 판정 함수 하나(`gate.ts: resolveEntry(snapshot, save)`)에 모은다. 규칙은 표 배열로 두어 추가가 쉽다.
- 판정 결과 `denied`가 나오면 필드는 열리되 **움직일 수 없는 안내 화면**이 먼저 뜬다(이유 한 줄 + 닫기). 모델 호출 없음.
- 어려운 부분: 상황판 `loc`(위치) 문자열을 거점·장면 id에 잇는 표가 필요하다. 사건 이름이 로어북 글이라 정확히 맞지 않을 수 있어, 못 맞추면 **안전한 쪽**(입장 허용 + 경고)이 아니라 **본편 값 그대로 보여 주고 사용자가 확인**하는 쪽으로 한다.

### 3-1. 「괴이 안」인지 판정하는 기준

핵심: **괴이 이름을 맞춰 보는 방식으로 판정하지 않는다.** 이름 매칭은 사전에 정의한 괴이만 되기 때문이다. 안인지 밖인지는 **투입이 일어났는지**라는 구조 신호로 판정하고, 이름은 「어느 괴이 장면으로 들어갈지」를 고를 때만 쓴다.

필드가 읽을 수 있는 신호 (모두 이미 플러그인이 읽는 것):

| 신호 | 어디서 | 신뢰 |
| --- | --- | --- |
| S1 **투입 지시문**: 사용자가 플러그인의 이동/임무 창으로 보낸 `[이동] 목표 … / 투입 …` 메시지(`SCENE_CARD`)와 투입 인원 | 채팅 메시지 | **높음**(플러그인이 만든 메시지라 모델이 틀릴 수 없음) |
| S2 **요원 상태 `작전투입`**(또는 외근): 투입 인원의 상태 | 세계 상태(`world.agents[].st`) | 중간(모델·상황판이 갱신) |
| S3 상태창 **목표 칸**(`[▣|…|위치|목표]`의 마지막 칸, 없음이면 비어 있음) | 마지막 응답의 상태창 | 중간: 목표가 있다는 건 「작전 단계 이상」이라는 뜻뿐, 투입 여부는 아님 |
| S4 상황판 **활성 괴이** 목록 | 세계 상태(`world.an`) | 낮음(괴이가 존재한다는 것뿐) |
| S5 **귀환 신호**: 투입 인원 상태가 작전투입에서 내근·휴게·부상 등으로 바뀜, 후송, 목표 칸이 다시 없음 | 위와 같음 | |

상태 세 가지:

```
none   목표 없음, 투입 없음                         → 밖. 필드 정상
prep   목표 있음, 투입 전 (작전 단계)               → 밖. 본부·준비 가능 (목표만 잡은 상태)
inside 투입됨 (S1 이후 귀환 신호 없음, 또는 S2 작전투입) → 안
```

- **prep와 inside를 가르는 건 S1/S2다.** 사용자가 말씀하신 대로 목표는 작전 단계에서도 잡히므로 S3 하나로는 판정하지 않는다.
- 사전 정의 안 된 괴이도 판정은 똑같다: 이름이 로어북에 없어도 S1(투입 지시문)과 S2(상태)는 이름과 상관없다.
- 신호가 서로 어긋나거나(S1 있는데 S2 아님, 둘 다 없는데 목표가 한참 유지) **주인공 요원이 없는 소속(D00 민간인·E00 프리랜서)** 이면 `unknown`: 입장 시 확인 카드 한 번(「지금 괴이 안에 계십니까? 예 / 아니오」)을 묻고 답을 저장한다.
- **틀렸을 때 고치기**: 필드가 입장할 때 판정 결과를 한 줄로 보여 준다(「괴이 밖으로 보고 열었습니다」/「괴이 안이라 못 들어옵니다」). 틀렸으면 그 자리의 버튼 하나로 뒤집는다. 별도 설정 항목은 없다.
- 한계(솔직히): 플러그인은 본편 이야기 속에서 실제 위치를 알 수 없다. 사용자가 투입 창을 안 쓰고 글로만 괴이에 들어가면 S1이 없다. 그때는 S2·S3로 추정하되 틀리면 확인 카드나 입장 때 보이는 「뒤집기」 버튼으로 바로잡는다.

### 3-2. 괴이 속 필드와 탈출·전화

괴이 장면이 생긴 뒤의 규칙. 괴이 정의표(9장 `AnomalyStageDef`)에 속성 하나를 둔다.

```ts
link: 'exit' | 'phone' | 'none';   // 이 괴이 안에서 밖과 이어지는 정도
```

| 괴이 | 필드 입장 시 |
| --- | --- |
| `exit` | 괴이 속 필드에서 시작. **탈출 조건을 채우면** 본부로 이동 가능(탈출 지점 도착 = `exit_anomaly`) |
| `phone` | 괴이 속 필드에서 시작. 탈출은 못 하고 **전화로만** 본부와 통화 |
| `none` | 괴이 속 필드에서 시작. 전화도 안 됨(신호 없음). 안내 한 줄 |
| **정의표 없음** | **지금처럼 입장 불가**(안내 한 줄). 기본값 |

지금은 괴이 장면이 하나도 없으니 모든 `inside`는 입장 불가다.

## 4. 지역, 중립지역, 이동

### 4-1. 지역 그래프

```
Region (도시 한 구역)  ──  Site (거점·중립지)  ──  Scene (걷는 화면)
```

- **Scene**: 걷는 화면 하나(지금 17장면과 같은 모양).
- **Site**: 장면 묶음. 종류는 `faction`(소속 거점) · `neutral`(중립지역: 중림 지하상가, 협회, 파스타집, 편의점 등) · `home`(자택) · `outside`(길거리·역).
- **Link**: 장면 사이 연결. 문(걸어서) 또는 이동수단(탈것). 문은 지금처럼 `HqDoor`, 이동수단은 4-3.
- 중립지역은 소속 거점과 같은 `SiteDef`를 쓰고 `access`가 비어 있다(누구나). 상인·의뢰·정보처럼 **그 지역에서만 되는 기능**은 장면의 자리(`spot`)에 붙인다. 지금 `spot.place`와 같은 방식.
- 중립지역 안에도 NPC가 산다(상인 마덕희, 고연지·윤지아 등). 일과는 5장 그대로.

### 4-2. 건물 밖(길거리)

- 도시는 **연속된 거리 장면 몇 개**로 만든다(종로 뒷골목처럼 좌우로 긴 장면). 한 도시 전체를 걷게 하지 않는다.
- 거리 장면에는 건물 입구(문)와 이동수단 승강장(역·정류장)이 있다.
- 거리에 사는 사람은 승객·주민·행인(엑스트라). 엑스트라는 대화 가능 여부를 데이터로 정한다(대화 불가면 말풍선 몇 줄만).

### 4-3. 이동수단

지하철·버스·택시·도보를 같은 표로 적는다.

```ts
interface TravelRoute {
  id: string;
  mode: 'walk' | 'subway' | 'bus' | 'taxi' | 'elevator' | 'stairs' | 'car';
  from: SceneId; to: SceneId;
  minutes: number;               // 월드 시계가 이만큼 흐른다
  cost?: number;                 // 예산(없으면 공짜)
  cond?: Cond[];                 // 열려 있는 시간·소속·해금
  ride?: SceneId;                // 가는 동안 보일 장면(지하철 칸 등). 없으면 암전 연출
  events?: TravelEvent[];        // 가는 도중 일어날 일(확률·조건)
}
```

- **지역 안은 걷기**(장면 안 이동 + 문), **지역 사이는 이동수단 고르기**. 승강장 앞 E → 행선지 목록(요금·시간) → 고르면 탑승.
- 탑승 연출은 두 단계: ① 짧은 암전과 도착 장면, ② (`ride`가 있으면) 탈것 장면에서 몇 초 머물기. 처음엔 ①만 만들고 ②는 그림이 생기면 켠다(표에 `ride`만 적으면 됨).
- **도중 사건은 본편 괴이와 이어진다.** 이동 경로가 지나는 지역(`geo` 지역 id)을 상황판 활성 괴이의 위치(`world.an[].loc`)와 맞춘다. 경로가 괴이 영향 지역을 지나면 이동 중에 조건·확률로 **징후 → 접촉 → 휘말림** 단계가 차례로 일어날 수 있다. 접촉은 `anomaly_contact` 사건으로 장부에 들어가 다음 본편 응답에 「이동 중 괴이 X의 징후를 만났다」로 전달되고, 휘말림이면 `inside`로 바뀐다(괴이 장면이 있으면 거기로, 없으면 본편이 이어받는다). 괴이와 상관없는 가벼운 사건(승객 대화 등)은 그 사이에 섞는다.
- 시간이 흐르므로 이동 중 NPC 일과(5장)와 본편 시각(3장)이 같이 움직인다.

## 5. 월드 시계와 NPC 자율 이동

### 5-1. 시계

시계는 **초 단위로 세고 분으로 보여 준다.** 걷는 시간은 **거리로 계산한다**: 걸은 거리(m) ÷ 보통 걸음 속도(약 1.3 m/s). 게임 속 이동이 화면에서 얼마나 빠르게 보이든, 시계에 드는 시간은 현실의 걸음과 같다. (화면 폭 1m = 142px 기준이라 걸은 px를 142로 나눠 m로 바꾼다.)

| 행동 | 드는 시간 |
| --- | --- |
| 같은 장면 안에서 걷기 | 거리 ÷ 1.3 m/s (22m 사무실을 끝에서 끝으로 약 17초, 26m 복도 약 20초). 한 걸음은 약 0.6초 |
| 문을 통과 | 약 3초 |
| 계단 / 엘리베이터 | 계단 한 층 약 20초 / 엘리베이터 대기+이동 약 30초 |
| 대화 | 주고받기 한 번에 약 40초 |
| 업무 창(치료·감정·보급·면담·접수) | 창이 정한 시간(치료 20~60분, 감정 30분 등) |
| 「시간 보내기」(기다리기·쉬기·잠) | 사용자가 고르는 만큼(10분 / 1시간 / 다음 시간대 / 수면=아침) |
| 지역 사이 이동 | 노선표의 `minutes`(도보는 거리 ÷ 속도) |
| 전투·괴이 안 | 괴이 안 시계는 괴이가 정한다(본편 이야기가 시간을 이끎) |

- 그래서 본부 안을 한참 오가도 몇 분이지 몇 시간이 아니다. 시간이 크게 흐르는 건 업무, 대화가 길어질 때, 지역 이동, 사용자가 고른 시간 보내기다.
- 가만히 서 있으면 시간이 안 간다(필요하면 「시간 보내기」). NPC 일과(5-2)는 이 시계를 따라 움직인다.
- **필드 시각은 본편 시각보다 앞서갈 수 있다.** 시계는 `max(필드, 본편)`이다. 필드가 본편보다 앞서면 장부 B(확정 사실)에 「필드 경과: 현재 시각 14:20(마지막 본편 시각 13:50)」을 넣어, 모델이 다음 상태창 시각을 이어 쓰게 한다. 모델이 더 앞서 쓰면 그 시각을 받아들인다. 필드를 닫아도 시계는 그대로 이어진다.
- 하루가 넘어가면 일과가 새로 계산된다(날짜는 시계가 가진다).

### 5-2. NPC 일과

```ts
interface Schedule { npc: string; blocks: { from: number; to: number; site: string; scene: SceneId; spot?: string; act: string; cond?: Cond[] }[] }
```

- 시간대마다 **어느 장면의 어느 자리에서 무슨 일**을 하는지 적는다(잼트리: 낮 운영 데스크, 점심 휴게실 …).
- 본편 상태가 먼저: 작전투입 → 필드에서 사라짐, 부상 → 의무실, 격리 → 격리 구역, 휴게 → 휴게실 쪽 블록. 기존 방문 대화의 분류(`내근→사무실` 등)를 이 규칙으로 흡수한다.
- 일과에 없는 시간은 `act: 'idle'`(그 거점 안에서 어슬렁).

### 5-3. 자율 이동 AI (모델 없음)

NPC 하나의 상태 기계:

```
idle(자리에서 작은 행동) → walk(목표로 이동) → work(자리 동작) → talk(대화 중 정지)
 → follow(동행) → react(놀람·도망·경계) → away(화면 밖)
```

- **목표 정하기**: 일과표 블록이 바뀌면 목표 장면·자리를 얻는다. 같은 장면이면 직선 이동 + 충돌 상자 회피(기존 `clearSpot`/`blockByProps`), 다른 장면이면 **장면 그래프 최단 경로**(문·승강기·계단의 `to`)를 따라 문 앞까지 걷고 문을 통과해 사라졌다가 다음 장면 문에서 나타난다.
- **단순 회피**: 길이 막히면 옆으로 한 걸음, 3번 실패하면 목표 자리로 순간 이동(끼임 방지).
- **idle 행동**: 요원별 목록에서 코드가 무작위로 고른다(기지개, 서류 보기, 서성임 …). 모델 호출 없음. 지금 계획대로 **일상 동작은 코드, 모델은 대사만**.
- **인사**: 가까이 가면 요원×방문자 관계표로 목례/손 인사/무시를 코드가 고른다.
- **LOD(성능)**: 지금 화면에 있는 장면의 NPC만 프레임마다 움직인다. 다른 장면의 NPC는 시계가 바뀔 때만 「지금 있어야 할 장면·자리」를 계산해 놓는다. 사용자가 그 장면에 들어가면 그 자리에 세운다(이동 중이어야 하면 문 근처). 그래서 사람이 많아도 가볍다.
- **저장**: NPC 위치는 저장하지 않는다. 일과와 시각으로 다시 계산한다. 저장하는 건 관계·플래그·동행 상태뿐.

## 6. E 상호작용, 호감·감정

### 6-1. E 흐름

지금 규칙: 대화할 수 있는 사람 앞 E = 대화창, 한 번 더 E = 원래 하던 일(임무·거래). 이걸 이렇게 바꾼다.

- 대상 앞 E → 화면 **아래 작은 입력칸 하나**가 뜬다(풀 패널 없음, 사용자 지시). 입력칸 위에 **선택줄**: `대화 · 부탁 · 물건 · 일`. 글을 바로 치면 대화.
- 도트 말풍선과 이름표는 그대로. 생각 중에는 머리 위에 작은 점 세 개.
- **기능 목록**(대상이 가진 것만 보임, `roster.ts`의 `effects`와 `spot` 데이터로 정함):

| 선택 | 하는 일 | 판정 |
| --- | --- | --- |
| 대화 | 자유 글 → 모델 | 모델 대사 + 태그를 `decide()`가 판정 |
| 부탁 | 「따라와」「기다려」「이거 해줘」 | 7장. 코드가 의도를 분류 |
| 물건 | 선물·거래·받기 | 호감·재고 규칙 |
| 일 | 그 사람/자리의 업무(임무, 감정, 치료, 접수) | 지금 `spot.place` 메뉴 창 |
| 정보 | 단서·소문 묻기 | 힌트 목록에서 하나씩, 만남당 제한 |
| 조사 | 물건·장소 살펴보기 | 자리 `act`, 문장은 코드 |

- 이동 중(승강장·문)과 구분: 문·승강장·물건의 E는 대화칸 없이 바로 동작한다.

### 6-2. 호감과 감정

지금은 호감 하나(−3~+3). 이렇게 넓힌다. 표시는 지금처럼 단어 한 줄, 내부는 숫자.

| 값 | 범위 | 움직이는 이유 | 마르는가 |
| --- | --- | --- | --- |
| 호감(affinity) | −100~100, 표시 7단계 | 대화 계기, 선물, 구해 줌, 방해·폭력, 약속 지킴 | 매우 느리게 0쪽으로 |
| 신뢰(trust) | 0~100 | 약속 이행, 비밀 지킴, 같이 겪은 일 | 안 마름, 배신하면 급락 |
| 기분(mood) | 평온·기쁨·화남·슬픔·불안·피곤 | 방금 일(대화, 사건, 시간대) | 몇 시간 안에 평온으로 |
| 경계(guard) | 0~3 | 위협, 낯선 방문자 | 시간이 지나면 풀림 |

- 모델 태그는 계기만(`[[호감 +1]]` 등). **수치 변화는 `decide()`가 정한다**: 한 번 대화로 ±5 이하, 하루 상한, 같은 계기 반복은 체감.
- 요원마다 **성격 계수**(쉽게 마음 여는 정도, 화 오래 가는 정도)를 로어북 시트 기준으로 표에 둔다. 쟈알디는 호감이 천천히 오르고, 데쥬레는 선물에 약한 식.
- 프롬프트에 **호감 단계·기분·경계**를 문장으로 넣어 말투가 변한다(`buildPrompt`에 칸 추가).
- 저장은 필드 저장 안의 `relations` 한 칸. **본편 채팅에는 자동으로 쓰지 않는다.** 사용자가 「본편에 기록」을 누르면 「관계 변화」 줄을 기록 로어북에 넣는다.
- 방문자 정체성은 이미 플레이어 블록(`applyPlayer`)을 쓰므로, 관계는 **방문자 이름 기준**으로 저장한다.

### 6-3. 전화 (새 기능)

계획에 없던 것을 추가한다. 쓰임: 괴이 안에서 밖과 통화(3-2), 약속 잡기, 멀리 있는 사람 부르기.

- 필드 메뉴(또는 단축키)에서 도트 **휴대폰 창**을 연다: 연락처(통화 가능한 NPC와 시간), 최근 통화.
- 통화는 NPC 대화 파이프라인을 그대로 쓴다. 통화 채널 표식만 붙이고 **얼굴 말풍선 대신 통화창**(글만, 전화 도트 프레임). 호감·기분·경계가 똑같이 반영된다.
- **통화 가능 조건**을 코드가 판정한다: 상대가 일과상 응답 가능한가(자리에 있거나 휴대폰을 가진 시간대), 내가 신호가 닿는 곳인가(괴이 `link`), 상대가 전투 중이거나 사망·격리가 아닌가. 안 되면 안내 한 줄(「받지 않는다」「신호가 닿지 않는다」).
- 통화도 `call` 사건으로 장부에 들어가 다음 본편 응답에 반영된다(8장). 약속은 `appoint` 사건으로 일과를 덮어쓴다.
- 본편의 괴담톡(채팅 속 문자 메신저)과는 다르다: 괴담톡은 본편 채팅 글이고, 필드 전화는 필드 안의 실시간 통화다. 같은 NPC의 연락처 정보(`phone_tabs`)는 공유한다.

## 7. 「따라와」 실제 동행

### 7-1. 어디서 말하나

- **필드 대화창**: 사용자가 「따라와」를 입력하면 모델이 응답하면서 `[[동행]]`을 달고, `decide()`가 조건을 본다(호감, 상태, 동행 가능). 지금도 있는 길.
- **본편 채팅**: 필드 밖 일반 채팅의 「따라와」는 필드와 따로다. 필드를 열 때 본편 최근 마디에서 **동행 요청을 감지**해 확인 카드를 한 번 보여 준다(「에일린에게 따라오라고 하셨습니다. 필드에서 동행시킬까요?」). 몰래 적용하지 않는다.

### 7-2. 의도 분류 (코드 우선)

1. 짧은 키워드 규칙(따라와/같이 가/기다려/여기 있어/돌아가)으로 먼저 거른다. 명확하면 모델 없이도 처리(`부탁` 선택에서 눌러도 같음).
2. 애매하면 대화로 넘겨 모델 태그를 받는다.

### 7-3. 동행 상태 기계

```
승낙 → follow(주인공 뒤 일정 거리) → 문 통과 시 같이 이동 → 이동수단도 같이 탑승 → 해제
```

- **추종**: 주인공이 걸은 길(발자국 열)을 따라 1.5초 뒤처져 걷는다. 막히면 가까이 순간 합류. 따로 길찾기를 하지 않아 단순하고 끼임이 적다.
- **장면 전환**: 문·승강기·계단·이동수단에서 주인공이 나가면 동행자도 같은 장면 도착 지점에 같이 나타난다.
- **동행 인원: 필드에 따라오는 건 최대 4명**(투입 편성과 같음). 모델이 적는 동행 칸에는 인원 제한이 없고(중요한 순서로 적게 함), 플러그인이 앞에서부터 4명을 쓴다. 나머지는 필드에는 안 나오지만 확정 사실에는 「그 외 동행: …」으로 남아 본편과 어긋나지 않는다. **사용자가 이름을 쓰거나 알려 주는 입력은 없다**(몰입이 깨지므로). 동행은 전부 자동으로 안다:
  1. 필드에서 `follow` 사건으로 시작한 동행,
  2. 투입 창에서 **목록에서 골라** 편성한 인원(투입 지시문 `투입:`),
  3. **상태창의 동행 칸**: 모델이 본편 응답에서 상태창에 동행 인물을 적게 한다(19장 모델 출력 규약). 명부에 없는 인물(민간인·구조한 생존자·상인)이어도 이름이 적히면 플러그인이 **임시 인물**(`Actor{id,name,source:'story'}`)로 등록한다. 모양은 **공용 캐릭 풀**(사용자가 따로 만들어 둘 성별·나이대별 공용 그림)에서 이름으로 고정해 고른다(같은 이름이면 늘 같은 모양). 이미 로어북에 시트가 있는 인물이면 그 시트를 쓴다,
  4. 구출 사건(필드·괴이 안)이 일어나면 구출된 인물이 자동 등록.
  상태창 칸이 비어 있거나 모델이 적지 않으면 그 동행은 필드에 안 나온다(침묵하는 쪽으로 틀린다. 본편이 먼저이므로 억지로 만들어 내지 않는다).
  상태(부상·작전투입·근무 중)·호감이 안 맞으면 거절 대사. 거절 이유는 문장으로 보여 준다.
- **해제**: 「기다려」「돌아가」, 호감 하락, 일과 시간이 중요한 NPC는 시간이 되면 스스로 「슬슬 돌아가야겠다」 하고 떠남.
- **일과와의 관계**: 동행 중에는 일과를 멈춘다. 해제하면 일과대로 복귀(가장 가까운 목표 자리로 걸어감).
- **전투/괴이 안**: 동행은 괴이 안 출동 장면에는 **들어가지 않는다**(1차). 출동 동행은 전투 설계가 정해진 뒤 따로.
- 저장: `companions: [{npc, since, mood}]`만 저장. 필드를 다시 열면 같은 장면에 같이 서 있다.

## 8. 필드 결과를 본편에 잇기 (장부)

필드에서 한 일이 다음 본편 응답에 반드시 반영돼야 한다. 말, 이동, 살해, 괴이 진입, 전투 전부. 모델을 부르지 않고 **플러그인이 기록하고, 요청이 나갈 때 정제해서 끼운다.** 지금도 대화는 이 방식이다(`goeiHqVisitV1`에 쌓고, `beforeRequest` 훅의 `withVisit`이 `[필드 막간]`을 해당 메시지 뒤에 끼움). 이걸 모든 사건으로 넓힌다.

### 8-1. 사건(FieldEvent)

```ts
interface FieldEvent {
  id: string;
  at: number;            // 게임 분 (월드 시계)
  anchor: string;        // 이 일이 일어났을 때 본편 마지막 메시지 chatId (다시 굴리기·삭제에 안전한 기준)
  scene: SceneId;        // 어디서
  who: string[];         // 관여한 사람 (주인공 포함)
  witnesses?: string[];  // 같은 장면에 있던 사람 (소문·반응에 씀)
  weight: 1 | 2 | 3;     // 중요도: 3 = 반드시 모델에 알림, 1 = 공간 남으면
  kind: EventKind;
  data: Record<string, unknown>;
}
type EventKind =
  | 'talk'       // 대화 (이미 있음: 사용자 글 + NPC 답 + 끼어듦)
  | 'act'        // 사용자가 쓴 행동 *…*
  | 'move'       // 장소 이동 {from,to,by,minutes}
  | 'hurt' | 'down' | 'kill' | 'flee'    // 전투 결과 {attacker,target,how}
  | 'provoke'    // 도발·선공 {by,target,level}
  | 'gift' | 'trade' | 'quest'            // 물건·의뢰
  | 'follow' | 'unfollow'                 // 동행
  | 'enter_anomaly' | 'exit_anomaly'      // 작전 투입(9장) {anomaly,party,log[],facts[]}
  | 'enter_site' | 'detected'             // 적대 거점 진입·발각(13장)
  | 'appoint';                            // 약속
```

모든 사건은 **게임 코드가 만든다.** 모델 응답에서 읽는 건 대화 태그(`[[동행]]` 등)뿐이고, 그것도 `decide()`가 통과시켜야 사건이 된다.

### 8-2. 저장

- 채팅 변수 `goeiFieldV1` 하나: `{ schema, clock, pos, events[], facts{}, relations{}, companions[], standing{} }`. 채팅에 붙으므로 채팅마다 따로고, Risu에서 채팅을 복제하거나 분기하면 같이 따라간다. 기존 `goeiHqVisitV1`은 `talk` 사건으로 흡수한다(옛 기록은 읽어서 옮기는 `migrate()`).
- 육성(숙련·재화·해금)은 기존 슬롯 저장 그대로. **세계 사실(위치·사망·관계·장부)은 채팅 귀속, 육성은 계정 귀속**으로 나눈다. 채팅을 바꾸면 세계가 바뀌고 육성은 이어진다.
- 상한: 사건 300건. 넘으면 오래되고 weight 1인 것부터 한 줄 요약(`[요약] 1일차 오전: 휴게실에서 에일린과 잡담 6회`)으로 접는다. 접는 건 코드(템플릿)가 한다.

### 8-3. 요청에 넣는 두 덩어리

요청 직전 `withField(messages)`가 `withVisit` 자리에서 두 가지를 끼운다. 쉽게 말해 **A = 지난 일을 적은 막간, B = 지금 상태를 적은 확정 사실**이다.

**A. 일어난 일 (이력)** — `[필드 막간]` 일반화. 사건을 코드 템플릿으로 사람이 읽는 줄로 바꿔 **해당 anchor 메시지 바로 뒤**에 넣는다(지금과 같은 위치 규칙).

```
[필드 막간]
— 2층 복도에서 휴게실로 이동 (14:10, 도보 2분) —
쟈알디 (행동): 에일린의 멱살을 잡았다.
에일린: "…손 놔."
쟈알디 (행동): 밀쳤다. → 에일린이 반격했다. 에일린이 쓰러졌다 (중상).
```

**B. 지금 확정된 사실 (상태)** — 이력과 별개로 항상 **최신 한 덩어리**를 마지막 사용자 메시지 앞에 넣는다. 크기가 일정하다.

```
[필드 확정 사항]
- 주인공 위치: 휴게실 (2일차 14:20)
- 에일린: 중상, 의무실 이송 예정. 이 일은 되돌릴 수 없다.
- 데드폴: 사망 (필드에서 살해됨, 2일차 11:05). 이후 장면에 살아서 나오지 않는다.
- 동행: 로제몬
- 평판: 가짜 관리국 거점 — 수배
- 약속: 15:00 면담실, 스팡달
```

- 규칙문(카드 로어북 「Visit」, 지금 `visitContextRules`)에 이렇게 적는다: 「A는 실제 있었던 일, B는 확정 상태. 어기지 않는다. **주인공 위치가 바뀌었으면 이전 장면을 잇지 말고 B의 위치에서 장면을 시작한다.**」 이동이 없고 대화만 있었으면 규칙문이 「막간」 문구를 쓰고, `move`가 있으면 「장면 전환」 문구로 바꾼다.
- **본편 상황판과의 정합**: 필드가 `사망`이라 적었는데 모델 응답이 상황판을 그렇게 고치면 그 사실은 B에서 뺀다(요청마다 스냅숏의 요원 상태와 비교하는 `reconcile()`). 모델이 안 고치면 계속 B에 남아 매번 알린다. 그래서 모델이 무시해도 사실이 사라지지 않는다.
- 필드가 상황판을 **직접 고치지는 않는다**(기획서 22.3 유지: 본편 상태는 모델과 사용자만 바꿈). 대신 위 B로 강하게 알린다. 직접 쓰기가 필요하면 별도 결정이다(열린 질문).
- **예산**: 1,500자는 임의로 쓴 숫자라 폐기한다. 크기는 이렇게 정한다.
  - **이력(A)**: Risu가 이번 요청에 실제로 싣는 본편 메시지에 붙은 막간만 넣는다(요청에서 그 메시지를 못 찾으면 안 넣는 규칙이 이미 있다). 그래서 본편 컨텍스트 창이 곧 예산이다. 막간은 원문 대화까지 그대로 넣는다. 안전 상한만 따로 둔다(기본 12,000자, 넘으면 가장 오래된 막간부터 코드가 요약).
  - **확정 사실(B)**: 항목은 한 줄씩이고 우선순위(사망·부상·위치·동행·평판·약속·시각)로 자른다. 상한 3,000자.
  - 같은 종류 연속 이동은 합치고, 전투는 라운드가 아니라 결과 한 줄 + 결정적 장면 하나로 줄인다.
  - 모델 응답 길이가 실제로 줄어드는지 시험해 본 뒤 상한 숫자를 조정한다.
- **다시 굴리기·삭제**: 기준 메시지가 사라진 사건은 A에 넣지 않는다(지금 `orphanTurns`와 같음). 사실(B)에 영향을 준 사건이 고아가 되면 설정 화면에 「고아 사건 N건」으로 보이고 사용자가 되살리거나 버린다. 몰래 지우지 않는다.
- **시험**: 사건 목록 → 정제 결과 글을 골든 파일로 비교하는 단위 시험(모델 없이 결정적으로 나옴). 이 장이 가장 중요하므로 먼저 만든다.

### 8-4. 본편에 쓰는 것

- 위 요청 삽입은 사용자 버튼 없이 자동이다(읽기 전용 삽입, 채팅 메시지는 안 건드림).
- 「본편에 기록」 버튼(지금 있음)은 작전 보고서 같은 **긴 기록 로어북**용으로 남긴다.

## 9. 작전 투입(괴이 안) 다시 짜기

지금 출동은 「본부 → 승강기 층 → 정산」이 따로 놀고 본편 괴이와 이어지지 않는다. 이렇게 바꾼다.

1. **먼저 현황 점검**: 지금 출동 흐름의 문제를 목록으로 뽑는다(어디서 끊기고 무엇이 본편과 안 이어지는지). 설계는 그 목록을 보고 고친다.
2. **흐름**: 임무 창구(잼트리) → 대상 괴이 고르기(본편 `events` 중 활성) → 편성(주인공+동행) → 장비 → 투입. 전부 코드, 모델 없음.
3. **괴이 정의표** `AnomalyStageDef`: 괴이 이름(본편 로어북과 같은 이름), 구조(층·구역), 규칙, 단서 목록, 적·수호자, 보상. **정의표가 있는 괴이만 필드에서 들어갈 수 있다.** 없는 괴이는 입구가 닫혀 「본편에서 처리」로 표시된다. 처음 지원: 차원 승강기, 명일 아파트(이미 스테이지 모듈 있음). 늘리는 건 표 채우기다.
4. **기록**: 투입 중 스테이지 `notes`(`stage.found`, `stage.rescued`, `stage.depth` 등 이미 있음)를 `RunLog`로 모은다: 지난 구역, 발견한 규칙과 단서, 만난 존재, 구한 사람, 부상·사망, 쓴 아이템, 위반한 규칙. 코드가 하이라이트 최대 8줄로 줄인다.
5. **퇴장·후송·철수** 때 `exit_anomaly` 사건 하나가 장부에 들어간다(결과 + 하이라이트 + 확정 사실). 다음 본편 응답이 이걸 받아 괴이 안에서 있었던 일을 잇는다.
6. 괴이 안에서 일어난 사망·부상은 B에도 같이 들어간다.

## 10. NPC 역할과 인터페이스

NPC마다 **역할**을 가지고, 역할이 열 창이 정해진다. 지금 `place`(임무·결재·보급·탕비·의무·면담·훈련·감정·연구·이빨·격리문)를 역할 단위로 정리한다.

```ts
interface RoleDef {
  id: 'mission' | 'approve' | 'supply' | 'shop' | 'clinic' | 'appraisal' | 'lab' | 'training' | 'interview' | 'info' | 'quest' | 'reception';
  window: WindowKind;              // 표준 창 틀 하나를 공유
  needs?: Cond[];                  // 열리는 조건(해금·호감·시간)
  emits: EventKind[];              // 이 창에서 일어나는 일이 어떤 사건이 되는지
}
```

- 창은 **표준 틀 하나**(목록 + 상세 + 확인 버튼)를 쓰고 역할마다 내용만 바꾼다. 도트 UI 키트(`ui/kit.ts`) 사용.
- NPC가 자리에 없는 시간(일과)에는 창이 안 열린다(「자리를 비웠다」). 호감이 낮으면 정보 역할은 줄어든다.
- 모든 창의 결과는 사건으로 남는다(임무 수락 `quest`, 구매 `trade`, 치료는 `act` 등).
- 미성년 인물 관련 안전 규칙은 그대로 (콘쥬스는 2026-10-26 20세로 변경, 해당 없음).

## 11. 메인 UI 프레임

기존 UI 셸(`ui/`: HUD, 조이스틱·터치 버튼, 메뉴, 효과)을 확장한다. 새로 만들지 않는다.

- **평시(필드)**: 좌상단 주인공 초상 + 이름, 그 아래 동행자 작은 초상 줄, 우상단 시각·날짜·장소 이름(작게), 알림 줄(최근 사건·약속), 퀵슬롯, 메뉴 버튼. 체력 바는 평시엔 접힘.
- **전투·작전 중**: 위에 더해 체력 바, 필살 게이지, 탄약, 아이템 칸이 열림.
- **모바일**: 왼쪽 가상 조이스틱, 오른쪽 버튼(E·행동·메뉴). **입력기가 뜨면(입력칸 focus 또는 `visualViewport` 높이 감소) 조이스틱과 버튼을 숨기고**, 닫히면 다시 보인다. 입력칸은 도트 틀, 키보드 위로 올라온다.
- 말풍선·이름표·입력칸·창은 전부 도트(Galmuri). 영어 문구 없음.

## 12. 반응과 전투 (도발·선공)

NPC의 태도는 상태 하나와 점수 하나로 코드가 굴린다.

```
stance:  friendly → neutral → wary(경계) → hostile → fight → flee / down
provocation: 0~100 점수. 시간이 지나면 줄어든다.
```

- **점수를 올리는 것**: 같은 불쾌한 말 반복(모델 태그 `[[불쾌]]`를 계기로 `decide()`가 통과), 밀치기·가로막기, 물건 부수기, 선제 공격, 그 사람의 친한 사람을 해침(목격자 기록). 내리는 것: 사과 말(태그 `[[진정]]`), 선물, 시간.
- **단계 문턱**: 요원마다 성격 계수로 다르다. 경고 대사 한 번 → 경계(거리를 둠) → 적대(공격 자세) → 전투 시작. 소심한 인물은 전투 대신 도망·신고, 호전적인 인물은 먼저 반격.
- **선제 공격**: 사용자가 NPC에게 공격 버튼으로 타격하면 즉시 `provoke(level 3)` + `attack`. 상대는 바로 적대로 넘어가고 같은 장면의 목격자는 점수가 오른다.
- **전투 실행**: 벨트스크롤 전투 엔진(이미 있음)을 필드 장면에서 그대로 쓴다. 전투가 가능한 NPC는 `combat` 표(체력·공격·동작)가 있는 사람뿐이다. **지금 움직임 그림이 있는 건 쟈알디 하나**라서, 표가 없는 NPC는 전투 대신 도망·제압당함·신고 같은 **비전투 반응**으로 끝낸다. 요원 그림이 들어오면 표만 채우면 전투가 된다.
- **살해**: 설정 「필드에서 NPC 살해 허용」이 **켜져 있을 때만** `kill`이 가능하다. 꺼져 있으면 체력이 0이 된 NPC는 쓰러짐(`down`, 중상)으로 끝난다. NPC별 예외는 두지 않는다(켜면 누구든, 끄면 아무도).
- **결과**: `hurt/down/kill/flee` 사건 → 장부(8장) → B의 확정 사실 + 관계·평판 변화 + 목격자 소문(같은 장면에 있던 사람의 호감·경계 변화).
- 이 전체가 코드라서 모델은 이후 본편 응답에서 결과를 받아 쓰기만 한다.

## 13. 거점 평판과 적대 거점

소속·지역마다 **평판(standing)** 값을 가진다: 호의 · 중립 · 경계 · 적대 · 수배.

```ts
interface SiteReaction { cond: Cond[]; behavior: 'ignore' | 'watch' | 'warn' | 'expel' | 'attack'; line?: string }
```

- 거점 입장 시 `enter_site` 사건 + 평판과 방문자 소속을 보고 표의 첫 일치 반응을 고른다. 일반 NPC는 `watch`(시선만, 접근하면 `warn`), 보안 담당은 `expel`, 수배면 `attack`.
- **발각 판정**: 변장·잠입 같은 건 1차에서 안 만든다. 소속이 다르면 처음부터 방문자로 보이고, 평판이 낮을수록 반응이 강하다(`detected`는 단순한 조건 판정).
- 평판은 사건으로 움직인다(그 거점 사람을 해침, 도와줌, 임무 완수). 저장은 `standing`, 요청에는 B에 한 줄.

## 14. 그 밖에 필요한 것 (구현 가능한 것만)

| 항목 | 방식 |
| --- | --- |

## 16. 만드는 순서 (그림 없음 전제)

각 단계는 임시 네모 모양으로 돌아가고 단위 시험·브라우저 시험이 같이 간다. 끝날 때마다 브랜치에 올리고 시험 링크를 「검수 전」으로 드린다. 릴리스는 말씀하실 때만.

1. **장부**: 사건 타입, 저장, `compile()`(A·B·예산·reconcile), `withField()` 삽입, 골든 시험. 기존 대화 막간을 여기로 옮긴다. *본편 반영의 뼈대라 맨 먼저.*
2. **세계 표·입장 판정·시계**: `SiteDef`, `resolveEntry()`, 월드 시계, 하루 흐름, 그림 검증기.

4. **일과·자율 이동**: 장면 그래프 경로, 보이는 장면만 실시간.
5. **E 틀·관계값·NPC 역할 창**.
6. **반응·전투·평판**: 도발 점수, 선공, 비전투 반응, 목격자.
7. **동행**.
8. **작전 투입 현황 점검 → 재설계**(9장).
9. **이동수단·중립지역 첫 곳·나머지 거점**(B00·C00·E00).

## 17. 설정으로 넣는 것 (켜고 끄는 기능)

정하는 문제가 아니라 **설정 항목**으로 둔다. 기본값은 안전한 쪽.

| 설정 | 선택 | 기본 |
| --- | --- | --- |
| 필드에서 NPC 살해 허용 | 끔(쓰러짐까지) / 켬. 예외 없음 | **끔** |
| 필드가 상황판 요원 상태를 직접 수정 (**시험용 옵션**) | 끔(모델에게 확정 사실로 알리기만) / 켬 | 끔 |
| 이력(A) 안전 상한 | 글자 수 | 12,000자 |
| 확정 사실(B) 상한 | 글자 수 | 3,000자 |
| 필드 되돌리기 (전송 전 사건만) | 끔 / 켬 | 켬 |

없앤 설정과 이유: 시간 속도·필드 시각(5-1장 규칙으로 고정), 괴이 판정 수동 모드(3-1장 확인 카드로 대체), 이동 중 사건 연결(항상 연결, 4-3장), 거점 방문 범위(막지 않음, 2장·13장), 동행 인원(4명 고정, 7-3장).

### 필드 대화에 본편 최근 장면 넣기

필드에서 NPC에게 말을 걸면 모델을 한 번 부른다. 이 호출에 **본편 최근 장면이 들어가지 않으면 NPC가 본편 이야기를 모르는 채 대답한다.** 본편과 이어지려면 항상 들어가야 하므로 꺼짐 선택지는 없앤다. 항상 들어가는 것: 상태창(시각·위치·목표), 최근 N마디(위 설정), 장부의 확정 사실(B), 그 NPC의 로어북 시트. 마디 수는 비용 때문에 조절할 뿐이다.

### 17-1. 직접 수정 옵션 시험 계획

직접 고치면 모델 응답과 충돌해 상황판이 꼬일 수 있어서 **옵션으로만** 넣고 먼저 시험한다. 같은 사건(요원 사망·부상·이동)을 켬/끔 두 방식으로 여러 번 돌려 비교한다: 다음 응답이 사실을 지키는지, 상황판이 이중으로 바뀌거나 되돌아가지 않는지, 다시 굴리기에서 안 깨지는지. 결과가 좋으면 기본값을 바꿀지 사용자에게 묻는다. 켜진 동안 고친 내용은 설정 화면에 목록으로 보여 되돌릴 수 있게 한다.

## 18. 정해진 것

- 괴이 안일 때 필드 입장: **지금은 입장 불가**. 괴이 장면이 생기면 괴이별 `link`(탈출/전화/없음)로 처리(3-2). 판정 기준은 3-1.
- 전화 기능을 계획에 넣는다(6-3).
- 조이스틱은 구현하고, 입력기가 뜨면 버튼을 숨긴다(11장).
- 시간은 걷는 동안 흐르지 않고 행동·이동에 드는 시간으로 흐른다. 필드 시각은 본편보다 앞서간다(5-1).
- 동행은 최대 4명, 임시 인물 허용(7-3). 다른 소속 거점은 막지 않고 NPC 반응으로 결과를 받는다(2·13장). 이동 중 사건은 본편 괴이와 이어진다(4-3).

## 19. 모델 출력 규약 (상태창 확장 제안)

플러그인이 본편 이야기 속 사실을 알려면 **모델이 이미 매 응답에 적는 상태창**을 쓰는 게 가장 안정적이다(사용자 입력 없이, 모델 추가 호출 없이). 지금 상태창은 `[▣|날짜|시각|날씨|기온|위치|목표]`이고 플러그인 파서(`world/status.ts`)는 칸 수가 달라도 너그럽게 읽는다. 여기에 칸을 더하자는 제안이다. **카드 로어북의 상태창 지시를 고치고 `minPlugin`을 올리는 일이라 사용자 승인이 필요하다.**

| 새 칸 | 내용 | 쓰임 |
| --- | --- | --- |
| 동행 | 지금 주인공과 같이 있는 인물 이름들(쉼표), 없으면 없음 | 7-3 동행 자동 인식 |
| 투입 | 투입 중이면 `투입`, 아니면 `없음`(목표는 있어도 투입 전이면 없음) | 3-1 괴이 안 판정의 가장 직접적인 신호(S1·S2가 없을 때도) |

- 모델이 칸을 틀리거나 빼도 파서가 기존 6칸으로 읽으므로 **깨지지 않는다.** 새 칸은 있을 때만 쓰는 추가 신호다.
- 판정 우선순위는 그대로: 투입 지시문(플러그인이 만든 메시지) > 요원 상태 > 새 칸 > 목표 칸.
- **어떻게 진행하나** (승인 후 이 순서):
  1. 카드에서 상태창 형식을 지시하는 로어북 항목을 찾아 **지시문 수정안**(칸 추가 + 예시)을 써서 사용자에게 보여 드린다. 적용은 승인 뒤에.
  2. 플러그인 파서(`world/status.ts`)에 칸 읽기를 추가한다. 옛 6칸 응답은 그대로 읽힌다(뒤 칸이 비면 없음).
  3. 연관 기능 점검: 채팅 속 상태창을 그리는 부분(새 칸을 보여 줄지 숨길지), 간이 상태창, 상황판, 괴이 로어북 고르기(목표 칸을 쓰는 곳), 로어북 선택 설정 화면. 칸이 늘어서 깨지는 곳이 없는지 시험으로 확인.
  4. 카드 빌드와 업데이트 목록에 반영하고 `minPlugin`을 올린다(새 카드를 옛 플러그인이 읽어도 안 깨지게).
  5. 실제 모델 응답으로 칸 정확도를 센다. 낮으면 새 칸은 쓰지 않는다.
- 시험: 실제 모델로 몇 십 응답을 돌려 칸이 얼마나 정확히 나오는지 먼저 센다. 정확도가 낮으면 이 칸은 쓰지 않는다.

### 19-1. 카드 지시문 수정안 (승인 대기)

고칠 곳은 카드 로어북 **🏷️Tag**의 `## Status` 절 하나뿐이다(카드 안에서 `[▣|` 형식을 설명하는 곳은 여기뿐이다).

지금:

```
## Status
[▣|YYYY.MM.DD|HH:MM AM/PM|weather|temperature|location|anomaly]

- Output exactly one [▣] at the very end of every response, as the final line.
- Anomaly = the exact Korean name of {{user}}'s current encounter, visit, or assigned target, including briefing and travel; otherwise `없음`.
- Example (no current anomaly):
[▣|2025.01.01|02:47 AM|☀️|4°C|서울 종로구 거리|없음]
```

고친 안:

```
## Status
[▣|YYYY.MM.DD|HH:MM AM/PM|weather|temperature|location|anomaly|companions|deployed]

- Output exactly one [▣] at the very end of every response, as the final line.
- Anomaly = (그대로)
- Companions = the named individuals currently travelling together with {{user}}, most important first, exact Korean names as used in the story, separated by `,`. `없음` if none. Only people who are physically with {{user}} right now; do not list unnamed crowds or groups.
- Deployed = `투입` only while {{user}} (or the party {{user}} leads) is physically inside an anomaly site on an operation. `없음` during briefing, preparation, travel to the site, and after leaving or being evacuated.
- Example (no current anomaly):
[▣|2025.01.01|02:47 AM|☀️|4°C|서울 종로구 거리|없음|없음|없음]
- Example (inside an anomaly with two companions):
[▣|2025.01.01|10:15 PM|🌫️|9°C|명일 아파트 3층 복도|명일 아파트|쟈알디,에일린|투입]
```

그 원문 지침에서 **괴이 칸이 「브리핑·이동을 포함한 배정 목표」**라고 되어 있다는 점이 확인됐다. 그래서 괴이 칸만으로 안/밖을 가를 수 없고, 새 「투입」 칸이 필요하다는 판단이 맞다.

플러그인 쪽 고칠 곳:
- `core/world/status.ts` `fieldsOf()`: 지금은 6칸이 아니면 위치 뒤 모든 칸을 이어 붙여 목표로 읽는다(`rest.slice(1).join(' | ')`). 칸이 8개가 되면 목표에 「동행 | 투입」까지 섞이므로 **위치 뒤 첫 칸 = 목표, 다음 = 동행, 다음 = 투입**으로 읽게 고친다. 옛 6칸은 그대로 읽힌다. `StatusTag`에 `companions`, `deployed` 추가.
- 상태창을 그리는 곳(새 칸은 그리지 않음), 간이 상태창(`tags.ts`), 상태창 줄을 맨 끝으로 옮기는 코드(`tags.ts`), 상황판 시각 읽기(`gnet.ts`)는 칸 수와 무관한지 시험으로 확인.
- 카드 빌드(`build_lite_card.py`)와 `package.json` `goei.minPlugin`을 올림.

## 20. 더 필요한 것

| 항목 | 방식 |
| --- | --- |
| **괴이 장면 만들기** | 본편에 괴이가 수십 개라 하나씩 못 만든다. **범용 괴이 템플릿** 몇 개(규칙형·추격형·퍼즐형) + 괴이별 값 표(규칙, 구조, 단서, 위협). 로어북 괴이 이름으로 템플릿을 고른다 |
| **필드 사건 되돌리기 (옵션)** | 가능하다. 필드 상태(위치·관계·부상)를 사건을 다시 재생해서 계산하는 방식으로 만들면, 사건 하나를 빼고 다시 재생하면 된다. 단 **아직 본편에 전송하기 전 사건만** 되돌린다(전송 뒤에는 모델이 이미 그 일을 알고 응답했으므로, 그때는 본편 다시 굴리기가 맡는다). 설정 「필드 되돌리기」 켬/끔 |
| **기록 보기** | 지금 있는 설정 「본편 로어북 확인」 안에 「필드 기록」 칸을 더한다. 거기서 지금 본편에 들어갈 막간(A)과 확정 사실(B) 글을 그대로 보여 준다 |
| **부상·사망 후처리** | 만들지 않는다. 상태 변화는 모델이 출력하고 필드는 그 상태를 읽기만 한다. 필드에 있는 동안 요원이 회복해 돌아오는 일은 없다. 다만 **부상·격리(오염 포함)여도 의식이 있으면 침대나 격리실로 가서 대화할 수 있다**: 상태가 부상·격리면 일과 대신 의무실 침대 / 격리실 자리에 고정되고 E로 대화 가능. 사망·실종·작전투입은 필드에 없다. 상황 글에 「의식불명·혼수」가 있으면 대화는 막힌다(키워드) |

### 20-1. 필드를 열고 닫는 흐름

현재 코드(`ui/app.ts`)에서 확인한 것:
- 다른 탭으로 가면 `hideGame()`: 게임을 화면에서 떼어 두고 멈추지만 **상태는 유지**한다.
- **창을 닫으면 `close()`가 `closeGame()`을 불러 필드가 초기화된다.** 이게 문제다.
- 본편이 한 턴 진행되면(마지막 메시지가 바뀜) 필드를 닫는 코드는 이미 있다(`anchor !== fieldAnchor`).

바꿀 것:

| 상황 | 동작 |
| --- | --- |
| 다른 탭으로 감 | 지금처럼 멈춤(유지) |
| **창(메인 패널)을 닫음** | `closeGame()` 대신 `hideGame()`: **유지하고 멈춘다.** 다시 열면 그 자리에서 이어진다 |
| 「필드 나가기」 버튼 | 필드를 끝내고 장부에 저장 |
| **채팅을 전송함** | 필드를 끝낸다. 먼저 장부를 저장하고(사건이 요청에 들어가야 하므로) 요청이 나가고, 모델 응답이 오면 다음에 필드를 열 때 새 본편 상태로 시작 |
| 채팅·캐릭터를 바꿈 | 필드를 끝낸다 |
| 새로고침·Risu 종료 | 장부는 채팅 변수에 이미 저장돼 있으므로 사건은 남는다. 필드 화면은 마지막 저장 위치에서 다시 시작 |

핵심은 두 가지다. 창을 닫는 것과 전송은 다르고(닫으면 유지, 전송하면 종료), 전송으로 필드가 끝나야 응답이 반영된 새 상태로 다시 열린다. 사용자가 짐작하신 구조가 맞다.

장부는 **사건이 일어날 때마다 즉시 저장**한다(종료를 기다리지 않는다). 그래서 어떤 이유로 필드가 끝나도 이미 일어난 일은 사라지지 않는다.
