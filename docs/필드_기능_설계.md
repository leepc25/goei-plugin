# 필드 기능 설계 (그림 없이 먼저 짜는 구조)

2026-10-23. 그림·요원 배치는 나중에 들어오고, 이 문서는 필드가 **어떻게 작동하는지**만 정한다. 그림이 하나도 없어도 네모 임시 모양으로 전부 돌아가게 만든다.

## 0. 원칙

1. **게임 코드가 정한다. 모델은 대사만 쓴다.** 위치·이동·일과·동행 같은 행동은 코드가 판정하고, 모델은 대화를 누를 때만 부른다. 모델이 태그로 계기를 줘도 받을지는 코드가 정한다(지금 NPC 대화 방식 그대로).
2. **세계는 데이터다.** 지역·장면·이동수단·거점·일과를 표 하나씩으로 적고, 엔진은 표를 읽기만 한다. 그림 파일은 표의 이름만 가리킨다. 그림이 없거나 지침과 달라도 표와 충돌 상자는 그대로 돈다.
3. **본편이 먼저다.** 본편 상황판(요원 상태·괴이 위치·시각)과 필드가 어긋나면 본편을 따른다. 필드는 본편에 마음대로 쓰지 않고, 사용자가 버튼을 누를 때만 기록한다.
4. **보이는 곳만 진짜로 움직인다.** 화면 밖 NPC는 일과표로 위치만 계산한다(5장).

## 2. 소속(조직 코드)에 따라 들어가는 곳

본편 `faction`이 시작 코드를 정한다. 코드는 시작 화면에서 고른 세력이고 지금 다섯 개다(`scenarios.json`).

| 코드 | 세력 | 거점(필드 시작 지점) | 비고 |
| --- | --- | --- | --- |
| A00 | 관리국 | 관리국 본부 (지금 17장면) | 이미 있음 |
| B00 | 가짜 관리국 | 가짜 관리국 거점 | 이도형·곽성주 쪽, 새로 |
| C00 | 백일몽 주식회사 | 백일몽 본사 | 새로. 위장 제약사 모습 |
| D00 | 민간인 | 자택 | 거점 없음. 방문만 가능 |
| E00 | 프리랜서 | 협회 접수창구·알선소 | 의뢰 중심 |

**거점(Site)** = 장면 묶음 + 입장 가능 소속 + 시작 장면. 데이터:

```ts
interface SiteDef {
  id: string;                    // 'hq_a00', 'daydream', 'assoc', 'mid_arcade' …
  name: string;
  kind: 'faction' | 'neutral' | 'home' | 'outside';
  scenes: SceneId[];             // 이 거점에 속한 장면
  entry: SceneId;                // 들어오는 장면
  // 들어올 수 있는 조건. 못 들어오면 문 앞에서 이유를 한 줄 보여 준다
  access: { factions?: string[]; needs?: Cond[]; deny?: Cond[]; denyText?: string };
}
```

- 필드에 들어가는 순간 `faction`으로 **시작 거점**을 고른다(위 표). 한 코드의 시작 거점은 하나, 나머지는 이동으로 간다.
- 다른 소속이 남의 거점에 가면 **방문자**로 들어간다: 문이 잠기거나(관리국 본부에 백일몽 직원), 접수창구까지만 열린다. 규칙은 `access`가 정하고, 못 들어올 때 이유(`denyText`)를 보여 준다.
- **새 소속(F00 이후)**은 코드를 더해도 `SiteDef` 한 줄 + 장면만 더하면 된다. 코드 확장은 [조직코드_확장_설계.md](조직코드_확장_설계.md) 3장과 같은 방향이다(소속 목록을 명부에서 읽는다).
- 같은 NPC 명단(`roster.ts`)의 `group`을 거점에 묶는다(예: 관리국 요원은 관리국 거점 소속). 거점이 달라도 NPC 대화 기술은 같다.

## 3. 처음 들어갈 때 위치 판정

필드를 열 때 **본편 스냅숏**으로 지금 어디에 있어야 하는지 정한다. 모델을 부르지 않고 코드 규칙으로만.

```
입력: faction, player(조작 요원), events[](loc,state), minute, 마지막 필드 위치(저장)
출력: { site, scene, x } 또는 { denied: '이유' }
```

| 본편 상황 | 판정 |
| --- | --- |
| 평소(진행 중 괴이 없음) | 마지막 필드 위치. 저장이 없으면 시작 거점 `entry` |
| 플레이어가 **괴이 안**(그 요원의 `events`가 활성) | 본부·중립 지역에 못 들어간다. 「지금은 나갈 수 없다」 한 줄. 괴이 안 필드(승강기·아파트 등 출동 장면)가 있으면 거기로, 없으면 입장 불가 |
| 플레이어가 부상·격리 | 의무실 또는 격리 구역 시작. 건물 밖으로 못 나감 |
| 본편 시각이 마지막 필드 시각보다 크게 지남 | 위치를 일과 기준으로 다시 정함(예: 밤이면 자택·숙소) |
| D00 민간인 | 자택 또는 길거리. 거점 문은 방문 규칙을 따름 |

- 판정 함수 하나(`gate.ts: resolveEntry(snapshot, save)`)에 모은다. 규칙은 표 배열로 두어 추가가 쉽다.
- 판정 결과 `denied`가 나오면 필드는 열리되 **움직일 수 없는 안내 화면**이 먼저 뜬다(이유 한 줄 + 닫기). 모델 호출 없음.
- 어려운 부분: 상황판 `loc`(위치) 문자열을 거점·장면 id에 잇는 표가 필요하다. 사건 이름이 로어북 글이라 정확히 맞지 않을 수 있어, 못 맞추면 **안전한 쪽**(입장 허용 + 경고)이 아니라 **본편 값 그대로 보여 주고 사용자가 확인**하는 쪽으로 한다.

## 4. 지역, 중립지역, 이동

### 4-1. 지역 그래프

```
Region (도시 한 구역)  ──  Site (거점·중립지)  ──  Scene (걷는 화면)
```

- **Scene**: 걷는 화면 하나(지금 17장면과 같은 모양).
- **Site**: 장면 묶음. 종류는 `faction`(소속 거점) · `neutral`(중립지역: 중림 지하상가, 협회, 파스타집, 편의점 등) · `home`(자택) · `outside`(길거리·역).
- **Link**: 장면 사이 연결. 문(걸어서) 또는 이동수단(탈것). 문은 지금처럼 `HqDoor`, 이동수단은 4-3.
- 중립지역은 소속 거점과 같은 `SiteDef`를 쓰고 `access`가 비어 있다(누구나). 상인·의뢰·정보처럼 **그 지역에서만 되는 기능**은 장면의 자리(`spot`)에 붙인다. 지금 `spot.place`와 같은 방식.
- 중립지역 안에도 NPC가 산다(상인 마덕희, 고연지·윤지아 등). 일과는 5장 그대로.

### 4-2. 건물 밖(길거리)

- 도시는 **연속된 거리 장면 몇 개**로 만든다(종로 뒷골목처럼 좌우로 긴 장면). 한 도시 전체를 걷게 하지 않는다.
- 거리 장면에는 건물 입구(문)와 이동수단 승강장(역·정류장)이 있다.
- 거리에 사는 사람은 승객·주민·행인(엑스트라). 엑스트라는 대화 가능 여부를 데이터로 정한다(대화 불가면 말풍선 몇 줄만).

### 4-3. 이동수단

지하철·버스·택시·도보를 같은 표로 적는다.

```ts
interface TravelRoute {
  id: string;
  mode: 'walk' | 'subway' | 'bus' | 'taxi' | 'elevator' | 'stairs' | 'car';
  from: SceneId; to: SceneId;
  minutes: number;               // 월드 시계가 이만큼 흐른다
  cost?: number;                 // 예산(없으면 공짜)
  cond?: Cond[];                 // 열려 있는 시간·소속·해금
  ride?: SceneId;                // 가는 동안 보일 장면(지하철 칸 등). 없으면 암전 연출
  events?: TravelEvent[];        // 가는 도중 일어날 일(확률·조건)
}
```

- **지역 안은 걷기**(장면 안 이동 + 문), **지역 사이는 이동수단 고르기**. 승강장 앞 E → 행선지 목록(요금·시간) → 고르면 탑승.
- 탑승 연출은 두 단계: ① 짧은 암전과 도착 장면, ② (`ride`가 있으면) 탈것 장면에서 몇 초 머물기. 처음엔 ①만 만들고 ②는 그림이 생기면 켠다(표에 `ride`만 적으면 됨).
- **도중 사건**: 지하철에서 괴이 단서·승객 대화 같은 일이 확률로 끼어든다. 본편 괴이와 이어질지는 별도 결정(열린 질문 2).
- 시간이 흐르므로 이동 중 NPC 일과(5장)와 본편 시각(3장)이 같이 움직인다.

## 5. 월드 시계와 NPC 자율 이동

### 5-1. 시계

- 월드 시계는 **분 단위 하나**. 본편 상황판 `minute`이 있으면 거기서 받고, 없으면 필드가 자체로 흘린다(걷기는 실시간 1초 ≒ 게임 1분 정도로 빠르게. 값은 설정).
- 필드를 닫으면 시계는 멈추고, 열 때 본편 시각이 앞서 있으면 따라간다. 필드가 본편 시각을 마음대로 올리지는 않는다.

### 5-2. NPC 일과

```ts
interface Schedule { npc: string; blocks: { from: number; to: number; site: string; scene: SceneId; spot?: string; act: string; cond?: Cond[] }[] }
```

- 시간대마다 **어느 장면의 어느 자리에서 무슨 일**을 하는지 적는다(잼트리: 낮 운영 데스크, 점심 휴게실 …).
- 본편 상태가 먼저: 작전투입 → 필드에서 사라짐, 부상 → 의무실, 격리 → 격리 구역, 휴게 → 휴게실 쪽 블록. 기존 방문 대화의 분류(`내근→사무실` 등)를 이 규칙으로 흡수한다.
- 일과에 없는 시간은 `act: 'idle'`(그 거점 안에서 어슬렁).

### 5-3. 자율 이동 AI (모델 없음)

NPC 하나의 상태 기계:

```
idle(자리에서 작은 행동) → walk(목표로 이동) → work(자리 동작) → talk(대화 중 정지)
 → follow(동행) → react(놀람·도망·경계) → away(화면 밖)
```

- **목표 정하기**: 일과표 블록이 바뀌면 목표 장면·자리를 얻는다. 같은 장면이면 직선 이동 + 충돌 상자 회피(기존 `clearSpot`/`blockByProps`), 다른 장면이면 **장면 그래프 최단 경로**(문·승강기·계단의 `to`)를 따라 문 앞까지 걷고 문을 통과해 사라졌다가 다음 장면 문에서 나타난다.
- **단순 회피**: 길이 막히면 옆으로 한 걸음, 3번 실패하면 목표 자리로 순간 이동(끼임 방지).
- **idle 행동**: 요원별 목록에서 코드가 무작위로 고른다(기지개, 서류 보기, 서성임 …). 모델 호출 없음. 지금 계획대로 **일상 동작은 코드, 모델은 대사만**.
- **인사**: 가까이 가면 요원×방문자 관계표로 목례/손 인사/무시를 코드가 고른다.
- **LOD(성능)**: 지금 화면에 있는 장면의 NPC만 프레임마다 움직인다. 다른 장면의 NPC는 시계가 바뀔 때만 「지금 있어야 할 장면·자리」를 계산해 놓는다. 사용자가 그 장면에 들어가면 그 자리에 세운다(이동 중이어야 하면 문 근처). 그래서 사람이 많아도 가볍다.
- **저장**: NPC 위치는 저장하지 않는다. 일과와 시각으로 다시 계산한다. 저장하는 건 관계·플래그·동행 상태뿐.

## 6. E 상호작용, 호감·감정

### 6-1. E 흐름

지금 규칙: 대화할 수 있는 사람 앞 E = 대화창, 한 번 더 E = 원래 하던 일(임무·거래). 이걸 이렇게 바꾼다.

- 대상 앞 E → 화면 **아래 작은 입력칸 하나**가 뜬다(풀 패널 없음, 사용자 지시). 입력칸 위에 **선택줄**: `대화 · 부탁 · 물건 · 일`. 글을 바로 치면 대화.
- 도트 말풍선과 이름표는 그대로. 생각 중에는 머리 위에 작은 점 세 개.
- **기능 목록**(대상이 가진 것만 보임, `roster.ts`의 `effects`와 `spot` 데이터로 정함):

| 선택 | 하는 일 | 판정 |
| --- | --- | --- |
| 대화 | 자유 글 → 모델 | 모델 대사 + 태그를 `decide()`가 판정 |
| 부탁 | 「따라와」「기다려」「이거 해줘」 | 7장. 코드가 의도를 분류 |
| 물건 | 선물·거래·받기 | 호감·재고 규칙 |
| 일 | 그 사람/자리의 업무(임무, 감정, 치료, 접수) | 지금 `spot.place` 메뉴 창 |
| 정보 | 단서·소문 묻기 | 힌트 목록에서 하나씩, 만남당 제한 |
| 조사 | 물건·장소 살펴보기 | 자리 `act`, 문장은 코드 |

- 이동 중(승강장·문)과 구분: 문·승강장·물건의 E는 대화칸 없이 바로 동작한다.

### 6-2. 호감과 감정

지금은 호감 하나(−3~+3). 이렇게 넓힌다. 표시는 지금처럼 단어 한 줄, 내부는 숫자.

| 값 | 범위 | 움직이는 이유 | 마르는가 |
| --- | --- | --- | --- |
| 호감(affinity) | −100~100, 표시 7단계 | 대화 계기, 선물, 구해 줌, 방해·폭력, 약속 지킴 | 매우 느리게 0쪽으로 |
| 신뢰(trust) | 0~100 | 약속 이행, 비밀 지킴, 같이 겪은 일 | 안 마름, 배신하면 급락 |
| 기분(mood) | 평온·기쁨·화남·슬픔·불안·피곤 | 방금 일(대화, 사건, 시간대) | 몇 시간 안에 평온으로 |
| 경계(guard) | 0~3 | 위협, 낯선 방문자 | 시간이 지나면 풀림 |

- 모델 태그는 계기만(`[[호감 +1]]` 등). **수치 변화는 `decide()`가 정한다**: 한 번 대화로 ±5 이하, 하루 상한, 같은 계기 반복은 체감.
- 요원마다 **성격 계수**(쉽게 마음 여는 정도, 화 오래 가는 정도)를 로어북 시트 기준으로 표에 둔다. 쟈알디는 호감이 천천히 오르고, 데쥬레는 선물에 약한 식.
- 프롬프트에 **호감 단계·기분·경계**를 문장으로 넣어 말투가 변한다(`buildPrompt`에 칸 추가).
- 저장은 필드 저장 안의 `relations` 한 칸. **본편 채팅에는 자동으로 쓰지 않는다.** 사용자가 「본편에 기록」을 누르면 「관계 변화」 줄을 기록 로어북에 넣는다.
- 방문자 정체성은 이미 플레이어 블록(`applyPlayer`)을 쓰므로, 관계는 **방문자 이름 기준**으로 저장한다.

## 7. 「따라와」 실제 동행

### 7-1. 어디서 말하나

- **필드 대화창**: 사용자가 「따라와」를 입력하면 모델이 응답하면서 `[[동행]]`을 달고, `decide()`가 조건을 본다(호감, 상태, 동행 가능). 지금도 있는 길.
- **본편 채팅**: 필드 밖 일반 채팅의 「따라와」는 필드와 따로다. 필드를 열 때 본편 최근 마디에서 **동행 요청을 감지**해 확인 카드를 한 번 보여 준다(「에일린에게 따라오라고 하셨습니다. 필드에서 동행시킬까요?」). 몰래 적용하지 않는다.

### 7-2. 의도 분류 (코드 우선)

1. 짧은 키워드 규칙(따라와/같이 가/기다려/여기 있어/돌아가)으로 먼저 거른다. 명확하면 모델 없이도 처리(`부탁` 선택에서 눌러도 같음).
2. 애매하면 대화로 넘겨 모델 태그를 받는다.

### 7-3. 동행 상태 기계

```
승낙 → follow(주인공 뒤 일정 거리) → 문 통과 시 같이 이동 → 이동수단도 같이 탑승 → 해제
```

- **추종**: 주인공이 걸은 길(발자국 열)을 따라 1.5초 뒤처져 걷는다. 막히면 가까이 순간 합류. 따로 길찾기를 하지 않아 단순하고 끼임이 적다.
- **장면 전환**: 문·승강기·계단·이동수단에서 주인공이 나가면 동행자도 같은 장면 도착 지점에 같이 나타난다.
- **제한**: 동행 인원 최대 2명(설정), 상태(부상·작전투입·근무 중)·호감·그림 유무가 안 맞으면 거절 대사. 거절 이유는 문장으로 보여 준다.
- **해제**: 「기다려」「돌아가」, 호감 하락, 일과 시간이 중요한 NPC는 시간이 되면 스스로 「슬슬 돌아가야겠다」 하고 떠남.
- **일과와의 관계**: 동행 중에는 일과를 멈춘다. 해제하면 일과대로 복귀(가장 가까운 목표 자리로 걸어감).
- **전투/괴이 안**: 동행은 괴이 안 출동 장면에는 **들어가지 않는다**(1차). 출동 동행은 전투 설계가 정해진 뒤 따로.
- 저장: `companions: [{npc, since, mood}]`만 저장. 필드를 다시 열면 같은 장면에 같이 서 있다.

## 8. 필드 결과를 본편에 잇기 (장부)

필드에서 한 일이 다음 본편 응답에 반드시 반영돼야 한다. 말, 이동, 살해, 괴이 진입, 전투 전부. 모델을 부르지 않고 **플러그인이 기록하고, 요청이 나갈 때 정제해서 끼운다.** 지금도 대화는 이 방식이다(`goeiHqVisitV1`에 쌓고, `beforeRequest` 훅의 `withVisit`이 `[필드 막간]`을 해당 메시지 뒤에 끼움). 이걸 모든 사건으로 넓힌다.

### 8-1. 사건(FieldEvent)

```ts
interface FieldEvent {
  id: string;
  at: number;            // 게임 분 (월드 시계)
  anchor: string;        // 이 일이 일어났을 때 본편 마지막 메시지 chatId (다시 굴리기·삭제에 안전한 기준)
  scene: SceneId;        // 어디서
  who: string[];         // 관여한 사람 (주인공 포함)
  witnesses?: string[];  // 같은 장면에 있던 사람 (소문·반응에 씀)
  weight: 1 | 2 | 3;     // 중요도: 3 = 반드시 모델에 알림, 1 = 공간 남으면
  kind: EventKind;
  data: Record<string, unknown>;
}
type EventKind =
  | 'talk'       // 대화 (이미 있음: 사용자 글 + NPC 답 + 끼어듦)
  | 'act'        // 사용자가 쓴 행동 *…*
  | 'move'       // 장소 이동 {from,to,by,minutes}
  | 'hurt' | 'down' | 'kill' | 'flee'    // 전투 결과 {attacker,target,how}
  | 'provoke'    // 도발·선공 {by,target,level}
  | 'gift' | 'trade' | 'quest'            // 물건·의뢰
  | 'follow' | 'unfollow'                 // 동행
  | 'enter_anomaly' | 'exit_anomaly'      // 작전 투입(9장) {anomaly,party,log[],facts[]}
  | 'enter_site' | 'detected'             // 적대 거점 진입·발각(13장)
  | 'appoint';                            // 약속
```

모든 사건은 **게임 코드가 만든다.** 모델 응답에서 읽는 건 대화 태그(`[[동행]]` 등)뿐이고, 그것도 `decide()`가 통과시켜야 사건이 된다.

### 8-2. 저장

- 채팅 변수 `goeiFieldV1` 하나: `{ schema, clock, pos, events[], facts{}, relations{}, companions[], standing{} }`. 채팅에 붙으므로 채팅마다 따로고, Risu에서 채팅을 복제하거나 분기하면 같이 따라간다. 기존 `goeiHqVisitV1`은 `talk` 사건으로 흡수한다(옛 기록은 읽어서 옮기는 `migrate()`).
- 육성(숙련·재화·해금)은 기존 슬롯 저장 그대로. **세계 사실(위치·사망·관계·장부)은 채팅 귀속, 육성은 계정 귀속**으로 나눈다. 채팅을 바꾸면 세계가 바뀌고 육성은 이어진다.
- 상한: 사건 300건. 넘으면 오래되고 weight 1인 것부터 한 줄 요약(`[요약] 1일차 오전: 휴게실에서 에일린과 잡담 6회`)으로 접는다. 접는 건 코드(템플릿)가 한다.

### 8-3. 요청에 넣는 두 덩어리

요청 직전 `withField(messages)`가 `withVisit` 자리에서 두 가지를 끼운다.

**A. 일어난 일 (이력)** — `[필드 막간]` 일반화. 사건을 코드 템플릿으로 사람이 읽는 줄로 바꿔 **해당 anchor 메시지 바로 뒤**에 넣는다(지금과 같은 위치 규칙).

```
[필드 막간]
— 2층 복도에서 휴게실로 이동 (14:10, 도보 2분) —
쟈알디 (행동): 에일린의 멱살을 잡았다.
에일린: "…손 놔."
쟈알디 (행동): 밀쳤다. → 에일린이 반격했다. 에일린이 쓰러졌다 (중상).
```

**B. 지금 확정된 사실 (상태)** — 이력과 별개로 항상 **최신 한 덩어리**를 마지막 사용자 메시지 앞에 넣는다. 크기가 일정하다.

```
[필드 확정 사항]
- 주인공 위치: 휴게실 (2일차 14:20)
- 에일린: 중상, 의무실 이송 예정. 이 일은 되돌릴 수 없다.
- 데드폴: 사망 (필드에서 살해됨, 2일차 11:05). 이후 장면에 살아서 나오지 않는다.
- 동행: 로제몬
- 평판: 가짜 관리국 거점 — 수배
- 약속: 15:00 면담실, 스팡달
```

- 규칙문(카드 로어북 「Visit」, 지금 `visitContextRules`)에 이렇게 적는다: 「A는 실제 있었던 일, B는 확정 상태. 어기지 않는다. **주인공 위치가 바뀌었으면 이전 장면을 잇지 말고 B의 위치에서 장면을 시작한다.**」 이동이 없고 대화만 있었으면 규칙문이 「막간」 문구를 쓰고, `move`가 있으면 「장면 전환」 문구로 바꾼다.
- **본편 상황판과의 정합**: 필드가 `사망`이라 적었는데 모델 응답이 상황판을 그렇게 고치면 그 사실은 B에서 뺀다(요청마다 스냅숏의 요원 상태와 비교하는 `reconcile()`). 모델이 안 고치면 계속 B에 남아 매번 알린다. 그래서 모델이 무시해도 사실이 사라지지 않는다.
- 필드가 상황판을 **직접 고치지는 않는다**(기획서 22.3 유지: 본편 상태는 모델과 사용자만 바꿈). 대신 위 B로 강하게 알린다. 직접 쓰기가 필요하면 별도 결정이다(열린 질문).
- **예산**: A와 B 합쳐 약 1,500자 상한(설정). 넘으면 weight 낮은 것부터 한 줄 요약으로 줄이고, 같은 종류 연속 이동은 합치고, 대화는 최근 몇 개만 원문으로 둔다. 전투는 라운드가 아니라 결과 한 줄 + 결정적 장면 하나.
- **다시 굴리기·삭제**: 기준 메시지가 사라진 사건은 A에 넣지 않는다(지금 `orphanTurns`와 같음). 사실(B)에 영향을 준 사건이 고아가 되면 설정 화면에 「고아 사건 N건」으로 보이고 사용자가 되살리거나 버린다. 몰래 지우지 않는다.
- **시험**: 사건 목록 → 정제 결과 글을 골든 파일로 비교하는 단위 시험(모델 없이 결정적으로 나옴). 이 장이 가장 중요하므로 먼저 만든다.

### 8-4. 본편에 쓰는 것

- 위 요청 삽입은 사용자 버튼 없이 자동이다(읽기 전용 삽입, 채팅 메시지는 안 건드림).
- 「본편에 기록」 버튼(지금 있음)은 작전 보고서 같은 **긴 기록 로어북**용으로 남긴다.

## 9. 작전 투입(괴이 안) 다시 짜기

지금 출동은 「본부 → 승강기 층 → 정산」이 따로 놀고 본편 괴이와 이어지지 않는다. 이렇게 바꾼다.

1. **먼저 현황 점검**: 지금 출동 흐름의 문제를 목록으로 뽑는다(어디서 끊기고 무엇이 본편과 안 이어지는지). 설계는 그 목록을 보고 고친다.
2. **흐름**: 임무 창구(잼트리) → 대상 괴이 고르기(본편 `events` 중 활성) → 편성(주인공+동행) → 장비 → 투입. 전부 코드, 모델 없음.
3. **괴이 정의표** `AnomalyStageDef`: 괴이 이름(본편 로어북과 같은 이름), 구조(층·구역), 규칙, 단서 목록, 적·수호자, 보상. **정의표가 있는 괴이만 필드에서 들어갈 수 있다.** 없는 괴이는 입구가 닫혀 「본편에서 처리」로 표시된다. 처음 지원: 차원 승강기, 명일 아파트(이미 스테이지 모듈 있음). 늘리는 건 표 채우기다.
4. **기록**: 투입 중 스테이지 `notes`(`stage.found`, `stage.rescued`, `stage.depth` 등 이미 있음)를 `RunLog`로 모은다: 지난 구역, 발견한 규칙과 단서, 만난 존재, 구한 사람, 부상·사망, 쓴 아이템, 위반한 규칙. 코드가 하이라이트 최대 8줄로 줄인다.
5. **퇴장·후송·철수** 때 `exit_anomaly` 사건 하나가 장부에 들어간다(결과 + 하이라이트 + 확정 사실). 다음 본편 응답이 이걸 받아 괴이 안에서 있었던 일을 잇는다.
6. 괴이 안에서 일어난 사망·부상은 B에도 같이 들어간다.

## 10. NPC 역할과 인터페이스

NPC마다 **역할**을 가지고, 역할이 열 창이 정해진다. 지금 `place`(임무·결재·보급·탕비·의무·면담·훈련·감정·연구·이빨·격리문)를 역할 단위로 정리한다.

```ts
interface RoleDef {
  id: 'mission' | 'approve' | 'supply' | 'shop' | 'clinic' | 'appraisal' | 'lab' | 'training' | 'interview' | 'info' | 'quest' | 'reception';
  window: WindowKind;              // 표준 창 틀 하나를 공유
  needs?: Cond[];                  // 열리는 조건(해금·호감·시간)
  emits: EventKind[];              // 이 창에서 일어나는 일이 어떤 사건이 되는지
}
```

- 창은 **표준 틀 하나**(목록 + 상세 + 확인 버튼)를 쓰고 역할마다 내용만 바꾼다. 도트 UI 키트(`ui/kit.ts`) 사용.
- NPC가 자리에 없는 시간(일과)에는 창이 안 열린다(「자리를 비웠다」). 호감이 낮으면 정보 역할은 줄어든다.
- 모든 창의 결과는 사건으로 남는다(임무 수락 `quest`, 구매 `trade`, 치료는 `act` 등).
- 콘쥬스(미성년) 관련 안전 규칙은 그대로.

## 11. 메인 UI 프레임

기존 UI 셸(`ui/`: HUD, 조이스틱·터치 버튼, 메뉴, 효과)을 확장한다. 새로 만들지 않는다.

- **평시(필드)**: 좌상단 주인공 초상 + 이름, 그 아래 동행자 작은 초상 줄, 우상단 시각·날짜·장소 이름(작게), 알림 줄(최근 사건·약속), 퀵슬롯, 메뉴 버튼. 체력 바는 평시엔 접힘.
- **전투·작전 중**: 위에 더해 체력 바, 필살 게이지, 탄약, 아이템 칸이 열림.
- **모바일**: 왼쪽 가상 조이스틱, 오른쪽 버튼(E·행동·메뉴). **입력기가 뜨면(입력칸 focus 또는 `visualViewport` 높이 감소) 조이스틱과 버튼을 숨기고**, 닫히면 다시 보인다. 입력칸은 도트 틀, 키보드 위로 올라온다.
- 말풍선·이름표·입력칸·창은 전부 도트(Galmuri). 영어 문구 없음.

## 12. 반응과 전투 (도발·선공)

NPC의 태도는 상태 하나와 점수 하나로 코드가 굴린다.

```
stance:  friendly → neutral → wary(경계) → hostile → fight → flee / down
provocation: 0~100 점수. 시간이 지나면 줄어든다.
```

- **점수를 올리는 것**: 같은 불쾌한 말 반복(모델 태그 `[[불쾌]]`를 계기로 `decide()`가 통과), 밀치기·가로막기, 물건 부수기, 선제 공격, 그 사람의 친한 사람을 해침(목격자 기록). 내리는 것: 사과 말(태그 `[[진정]]`), 선물, 시간.
- **단계 문턱**: 요원마다 성격 계수로 다르다. 경고 대사 한 번 → 경계(거리를 둠) → 적대(공격 자세) → 전투 시작. 소심한 인물은 전투 대신 도망·신고, 호전적인 인물은 먼저 반격.
- **선제 공격**: 사용자가 NPC에게 공격 버튼으로 타격하면 즉시 `provoke(level 3)` + `attack`. 상대는 바로 적대로 넘어가고 같은 장면의 목격자는 점수가 오른다.
- **전투 실행**: 벨트스크롤 전투 엔진(이미 있음)을 필드 장면에서 그대로 쓴다. 전투가 가능한 NPC는 `combat` 표(체력·공격·동작)가 있는 사람뿐이다. **지금 움직임 그림이 있는 건 쟈알디 하나**라서, 표가 없는 NPC는 전투 대신 도망·제압당함·신고 같은 **비전투 반응**으로 끝낸다. 요원 그림이 들어오면 표만 채우면 전투가 된다.
- **살해**: `kill`은 설정이 켜져 있을 때, 그리고 NPC가 `killable`일 때만 가능하다. 아니면 쓰러짐(`down`, 중상)으로 끝난다. 기본값: 핵심 인물은 `killable: false`, 콘쥬스는 항상 false. 사용자 설정 「필드에서 살해 허용」 기본 끔(17장 열린 질문).
- **결과**: `hurt/down/kill/flee` 사건 → 장부(8장) → B의 확정 사실 + 관계·평판 변화 + 목격자 소문(같은 장면에 있던 사람의 호감·경계 변화).
- 이 전체가 코드라서 모델은 이후 본편 응답에서 결과를 받아 쓰기만 한다.

## 13. 거점 평판과 적대 거점

소속·지역마다 **평판(standing)** 값을 가진다: 호의 · 중립 · 경계 · 적대 · 수배.

```ts
interface SiteReaction { cond: Cond[]; behavior: 'ignore' | 'watch' | 'warn' | 'expel' | 'attack'; line?: string }
```

- 거점 입장 시 `enter_site` 사건 + 평판과 방문자 소속을 보고 표의 첫 일치 반응을 고른다. 일반 NPC는 `watch`(시선만, 접근하면 `warn`), 보안 담당은 `expel`, 수배면 `attack`.
- **발각 판정**: 변장·잠입 같은 건 1차에서 안 만든다. 소속이 다르면 처음부터 방문자로 보이고, 평판이 낮을수록 반응이 강하다(`detected`는 단순한 조건 판정).
- 평판은 사건으로 움직인다(그 거점 사람을 해침, 도와줌, 임무 완수). 저장은 `standing`, 요청에는 B에 한 줄.

## 16. 만드는 순서 (그림 없음 전제)

각 단계는 임시 네모 모양으로 돌아가고 단위 시험·브라우저 시험이 같이 간다. 끝날 때마다 브랜치에 올리고 시험 링크를 「검수 전」으로 드린다. 릴리스는 말씀하실 때만.

1. **장부**: 사건 타입, 저장, `compile()`(A·B·예산·reconcile), `withField()` 삽입, 골든 시험. 기존 대화 막간을 여기로 옮긴다. *본편 반영의 뼈대라 맨 먼저.*
2. **세계 표·입장 판정·시계**: `SiteDef`, `resolveEntry()`, 월드 시계, 하루 흐름, 그림 검증기.
3. **UI 프레임**: 평시/전투 HUD, 조이스틱, 입력기 감지로 버튼 숨기기.
4. **일과·자율 이동**: 장면 그래프 경로, 보이는 장면만 실시간.
5. **E 틀·관계값·NPC 역할 창**.
6. **반응·전투·평판**: 도발 점수, 선공, 비전투 반응, 목격자.
7. **동행**.
8. **작전 투입 현황 점검 → 재설계**(9장).
9. **이동수단·중립지역 첫 곳·나머지 거점**(B00·C00·E00).

## 17. 사용자가 정할 것

1. 괴이 안일 때 본부 입장: 완전 불가인지, 전화 대화만 허용인지.
2. 필드에서 NPC **살해 허용**: 기본 끔(쓰러짐까지)으로 할지, 켜고 핵심 인물만 막을지.
3. 필드가 상황판 요원 상태를 **직접 고치게** 할지(지금은 모델에게 확정 사실로 알리기만).
4. 동행 인원(1명으로 시작 / 2명).
5. 시간 속도, 그리고 필드가 본편 시각보다 앞서가도 되는지.
6. 지하철 도중 사건을 본편 괴이와 연결할지.
7. 다른 소속의 거점 방문 범위(접수창구까지 / 전부 막힘).
