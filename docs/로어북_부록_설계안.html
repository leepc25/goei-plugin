1. 무엇인가

  • 길어진 로어북 항목 하나를 본 항목 + 부록으로 쪼개고, 부록에는 더 좁은 키를 거는 방식이다.
  • 본질은 로어북 항목이 하나 더 생기는 것뿐이다. 켜지는 방식은 지금과 같은 키워드 방식이다. 새 호출 방식을 만드는 게 아니다.
  • 목적은 토큰 절약이다. 늘 필요한 핵심은 본 항목에 두고, 장면이 깊이 들어갔을 때만 필요한 세부(시설 목록, 안내 방송, 상품 목록, 숨은 경로 등)는 부록으로 뺀다.
  • 쓰는 곳: 🌆세력, 🎁파밍, 🚧괴이, 🙂요원 어디든.

2. 어떻게 넣나

항목 규칙
위치 본 항목과 같은 폴더. 괴이 부록은 🚧괴이, 세력 부록은 🌆세력
이름 본 항목 이름 · 부록. 여러 개면 · 부록 2, · 부록 3
키 그 장면 안에서만 나오는 고유 명칭. 본 항목 키는 넣지 않음 (넣으면 늘 같이 켜져서 쪼갠 의미가 없음)
순서(insertorder) 본 항목 + 1. 같은 자리에서 본 항목 바로 뒤에 붙음
첫 줄 무엇의 부록인지 밝힘. 예: ### Namhae Branch Appendix: facilities and Worker system (부록만 켜져도 뜻이 통하게)

예: 남해지사

  • 본 항목 「남해지사」: 정체, 위치, 인원, 작업자 제도 요약, 관계 / 키 Namhae Branch, 남해지사, 남해 지사, Baekilmong Namhae
  • 부록 「남해지사 · 부록」: 시설 목록, 안내 방송, 숨은 진실, 등록 괴이 목록, 사건 씨앗 / 키 휴무 구역, 남해술집, 특별 재배치, 야간 특별작업, 근로실험, 작업자 정리, 작업자 스티커, 광차, Worker Grade

3. 어떻게 켜지나

  1. 대화에 본 항목 키(남해지사)가 나오면 본 항목이 켜진다.
  2. 모델이 본 항목을 보고 고유 명칭(휴무 구역, Z999 등)을 쓰기 시작한다.
  3. 그 말이 최근 메시지에 나오면 부록 키에 걸려 부록도 켜진다.
  4. 일반 장면에선 고유 명칭이 안 나오니 부록도 꺼져 있다.
  • 플러그인이 고르는 방식(기본)과 Risu가 직접 고르는 방식 둘 다 그대로 동작한다. 부록도 같은 폴더라 @@dont_activate 줄과 예산 관리가 저절로 붙는다.

4. 코드로 바꿀 것

할 일 파일 이유
명부가 · 부록 항목을 괴이·특수·요원으로 따로 세지 않기 src/core/world/directory.ts 지금은 🚧괴이·🎁파밍·🙂요원 폴더 항목을 모두 명부에 새 줄로 넣고, 괴이·특수는 무작위 발생 후보로 켠다. 안 막으면 "빛이 없으라 · 부록"이 독립 괴이로 생성됨
명부 화면에서 본 항목 줄 아래에 부록을 접힌 하위 줄로 표시 src/ui/directory.ts 관리용. 부록 키·분량을 보고, 본 항목이 없는 부록엔 경고
(선택) 현장 대상이면 부록도 같이 켜기 src/core/lore.ts pickLore 지금은 상태줄의 현장 대상(탐사 중인 괴이)이 본 항목에만 점수 100을 준다. 괴이 안에 들어가 있는 동안엔 부록도 필요할 가능성이 높음
이름 비교 때 가운뎃점 변형(· ・ ㆍ) 통일 위 두 곳 사람이 직접 입력할 때 다른 점을 쓸 수 있음
테스트 tests/ 명부 제외, 하위 표시, (선택) 현장 대상
  • 🌆세력 폴더는 명부가 보지 않으므로 세력 부록은 코드 수정 없이도 지금 바로 쓸 수 있다. 코드가 필요한 건 괴이·파밍·요원 부록부터.

5. 장점

  • 핵심 정보는 늘 들어가고, 세부는 필요할 때만 들어가서 토큰이 준다.
  • 정보를 버리지 않고도 기존 항목 분량 기준을 맞출 수 있다.
  • 새 폴더·새 호출 방식이 없어서 코드 변경이 작다. 켜는 쪽(lore.ts)은 거의 손댈 게 없다.
  • 슬롯 자리가 폴더로 저절로 정해진다.
  • 카드 제작자는 로어북에 항목 하나를 더 만들고 이름만 규칙대로 지으면 된다.

6. 단점·문제점

문제 영향 대응
모델이 고유 명칭을 안 쓰면 부록이 안 켜짐 세부 정보가 빠진 채 진행 RP로 돌려 보고 키를 늘림. (선택) 현장 대상이면 같이 켜기
부록만 켜지고 본 항목은 안 켜질 수 있음 드묾. 문맥이 조금 빔 부록 첫 줄에 무엇의 부록인지 밝힘
예산이 빠듯하면 점수 낮은 쪽이 잘림 본 항목이 잘리고 부록만 남을 수도 있음 드묾. 필요하면 정렬 때 본 항목 우선 규칙 추가
내용이 두 곳에 나뉨 고칠 때 둘 다 봐야 함 명부 하위 줄로 같이 보이게 함
옛 플러그인 + 새 카드 옛 플러그인은 괴이·파밍 부록을 독립 괴이로 등록 괴이·파밍 부록이 든 카드를 낼 때 goei.minPlugin을 그 판으로 올림
위키 기본 문서·사진 부록은 위키 문서·사진이 없음 명부에서 제외되므로 상관없음

7. 다른 방법과 비교

방법 내용 판단
그대로 둠 한 항목에 다 넣음 정보는 다 있지만 켜질 때마다 전부 들어감
정보를 덜어 냄 항목을 줄임 정보 손실. 사용자 거절
별도 📎부록 폴더 + 부록 탭 부록을 한 폴더에 모음 플러그인이 모르는 폴더라 슬롯 이어받기 코드가 따로 필요. 하위 방식보다 큼
같은 폴더 + 이름 규칙 + 명부 하위 표시 이 설계안 코드가 가장 작고 모든 폴더에 쓸 수 있음. 추천

8. 정할 것

  1. 이 방식(같은 폴더 + 하위 표시)으로 갈지
  2. 현장 대상이면 부록도 같이 켜는 규칙을 넣을지
  3. 첫 적용 대상: 남해지사(코드 없이 가능)부터 할지, 코드 작업과 같이 할지
