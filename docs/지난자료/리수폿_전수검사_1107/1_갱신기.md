## 3. 지침(규칙) 대조

같은 것(우리 지침이 원문을 재구성): 제어정보/자료 구분, 확정·맥락 구분, 6관점, 신규 인물 먼저, 슬롯별 규칙(identity·state·relationship·speech·knowledge·threads·history), 중복 금지·불변 항목 유지, 호감 계기표(+1/+3/+5/+10/−2/−4/−5/−10/−50), 턴당 ±10 상한, 중대위반 예외, 단계 경계(−71/−31/−1/60/120/180/240/300), 취향 띠 −3~+3 7단계, 음란도 0~300 5단계, 의심 0~100 5단계·전이, 리듬 훅 창·상한·연장, 인식(지각·전달 경로), 정성 모드.

다른 것:
1. **빈 답 금지 규칙이 없다.** 원본 base.writer 4절: 「documents·metric_ops·people_ops·issues가 전부 빈 응답을 절대 내지 말 것. 바뀐 게 없으면 `no_canonical_change` issue를 최소 하나(문서별 또는 전체)」. 그리고 `mentioned_character_review`: 이름이 나온 기존 인물마다 「변경」 아니면 「그 인물의 no_canonical_change 사유」. 우리 지침·출력에는 `issues` 채널 자체가 없다 → 모델이 「할 일 없음」과 「안 했음」을 구분해 말할 길이 없고, 사용자는 빈 JSON만 본다.
2. **호감 수치 출력 방식**: 원본은 `metric_ops.delta.events[{base_delta, evidence_quote}]`(숫자 직접, 허용값 목록), 우리는 `cues[{cue:'도움', m, quote}]`(이름 → 코드가 숫자). 뜻은 같은 표. 우리 방식이 모델 실수(임의 숫자)에 강함. **유지해도 됨.**
3. **호감 시작값**: 원본은 모델이 로어·기존 관계 근거로 표(0/90/150/210/270/−25/−60/−100)에서 고름(`init`). 우리는 코드가 **조직×조직 표**(`base.ts` userAffinityBase)로 정함, 모델은 관여 안 함. 다름. 게임 설정(세력 관계)에는 우리 쪽이 맞음. 단 「같은 조직 = 0」이라 동료·상사 관계의 개인 친분을 시작값에 못 넣음.
4. **유저 입력의 지위**: 원본은 `source:user`를 context_only, 우리는 confirmed(유저 캐릭터가 한 일). 우리 쪽이 벨트스크롤 게임(유저 행동이 서사)에 맞음. 의도된 차이.
5. **수정 항목(manual_edited)·압축 요청(needs_compaction·target_chars)**: 원본은 항목 단위로 플래그를 보내 모델이 그 항목을 압축·갱신. 우리는 `pin`(고정)만 있고, 압축은 인물 단위 `tidy`(상한 넘긴 인물 전체를 합쳐라). 더 거친 단위.
6. **bootstrap_required / speech_bootstrap**: 원본은 「기록은 있는데 항목이 빈 인물」·「말했는데 말투 항목이 없는 인물」을 코드가 찾아 명시적 과제로 줌. 우리는 지침 문장(「말투 항목이 없으면 만들라」)만 있고 명단은 안 줌.
7. **직전 쌍 기본값** 2 vs 1 (1절).
8. **입력 예산** 거부 vs 접기 (1절).

## 5. 「빈 답」 원인 판단

사용자가 받은 답: 모든 배열이 빈 JSON(`entries:[]…next_note:[]`). 코드 쪽 입력은 정상(0절). 남는 원인:
- (가) **모델이 실제로 「바뀐 것 없음」으로 판단**. 원본이라면 `issues:[no_canonical_change …]`로 이유가 왔을 것. 우리는 이유를 받을 칸이 없어 구분 불가.
- (나) **보조 모델이 지침(자세히 ≈ 2만 토큰)을 못 따라가 빈 틀만 냄**. 원본도 Writer 2.7만 토큰이라 같은 급의 모델을 전제. 보조 모델이 작은 모델이면 원본도 같은 증상.
- (다) 첫 답이 형식 오류 → 재시도에 빈 틀로 때움. 갱신 기록에 「다시 물음」 흔적으로 확인 가능.

**확인 방법**: 「진단 → 갱신 기록」의 그 줄에서 ① 인물 목록·입력 크기, ② 재시도 여부, ③ 보조 모델 이름, ④ 프롬프트 원문(원문 보관). 이 넷을 받으면 (가)(나)(다) 중 하나로 확정.

**보고 뒤 고칠 안(승인 전 미착수)**:
1. 출력에 `issues[]`를 더하고, 지침에 원본 4절 「빈 답 금지 + 인물별 no_canonical_change 사유」를 넣는다. 갱신 기록 화면에 issues를 보여 준다. → (가)와 (나)가 갈라진다.
2. 장면 인물마다 「바뀜 또는 사유」를 강제(mentioned_character_review 상당).
3. 직전 쌍 기본값 1 → 2 (원본과 같게). 토큰 약간 증가.
4. 입력 예산 넘김: 접기 대신 거부 + 안내(원본 방식)로 할지 사용자 결정.
5. 시작값(조직 표)과 로어 미전달은 의도된 차이로 두되, 「같은 조직 개인 친분」은 시트 호감 칸이 있으면 그걸 쓰는지 확인(다음 항목에서).
