# 배경 그림 생성 공용 지침 (PixelLab) — 매번 적용

필드 장소 배경을 뽑을 때 **매번 이 문서를 처음부터 끝까지 따른다.** 하나라도 어기면 뽑지 않는다.
근거: 2026-10-28~30 헐값매입·영창·손길 의원(대기실·진료실·수술실)에서 실패하고 고친 기록(`docs/결정_필드_조립식_타일.md`).

## 1. 고정 설정 (바꾸지 않는다)

| 항목 | 값 |
|---|---|
| 기능 | `POST /v2/generate-image-v2` (비동기, `background_job_id`를 10초마다 확인) |
| 크기 | 632×424 1장, 게임에서 2배(1264×848) |
| `no_background` | false |
| 화풍 그림 `style_image` | 에일린 서기 두 장 256×256 (헐값매입 v8 요청과 같은 것), `style_options`: color_palette **false**, outline·detail·shading true |
| 참고 그림 1 (항상) | 헐값매입 최초 그림 `game-src/art/pixellab-test-20261028/shop_heolgap_632x424.png` + 쓰는 법(아래 문구 그대로) |
| 비용 | 1장 25회 (job의 `usage`로 확인. 잔액 차이로 재지 않는다: 사용자도 같이 씀) |

참고 그림 1 쓰는 법(그대로):
> Copy only the camera angle, the low viewing height, the perspective, the pixel density and the level of detail and shading of this image. Do not copy any of its objects, furniture, layout, room shape or colors.

요청 몸통은 `tools/pixellab/req/base_req.json`(화풍 그림·참고 그림 1·설정이 들어 있음)을 복사해 `description`만 바꾼다. 화풍 그림 원본: `tools/pixellab/req/style_eileen_256.png`. 요청 JSON·결과는 저장소에 남긴다.

## 2. 요청문 틀 (2,000자 이하, 넘으면 묘사가 아니라 군더더기를 줄인다)

순서와 카메라 문장은 고정. `<>`만 채운다.

```
Pixel art game background: <장소 한 줄: 무엇을 하는 곳, 낡음/깨끗함, 1990s Seoul underground arcade>, <시간>, <빛 한 줄>.
Camera about 20 degrees above the floor looking down: the floor fills the lower half, the back wall shows only as a low strip with its baseboard along the top edge. No vanishing point. <양옆 벽: 아래 4-3에서 정한 것>.
FLOOR (lower half): <재질>, <닳음·얼룩·먼지 등 사용감>, <빛 웅덩이와 가구 아래 짙은 그림자>.
WALLS: <재질>, <얼룩·벗겨짐·금 등>, <걸레받이>; <천장 조명>.
<물건: 아래 3장 규칙대로. 자리 말(on the back wall / left / right / in front of …)을 붙여 한 문장씩>
LIGHT: <밝은 곳과 짙은 그림자가 어디인지 — 반드시 명암 대비를 적는다>.
STYLE: dense, highly detailed pixel art, crisp pixel clusters, selective dark outline, rich medium-to-detailed shading, <팔레트: 어둡거나 약간 바랜 바탕 + 밝은 포인트>, no dithering, no blur. No people, no chairs, no sofas, no benches, no clocks, no <그리지 않을 문>.
```

- **카메라 문장은 줄이지 않는다.** (10-30 수술실 3차에서 글자 수 맞추느라 잘라서 지적받음)
- **빛과 그림자를 반드시 적는다.** 밝고 하얀 방도 「가장자리·가구 아래 짙은 그림자」를 넣는다. 명암 대비가 없으면 평평하게 나온다(수술실 2차).
- 팔레트는 대비가 생기게: 어둡거나 바랜 바탕 + 밝은 포인트.
- 「꽉 채워라 / 비워라」 같은 지시문은 넣지 않는다(사용자 10-30). 들어갈 물건과 자리만 적는다.
- 크기: 서 있는 사람 = 배경 **150px** 기준. 큰 가구와 문만 픽셀로 적는다(문 170×80, 가슴 높이 100, 허리 75 등). 숫자를 남발하지 않는다.
- 글자(포스터 글씨)는 상관없다(사용자 10-30).

## 3. 물건 규칙

1. **위키를 먼저 읽는다** (`card/wiki-base.json`의 그 장소 문단). 위키에 나온 물건과 그 장소만의 성격(무엇을 하는 곳인지)을 보여 주는 물건을 반드시 넣는다. 어느 병원에나 있는 물건만 넣지 않는다.
2. **그 방에 있을 물건만.** 물건마다 「이게 이 방에 있나?」를 확인한다. (대기실에 엑스레이 판 = 실패)
3. **쓰는 사람 쪽에 둔다.** 손님이 쓰는 것(혈압계·체중계·정수기)은 손님 쪽, 직원 것은 직원 쪽. 접수대 뒤에 손님 물건을 두지 않는다.
4. **수는 20~25개 안팎**, 크기는 사람 기준. 너무 많거나 큰 가구를 넣지 않는다(헐값매입 1차: 물건이 많아 전부 작아짐).
5. **사람이 뒤로 지나가는 가구 위에 위로 솟은 물건(스탠드 등)을 두지 않는다** — 가림 따기가 어려워진다.
6. **시키지 않은 것을 지어내지 않는다**: 천장 누수·양동이, 커튼으로 빈 벽 메우기 같은 억지 채우기 금지. 빈 곳은 그 방의 진짜 물건으로 채운다.
7. **의자·소파·벤치·휠체어는 배경에 그리지 않는다.** 앉는 것은 의자 오브젝트로 따로 놓는다.
8. 시계는 넣지 않는다.

## 4. 배치·문·벽

1. **문은 최소로.** 플레이어가 「어디로 가는지」 알아야 하는 곳만 문을 그린다(예: 대기실의 진료실·수술실 문). 나머지 출입은 화면 아래 출구 표시(문 안 그림).
2. 그리는 문은 **뒷벽(또는 옆벽 뒤쪽)에 닫힌 채 정면**으로. 화면 아래에 문을 두지 않는다(화면을 가림). 출입 방향이 공간 순서와 맞을 필요는 없다.
3. **양옆 벽은 방마다 성격으로 정하고 이유를 말한다.** 일괄 적용 금지. 넓은 공간의 일부로 보여야 하면 한쪽을 그림 끝에서 잘리게 열고, 작은 밀실이면 양쪽을 닫는다.
4. **문 앞과 통로는 비워 둔다.** 가구로 문을 가두지 않는다(대기실 3차: 진료실 문이 접수대 뒤 직원 공간에 갇힘).
5. 문과 가구 사이 간격을 충분히(접수대가 문에 붙지 않게).
6. 옆벽 앞쪽 문은 원근으로 과하게 커진다 → 옆벽 문은 뒷벽 쪽 모서리 가까이, 「뒷벽 문과 같은 높이」로 적는다.
7. 정하지 않은 것(문 여닫기 동작 등)은 **내가 정하지 않고 묻는다.**

## 5. 배치 밑그림 (참고 그림 2)

- **기본은 넣지 않는다.** 배치가 게임 진행에 꼭 필요할 때만(문 앞 길, 접수대 모양처럼 틀어지면 못 들어가는 경우) 넣는다. 단색 밑그림이 결과를 밋밋하게 만들 수 있다.
- 넣을 때: 모든 선을 한 소실점에 맞춘다(벽과 가구가 삐뚤면 안 됨), 바닥·벽에도 재질 선(타일 줄눈 등)을 그린다, 문처럼 보이는 키 큰 직사각형을 만들지 않는다(약장=선반과 병, 칸막이=접힌 틀과 다리), 사람 크기 실루엣(뒤 142·앞 167)을 넣고 「그리지 말 것」을 적는다.
- 스크립트는 `tools/pixellab/sketch_<장면>_v<n>.py`로 남긴다.

## 6. 보여 주기 전 점검표 (전부 내가 먼저 확인)

- [ ] 물건마다 그 방에 맞는지, 쓰는 사람 쪽에 있는지
- [ ] 문 수 최소, 문 앞 비어 있음, 문은 뒷벽 정면 닫힘
- [ ] 의자류·시계·억지 채우기 없음
- [ ] 양옆 벽 열고 닫음과 그 이유
- [ ] 크기가 사람 150px 기준과 맞음

- [ ] (밑그림을 넣으면) 5장 규칙

## 7. 진행 순서 (CLAUDE.md 규칙)

1. 요청문(과 밑그림) + 기능·설정·비용을 **한 번에** 보여 주고 허락받는다. 쪼개서 여러 번 고치지 않는다.
2. 허락받은 1장만 뽑는다. 허락 없이 절대 뽑지 않는다.
3. 규격 크기 에일린을 세워 보여 준다: 맨 앞 배율 `F = 1.5 × 848 / 890`, 깊이에 따라 0.85~1배(`tools/mapedit/eileen_stand.png`).
4. 문·주요 가구 크기를 재서(에일린 대비 배율) 사실대로 보고한다. 요청과 다른 것은 숨기지 않는다.
5. 그림·요청문·요청 JSON·합성 그림을 `game-src/art/pixellab-test-20261028/`에 커밋, 결정 문서에 기록.
6. 쓰기로 하면 게임에 넣는다: 장면 원본(map.json: 바닥·막힘·GrabCut 가림·문·조명·앉는 자리) → `python3 tools/mapedit/import.py` → `npm run build` → `npm run demo:field` → 게임 화면에서 뒤로 지나가기·막힘·문 이동을 확인 → 커밋.
