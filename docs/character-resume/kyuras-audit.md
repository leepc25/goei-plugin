## 다음 제작 설계와 중복 방지

1. 두 과금 ID를 조회하여 서비스 응답·원본 4/8장·작업별 비용을 회수한다. 작업 실패/만료라고 확인되기 전에는 새 제출을 하지 않는다. 회수 원본은 독립 경로에 저장하고 기존 결과를 덮어쓰지 않는다.
2. `krig_v4_snaps_unrun.py`는 **미생성 설계**다. snap1 팔꿈치를 굽힌 세운 손, snap2 머리 위 뒷손, snap3 앞위/뒤아래 벌림은 현재 수평 지르기 실패와 다른 핵심 자세다. 1타부터 핵심 자세 실루엣과 엄지·중지 장전/해제를 확인한다. 손끝만 강조하는 프롬프트 수정으로 같은 수평팔을 재생성하지 않는다.
3. 2타 머리 위 스냅은 1타와 손 교대가 읽혀야 하고, 3타는 양손 X자에서 분리되는 큰 실루엣이 읽혀야 한다. 타격 인덱스 2/3/3과 실제 손 해제 장의 일치를 검수한다.
4. idle_pipe·walk_pipe·shotgun의 미완료는 사실이나, 전체 원격 job 목록을 확인한 뒤에만 신규 견적을 확정한다. 이미 회수된 walk_shotgun과 후속 씻기 4클립은 재발주하지 않는다.
5. 납품자는 manifest 기반 허용 목록과 `legacy_orphan_do_not_package` 차단 목록을 함께 제공한다. 기존 final 파일은 보존하되 새 패키지에서 5개 구형 파일을 배제한다. 회수 후에는 작업 ID·SHA-256·프레임 수를 연결하고, 새 manifest에 실제 새 스트립만 등록한다.
