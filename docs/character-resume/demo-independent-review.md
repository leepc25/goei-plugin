## 발견·수정 요청

1. 키보드 처리에서 BUTTON 포커스의 모든 키를 무시하는 코드를 발견해 구현 담당에게 전달했다. 담당이 이동·Shift·장 넘김은 버튼 포커스에서도 처리하도록 고쳤고, 수정본을 실행해 탭 클릭 후 방향키 이동을 확인했다.
2. 모바일 가로 최초 화면에서 동작/속도 조작이 두 줄로 펼쳐지고 무대·상태줄 아래 터치 버튼이 화면 밖으로 내려간다. 첫 화면 스크린샷에서 무대 하단도 잘린다. 스크롤 후 버튼은 작동하지만 무대와 조작부를 한 화면에서 확인할 수 있도록 수정 요청했다.
3. 캐릭터와 바닥 눈금이 서로 반대 방향으로 함께 움직여 상대 이동량이 커지는 코드도 전달했다. 실제 그림 접지와 시연 코드 이동을 섞어 판단하지 않도록 눈금 기준을 명확히 할 필요가 있다.

## 표시의 정직성

- 상단에 ‘기존 원본 검수판 · 새 그림 생성 0회 · 시각 승인 대기’가 표시된다.
- 큐라스 설명은 `idle_shotgun`·`run_shotgun` 회수 미확인과 전시 제외를 명시한다. 전시 목록에 이 두 클립이 없다.
- 쟈알디 A는 ‘승인 이력’, A2는 ‘후속 재킷 수정’으로 구분한다. A2에 별도 승인 이력이 있는 것처럼 표시하지 않는다.
- 에일린은 총이 원본에 그려져 있다는 사실과 무기 합성·전투 판정 미연결을 명시한다.
- 개인 체크 항목이 사용자 승인으로 저장되지 않는다는 설명이 있다.

새 그림을 만들었다거나 고친 것으로 오인하게 하는 표시는 발견하지 않았다. 그림 자체의 결함 판정은 `jyaldi-audit.md`, `kyuras-audit.md`, `other-agents-audit.md`와 함께 읽어야 한다.

## 최종 재검수

**독립 검수판의 실행·배치 검사 통과. 캐릭터 그림 품질 승인은 보류.**

모바일 가로 배치 수정 후 세 뷰포트 전부 다시 실행했다. 모바일 가로는 무대 y=147.94–297.94, 이동 조작 y=343.19–380.44로 화면 높이 390 안에 모두 표시된다. PC와 모바일 세로도 무대·조작부가 처음 화면 안에 들어온다. 화면의 작은 문자/픽셀은 모바일에서 1배 표시되므로 정밀 얼굴 검수는 장별 원본 확대와 병행한다.

- 모든 뷰포트: 89/89 이미지 정상, JavaScript 오류 0, 깨진 표시 이미지 0, 페이지 가로 넘침 없음.
- 정지 유지·이전/다음 장·방향키·Shift 달리기·캐릭터 탭 클릭 뒤 방향키·포인터 누름/해제·마지막 7장→0장 모두 재통과.
- 모바일 두 뷰포트에서 CDP `Input.dispatchTouchEvent`의 실제 `touchStart`/`touchEnd`를 보내 왼쪽 이동과 손을 뗀 뒤 정지를 확인했다. 마우스 포인터 시험만으로 터치 통과 처리하지 않았다.
- 쟈알디뿐 아니라 에일린 선택 후 이동, 큐라스 선택 후 기본 공격 표시도 실행했다. `independent-<viewport>-kyuras.png`가 추가 증거다.
- 바닥 눈금은 고정되고 캐릭터의 시연 위치만 움직이도록 수정됐다. 그림의 발 미끄러짐을 엔진 결함 수정 완료로 오인할 여지가 줄었다.
- HTML의 전시 89프레임 각각이 명시된 원본 PNG 바이트 및 SHA-256와 정확히 일치한다. 원본에서 생긴 그림 결함은 이 HTML에도 그대로 남아 있다.

검수 대상 HTML은 592,024바이트인 최종 재빌드본이다. 이후 HTML 변경 시 그 변경 범위를 다시 검수해야 한다.
