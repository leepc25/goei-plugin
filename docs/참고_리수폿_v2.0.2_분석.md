# 참고 · 리수폿 v2.0.2 분석 (2026-10-25)

사용자가 준 다른 사람의 RisuAI 플러그인 `risupot_v2_0_2.js`(2.1MB, 10,631줄). 관계도 설계 참고용. 원본은 저장소에 넣지 않았다.

## 전체 구조
매 턴 본편 응답 앞뒤로 **보조 모델을 따로 3번 부른다.**
1. **Router** (응답 전): 위키 목록(제목·별명만)과 최근 대화를 보고, 이번 응답에 필요한 인물·장소 문서를 고르고 처음 나온 이름을 알린다.
2. **Director** (응답 전): 고른 문서·수치를 읽고 「연출 메모」를 써서 본편 요청에 끼운다.
3. **Main**: 본편 모델이 평소처럼 응답한다.
4. **Writer** (응답 후): 본편 응답을 읽고 인물 위키를 고친다(새 인물, 사실, 말투, 감정, 수치 변경 제안). JSON으로 내고 **계산은 JS가 한다.**
- 저장: 플러그인 저장소(RisuAI 세이브에 포함). 기록 상한 200만 자.
- 보조 모델: OpenAI·OpenRouter·DeepSeek·Vertex·Copilot·RisuAI 보조 모델 중 선택.

## 기능 목록
- 인물 위키(People): 인물별 문서, 개요, 첫인상·현재 평가, 고정(핀), 폴더, 합치기, 로어북에서 가져오기, 문서 정리(요약).
- **호감·취향**(아래), **관계·호칭**(말투 기록·말투 변화), 지각(누가 무엇을 실제로 알았나), 서사 리듬(긴장·떡밥 회수).
- NPC끼리 감정(방향 있는 한 칸, 새로 쓰면 덮어씀), 관계 이력(이전 값 보관).
- 성인용: 불륜 의심도, 음란도·피임 태도.
- 관찰자 모드, 추가 프롬프트, 봇별 기능 세트, 실행 기록·토큰 사용량, 백업, 밝은/어두운 화면.

## 호감도 작동 방식
- 칸: `affinity.score`. **말하는 NPC → 대상(유저 또는 다른 인물) 한 방향.** 유저의 감정은 기록하지 않는다.
- 범위 **-100 ~ 300**. 단계 8개: 극도의 적대(~-71) / 적대(~-31) / 혐오(~-1) / 무관심(~60) / 인식(~120) / 관심(~180) / 끌림(~240) / 애정(~300).
- **초기값**: 처음 등장할 때 설정·로어북 근거로 표에서 하나만 고른다. 근거 없으면 0. 친한 지인 90, 믿는 동료 150, 뚜렷한 애착 210, 깊은 애정 270, 냉담 -25, 적대 -60, 원수 -100. 「배우자·상사」 같은 이름표만으로 높이지 않는다.
- **변화**: Writer가 이번 턴에 새로 생긴 사건만 골라 정해진 값 중 하나를 제안한다. +1(작은 친절) +3(약속 지킴) +5(대가 치른 도움) +10(희생) / -2 -4 -5 -10, 예외 -50(심각한 배신). 사건마다 **본문에서 그대로 인용한 근거**가 필요하다. 인사·외모·일상 업무는 점수 없음. 한 턴 합계 -10~+10.
- JS가 배율(설정의 증가·감소 배율), 턴 상한, 범위, 중복 방지(같은 사건 두 번 금지, 다시 생성해도 중복 안 됨), 단계를 계산한다. 사용자가 직접 고칠 수 있다(이유 필수).
- 별도 축 **취향(첫인상)** `taste_band` -3~+3: 외모·태도가 그 인물 취향에 맞는지. 호감 점수와 섞지 않는다. 올라갈 땐 한 칸씩, 내려갈 땐 여러 칸.
- 단계는 Director가 「이 단계면 이렇게 대한다」로 연출 메모에 넣는다. 높은 호감이 연애·반말·복종을 허락하지 않는다.
- 지침 핵심: 취향·쌓인 호감·실제 관계(상하·직무)를 서로 다른 축으로 본다.

## 관계·호칭
- 대상별 **호칭·말투(존댓말/반말)를 「천천히 바뀌는 설정」으로 기록**한다. 한 장면의 기분으로 바꾸지 않는다. 명시적 허락·관계 변화가 있거나 두 장면 이상 일관되게 바뀌어야 고친다. 방향마다 따로.
- 판단 축: 관계 종류, 지위 차, 나이·연차, 친밀도.
- 말투 다양성(선택): 대상별 말버릇 기록, 말투 변화 징후를 JS가 세어 같은 방향 3번(1~9 설정)이면 바꿈(묻기/자동).

## 우리 필드 대사에 주는 시사점
- 좋은 점: **판단은 모델, 계산·저장·중복 방지는 코드**. 근거 인용 필수. 상하 관계·호감·취향·호칭을 서로 다른 축으로 둔다. 초기값을 설정에서 한 번만 정하는 표.
- 무거운 점: 매 턴 보조 모델 3번 호출(비용·지연). 우리 결정(본편 모델이 숨김 칸을 씀, 따로 부르지 않음)과 방식이 다르다.
- 가져올 만한 것: 호감 단계 표와 변화량 표, 「이름표만으로 높이지 않기」, 방향 있는 관계, 호칭을 느리게 바뀌는 기록으로 두기.
