# 새 계정 설정 매뉴얼 (괴이봇 작업 옮기기)

옛 계정의 「괴이봇 플러그인 개발」 프로젝트를 새 Claude 계정으로 옮기는 순서예요. 위에서부터 차례로 하면 돼요. 전체 30분 안쪽이에요.

**옮겨지는 것과 안 옮겨지는 것**
- 그대로 이어지는 것: GitHub 저장소 `leepc25/goei-plugin`의 코드·문서·릴리스 전부. 인계서와 메모리 사본도 저장소에 넣어 두었어요(`docs/인계서.md`, `docs/인계/`).
- 안 옮겨지는 것: 옛 프로젝트의 메모리, 공유 폴더(Library) 파일, 스레드 대화, 아티팩트 링크, PixelLab 연결, 프로젝트 설정. 아래 단계에서 다시 만들어요.

---

## 0단계. 옛 계정에서 먼저 할 일 (옮기기 전에)

1. **큰 파일 내려받기 (필요한 것만).** 옛 프로젝트 공유 폴더의 큰 파일은 저장소에 넣지 않았어요. 나중에 쓸 것 같은 것만 옛 프로젝트 화면의 Library(파일 목록)에서 내려받아 두세요.
   - `Asset.zip` (81MB), `공용그림_71종_PNG.zip` (110MB), `디폴트.zip` (56MB), `봇카드.jpeg` (8MB)
   - 전체 목록과 크기는 저장소 `docs/인계/공유폴더_목록.md`에 있어요. 거기서 ✅ 표시된 것은 이미 저장소에 있으니 안 받아도 돼요.
2. **PixelLab API 키 확인.** pixellab.ai에 로그인해서 계정 설정(API) 화면에서 키를 복사해 둘 준비를 해요. 키는 채팅창에 붙여 넣지 마세요. 5단계에서 설정 화면에만 넣어요.
3. 옛 프로젝트는 새 쪽이 잘 되는 걸 확인할 때까지 **지우지 마세요.**

---

## 1단계. 새 계정에 GitHub 연결

1. 새 Claude 계정으로 로그인한 상태에서 **https://claude.ai/connect-github** 를 열어요.
2. GitHub 로그인 창이 뜨면 **leepc25** 계정으로 로그인하고 허용해요.
3. 「Claude GitHub App」 설치 화면이 나오면 `leepc25/goei-plugin` 저장소를 포함해서 설치해요. 이미 설치돼 있으면 이 화면은 건너뛰어져요.
   - 직접 확인하려면 **https://github.com/apps/claude/installations/select_target** 에서 leepc25 계정을 고르고, 저장소 목록에 `goei-plugin`이 들어 있는지 봐요(「All repositories」이거나 목록에 체크).

✔ 확인: connect-github 화면에 GitHub 계정이 「연결됨」으로 보이면 돼요.

---

## 2단계. 프로젝트 만들기

1. **https://claude.ai/code** 를 열어요.
2. 새 프로젝트를 만들어요. 이름은 옛 것과 같게 **「괴이봇 플러그인 개발」** 로 하면 헷갈리지 않아요.
3. 공개 범위는 지금처럼 **비공개(개인)** 로 해요.

---

## 3단계. 저장소 넣기

1. 새 프로젝트에서 **프로젝트 설정 → 리소스(Resources)** 로 가요.
2. 저장소 추가에서 **`leepc25/goei-plugin`** 을 골라요.
   - 목록에 안 보이면 1단계의 GitHub App 설치에 이 저장소가 빠진 거예요. 1단계 3번을 다시 해요.

✔ 확인: 리소스 목록에 `leepc25/goei-plugin`이 보이면 돼요.

---

## 4단계. 프로젝트 지침 붙여 넣기

프로젝트 설정에서 프로젝트 지침(Instructions) 칸을 찾아 아래를 그대로 붙여 넣어요. 새 스레드가 생길 때마다 이 규칙을 따르게 돼요.

```
이 프로젝트는 괴이봇(Anomaly Sim 2.4, RisuAI 괴담 롤플레이 봇)의 플러그인·게임 개발이다. 저장소 leepc25/goei-plugin.
- 모든 답은 한국어로, 짧게. 사용자는 한국어만 읽는다.
- 처음이거나 맥락이 없으면 docs/인계서.md 와 docs/인계/memory/MEMORY.md 를 먼저 읽는다.
- 시키지 않은 작업을 시작하지 않는다. 질문에는 답과 추천만 하고 멈춘다. 「해/만들어/계속 가/릴리스해」라고 해야 시작한다. 「기다려」면 아무것도 하지 않는다.
- 그림은 GPT 몫이다. Claude는 코드·모델 연결·프롬프트·플러그인을 맡는다. GPT에게 도트화·축소·변환 절차를 시키지 않는다. GPT 지침은 docs/필드_그림_통합_지침.md 하나뿐이다.
- PixelLab 생성은 사용자가 시킨 것만, 비용을 먼저 말하고 작게 한 장씩 확인한다.
- 설계 전에 원본 설정(card/wiki-base.json, 로어북)을 먼저 읽는다.
- 문서는 앱에서 열 수 있게 파일 첨부나 아티팩트로 준다.
- 릴리스는 사용자가 「릴리스해」라고 할 때만 하고, GitHub Actions가 끝나면 바로 알린다.
- 미성년자(콘쥬스)의 목욕·탈의 장면은 절대 만들지 않는다.
```

## 5단계. PixelLab 연결 (클라우드 환경 설정)

옛 프로젝트는 클라우드 환경에 PixelLab 키를 넣어서 Claude가 `api.pixellab.ai`를 바로 부를 수 있었어요. 새 프로젝트도 똑같이 해 줘야 해요.

1. **프로젝트 설정 → 환경(Environment)** 으로 가요.
2. **클라우드 환경(Cloud environment)** 메뉴를 열고, 선택된 환경 옆의 **톱니바퀴**를 눌러요.
3. **네트워크 접근(Network access)**
   - 「제한(Limited)」 단계라면 **허용 도메인(Allowed domains)** 에 `api.pixellab.ai` 를 추가해요. 「패키지 관리자 허용」 칸은 체크된 채로 둬요(npm 설치에 필요).
   - 더 넓은 단계(전체 허용)를 골라도 돼요.
4. **네트워크 비밀값(Network secrets)** — 옛 앱에서는 「API 자격 증명(API credentials)」이라고 나와요.
   - 호스트: `api.pixellab.ai`
   - 값: 0단계에서 준비한 PixelLab API 키 (형식을 고르라고 하면 Bearer 토큰)
   - 이 칸이 없는 화면이면 환경 변수로 `PIXELLAB_API_KEY` 이름에 키를 넣어요.
5. 저장해요. **새로 시작하는 스레드부터** 적용돼요.

✔ 확인은 7단계에서 해요.

참고 문서: https://code.claude.com/docs/en/cloud-environments#network-access

## 6단계. 첫 메시지 보내기

새 프로젝트 대화창에 이렇게 보내요.

```
docs/인계서.md 먼저 읽고 이어가. 다 읽으면 바로 일 시작하지 말고, 이해한 규칙과 열린 일을 짧게 말한 다음 뭐부터 할지 물어봐. 그리고 인계서 1장 규칙은 이 프로젝트 메모리에 저장해 둬.
```

## 7단계. 잘 됐는지 확인

| 확인할 것 | 이렇게 물어보기 | 이러면 정상 |
| --- | --- | --- |
| 인계서를 읽었나 | (6단계 답을 봐요) | 한국어로, v0.16.56, 「쟈알디 동작 2판」과 「필드 배경 방식」 두 가지 열린 일을 말하고 먼저 일을 시작하지 않아요 |
| 저장소가 붙었나 | 「저장소 main 최신 커밋 뭐야?」 | 인계 자료를 올린 커밋(「인계서」가 들어간 커밋)을 말해요 |
| PixelLab이 되나 | 「PixelLab 잔액만 확인해줘. 생성은 하지 마」 | 약 10,700회 안팎의 숫자를 말해요 |
| 테스트룸이 열리나 | 「docs/인계/쟈알디/쟈알디_테스트룸_v2.html 을 아티팩트로 올려줘」 | 새 링크가 오고, 열면 쟈알디가 로비에서 움직여요 |
| 규칙을 지키나 | 아무 질문 하나 | 답만 하고 멋대로 작업을 시작하지 않아요 |

## 문제가 생기면

| 증상 | 해결 |
| --- | --- |
| 「저장소에 접근할 수 없어요」 | 1단계(GitHub 연결, App 설치)와 3단계(리소스에 저장소 추가)를 다시 확인 |
| push가 거절돼요 | GitHub App에 이 저장소의 쓰기 권한이 있는지 확인(1단계 3번 화면) |
| 「api.pixellab.ai 가 막혔어요」 | 5단계 3번 허용 도메인 확인 |
| PixelLab이 401/403 | 5단계 4번 키가 맞는지, 호스트 이름이 정확히 `api.pixellab.ai`인지 확인. 키는 채팅에 붙여 넣지 말기 |
| 설정을 바꿨는데 그대로예요 | 새 스레드를 열어야 적용돼요 |
| 옛 아티팩트 링크가 안 열려요 | 옛 계정 소유라서 그래요. 저장소 사본(`docs/인계/`)으로 새로 올려 달라고 하면 돼요 |
| 큰 zip이 필요해요 | 0단계에서 받아 둔 파일을 새 프로젝트에 올려 주세요 |

## 옛 계정 정리 (마지막에)

새 프로젝트에서 7단계가 모두 정상이면, 옛 프로젝트는 남겨 둬도 되고 지워도 돼요. 지우면 옛 공유 폴더 파일과 아티팩트도 사라지니까, 0단계에서 필요한 파일을 다 받았는지 한 번 더 확인하고 지우세요.
