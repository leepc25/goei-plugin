**10:42 다시 실패**: 훈련장→사격장 잇기에서 ov=60 칸을 줬지만 칸 안 옛 그림(사물함·꺾인 모서리)을 지우지 않고 보냄 → inpaint-v3는 칸 안 옛 그림을 거의 똑같이 다시 그리므로 사실상 겹침 0, 옛 끝선(x632)에 세로 이음선. 사용자 「겹치게 이었어 안 이었어」.
**How to apply:** `tools/pixellab/extend_right.py`는 `ERASE=1` 환경변수로 겹침 칸을 줄별 중간값 색으로 지운다(브랜치 claude/project-thread-v8cg9c). 잇기마다 ERASE=1, ov≥60(옛 끝에 모서리·큰 물건이 있으면 그것까지 덮게 120 등). extend_left.py에도 같은 기능 필요(아직 없음). 물건 지우기도 칸을 단색으로 지우고 보내고, 없앨 물건 이름은 요청문에 쓰지 않는다. See [[goei-hq-f1-bg-lessons]], [[goei-pixellab-one-per-scene]].

**11:38 화장실 왼쪽 잇기 실패(사용자 「못써」「원근 안 맞고」「겹친 부분 망함」)**: keep 100·ov 70 → 보이는 옛 그림 30px뿐이라 벽 밑선 못 봐 원근 어긋남; 40px 반투명 섞기로 새 기둥·건조기가 유령처럼 겹침. 고침: extend_left.py는 섞지 않고 겹침 칸 안 DP 최소차 세로선으로 자름(브랜치 v8cg9c). 보이는 옛 그림은 90px 이상(벽 밑선·물건 하나 보이게). 「칸(cubicle)」이라 쓰면 문·변기까지 그림 → 칸은 오브젝트, 벽에 박히지 말고 튀어나와야 함(사용자). 칸 오브젝트는 사용자 「기다려봐」.

**11:47 잇기2도 실패**: 잇기 요청문에 3층 채우기 문장(「walls, floor... full of objects; a busy restroom」)을 넣고 p1의 「nothing stands on it」을 뺌 → 바닥에 칸막이·대걸레통. 잇기 요청문은 **그 방 원본(p1) 문장 그대로**, 첫 줄만 바꾼다.
