- **요원(캐릭터) 테스트룸**과 **NPC 테스트룸** 두 개.
- **키 바인딩·세팅 = 지금 라이브(릴리스) 버전 에일린 기준.** 라이브 빌드는 `release/game/`(goei-game.*.txt), 데모 `release/demo/eileen-full.html` 등. 라이브 에일린의 키·조작감·카메라·속도 값을 먼저 읽어 그대로 맞춘다. 지금 testroom3의 키(`[` `]` 인물 바꾸기, S 고유기술, D 충전, F 필살기, Y 기술2)와 다르면 라이브 쪽을 따른다(인물 바꾸기 키만 테스트룸 전용으로 둔다).
- **스킬·이펙트 연결**: 3판 기술 설계(`docs/기술_재설계/`)와 이펙트 3판(`game-src/action/testroom3/vfx/x3-*`, 목록 `motion3/fx3_manifest.json`)을 인물별 `chars/<키>.json`의 skills에 연결. NPC는 `docs/NPC_기술_설계.md`.
- **새 동작 반영**: 동작 3판 전부(`game-src/action/motion3/<키>/<줄>/`), 앉기 3판 다시(60·61·96 + 앉은 줄), 굴러떨어지기(169), 크게 밀려나기(18_2), 생활·직무 줄. 샤워 세트(`motion3/_test/<키>/샤워2_*`)는 테스트룸에 넣을지 사용자 판단 전이라 **넣지 말 것**(노출).
- 멈추지 말고 끝까지. 시키지 않은 PixelLab 생성 금지(크레딧). 다 되면 Artifact로 두 테스트룸 링크 + 「검수 전」 표시 + 알려진 결함 목록.
