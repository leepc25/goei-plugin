## 현재 상태 (실제 Risu에서 확인)

**동작하는 것:**
- 상황판 버튼 → 「받기」 → 본부 시작 방(2층 종합대응팀 사무실) → 걸어서 요원에게 가서 E → 대화 → 기록 저장. 실제 Risu(공식 소스 로컬 실행)에서 종단 확인했다.
- 요원 배치: 상태 태그 `[AG|이름|상태|상황]`로 방을 정한다(`src/core/visit.ts` `visitRoom`).

| 상태 | 방 |
|---|---|
| 내근·대기 | `office` → 사무실 장면 |
| 휴게·휴식 | `lounge` → 휴게실 |
| 부상·치료 | `infirmary` → 의무실(`clinic`) |
| 수면·취침 | `quarters` → **장면 없음, 지금은 안 보임** |
| 외근·비번·격리·작전투입·실종·사망·미정 | 본부에 없음 |

- 요원 그림: `game-pack/visit-agents` (`tools/build_visit_agents.py`가 기존 idle 클립만 모아 만든 아틀라스). 들어 있는 요원은 쟈알디, 에일린, 스팡달, 데드폴, 게슈간, 로제몬, 큐라스, 고르고디오, 잼트리, 데쥬레다. **콘쥬스·고그니쟈는 그림이 없어 배치되지 않는다.**

**제대로 안 된 것 (GPT 범위):**
1. **플레이어 그림이 쟈알디로 고정**돼 있다(`src/game/action/main.ts`가 `jyaldi` 팩을 엔진 그림으로 씀). 상황판 주인공이 다른 요원이거나 페르소나여도 쟈알디로 걷는다. 페르소나 원본(`game-src/persona-reference-20261022/`, 남녀 128×256, **1배 표시**)은 아직 게임에 안 붙었다. 걷기 프레임이 없으므로 이동 표현 방식도 정해야 한다(새 그림 없이).
2. **방 그림**: 벽·바닥은 `src/game/action/art/bg.ts`의 `HQ_PLACE` 매핑(본부배경 요청 59장 도트화본)으로 그린다. 전용 그림과 가구가 갖춰진 곳은 시작 방(2층 사무실, `start-room`·`hq-textures`·`hq-door-round2` 팩)뿐이다. 나머지 방이 요원을 세워 대화할 공간으로 충분한지, 가구·소품·자리가 맞는지는 실제 화면에서 방마다 점검해야 한다(`hub.ts` 그리기, `hq/map.ts` 장면 정의).
3. **요원 배치 위치**: 지금은 `src/game/action/engine/modules.ts` `hqAdapter.visitors`에 하드코딩한 빈 바닥 좌표(사무실 6자리, 다른 방은 비율)다. 요원별 자리(책상·소파·침대)와 자세(앉기·눕기)가 없다. 부상 요원도 서 있다.
4. **수면(`quarters`) 방이 없다.** 승인된 평면도에 숙소가 없으므로, 장면을 새로 만들지 아니면 다른 방에 매핑할지 사용자에게 묻는다.
5. 요원이 걷거나 자리를 옮기는 생활 동작이 없다(idle만).
6. 요원끼리 겹침, 플레이어 시작 위치와의 겹침을 좌표 몇 개로 피하고 있을 뿐이다.

## 건드리지 말 연결부 (Claude가 쓰는 것)

Claude는 이 위에 말풍선 대화와 「옆 사람 끼어들기」를 올린다. 아래 모양은 유지하고, 바꿔야 하면 먼저 문서로 알려 준다.

- `HubHost.visitors?(sceneId)` → `{ name, x, y, face }[]` (`src/game/action/engine/hub.ts`). 이름은 명부 이름 그대로.
- 대화 지점: 장면 spot `id: 'visit:<이름>'`, `who: <이름>`, `verb: '대화'`. E로 열리는 경로(`npcLink` → `hubTalk` → `visit(name)`).
- `VisitState.agents[].room` 값(`office`/`lounge`/`infirmary`/`quarters`)과 `VisitState.visitor`(상황판 주인공, 방문 대상 목록에서 빠짐).
- **요청: 말풍선 위치용 머리 높이.** 요원 그림마다 발끝 기준 머리 꼭대기 높이(px, 표시 배율 적용 전)를 `game-pack/visit-agents/frames.json`의 요원 항목에 `head`로 넣어 주면 Claude가 말풍선을 그 위에 띄운다. 이후 그림을 바꿔도 이 값을 같이 갱신한다.
- 요원 위치를 실시간으로 옮기게 되면(걷기·끼어들기) 화면 좌표를 얻을 함수가 필요하다. 만들게 되면 `hub` 쪽에 `agentAt(name) → { x, y, face } | null` 형태로 노출해 주면 좋다.

**파일 구분:**
- GPT: `src/game/action/hq/**`, `src/game/action/art/**`, `hub.ts`의 그리기 부분, `game-pack/**`, `game-src/**`, `tools/build_visit_agents.py` 등 그림 빌드 도구.
- Claude: `src/host/game/**`, `src/core/visit.ts`, `src/core/player.ts`, `src/game/visit.ts`(대화 UI), 새 말풍선 코드, `src/ui/**` 설정.
- 같이 쓰는 곳: `src/game/action/engine/modules.ts`의 `hqAdapter`(배치·visitReady). 고칠 때 커밋 메시지에 무엇을 바꿨는지 분명히 적는다.

## Risu에서 반드시 지킬 것 (실제로 검은 화면이 났던 원인)

게임은 Risu 플러그인 iframe 안에서 돈다.
- CSP `connect-src 'none'`: `fetch(blob:…)` 불가. 그림 외 데이터(JSON)는 `bridge.assets.bytes(pack, file)`로 읽는다(`src/game/action/engine/art.ts` `loadArt` 참고).
- `allow-same-origin` 없음: `localStorage`에 손만 대도 throw. `src/game/entry.ts`가 메모리 대체를 깔아 두었으니 직접 쓰지 말고 기존 저장 모듈을 쓴다.
- `allow-forms` 없음: form submit이 안 난다. 버튼은 `type="button"` + click, 입력은 Enter(`isComposing` 제외).
- 새 그림 팩은 `game-pack/<id>/pack.json`에 `required: true`로 넣고 `bridge.assets.url/bytes`로만 읽는다. 저장소에서 내려받는 데 기대는 기능은 금지.
- 정적 합성 이미지·가짜 API 시험을 실제 Risu 검증이라고 쓰지 않는다.

## 시험 방법

- 단위: `npm test`, 화면: `node tests/browser.mjs`.
- 실제 Risu: `kwaroran/Risuai`(확인 커밋 `02a8369`) 클론 → `pnpm install --ignore-scripts` → `VITE_RISU_LEGAL_CONFIGURED=TRUE npx vite`. Playwright로 연 뒤 `page.evaluate(() => import('/src/ts/...'))`로 카드·플러그인을 넣는다. 95MB 카드는 탭이 죽으므로 v0.16.40 카드(약 12MB)로 시험한다. 모델은 가짜 OpenAI 호환 서버를 `https://fake-model.example/…`로 설정하고 `page.route`로 가로채면 된다(`usePlainFetch: true`, `maxContext` 크게).
- 게임 빌드마다 화면별 스크린샷을 남기고 독립 검수(냉정한 이미지별 검토)를 받는다.
