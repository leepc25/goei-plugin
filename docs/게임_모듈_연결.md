# 게임 모듈 연결

작성 2026-10-21 · 주인: 「게임 전투와 조작」 스레드 (엔진·입력·주 루프·최종 통합).
타입 원본: `src/game/action/engine/contract.ts`. 이 문서와 그 파일이 다르면 파일이 맞다.

## 0. 원칙

- 각 스레드는 **자기 폴더만** 고친다. 다른 폴더의 파일은 읽기만 한다.
- 각 모듈은 **자기 API를 그대로 유지**한다(아래 표). 엔진 통합 파일 `src/game/action/engine/modules.ts`가 그 API를 엔진 타입으로 이어 붙인다. 모듈끼리 서로 import하지 않는다. 필요한 값은 엔진 이벤트·`WorldView`로 받는다.
- 엔진 쪽 타입을 바꿀 일이 생기면 고치지 말고 「게임 전투와 조작」에 메시지로 알린다. 새 필드는 선택(`?`)으로만 더한다.
- 그림은 새로 만들지 않는다. 플레이어는 기존 쟈알디 클립(`game-src/action/jyaldi-v5/full/clips/`), 나머지는 회색 상자.

## 1. 좌표와 시간 (모두 공통)

| 항목 | 값 |
| --- | --- |
| 화면 | 1280×720 논리 px (회색 상자 sim.ts와 같음). 도트 1px = 논리 2px |
| x | 가로, 왼쪽 0 |
| y | 바닥 깊이 = 발이 닿는 화면 y. 보통 500~680, 클수록 앞 |
| z | 높이, 바닥 0, 위가 + |
| 그리는 위치 | 화면 y = y − z, 정렬은 y 순서 |
| 틱 | 30Hz 고정. 경직·히트스톱·무적 등 시간 수치는 틱 단위 |
| 난수 | 출동 시드에서 나온 `world.rand()`만 쓴다 (`Math.random` 금지, 재현 시험 때문) |

## 2. 판정 (적·아이템·엔진 공통)

- 판정 상자는 **월드 AABB** `WBox {x0,x1,z0,z1,y,dy?}`. 깊이는 두 상자의 y 차이가 `dy`(기본 18) 합 안이어야 겹친다.
- 공격은 `Hit` (`WBox` + `attackId, dmg, react, dir, push, lift, stop, low, grab, armorBreak, strength`). 반응 등급 `react`는 부록 E.1: `none | flinch | stagger | launch | down | bind`.
- 매 틱 엔진이 모든 몸의 `frame()`을 읽고 공격 상자 × 피격 상자를 겹쳐 본 뒤 맞은 쪽 `applyHit(hit, world)`를 부른다. **피해·반응·넉백은 맞은 쪽이 스스로 적용**하고 `{kind:'hit'|'guard'|'armor'|'immune', killed?}`를 돌려준다. 히트스톱은 엔진이 양쪽에 건다.
- 같은 `attackId`로는 같은 상대를 한 번만 때린다.
- 판정 보기: 게임 중 **H** 키(터치는 메뉴). 빨강 = 공격, 초록 = 피격, 노랑 = 잡기.

## 3. 모듈별 연결

| 스레드 · 폴더 | 모듈이 내보내는 것 (그쪽 API 그대로) | 엔진이 하는 것 |
| --- | --- | --- |
| 적과 수호자 · `enemy/` | `createEnemy(kind, x, y, rng)`, `stepEnemies(world, ticks)`, `enemy.frame()` → `{hit: Hit[], hurt: WBox[]}` (월드 좌표), `applyHit(enemy, hit)`, `spawnWave(budget, floorType, depth, rng)`, 드랍 훅 | `WorldView` 제공 (`player`·`bodies`·`noise`·`light`·`floor.type`·`emit`). 적의 공격 상자 × 플레이어 피격 상자 판정. 적이 없으면 엔진의 **허수아비**(`dummy`)를 쓴다 |
| 차원 승강기 층 생성 · `stage/` | `StageModule` (`firstFloor(run)`, `nextFloor(run, prev, how)`, `tick?`, `onInteract?`, `onEvent?`) → `FloorPlan` | 층 길이·깊이 범위·싸움 구간(`Encounter`: 넘으면 화면 잠금 → 파도 → 「GO →」)·소품·출구 처리. `StageApi`로 `spawn/setProp/hurtPlayer/heal/note/finish` 제공 |
| 본부와 임무 흐름 · `hq/` | `hq/contract.ts`의 `MissionLaunch`(출동 정보), `RunResult`(정산), 출동 중 Esc 가방 `openRunMenu(box, inv, onUse)`, `useItem(inv, slot)` | `MissionLaunch`에서 `seed, agent, items, 능력치(hpMax 등), danger, 해금 동작`을 읽어 출동. 끝나면 `RunResult`를 채워 본부로 돌려준다 (`how: 'return'|'withdraw'|'evac'`, 전투 기록 + 층·아이템 모듈이 `note`로 남긴 것) |
| 아이템과 무기 · `items/` | `createItemRun(agentId, seed)`, `stepField(run, field, actor, input, dt)` → `ItemEvent[]`, `hitProp`, `dropFromKill`, `weaponAttack(run, 'melee'|'shot')` | 플레이어 위치·입력을 넘기고, 투척물을 적 판정에 넣고, 임시 무기 배율을 공격에 곱한다. 1~4키 → 아이템 사용 → 몸짓 클립(`drink/eat/bandage/toss`) |
| 대사와 컷신 · `story/` | `mountStory(root, host)` → `{say, bark, cutscene, update, isBlocking, flags, dispose}` | `StoryHost`(pause, camera, actor, fade, sfx, getAgent) 채움. `isBlocking()` 동안 전투 멈춤. 엔진 이벤트 `combat:start`, `combat:boss`, `hp:low`, `enter:floor` 등을 넘김. `flags`를 저장에 같이 넣음 |
| 화면 표시와 터치 조작 · `ui/` | `InputHub`(KeyboardEvent.code로 누름/뗌), `mountStage(box)` (1280×720 캔버스), `drawHud(ctx, HudState)`, `ui/fx.ts` | 엔진은 **키보드 code**로 입력을 받는다(아래 4장). 터치·패드는 같은 code를 쏜다. 매 프레임 `HudState`를 채워 `drawHud` 호출 |
| 효과음과 음악 · `audio/` | `createGameAudio({load, save})`, `audio.event({type, …})`, `audio.floor(type)`, `audio.duck(sec)` | 엔진 `GameEvent`를 그대로 `audio.event`에 넘긴다 (이벤트 이름을 그쪽 목록에 맞춤). 층 들어갈 때 `audio.floor(floor.type)`, 필살기 때 `duck` |
| 리스 플러그인 탑재 | `src/game/bridge.ts`의 `GameBridge` (saves, assets, card, report, viewport, waiting) | 진입점 **`src/game/action/main.ts`의 `mountGame(box, bridge): () => void`** 하나 |

| 행동 | 키 | 비고 |

## 5. 이벤트 이름 (엔진 → 모두)

효과음 스레드 목록에 맞췄다: `hit`(strength 1·2·3), `whiff`, `shot`, `empty`, `reload`, `guard`, `guardBreak`, `evade`, `jump`, `land`, `hurt`, `down`, `ability`, `super`, `heal`, `item`, `pickup`, `enemyDie`, `enemySpawn`, `enemyTell`, `bossTell`, `bossRoar`, `step`, `door`, `ding`, `ruleFound`, `combat:start`, `combat:boss`, `combat:clear`, `enter:floor`, `hp:low`, `run:end`, `custom`. 모양은 `contract.ts`의 `GameEvent`.

## 6. 장면 흐름 (엔진 주 루프)

```
mountGame(box, bridge)
  └ 장면 관리자: 제목 → 본부(hq 모듈, 없으면 간이 출동 화면) → 출동(전투 장면: 층 → 층 …) → 정산(본부가 그림) → 본부
     전투 장면 = 고정 30Hz 틱: 입력 → 플레이어 → 몸들 step → 판정 → 히트스톱/넉백 → 층 tick → 카메라 → 그리기(보간)
     일시정지: Esc, 대사 isBlocking, 창 초점 잃음
```

## 7. 브랜치와 합치기

각 스레드는 자기 브랜치에 자기 폴더만 올린다. 최종 통합(`engine/modules.ts`, `main.ts`, 빌드 스크립트의 시연판 항목)은 「게임 전투와 조작」이 한다. 빌드 스크립트(`scripts/build.mjs`)에 줄을 더해야 하면 직접 고치지 말고 알려 달라(충돌 방지).
