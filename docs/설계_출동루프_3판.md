# 필드·출동 루프와 전투 성장 설계 (3판 · 2026-10-30, 검토안)

사용자가 10-30에 정한 방식으로 처음부터 다시 정리했다. 2판(`설계_로그라이크_전투성장_2판.md`)은 하데스를 그대로 옮긴 부분이 많아서 이 문서가 대신한다.

- 하데스는 **임시 퍽을 쌓는 원리만** 참고한다. 해부 자료는 `docs/하데스_해부/`에 근거로 남긴다.
- 괴이는 여러 개다. 이 문서의 규칙은 **모든 괴이에 공통으로 쓰는 틀**이다. 괴이마다 다른 것(구역·규칙·적·보스·전용 퍽)은 각 괴이 데이터가 채운다.
- 「코드」 칸은 2026-10-30에 확인했다. 경로는 `src/` 기준이다.
- **코드는 만들지 않는다.** 7장 결정이 난 뒤에 만든다.

---

## 1. 전체 흐름

```
채팅 시작(페르소나/캐릭터)
  → 필드 입장 (괴이 안이면 막힘)
  → 본부: 요원 태그대로 NPC 배치, 자유 행동
  → 임무 + 출동 요원 고르기 (다른 요원을 고르면 시점이 그 요원에게 감)
  → 지하 출동장: 장비 보급 → 차량 탑승 → 출동
  → 괴이 던전(프리셋 + 절차적 생성): 방마다 보상 = 임시 퍽
      · 사망 → 초기화 (영구 사망 / 패퇴는 옵션)
      · 중간 복귀 → 초기화
      · 임무 완료 → 귀환
  → 원래 채팅 캐릭터로 돌아옴
  → 필드를 나가면 필드 보고서 → 다음 채팅 요청에 짧게 들어감
```

## 2. 단계별 규칙과 현재 코드

### 2-1. 처음 들어가는 캐릭터

| 규칙 | 코드 |
| --- | --- |
| 「캐릭터로 플레이」 중이면 그 캐릭터로 들어간다 | **있음**. `game/action/main.ts:54-58`에서 방문 요원(`$st_player` → `core/player.ts:9-20`)을 고른다 |
| 유저 페르소나로 들어오면 **공용 페르소나 캐릭터**로 들어간다 | **없음**. 지금은 에일린으로 떨어진다. 공용 캐릭터의 그림·동작·기술이 필요하다(미구현) |

### 2-2. 입장 제한

| 규칙 | 코드 |
| --- | --- |
| 괴이 안에 있을 때는 본부에 못 들어간다 | **있음**. `core/fieldgate.ts:46`에서 「작전투입」이거나 투입 칸이 켜져 있으면 막는다(`host/game/field.ts:24`). 사용자가 판정을 직접 고칠 수 있다(override) |

### 2-3. 본부 NPC 배치 (요원 태그)

| 규칙 | 코드 |
| --- | --- |
| 출동 중이거나 외근 중인 요원은 본부에 없다 | **있음**. `core/visit.ts:21` `visitRoom()`: 외근·비번·격리·작전투입·실종·사망이면 배치하지 않는다 |
| 상태에 맞는 자리에 둔다 | **있음**. 부상은 의무실, 휴게는 라운지, 내근은 사무실, 수면은 숙소 |

- 태그 원본은 채팅 변수 `$goei_world`이다(`core/world/tags.ts:37`, 모델이 쓰는 상황판에서 읽는다).
- 남은 일: 지금 본부 지도(회색 방 + 의자)의 방 이름과 `visitRoom`의 네 자리를 서로 맞추는 것뿐이다.

### 2-4. 출동 요원 고르기와 시점 전환

| 규칙 | 코드 |
| --- | --- |
| 본부에서 출동할 요원을 고른다 | **없음** |
| 지금 조작 중인 캐릭터가 아니라 **가용한 다른 요원**을 고르면 시점이 그 요원 위치로 간다. 그 뒤로는 그 요원을 조작한다 | **없음**. 주인공은 시작할 때 한 번만 정해진다(`engine/player.ts:33`) |

- 「가용」의 뜻(안): 본부에 배치된 요원, 즉 `visitRoom`이 자리를 준 요원이다. 부상자도 포함할지는 결정이 필요하다(7장).
- 바꾸는 방법(안): 그 요원의 NPC 몸을 지우고 같은 자리에 플레이어 몸을 세운다. 원래 캐릭터는 그 자리에 NPC로 남긴다.

### 2-5. 지하 출동장 → 출동

| 규칙 | 코드 |
| --- | --- |
| 임무와 요원을 고르면 지하 출동장으로 이동한다 | **지도만 있음**. B3 지하 주차장·보급실(`game/action/hq/map.ts:253-254`), 승강기 B3(`:300`) |
| 장비를 보급받는다 | **부분**. 시작 칸 회복약·섬광·각성제(`engine/itemsLink.ts`). 보급 화면은 없다 |
| 차량을 타고 출동한다 | **없음**. 옛 승합차 자리는 10-28에 삭제됐다(`docs/인계서.md` 4-4). 엔진의 `deploy`·`endRun` 틀은 남아 있다 |

### 2-6. 임무

- **결정 필요**: 그때그때 랜덤으로 생길지, 풀에서 고를지.

| 안 | 장점 | 단점 |
| --- | --- | --- |
| 랜덤 발생 | 매번 새롭고, 본편 상황판 사건과 엮기 좋다 | 괴이 프리셋이 없는 임무가 나올 수 있다 |
| 풀에서 고름 | 프리셋이 있는 괴이만 나와서 안전하다 | 반복감이 있다 |
| 섞음(안) | 풀(프리셋이 있는 괴이) 안에서 그때그때 몇 개가 열린다 | — |

- 어느 쪽이든 임무 하나 = 괴이 하나다. 그 괴이에 **프리셋**(구역 구조·방 틀·규칙·적·보스)이 있어야 하고, 출동 때 프리셋으로 던전을 **절차적 생성**한다.
- 코드: 임무 생성기와 던전 생성기는 **없다**. 옛 `stage/` 생성기는 삭제됐다. 본편 UI의 `missionList`(`ui/field.ts:497`)는 상황판 사건 목록이라 게임 임무와는 다르다.
- 생성 규칙의 기준은 `docs/관리국_괴이탐사_게임_상세기획서.md` 9장(파이프라인·방 틀 규격)이다. 괴이 하나의 예는 `스테이지설계서_명일아파트.md`이다.

### 2-7. 괴이 안: 방마다 임시 퍽

레벨업은 없다. **방을 깰 때마다 보상으로 임시 퍽을 얻는다.**

| 종류 | 예 | 코드에서 걸리는 곳 |
| --- | --- | --- |
| 공격 | 공격력 +%, 특정 기술 +% | 피해 계산 `fighter/player.ts:151` |
| 투사체 | 탄 +1, 관통 | 기본 사격은 개수 칸이 **없다**(`fighter/core.ts:610-620`). 기술 부품은 개수가 있다(`lob n`·`spikes n`·`proj spread`) |
| 이동 | 3단 점프, 이동 속도, 회피 +1 | 점프는 2단까지 숫자로 박혀 있다(`core.ts:907` `P.jumps < 2`). 숫자 하나만 바꾸면 된다 |
| 생존 | 최대 체력, 받는 피해 감소, 회복 | `engine/progression.ts`의 hp·defense |
| 괴이 전용 | 그 괴이에서만 나오는 퍽(부작용 포함) | 괴이 데이터 |

- 고르는 법(안): 3개 중 1개. 하데스에서 가져오는 것은 이것 하나다.
- 쌓는 법(안): 보너스는 **더한다**. 곱하면 폭주한다(하데스 패치 교훈).
- 저장: 임시 퍽은 **판 상태에 저장**한다. 출동 중에 닫았다 열어도 유지된다. 출동 저장은 지금 꺼져 있다(`engine/game.ts:326-341` 틀만 있음).
- 유지 범위: **괴이 안에서만** 유지된다.
  - 사망하면 초기화된다.
  - 중간 복귀하면 초기화된다.
  - 임무를 완료해도 귀환하면 사라진다.
- 인플레 억제: 괴이는 방을 거듭할수록 강해진다(생성 규칙). 퍽도 괴이를 나오면 끝나므로 쌓이지 않는다.

### 2-8. 사망 처리 (옵션)

| 옵션 | 뜻 |
| --- | --- |
| **영구 사망(기본, 10-30 결정)** | 보고서에 「사망」으로 적는다 |
| 패퇴 | 후송된다. 보고서에 「부상·후송」으로 적는다 |

- 둘 다 **우리가 태그를 직접 바꾸지 않는다.** 보고서로 알리기만 하고, 상황판 태그를 바꾸는 것은 모델의 몫이다.
- 코드(10-30): 설정 `deathMode`(`ui/settings.ts`, 기본 perma). 영구 사망 → `player.ts` dieNow(44/45) → `world.ended = 'death'` → 결과 「사망」·`gamelink` 보고서 「사망」. 패퇴 → 후송, 보고서 「부상·후송」.

### 2-9. 귀환 → 원래 캐릭터 → 필드 보고서

| 규칙 | 코드 |
| --- | --- |
| 임무를 마치면 원래 채팅 캐릭터로 돌아온다 | **없음**(2-4 전환의 반대 방향) |
| 필드에서 한 일을 기록한다 | **있음**. `bridge.field.record`가 거래·행동·폭행·피해·대화·선물·이동을 남긴다(`engine/modules.ts:130-335`). 채팅의 `goeiFieldV1`에 최대 300건 쌓인다 |
| 필드를 나가면 보고서를 만든다 | **부분**. `bridge.report`가 있지만 보류 목록에만 들어가고, 사용자가 「보고서 붙이기」를 눌러야 쓰인다(`host/game/card.ts:54`) |
| 모델에 넣는다 | **부분**. `beforeRequest`(`main.ts:135`) → `core/interlude.ts`가 두 가지를 넣는다. 필드 대화는 막간으로(`withInterludes`), 확정 사실은 사실 목록으로(`withFieldFacts`). 「활동 결과」 요약은 없다 |
| 본편 연동을 켜고 끄기 | **없음**. 필드 설정에는 「보내는 내용 보기」만 있다(`ui/visitset.ts`) |

**보고서는 두 갈래로 나눈다 (10-30 결정)**

| | ① 채팅에 붙는 보고서 | ② 모델에 들어가는 활동 결과 |
| --- | --- | --- |
| 목적 | 사용자가 **보는** 것(시각용) | 모델이 「지난 채팅 이후에 있었던 일」을 아는 것 |
| 길이 | 상세하게 | 간략하게(토큰 절약). 다만 모델이 이해할 만큼은 쓴다 |
| 들어가는 것 | 방마다 기록, 얻은 임시 퍽, 처치·구조·회수, 받은 피해, 필드 대화와 사건 전부 | 최종 결과만: 누가 / 어디서 / 무엇을 / 결과 / 지금 상태 / 눈에 띄는 일 |
| 넣는 시점 | 필드를 나갈 때 **자동**으로 | 다음 채팅 요청에 **자동**으로, 한 번만 |
| 모델에 보내나 | 보내지 않는다(요청에서 뺀다) | 보낸다 |

②의 모양(안). 목표는 5~8줄, 한국어 약 150~300자다.

```
[필드 활동 결과 · 지난 채팅 이후]
- 누가: 에일린 (유저 본인 아님)
- 출동: 명일아파트 · 구조 임무 → 완료. 생존자 2명 구조, 4층 보스 처치
- 상태: 부상(체력 30%)으로 귀환
- 본부: 라운지에서 잼트리와 대화, 사무실에서 스팡달과 몸싸움 1회
```

- 「누가」는 꼭 넣는다.
  - 유저 본인이면 모델이 직접 겪은 일로 쓴다.
  - 다른 요원이면 모델이 소문·목격·전해 들은 얘기로 쓴다.
  - 어떻게 반영할지는 모델이 정한다. **우리는 정보만 준다.**
- 괴이에 안 나가고 필드에서만 깽판을 쳐도 같은 모양으로 들어간다(「출동」 줄이 빠지고 「본부」 줄이 늘어난다).
- 지금 있는 막간·확정 사실과 겹치지 않게 한다. 필드 대화 원문은 막간으로 이미 들어가므로, ②에는 「누구와 무슨 일」 한 줄만 쓴다.
- 지금 기록에는 **「누가 했는가」 칸이 없다.** 시점 전환이 생기면 기록마다 행위자를 붙여야 한다.

**본편 연동 옵션(새로)**: 필드 설정에 「본편 연동」 켜기/끄기를 둔다. 끄면 ①도 ②도 막간도 확정 사실도 본편에 넣지 않는다. 필드만 따로 논다.

## 3. 능력치: 두 벌

| 상태 | 목적 | 값 |
| --- | --- | --- |
| **NPC 상태**(필드 본부·거리, 적이나 동료로 나올 때) | 네임드답게 강하다. 유저가 마음대로 패 죽이지 못한다 | 등급표(4장 「NPC값」) |
| **조작 상태**(유저가 그 요원으로 괴이에서 조작할 때) | 괴이가 추풍낙엽이 되지 않는다. 임시 퍽으로 강해진다 | 요원마다 **고정 초기값** = 4축 공식(4-1) + 고유 퍽 1개(4-2) |

- 코드: 플레이어 몸(`FighterPlayer`)과 NPC 몸(`FighterAi`)은 이미 따로 만들어진다.
  - 체력은 따로 준다. NPC는 `engine/modules.ts:523`의 160, 필드 도전자는 `world/actors.ts:178`의 등급 체력, 플레이어는 `engine/progression.ts:30`의 220.
  - 기술 피해는 같은 인물 팩 값(`cfg.bal.atk`)을 함께 쓴다. 그래서 두 벌로 나누려면 **배율 칸을 몸마다 따로** 두면 된다. 그림이나 동작은 바꿀 필요가 없다.
- 필드에서 유저 페르소나(또는 조작 상태의 요원)가 NPC 요원과 싸우면 「조작값 vs NPC값」이 된다. 그래서 네임드에게 쉽게 이기지 못한다.

## 4. 값 (안)

### 4-1. 조작값: 요원마다 고정된 숨은 능력치

「조작 상태」는 유저가 그 요원을 골라 조작하는 상태를 말한다. 퍽(4-2)과 헷갈리지 않게 「픽」이라는 말은 쓰지 않는다.

**숨은 능력치 6개.** 화면에는 나오지 않는다.

| 값 | 뜻 | 코드 |
| --- | --- | --- |
| 체력 | 최대 체력 | `progression` hp |
| 피해 | 내 모든 공격 피해 배율 | `power`·`aim` |
| 속도 | 이동·회피 속도 | `speed` |
| 쿨 | 기술 재사용 대기 배율 | 새 칸(`setCd`에 곱함) |
| 받는 피해 | 맞을 때 배율 | `defense` |
| 경직 저항 | 잘 안 밀림 | `poise` |

**값을 정하는 법(안)**: 요원마다 성향 4축을 1~5로 매기고, 정해진 공식으로 숨은 수치를 만든다.

- 4축은 `관리국_괴이탐사_게임_상세기획서.md` 5.1의 축(생존 여유·기본 화력·기동·제어)을 그대로 쓴다.
- 3이 기준이다. 한 칸마다 바뀌는 폭은 **작게** 둔다. 그래야 누구를 골라도 괴이를 추풍낙엽처럼 쓸지 않는다.

| 축 | 한 칸당 | 1일 때 | 5일 때 |
| --- | --- | --- | --- |
| 생존 여유 | 체력 ±8% (기준 1,000) | 840 | 1,160 |
| 기본 화력 | 피해 ±5% | 0.90 | 1.10 |
| 기동 | 속도 ±5% | 0.90 | 1.10 |
| 제어 | 쿨 ∓5% | 1.10 | 0.90 |

- 받는 피해와 경직 저항은 기본이 1.0과 0이다. 퍽이나 방패형 성향에서만 바꾼다.

### 4-2. 고유 퍽 1개 (폴아웃식)

폴아웃의 퍽처럼 만든다.

- 이름과 짧은 설명(설정 한 줄)이 있고, 효과는 구체적인 숫자 하나다.
- 요원마다 처음부터 하나 붙어 있다. 조작 상태와 NPC 상태에 모두 붙는다.
- 괴이 안에서 방마다 얻는 **임시 퍽**과 같은 틀을 쓴다. 차이는 하나다: 고유 퍽은 **늘** 붙어 있고, 임시 퍽은 괴이를 나오면 사라진다.
- 결정 필요: 장점만 주는 퍽(폴아웃 Perk)으로 할지, 장점과 대가가 같이 붙는 특성(폴아웃 1·2·뉴베가스 Trait)도 섞을지.

예시. 근거는 기획서 5장 인물 제목과 `기술_재설계/`이고, 숫자는 안이다.

| 요원 | 퍽 이름(가칭) | 설명 | 효과 |
| --- | --- | --- | --- |
| 데드폴 | 죽은 채로 있을 수가 없다 | 쓰러져도 신음하며 일어난다 | 괴이 한 번에 1회, 체력 0이 되면 30%로 일어남 |
| 스팡달 | 그림자 기습 | 등 뒤에서 나타난다 | 등 뒤에서 때리면 피해 +25% |
| 에일린 | 준비된 사수 | 준비와 거리로 싸운다 | 멀리 있는 적에게 사격 피해 +15% |
| 쟈알디 | 큰 파괴 | 절제된 동작, 큰 결과 | 폭발 범위 +20% |
| 고르고디오 | 아머 | 맞으면서 들어간다 | 돌진 중 경직 면역 |

- 55명분 목록은 따로 만든다(결정 뒤).
