## 1. 꼭 지킬 사용자 규칙

1. **한국어로만, 짧게 답한다.** 코드 이름만 영어로 둬도 돼요.
2. **시키지 않은 일을 시작하지 않는다.** 질문에는 답과 추천만 하고 멈춰요. 「해 / 만들어 / 계속 가 / 릴리스해」라고 해야 시작해요. 「기다려 / 아직」이면 아무것도 안 해요. 「계속 가」를 들은 계획은 끝까지 하고, 특이한 점만 기록해요.
3. **그림은 GPT 몫이다.** Claude는 그림을 그리거나 도트화하지 않아요(사용자가 시킬 때만 예외). Claude는 코드·모델 연결·프롬프트·플러그인을 맡아요.
4. **배경은 가구 포함 완성 장면 → 같은 장면에서 오브젝트 분리 순서다.** 편집·합성·변환·리사이즈·코드 검증을 허용한다. 화풍 기준은 `game-src/art/start-room/design.png`, 현행 제작 규정은 `docs/필드_그림_통합_지침.md` 0-1절이다. GPT에 붙여 넣을 말에는 저장소 `leepc25/goei-plugin`(main)과 전체 URL을 넣는다.
5. **PixelLab 생성은 사용자가 시킨 것만.** 먼저 비용(생성 회수)을 말하고, 작게 한 장씩 확인하고, 장마다 쓴 회수를 알려요. 시험 삼아 약 360회를 쓴 적이 있는데 사용자가 화를 냈어요. 같은 방식으로 실패를 반복하지 않아요(AGENTS.md 「PixelLab 생성 규칙」).
6. **설계 전에 원본 설정을 먼저 읽는다.** 위키 `card/wiki-base.json`, 로어북.
7. **문서는 앱에서 열 수 있게 준다.** GitHub 링크만 주지 말고 파일을 첨부하거나 아티팩트로 줘요.
8. 새 스레드를 열자고 하면서 주제를 안 말하면 주제를 물어요. 다듬기 작업은 주제마다 새 스레드로.
9. 결정·승인 요청이 생기면 사용자가 볼 수 있는 곳에 바로 알려요. 사용자가 이 스레드에 없으면 프로젝트 대화에도 알려요.
10. 새 게임 빌드를 만들면 바로 「검수 전」 표시와 알려진 결함을 붙여 링크를 줘요. 화면마다 독립 검수(냉정하게 한 장씩)를 해요.
11. 릴리스는 브랜치에 모아 두었다가 **사용자가 「릴리스해」라고 할 때 한 번에** 해요. GitHub Actions가 끝나는 즉시 완료를 알려요.
12. 미성년자의 목욕·탈의 장면은 절대 만들지 않아요. (콘쥬스는 2026-10-26 사용자 지시로 **20세 대학생**으로 바뀌어 이 규칙의 대상이 아니에요. 학생 NPC 등은 그대로.)

- 감정 동작은 키용이 아니라 **NPC 자동 행동용**(오래 대기, 논플레이어블이 돌아다닐 때).
- 사용자가 고민 중이던 것: 공격 버튼 2개로 충분한가, 3개인가, 각 몇 타인가.

**Claude가 답한 안 (동작 2판, 사용자 확인 대기)**
- 버튼 2개 추천. 강은 약 몇 타 뒤냐에 따라 마무리가 다름: 단독·약1 뒤 = 스턴, 약2 뒤 = 띄우기, 약3 뒤 = 멀리 날리기. 달리다 약 = 돌진 공격, 공중 약 = 점프 공격.
- 필살기는 하나(8장 제한 때문에 A·B 두 클립으로 나눈 것).
- 점프 높이는 코드가 정함. 2단 점프는 상승 장 재생 + 효과(비용 0).
- 섭취 = 기존 깨끗한 「먹기」 글 동작 + 머리 위 아이템 아이콘(비용 0).
- 감정은 쓰임이 분명한 12개만(박수·몸 떨기·주먹 불끈 뺌).
- 쟈알디에게 새로 만들 글 동작 **15개, 약 120회** + PixMiniMax 걷기·뛰기. 55명 전체는 약 11,000회로 잔액과 비슷 → 감정은 나눠서.
- **아직 아무것도 생성하지 않았어요.** 다음 단계는 사용자가 2판을 보고 고친 뒤 「만들어」라고 할 때 프롬프트를 먼저 보여 주는 것.

## 6. 진행 중인 일 ② 필드 배경 (방식 결정 대기)

자세한 건 `docs/인계/필드작업_인수인계_2026-10-24.md`. 요점만:
- GPT는 긴 그림(높이 700 × 가로 1600 이상)을 못 그리고, 따로 그린 그림끼리 화풍이 안 맞아요. 이번에 건진 GPT 배경은 2장(`docs/인계/배경/GPT_배경/`의 로비·거리).
- 확정: **낮 그림만, 밤은 코드로 어둡게.** 관리국과 가짜 관리국은 **같은 그림, 배치로만 구분.** 사무실 바닥은 **카펫 아님**, 줄 없는 밝은 회색 한 종류. 벽은 가장 단순하게 밝은 색(짙은 남색 금지, 기둥 없음). 문은 따로 그려 얹음. 바닥에 원근 있음(뒤 0.85배 → 앞 1배). 벽·바닥 종류는 최소(비용).
- GPT 부품 시트 방식(P1~P8, 마젠타 배경에 물건만, 1m=284px)을 지침 「0-1」에 써 두었어요. 붙여 넣을 말은 `docs/인계/배경/필드배경_GPT_붙여넣기.md`. **다음 단계: GPT가 P1만 그려 사용자가 화풍·배율 확인.** 아직 시험 전.
- 대안 PixelLab: `/v2/generate-image-v2`에 `style_image`로 `game-pack/start-room/room.png`를 주면 화풍이 맞았어요. 벽 한 칸 640×352 약 25~35회, 가구 10~20회. 시험 그림 `docs/인계/배경/pixellab_로비시험/`. 사용자 비용 규칙: 관리국 공통 바닥 하나, 벽 몇 종만, 가짜 관리국은 관리국 부품 재사용.
- 규격: 배경 높이 700, 벽선 y420, 걷는 띠 y420~669, 1m=142px. 요원 캔버스 128×256, 남동만 쓰고 왼쪽은 좌우 뒤집기, 앞 1.5배 / 뒤 0.85배, 다리 긴 비율 금지.
- 장면 약 120개는 `docs/필드_거점_설계안.md`.
- 코드 남은 일: 배경 조립기(벽·바닥 칠하기, 시트에서 물건 오려 배치, 문 얹기, 밤 처리) — 기존 `src/game/action/art/bg.ts`(`drawHqWall`, `DOOR_WALLS`)를 고쳐요.
