# 설계안 · 인물 기록에 세력 평판 더하기 (2026-10-26)

> 의뢰: `docs/의뢰_세력평판_인물기록확장.md` (필드 세계 설계 스레드, 2026-10-26 수정판: 수배·표적 상태 없음, 몹 반응은 값 구간으로만). 이 문서는 그 답.
> 상태: **설계안. 사용자 결정 전 코드 시작 안 함.** 7장의 결정 항목에 답을 주시면 구현.
> 전제: 인물 기록 v0.16.62 + 상한 개편(저장 10,000자·본편 16,000자·정리 얹기) + 선택 기능 3종(취향·음란도·리듬) 위에 올린다.

## 1. 한 줄 요약

세력(관리국·가짜 관리국·백일몽·민간·프리랜서 협회·사용자 추가 세력)을 **인물처럼 장부를 가진 대상**으로 하나 더 둔다. 값은 저장하지 않고 변경 기록에서 매번 계산(인물 호감과 같은 엔진), 근거·되감기·취소·고정·화면을 그대로 재사용한다. 본편 갱신기와 필드 게임 코드가 같은 장부에 쓰고, 본편 요청과 필드 몹 반응이 같은 값을 읽는다. **수배·표적 같은 별도 상태는 없다.** 값 하나와 그 구간뿐이다.

## 2. 저장 모양

```ts
// PeopleStore (goeiPeopleV1) 에 한 칸 추가. 옛 채팅은 비어 있음 = 시작값
factions: Record<string, FactionRecord>;   // 열쇠 = 조직 코드 A00·B00·C00·D00·E00·(사용자 추가 F00…)

interface FactionRecord {
  code: string;            // 'B00'
  name: string;            // 명부 세력 이름 (화면용, 코드가 바뀌면 다시 읽음)
  seeded: { at: string };  // 처음 만든 때
  // 값은 없음. 시작값은 relations-base orgs['세력>유저소속'] 을 매번 읽는다 (유저 소속이 바뀌면 시작값도 따라감)
}
```

- 변경 기록은 기존 `Change` 를 그대로 쓰고 `who` 에 `세력:B00` 을 넣는다. 엔진(`affinityOf`)·살아 있음 판정·되감기·접기(`foldLog`)·변경 기록 화면이 수정 없이 돈다. 인물 이름과 섞이지 않게 `세력:` 접두사를 예약어로 둔다(인물 이름에 `:` 금지는 이미 별명 검사에 있음).
- 시작값 표는 지금 있는 `relations-base.json orgs`(40칸, `세력>유저소속`) 그대로. 유저 소속은 `store.identity.faction`(상태창 신분), 없으면 `$st_faction`.

## 3. 값과 단계

| 항목 | 제안 | 근거 |
| --- | --- | --- |
| 범위 | **−100 ~ +100** | 인물(−100~300)보다 좁게. 세력은 「애정」까지 갈 일이 없고, 시작값 표가 −25 단위라 ±100 안에서 충분히 움직인다 |
| 단계 | **5단계** (필드 세계 설계 8-6 표와 같음): 우호 61~100 · 호의 21~60 · 중립 −20~20 · 경계 −60~−21 · 적대 −100~−61. **경계값 4개는 설정에서 조정**(필드가 같은 값을 읽는다) | 시작값 −25 는 「경계」로 시작. 필드 몹 반응: 우호 = 반기고 편듦 · 호의 = 인사하고 길을 비킴 · 중립 = 무시 · 경계 = 지켜보고 자기 구역에서 경고·쫓아냄 · 적대 = 보자마자 공격 |
| 계기 | 기존 `CUES` 재사용: 작은친절 +1 · 도움 +3 · 큰도움 +5 · 헌신 +10 · 실망 −2 · 무시 −4 · 배신 −5 · 파탄 −10 · 중대위반 −50(예외) | 값 표와 메시지당 ±10 상한을 그대로 쓰면 엔진 공유가 됨 |
| 배율 | 인물 성격 계수 대신 **세력 계수 1.0 고정**, 설정 「호감 변화 속도」는 같이 적용 | 세력별 계수 표는 나중에 |
| 개인 → 세력 | **번지지 않음** | 의뢰 3-2. 인물 계기는 인물 장부에만 |
| 별도 상태 | **없음** | 수배·표적 없음. 본편 서사에도 그런 말이 들어가지 않는다 |

본편에 넣는 영문 단계 문장(인물의 `STAGES.behavior` 와 같은 형식):
- 우호: `Friendly. Members welcome {{user}}, share information freely and take {{user}}'s side in a fight.`
- 호의: `Favorable. Members greet {{user}}, make way and extend small favors.`
- 중립: `Neutral. Ordinary procedure; members take no special notice.`
- 경계: `Wary. Members watch and verify; on their own ground they warn {{user}} off or expel; elsewhere they only observe.`
- 적대: `Hostile. Members attack {{user}} on sight, even outside their own ground.`

## 4. 무엇이 값을 바꾸나

### 4-1. 필드 (모델 0)
- `FieldEvent` 에 `witness?: { faction: string; named: boolean }` 를 더한다. 게임 코드가 유저 행동을 목격한 **소속**과 「명단 인물인지(named) / 이름 없는 몹인지」를 적는다.
- `src/core/people/field.ts applyFieldEvent` 에 세력 경로: `CUE_OF[ev.kind]` 가 있고 `witness.faction` 이 있으면 `who: '세력:<코드>'` 로 계기 1건. **무게**: 명단 인물 목격은 표 값, 몹 목격은 **절반(소수점 버림, 0이면 기록 안 함)** → 작은친절 +1 은 몹이 봐도 0 이라 안 쌓이고, 도움 +3 → +1, 배신 −5 → −2. 필드 한 판에 수십 건이 쌓여도 세력 값이 인물 값보다 빨리 뛰지 않는다.
- 되감기 기준은 지금처럼 `ev.anchor`(본편 마지막 메시지 chatId).

### 4-2. 본편 (갱신기 출력 칸 하나, 추가 호출 없음)
출력 계약에 절 표식 `<<SECTION:faction_rep>>` 로 한 칸:
```
"faction_cues":[{"faction":"<조직 코드 또는 이름>","cue":"<cue name>","m":"m2","quote":"<verbatim>","reason":"<Korean ≤40>"}]
```
지침 요지(자세히판·간결판 같은 규칙):
- 세력 계기는 **세력이 집단으로 반응했을 때만**: 출입 금지·해제, 보복·배제 지시, 공식 감사·징계, 공식 포상·거래 성사, 공문·방송, 조직적 공격·보호. 구성원 한 명의 기분·말·행동은 그 사람의 인물 장부로 가고 세력 장부로 오지 않는다(「쟈알디가 화냈다」≠「관리국이 적대」).
- 인용은 집단 행위 문장이어야 하고, 세력당 응답에 1건.
- 세력 문서(`docs_faction`)와의 경계: 문서 = 세력끼리의 일(글), 평판 = 세력 → 유저(값). 같은 사건이 둘 다에 적혀도 된다.

코드 검사(남발 방지, 의뢰 5-2): 계기 `reason`+`quote` 에 집단 행위 낱말(출입 금지·금지 해제·지시·감사·징계·공문·포상·거래·계약·방송·명령·보복·배제·보호) 중 하나가 없으면 버림(사유 「집단 반응 근거 없음」). 세력 이름은 `factionCode()` 로 코드로 바꾸고 모르는 이름은 버림.

## 5. 필드에서 크게 깎이는 일 (필드 세계 설계가 정한 것)

필드 코드가 다음을 목격당하면 큰 계기로 보낸다(값은 `CUES` 표, 몹 무게 규칙 적용):
- 그 세력 거점에서 진압 단계까지 난동 → 파탄(−10)
- 그 세력 이름 인물 살해·중상 → 중대위반(−50, 예외 계기라 메시지당 상한 밖)
- 그 세력 몹 여럿을 쓰러뜨리는 것을 목격당함 → 파탄(−10)
구체 매핑은 필드 쪽이 `FieldEvent.kind` 로 정하고, 인물 기록은 `CUE_OF` 표에 받기만 한다.

## 7. 사용자가 정할 것 (추천 굵게)

1. 단계·경계값: **5단계, −100~100, 경계값 61·21·−20·−60 (필드 세계 설계 8-6 표 그대로, 설정에서 조정)**.
2. 본편 주입 기본: **켬** (장면 세력만, 중립은 생략).
3. 몹 목격 무게: **절반(소수점 버림)**. 명단 인물 목격은 원래 값.
4. 기능 기본값: **켬**. 끄면 필드 몹이 유저를 기억할 통로가 없다.

## 9. 위험

1. 갱신기 출력 칸이 둘 늘어 기존 정확도에 영향 → 기능 끄면 지금과 완전히 같음(절 표식). 켬 정확도는 실제 모델 측정 세트로.
2. 세력 이름 해석: 모델이 「회사」「본부」처럼 쓸 때 `factionCode()` 가 못 잡으면 버려짐. 모르는 이름은 진단에 남겨 사용자가 보게.
3. 사용자 추가 세력(F00…): 명부에 있으면 코드로 잡히고 시작값은 0.
4. 필드 쪽 `witness` 를 채우는 일은 필드 브랜치 몫. 다리와 `field.ts` 까지만 이번 범위.
