## 2. 아직 안 된 것
1. **필드 게임 연결**: 대사 선택기(호감 단계 → 칸, `{호칭}` 채우기·조사), `npcLink.ts`·`brain.ts`의 시트 자리·`RelationStore`·태그 `[[관계 계기]]`, 옛 localStorage 이전. 필드 브랜치가 멈추면.
2. **실제 모델 측정**: 갱신기 정확도(시험 세트 30구간), 신분 칸 정확도, 지침 자세히/간결 비교. Risu 실행 환경이 필요.
3. **chatId 실측**: 다시 굴리기·스와이프·편집에서 메시지 chatId가 어떻게 되는지. 사용자 도움.
4. 「이 인물 다시 읽기」(인물별 재읽기), 옛 채팅 소급(「최근 30턴 읽기」), 인물끼리 감정(`npc_emotion`) 실제 갱신 규칙, 조짐 세기, 취향 띠.
5. 카드 패치는 다음 릴리스 빌드에서 적용. 옛 플러그인은 9칸을 추측 경로로 읽어 신분만 버리므로 `minPlugin` 올림은 불필요.
6. 저장 크기 실측(인물 20명·기록 800건) 뒤 상한 조정.

## 3. 쓰는 법 (검수용)
1. 설정 → 기능별 설정 → 인물 기록: 켬, 갱신 매 턴, 모델 보조(기본).
2. 본편을 몇 턴 진행하면 등장한 요원 기록이 생기고(시트 시작값), 응답마다 갱신기가 돈다. 위키 탭 → 이 채팅의 인물에서 확인.
3. 설정 맨 아래 진단에서 보낸 프롬프트·응답 원문·버린 항목 이유를 본다.
4. 상태창에 신분 칸이 나오게 하려면 다음 릴리스 카드가 필요하다(그 전에는 갱신기의 `identity` 참고값만).

## 4. 1차 검수 반영 (2026-10-26, v0.16.62 뒤)

### 동작
| 피드백 | 반영 |
| --- | --- |
| 유저가 연기하는 요원(이도형)의 기록이 생김 | `playerAgent` 이름을 **제외 목록**으로: 시드 안 함, 장면 인물·갱신기 `people` 에서 빼고, 모델이 `new_people` 로 올려도 「유저가 연기하는 요원」 사유로 버림. 이미 생긴 기록·계기는 다음 갱신 때 지움 (`dropExcluded`) |
| 호감·호칭이 비어 깨짐 | **호칭 표** `game-src/dialogue/address.json` (52명: 직급 단계·말투·자기 호칭·유저가 상급/동급/하급/외부인일 때 부르는 말). 처음 등장 때 상태창 신분(`store.identity`)과 `relativeRank` 로 골라 시작값으로 넣음. 신분을 모르면 외부인 호칭. 이후는 갱신기가 바꿈 |
| 말투 종류 | `Register` 를 존댓말·반말·혼합·**하게체·하오체** 5종으로 (고그니쟈·도필헌·청달래 하게체, 살라딘 하오체). 본편 블록 영문 표기, 저장 읽기, 게임 다리 타입 함께 |
| 인물끼리 감정 기본 끔 | 기본 **켬**. 「인물끼리 감정」= 인물 A 가 인물 B 에게 갖는 관계·감정 항목(relationship 칸의 target 이 유저가 아닌 인물)도 기록하는 기능. 리수폿은 늘 기록 |
| 인물당 기록 상한 800 | 기본 **2,000자** (선택 800·1,200·2,000·3,000). 리수폿은 인물당 상한이 없고 Writer 입력 예산 48,000 tok 안에서 문서 전체를 넣는다. 우리는 장면 인물 ≤6명 × 상한이 본편 요청에 더해지므로 상한을 둠 |
| 응답 접기 상한 12,000 | 기본 **20,000자** (선택 12,000·20,000·40,000). 리수폿은 최근 맥락 16,000자 + 참고 문서 총 16,000자(문서당 ≈2,700자)로 자르고 RP 본문은 자르지 않음. 우리는 한 묶음의 응답 글을 이 상한에서 중간을 접음 |

| 2턴 규칙 기본 켬 | 기본 **끔** (`twoturn '0'`): 처음 나온 이름도 바로 등록 |
| 진단 「doc 인용 없음」 버림 | 문서(사건·장소·세력·물건)는 구간을 요약한 것이라 모델이 인용을 안 줄 때가 많다 → **인용 없이도 받음**(기준 메시지만 확정 구간이면). 인용을 주면 원문에 있어야 함 |
| 진단이 채팅별로 안 나뉨 | 진단 행에 채팅 열쇠가 있었는데 화면이 안 걸렀음 → **이 채팅만** 기본, 「모든 채팅 보기」 토글. 보관은 성공 10건·실패 30건(그 뒤는 오래된 것부터 지움), 「진단 지우기」로 전부 삭제 |
| 사원증 「기록」→ 뒤로가기가 위키 메인 | 뒤로가기를 「이 채팅의 인물」 목록으로. 위키 홈 맨 위에 「이 채팅의 기록」 절(요원 아닌 사람도 여기) |
| 시작 메시지 표정 태그가 세트에 없음 | 빌드 때 `EMOTION_FIX` 표로 가까운 표정으로 바꿈(acting coy→shy, determined→serious, enraged→angry, seductive smile→smirk …). 세트·표 둘 다 없으면 빌드 중단. 플러그인은 **목록에 없는 이름·표정 태그를 그냥 지움**(빈 칸도 기본 그림도 없음). 화면 처리기는 에셋 목록 첫 읽기를 기다렸다가 그리므로 새로고침 없이 뜸 |

| 「메시지가 사라져 빠짐」이 멀쩡한 메시지에도 뜸 | 원인: 새 항목이 **대체**(upsert)한 옛 항목까지 같은 글로 표시. 이제 상태를 구분: 새 항목으로 바뀜 / 요약에 합쳐짐 / 취소됨 / 메시지가 사라져 빠짐. 지난 항목은 칸마다 「지난 항목 n」으로 접음 |
| 항목이 끝없이 쌓이나 | 칸 상한(기본정보 6·성격 8·상태 6·관계 8·말투 4·행동 8·아는 것 10·목표 8·지난 일 12·장면 3·의심 6). 상한이 있는 칸은 넘으면 가장 오래된 비고정 항목을 새 항목이 대체. **지난 일·아는 것**은 넘치면 오래된 것들을 요약 한 줄로 접음(`foldSlotEntries`, 되돌릴 수 없음). 안 살아 있는 항목(대체·접힘·취소·사라짐)은 칸마다 최근 6개만 보관(`pruneEntries`, 되살리기용). 문서도 같음 |
| 갱신기 뒤에 보조 모델이 `<img=>` 를 끼우면 그 응답을 다음 턴에 또 읽음 | 읽음 해시를 본문 기준(이미지 태그·공백 무시)으로 바꿈 |
| 기본정보·성격이 영어 | 로어북 시트(영어) 절을 시작값으로 그대로 옮긴 것. 이야기에서 생기는 항목은 한국어. 본편 모델은 둘 다 읽음 |

### 화면 (`src/ui/*`)
메인 설정에 「인물 기록」 켬·끔(채팅 시작 설정에 포함) / 시작 패널에서 기능별 설정 5칸이 보이게 / 기능 단추 PC 1줄·모바일 2줄×3칸 / 추가 지침 두 개를 한 묶음으로, 글칸 위 여백 제거 / 진단 「기록」·「보낸 프롬프트」·「응답 원문」 펼칠 때 화면이 위로 튀는 것 고침 / 호감 막대는 무관심(0)을 중심에 / 호칭이 비면 「아직 모름」 / 근거 「#n」 단추·슬롯 이름 설명(기본정보·성격·상태·관계·말투·행동·아는 것·미해결·지난 일·장면·의심) / 인물 화면 머리에 설명 한 줄.

### 답한 것
- 「인물끼리 감정」: 인물 A 가 유저 아닌 인물 B 에게 갖는 관계·감정 기록. 리수폿은 늘 기록 → 기본 켬.
- 지침 73,124자(≈22k tok): 자세히판 = 리수폿 Writer 지침(최대 ≈38k tok)을 재구성한 것 + 켜진 절 전부. 간결판은 ≈13.6k tok. 비용이 부담이면 설정 「지침: 간결」.
- 「보류」: 모델이 항목 삭제(remove)를 요구했는데 인용에 해소·회복 같은 근거 말이 없어 반영하지 않은 것. 항목은 그대로 남고 진단에만 표시.

## 7. 세력 평판 (2026-10-26, 의뢰 → 설계안 → 사용자 결정 「들어가」)
