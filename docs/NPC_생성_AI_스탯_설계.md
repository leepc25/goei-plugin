# NPC 생성 · AI 행동 · 스탯 시스템 설계 (2판, 2026-10-26)

> 상태: **제안. 사용자 확인 전.** 코드·그림 변경 없음. 확정 규칙은 그대로 따르고, 고치는 곳은 「결정 필요」(10장)에 모았다.
> **2판 확정 (2026-10-26 사용자):** 일반 NPC 71종은 개별 관리 대상이 아니라 **상호작용 가능한 몹**이다. 끊임없이 보충되어야 손맛이 난다. 이름 있는 55명만 개인별로 관리한다(호감·일과·본편 연결). → 3-3장·3-5장·6장을 바꿨다.
> **확정 (2026-10-26 사용자): 몹은 성향이 고정된 개체로 뽑지 않는다.** 외형(그림 71종)·역할(직무·소속)·성향·상태를 떼어 놓는다. 성향(용기·친화·성급함·호기심·수다 등 연속 수치)은 **나올 때마다 새로 뽑고**, 역할은 뽑는 범위만 좁힌다. 상태(기분·공포·피로·소란도·주변 동료)가 성향을 덮기도 한다. 그림에 붙는 것은 「어떻게 때리나」(동작 모양)뿐이고 「때릴지 말지」는 개체의 성향·상태가 정한다. 동작표의 「대부분 패닉」 같은 성향 표기는 뽑는 범위의 참고일 뿐이다. 이름 NPC 55명은 원작 성격이 고정이고, 욕구·기분·관계·본편 상황으로 행동이 달라진다.
> **2판 추가 (2026-10-26 사용자):** 몹 중에는 정해진 상황에서만 나오는 **근무형**이 있다. 청소부는 각 본부를 돌아다니고, 안내데스크 직원은 자리 고정. 24시간이 아니라 **근무시간**이 있다. → 3-4장.

## 0. 지키는 확정 원칙

1. **행동은 게임 코드가 정하고, 모델은 대사만 쓴다.** 평소 행동에 모델 호출 없음. 모델 태그(`[[동행]]` 등)는 계기일 뿐이고 `decide()`가 허락한다.
2. 필드는 **관리국 본부 방문 체험**이 우선. 전투는 틀만 두고 확대 보류. 그래서 이 설계는 **같은 NPC가 평소엔 생활하고, 필요할 때만 싸우는** 한 구조로 짠다.
3. 감정 동작은 키용이 아니라 **NPC 자동 행동용**. 모든 캐릭터(이름 55 + 일반 71) 고유 대기.
4. NPC 위치는 저장하지 않는다. 일과 + 시각 + 본편 상태로 다시 만든다.
5. 콘쥬스(미성년) 안전선 유지: 목욕탕 일과 없음, 프롬프트 안전 문구 항상.
6. 저장소에서 내용을 영구히 받아 오는 데 의존하지 않는다(모든 NPC 자료는 코드 팩·자산 팩 안에).
7. **(2판 확정) 두 갈래.** 이름 NPC 55명 = 개인(관계·일과·기억). 일반 NPC 71종 = 몹(끝없이 보충, 개인 기록 없음, 원형 성향만).

## 2. 전체 구조 한 장

```
   [자료]                         [생성]                    [실행: 30Hz 틱]
 NpcDef(대화, roster.ts) ─┐
 NpcSheet(로어북 시트) ───┤
 Archetype(일반 NPC 틀) ──┼─▶ NpcSpec(확정 명세) ─▶ Director(장면 감독) ─▶ Actor(몸)
 StatBlock(스탯) ─────────┤      buildSpec()          일과·스냅숏·인구         ├ Body/Fighter (엔진 그대로)
 BehaviorProfile ─────────┤                          ↑ 시각, 본편 상태          ├ Mind  (관계·기분·태도)
 MotionSet(동작 목록) ────┘                          └ LOD: 보이는 장면만       ├ Brain (행동 선택)
                                                                               └ Motor (길찾기·클립·감정)
 모델(대사) ── 태그 ─▶ decide() ─▶ Mind 이벤트 ─────────────────────────────────┘
```

- **명세(Spec)는 읽기 전용, 상태(State)는 따로.** 같은 쟈알디 명세로 필드 요원·출동 요원·동행자를 모두 만든다.
- **몹은 감독 대신 스포너(3-3)가 원형에서 바로 찍어 낸다.** 개인 명세·기록 없음.
- **몸 하나 원칙.** 필드 NPC, 동행자, 적, 일반 시민이 모두 `Actor` 하나로 돈다. 적의 `Enemy`는 `Actor`의 전투 두뇌 묶음으로 흡수한다(10장 결정 ①).

## 3. NPC 생성

### 3-1. 정체(id) 하나로 통일

- `NpcId` = 영문 소문자 한 벌(`jyaldi`, `eileen`, `spangdal` … 이름 55명 전원). 카드 명부 id·한글 이름·옛 짧은 id는 `ID_ALIAS` 표 하나에서 바꾼다.
- 일반 NPC(몹)는 정체 없음. 원형 이름(`office_f` 등) + 그 판 안에서만 쓰는 몸 번호뿐.

### 3-2. 명세 자료 모양

```ts
interface NpcSpec {
  id: NpcId;
  name: string;            // 이름표 (일반 NPC는 「직원」「시민」 등)
  group: NpcGroup;         // 기존 11종 그대로
  faction: 'A00'|'B00'|'C00'|'D00'|'E00'|'etc';
  rank?: string;           // 부장·선임·과장… (원작 직급, 대사·인사 순서용)
  minor?: true;
  talk: NpcDef;            // 기존 대화 정의 재사용
  stats: StatBlock;        // 4장
  temper: Temperament;     // 4-4장 성격 계수
  profile: BehaviorProfile;// 5장 행동 성향
  motions: MotionSet;      // 가진 클립 목록. 없는 클립은 대체 규칙(5-6)
  schedule?: ScheduleRef;  // 일과 표 이름 (이름 NPC만)
  combat?: CombatKit;      // 없으면 싸우지 않음(도망·신고만)
}
```

- **이름 NPC 55명**: 손으로 쓴 JSON 한 벌(`src/game/action/npc/specs/<id>.json`). 원작 Infobox에서 직급·소속·「전투력: 없음」을 옮겨 적고, 수치는 4장 공식으로 계산한 기본값을 쓴 뒤 사람이 고친다.
- **일반 NPC 71종**: 원형(Archetype) 표 하나 + 씨앗으로 찍어 낸다.

### 3-3. 일반 NPC = 상호작용 몹 (2판)

**원칙:** 누가 누군지 기억하지 않는다. 장면은 「이런 사람들이 이만큼 있어야 한다」만 알고, 모자라면 계속 채운다. 쓰러뜨려도 곧 다시 찬다(손맛).

**찍어 내기** (나올 때마다 새로, 저장 없음)

```
spec = archetype.base                       // 71종 원형
     + 몸 변형(같은 원형 안 색·머리 변형)
     + 성향 연속 수치 새로 뽑기(용기·친화·성급함·호기심·수다, 역할이 범위만 좁힘) → 도망·반격·떼 몰려오기 확률
     + 스탯 = 원형 값 ±10%
     + 이름표 = 원형 이름(「행정 직원」「불량배」)
```

**스포너(보충기)** — 장면마다:

| 칸 | 뜻 | 예 (1F 로비 낮) |
| --- | --- | --- |
| `gates` | 들어오는 곳: 문·골목 끝·엘리베이터·계단 | 현관, 엘리베이터 |
| `mix[시간대]` | 원형별 비율 | 행정 직원 50%, 방문객 30%, 경비 20% |
| `target` | 목표 인원 | 낮 5, 밤 2 |
| `refill` | 모자랄 때 보충 간격 | 3~6초에 1명 |
| `cap` | 한 화면 몹 상한 | 8 |

- 모자라면 `gates` 중 플레이어에서 먼 곳에서 **걸어 들어온다**(눈앞에서 갑자기 생기지 않음).
- 남으면 할 일을 마친 몹이 출구로 걸어 나간다(오가는 거리 느낌).
- 쓰러진 몹은 잠깐 누워 있다가 깜빡이며 사라지고, 떨어뜨린 것을 남긴다(돈·소모품, 원형별 표).

**소란도 (장면 단위 하나, 개인 기록 대신)**

| 소란도 | 올리는 것 | 몹 구성 변화 |
| --- | --- | --- |
| 0 평온 | — | 평소 `mix` |
| 1 웅성 | 몹을 때림, 물건 부숨 | 겁 많은 원형 도망·구경꾼 늘어남, 보충 느려짐 |
| 2 소동 | 몹 여럿 쓰러뜨림 | 싸우는 원형(경비·불량배·경찰) 섞여 들어옴 |
| 3 진압 | 계속 싸움 | 소속별 진압 원형이 떼로(관리국 안 = 관리국 전술 요원, 거리 = 경찰, 가짜 관리국 구역 = 가짜 관리국 사원) |

- 몹이 쓰러질 때마다 소란도 점수가 오르고, 싸움이 멎으면 초마다 식는다. 장면을 나가면 빨리 식는다.
- 갈수록 세지는 흐름 = 손맛. 상한(3)이 있어 끝없이 어려워지지는 않는다.
- 소란도는 **소속 평판**(`fieldstanding`)에만 흔적을 남긴다. 몹 개인 호감은 없다.

**상호작용 몹이 하는 것**

- 말 걸기(E): 원형별 미리 쓴 짧은 대답이 기본. 모델 대화는 원형에 `talk` 표시가 있을 때만(예: 상인·협회 직원), 그 판 동안만 기억.
- 반응 13종(응대·손짓·놀라기·도망·뒷걸음·주저앉기 …)을 사건에 따라 재생.
- 맞으면 성향대로: 도망 / 반격 / 동료 불러 떼로.
- 원거리는 경찰·관리국·가짜 관리국·프리랜서·협회·백일몽 원형만(확정).

### 3-4. 근무형 몹 (직무 표, 2판 추가)

몹(개인 기록 없음)이지만 **정해진 자리·시간·상황에만** 나온다. 스포너의 「아무나 채우기」와 별개로, 직무 표가 먼저 자리를 잡는다.

**직무(Post) 모양**

```ts
interface Post {
  archetype: string;            // 몹 원형 (청소부·안내 직원·경비 …)
  bases: BaseId[];              // 어느 본부에 두는가 (관리국·가짜 관리국·백일몽·협회 …)
  how: 'fixed' | 'patrol' | 'roam';
  spot?: string;                // fixed: 서 있는 자리 (예: 로비 데스크 뒤)
  route?: string[];             // patrol: 한 장면 안 순찰 지점 / roam: 본부 안 장면 순서
  shifts: [string, string][];   // 근무시간, 예 [['09:00','18:00']]
  count: number;                // 동시에 몇 명
  cond?: Cond;                  // 추가 조건: 소란도≥2, 비, 본편 사건 중, 요일 …
  relief?: number;              // 쓰러지면 대체 근무자가 오기까지 초 (기본 60)
}
```

**세 가지 방식**

| 방식 | 움직임 | 예 |
| --- | --- | --- |
| `fixed` 고정 | 자리에 서서 일함. 자리를 비우지 않음(앉기는 보류라 서서) | 안내데스크 직원, 매점 직원, 보급 창구 |
| `patrol` 순찰 | 한 장면 안 지점을 오감 | 로비 경비, 주차장 경비 |
| `roam` 순회 | 본부 안 여러 장면을 순서대로 돎(문·계단·엘리베이터 이용) | 청소부, 택배 기사 |

**근무 흐름**

```
근무 시작 시각 → 출입구로 걸어 들어와 자리·경로로 → 일함(직무 동작·대기)
근무 끝 시각   → 하던 동작 마치고 출입구로 퇴근
교대 직무      → 다음 근무자가 도착하면 그때 퇴근 (빈 데스크 없게)
근무 시간 밖   → 그 자리는 비어 있음 (스포너도 채우지 않음)
```

- **순회(roam) 위치 계산**: 저장하지 않는다. `(시각 − 근무 시작) ÷ 장면당 머무는 시간`으로 지금 어느 장면에 있는지 계산 → 플레이어가 그 장면에 들어가면 그 자리에 있다. 이름 NPC 일과(`whereAt`)와 같은 방식.
- **쓰러지면**: 몹이므로 보충한다. 근무 시간 중이면 `relief`초 뒤 같은 원형의 대체 근무자가 출입구로 들어온다.
- **소란도와 연결**: 소란도가 오르면 고정·순회 직원은 도망(자리 비움), 경비는 반격. 식으면 근무 시간 안이면 다시 돌아온다.
- **본부마다 재사용**: 같은 직무 표를 본부 목록만 바꿔 쓴다. 관리국과 가짜 관리국은 같은 그림, 배치로만 구분(확정)이므로 직무 표도 원형만 바꿔 끼운다(예: 관리국 경비 ↔ 가짜 관리국 사원 경비).

### 3-5. 장면 감독(Director): 누가 어디에 서는가

장면에 들어갈 때 한 번, 그리고 시계가 바뀔 때 다시 계산한다.

1. **본편 상태가 먼저** (`stateOverride` 그대로): 작전투입·외근·실종·사망 → 없음, 부상 → 의무실 침대, 격리 → B2 격리실, 휴게 → 휴게실.
2. **일과 표**: `whereAt(schedule, 시각)` → 장면 + 자리 + 할 일.
3. **동행 중이면** 일과 정지, 주인공 장면으로.
4. **근무형 몹(3-4)** 이 직무 표대로 자리를 잡는다.
5. **나머지 몹은 스포너(3-3)가 채운다.**
6. **상한**: 한 화면 이름 NPC 6 + 몹 8 = 14몸. 넘으면 몹 보충을 멈춘다(모바일 성능).

- **LOD**: 보이는 장면만 `Actor`를 만든다. 안 보이는 장면은 이름 NPC 「지금 어디에 있어야 하나」만 계산(문서 5-3장 그대로). 몹은 안 보이는 장면에 존재하지 않는다(들어가면 `target`만큼 바로 깔고 시작).

## 4. 스탯 시스템

### 4-1. 원칙

- 원작엔 숫자가 없으니 **원작의 글 평가 → 등급 → 숫자** 순서로 만든다. 사람이 고치는 건 등급과 모양(체형)뿐, 숫자는 공식이 낸다.
- **이름 NPC는 기본 스탯이 거의 자라지 않는다**(기본기획서 16장 그대로). 자람은 숙련 해금·출동 레벨로만.
- 같은 수치를 필드·출동 양쪽에서 쓴다. 기존 `AgentStats`는 이 스탯의 **계산 결과**가 된다(호환).

### 4-2. 전투 등급(위협 등급 사다리 재사용)

원작 괴이 등급 F~S를 사람에게도 쓴다. 근거와 기본 배정:

| 등급 | 뜻 | 원작 근거 예 | 예시 |
| --- | --- | --- | --- |
| — | 전투력 없음 | Infobox 「전투력: 없음」 | 데쥬레, 로제몬, 도필헌, 곽제강, 이연화, 이병진, 시민 |
| F | 몸싸움 정도 | 일반인·불량배 | 시민 남, 불량배 |
| E | 훈련된 일반인 | 프리랜서 5~4급, 경찰 | 경찰, 협회 직원, 가짜 관리국 사원 |
| D | 숙련 전투원 | 프리랜서 3급, 백일몽 조원 | 김성진, 박민성, 일반 관리국 전술 요원 |
| C | 정예 | 프리랜서 2~1급, 백일몽 A·B조 | 진나솔, 송주익, 노기균 |
| B | 이능 요원 | 「요원 한 명 = 다른 조직 한 분대」 | 에일린, 게슈간, 큐라스, 스팡달, 데드폴 |
| A | 간부급 | 부장·적합자 | 쟈알디, 고르고디오, 이도형, 곽성주 |
| S | 재난급 | 「상시 재난급 위협」「교전 금지」 | 세크리엠, 살라딘, 탐미주의 (보스 전용) |

- 콘쥬스: 힘은 A급이지만 「출동 안 함」 → 전투 등급 B, `canFight` 참, **절대 출동·동행 전투 안 함** 표시.
- 비전투 원작 인물도 `요원_기술안.md`의 지원·방해 기술은 그대로 쓸 수 있다(전투 등급 「—」 = 맞서 싸우지 않음, 기술만).

### 4-3. 전투 스탯 7칸 (기존 `AgentStats` 이름 유지)

등급별 **예산(점수)**을 정하고, **체형 모양**이 예산을 칸에 나눈다.

| 등급 | — | F | E | D | C | B | A | S |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 예산 | 2 | 4 | 6 | 8 | 10 | 12 | 14 | 18 |

칸마다 0~5점. 점수 → 실제 값:

| 칸 | 1점당 | 기본(0점) | 쓰는 곳 |
| --- | --- | --- | --- |
| `hp` 체력 | +40 | 60 | 최대 체력. 4점 = 220 (현 필드 시험값 크기) |
| `power` 근접 | +0.12배 | 0.8배 | 근접 피해 배율 |
| `aim` 사격 | +0.12배 | 0.8배 | 원거리 피해 배율, 조준 흔들림 감소 |
| `defense` 방어 | +0.08 | 0 | 받는 피해 감소 (상한 0.5, 기존과 같음) |
| `speed` 민첩 | +6% | 0.9배 | 걷기·뛰기·회피 속도 |
| `poise` 강인 | +1 (0~3에 맞춤: 0·1점=0, 2·3=1, 4=2, 5=3) | 0 | 경직 저항 (4-5) |
| `charge` 기세 | +0.1배 | 0.8배 | 필살 게이지 차는 속도 |

체형 모양 예(예산 비율):

| 모양 | hp | power | aim | def | speed | poise | charge |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 돌격(쟈알디·조성춘) | 3 | 3 | 0 | 2 | 2 | 3 | 1 |
| 중장(고르고디오·곽성주) | 4 | 3 | 1 | 3 | 0 | 3 | 0 |
| 사격(에일린·경찰) | 2 | 1 | 4 | 1 | 2 | 1 | 1 |
| 암살(스팡달·백사헌) | 1 | 3 | 1 | 0 | 4 | 1 | 2 |
| 이능 원거리(게슈간·큐라스) | 2 | 1 | 3 | 1 | 2 | 1 | 2 |
| 불사(데드폴) | 2 | 2 | 1 | 0 | 2 | 1 | 2 + 특수(부활) |
| 비전투(데쥬레·시민) | 1 | 0 | 0 | 0 | 1 | 0 | 0 |

→ 예산 합에 맞게 비율을 반올림. 사람은 등급·모양만 고르고, 튀는 캐릭터는 칸 하나를 ±1 손본다.

### 4-4. 성격 계수 (Temperament, 수치 아닌 성향)

기존 `Temper{open, grudge}` + `Nerve{edge, timid, canFight}`를 합친다. **이름 NPC 전용.** 몹은 원형 성향(3-3)만 쓴다.

| 칸 | 범위 | 뜻 | 예 |
| --- | --- | --- | --- |
| `open` | 0.5~1.5 | 호감 오르는 속도 | 쟈알디 0.6(천천히), 잼트리 1.3 |
| `grudge` | 0.5~1.5 | 화가 오래 감 | 게슈간 1.4 |
| `edge` | 0.5~1.5 | 도발 문턱 (작을수록 쉽게 화냄) | 조성춘 0.6, 에일린 1.2 |
| `timid` | 참/거짓 | 위협에 도망 | 데쥬레·박민성 참 |
| `social` | 0~1 | 수다·다가오기 빈도 | 큐라스 0.9, 게슈간 0.2 |
| `restless` | 0~1 | 돌아다니는 빈도 | 콘쥬스 0.8, 에일린 0.2 |
| `giftWeak` | 0.5~2 | 선물 효과 배율 | 데쥬레 2 |

### 4-5. 강인(poise)과 슈퍼아머 공식 (빈칸이던 것)

- 맞는 힘 `hit.strength`(1~3)에서 강인을 뺀 만큼 반응이 내려간다:
  - `차이 ≥ 2` → 반응 그대로, `1` → 한 단계 약하게(launch→stagger→flinch), `≤0` → none(피해만, 붉은 테 깜빡).
  - `armorBreak` 공격은 강인 무시.
- **경직치(그로기)**: 맞을 때마다 `stagger += 피해 × (1 − 0.2×poise)`. `최대체력×0.4` 넘으면 스턴(헤롱헤롱) 1.5초 뒤 0으로. 강공격 단독 스턴(확정)과 같은 연출.
- 슈퍼아머 4단(없음·경·중·절대)은 **강인과 별개로 동작 중에만** 덧붙는다(부록 E 그대로). 실제 효과 = `max(강인, 동작 아머)`.

### 4-6. 상태 자원 (싸울 때·평소 공통)

| 자원 | 범위 | 줄어듦/늘어남 | 효과 |
| --- | --- | --- | --- |
| 체력 HP | 0~hp | 피격 / 의무실·치료 | 0 = 「쓰러짐」(죽이기 설정 기본 꺼짐) |
| 필살 게이지 | 0~100 | 때림·맞음 × `charge` | 100에서 필살 |
| 경직치 | 0~한도 | 4-5 | 스턴 |
| **오염** | 0~100 | 괴이 노출·괴이 공격 / 여우상담실·손길의원·정신 관리팀 | 30·60·90마다 1단(최대 3단): 최대 체력 −20%(기존 디버프 그대로) + 대사에 증상(불면·환청·손 떨림, 원작 여우상담실 근거) |
| 피로 | 0~3 | 출동 +1 / 하루 휴식 −1 | 시작 체력 −6%씩(기존) |

- 오염은 본편과 잇는다: 본편 `[AG|..|격리|..]`(오염 별칭 포함)이면 오염 90 이상으로 간주해 격리실에 둔다. 거꾸로 게임이 오염을 본편 상태로 바꾸지는 않는다(본편이 주인).

### 4-7. 관계 스탯 (하나로 합침)

- **이름 NPC 전용.** 몹에는 개인 관계가 없다(소란도·소속 평판만).
- **속값은 `fieldrel.Rel` 하나**(호감 −100~100, 신뢰 0~100, 기분 6종, 경계 0~3).
- 화면·대화 규칙의 −3~+3은 **속값을 7칸으로 자른 표시**로 바꾼다: `칸 = round(호감 / 33)`. `decide()`의 조건(적대 ≤−2, 동행 ≥+1)은 그 칸으로 그대로 판정 → 기존 규칙·문구 유지.
- 대화 태그 → 계기(Cue) 연결: `[[호감 +1]]`→호감, `[[호감 -1]]`→불쾌, `[[진정]]`→진정, `[[선물]]`→선물. 게임 행동: 구함·폭력·방해·약속지킴(문서 6-2 그대로).
- 저장: 이름 NPC 관계는 저장 칸(슬롯)의 `hq.relations[방문자 이름][NpcId]`로 옮긴다(지금은 localStorage 따로라 칸 바꾸면 안 따라감).

## 5. AI 행동 구조

### 5-1. 네 층

| 층 | 하는 일 | 주기 | 모델 호출 |
| --- | --- | --- | --- |
| ① 감독 Director | 어느 장면·어느 자리에 누가 (3-5) | 장면 입장·시계 변화 | 없음 |
| ② 마음 Mind | 관계·기분·태도(stance)·도발 수치 갱신, 사건 받기 | 사건 때 + 1초마다 식힘 | 없음 |
| ③ 두뇌 Brain | 지금 할 활동 고르기 (5-3) | 0.5초마다(+사건 즉시) | 없음 |
| ④ 몸짓 Motor | 길찾기, 걷기/뛰기, 클립 재생, 머리 아이콘·말풍선 | 매 틱(30Hz) | 없음 |
| (대화) | 플레이어가 E로 말 걸 때만 | — | **있음(대사만)** |

### 5-2. 마음: 태도 상태 기계 (문서 12장 구현)

```
friendly ⇄ neutral ⇄ wary ⇄ hostile → fight → (flee | down)
```

- 입력 사건(`NpcEvent`): `seen_player`, `greeted`, `talk_cue(Cue)`, `hit_by(who)`, `ally_hit(who)`, `property_broken`, `shout`, `gift`, `anomaly_near`, `night`.
- **목격자 규칙**: 시야(앞 300px, 뒤 80px, 같은 장면) 안 NPC만 `witness` 사건을 받는다. 동료(같은 소속)가 맞으면 `provoke(2)`.
- 태도 → 반응(소속 평판 `fieldstanding.reaction` 결합): 무시·지켜봄·경고·쫓아냄·공격. 중립 구역에선 NPC끼리 싸우지 않음(확정).
- 비전투(`combat` 없음)는 hostile 이상이 되면 **fight 대신 flee** 또는 「신고」(근처 경비를 부름).

### 5-3. 두뇌: 활동 고르기 (점수식)

활동마다 점수를 매겨 가장 높은 것을 고른다. 행동 트리보다 짜기 쉽고, 성격 계수가 점수에 바로 곱해져 캐릭터 차이가 난다.

| 활동 | 점수 식 (요약) | 끝나는 때 |
| --- | --- | --- |
| `work` 일과 자리에서 일 | 일과 블록 있음 → 60 | 블록 끝, 방해받음 |
| `idle` 제자리 대기·고유 대기 | 20 | 3~8초 |
| `wander` 장면 안 서성임 | 15 × restless | 목적지 도착 |
| `emote` 감정 동작(기지개·한숨·팔짱·생각·머리 긁기) | 10 × (오래 대기한 초/30) | 클립 끝 |
| `chat` 옆 NPC와 수다(말풍선 아이콘만, 대사 없음) | 25 × social, 2m 안 친한 NPC | 4~10초 |
| `greet` 주인공에게 인사(목례/손 인사는 관계표) | 70, 2m 안 첫 만남·오늘 첫 | 클립 끝 |
| `face` 주인공 쪽 보기 | 40, 2m 안 | 멀어짐 |
| `follow` 따라가기 | 90, 동행 중 | 「기다려」「돌아가」 등 |
| `react` 놀람·도망·뒷걸음·주저앉기 | 사건 즉시 100 | 클립 끝 |
| `fight` 싸움(전투 두뇌로 넘김) | stance=fight → 100 | 이김·짐·진정 |
| `flee` 도망 | stance=flee → 100 | 화면 밖·문 |
| `talk` 대화 중 정지 | E 대화 열림 → 1000 | 창 닫힘 |

- **같은 활동 연속 감점**(−50%)으로 반복 줄이기. 밤에는 wander·chat ×0.5, idle 속도 느리게(확정 「밤엔 느리게」).
- 일정 흔들림: NPC마다 재생 속도 0.9~1.1배, 판단 주기 엇갈리게(확정).

### 5-4. 전투 두뇌 (fight 활동 안)

- 기존 `enemy/ai.ts`의 역할 7종(돌격·사격·방해·방패·소환·규칙·환경)을 그대로 쓰고, **표적 고르기**만 새로 둔다:
  `표적 점수 = 위협(최근 나를 때림 +50) + 거리 가까움 + 플레이어 편이면 +10 − 이미 2명이 노림이면 −40`.
- 공격권 `MAX_ATTACKERS = 2`는 표적별로 센다(동행자도 대상).
- 동행 두뇌(`ally`)는 같은 점수식에 「주인공 보호 +30」만 더한다. 20% 확률 공격 대신 공격권 순서로.
- 약3 + 강1 콤보 규칙(확정 2판)은 플레이어와 NPC가 같은 `CombatKit` 자료를 쓴다. NPC는 콤보 길이를 성격으로 고른다(성급 = 강 단독 많이).
- 체력 30% 이하 + timid → flee. 보스 규칙(기술 덱, 70%·35% 국면)은 보스 두뇌가 따로.

### 5-5. 몸짓: 길찾기와 동작

- 장면 사이: `routeScenes`(문 그래프 BFS). 장면 안: 걷는 띠(y420~669)에서 x 직진 + 깊이 y 보간, 막히면 옆걸음, 3번 실패하면 순간 이동(문서 그대로).
- 플레이어가 일 자리에 서 있으면 2초 기다렸다가 비켜 달라는 머리 아이콘(확정 「서둘러 돌아옴」과 함께).
- 머리 아이콘 7종(? ! … ♪ 땀 하트 분노)과 혼잣말 말풍선(미리 쓴 대사 표, 모델 호출 없음).

### 5-6. 클립이 없을 때 (지금 그림 현실)

요원은 지금 서 있는 그림 하나뿐. 그래서 동작 요청은 **대체 사다리**를 탄다:

```
원하는 클립 → 같은 계열 클립 → 대기 + 코드 효과 → 머리 아이콘만
예) 놀라기 없음 → 대기 그림을 위로 4px 튀기 + 「!」
    걷기 없음  → 대기 그림 좌우 미끄러짐 + 발밑 그림자 흔들림 (검수 전 표시)
```

- 그림이 들어오면 `MotionSet`에 클립 이름만 추가하면 된다. AI 코드는 그대로.

### 5-7. 모델과 만나는 곳 (대화)

- 대화 프롬프트에 **마음 상태를 한 줄로** 넣는다: `relLine()` + 태도 + 오염 단계 + 지금 활동(「커피 타던 중」). 대사가 상황과 맞게 된다.
- 응답 태그 → `decide()` → Mind 사건. 감정 태그(`[목례]` 등, 한 줄에 하나) → Motor 클립. 모델은 위치·전투를 직접 못 바꾼다.

## 8. 구현 순서 (그림 없이 먼저 되는 것부터)

1. **id 통일 + 스탯 계산기 + 시험** — 그림 불필요. 55명 명세 JSON 초안을 원작 Infobox에서 자동 생성 → 사용자 검토.
2. **관계 하나로 합치기 + 저장 칸 이사** — 그림 불필요. 기존 화면 동작 그대로여야 함.
3. **Actor + Director로 본부 요원 세우기** — 지금 서 있는 그림으로. 정지·주인공 보기·인사 아이콘까지.
4. **두뇌 점수식 + 대체 사다리로 서성이기** — 걷기 그림 없으면 미끄러짐(검수 전 표시).
5. **근무형 몹 + 몹 스포너 + 소란도** — 출근·퇴근·교대, 순회, 걸어 들어오기·나가기, 반응 13종 대체 사다리, 쓰러짐·보충.
6. **마음·목격·도망** — 이름 NPC 반응.
7. **전투 두뇌 통합(Enemy 흡수), 몹 반격·진압 원형, 동행 전투** — 전투 확대 보류 해제 뒤.

각 단계는 단독 HTML 시연판 + 「검수 전」 표시로 전달.

## 9. 그림 비용과의 관계

- 이 구조는 **그림 없이 돈다.** 그림은 `MotionSet`을 채울수록 좋아질 뿐이다.
- 그림 우선순위 제안(생성은 사용자가 시킬 때만): 걷기 > 인사·목례 > 놀라기 > 감정 5종 > 반응 13종 > 전투.

## 10. 결정 필요 (사용자)

1. **적(Enemy)을 Actor로 흡수할지**: 추천 「예, 단 7단계에서」. 그 전엔 적 코드는 건드리지 않음.
2. **전투 등급 F~S를 사람에게 쓰는 것**: 원작 괴이 등급 사다리 재사용. 다른 안은 프리랜서 5급~특급.
3. **등급 배정표(4-2)** 이름 NPC 55명 배정 — 1단계에서 표로 뽑아 확인받음.
4. **오염 자원 도입 여부**와 본편 연결 방향(본편 → 게임 한 방향 추천).
5. **호감 −3~+3 표시 유지**하고 속값만 −100~100으로 합치는 것.
6. **한 화면 상한**: 이름 NPC 6 + 몹 8 = 14몸.
7. **몹 보충 속도·소란도 단계 수치**(3~6초에 1명, 3단계) — 시연판에서 손맛 보고 조정.
8. **쓰러진 몹을 「죽음」으로 그릴지 「기절 후 퇴장」으로 그릴지** — 죽이기 설정(기본 꺼짐)과 연결.
9. **근무표 초안(3-4)의 직무·시간·인원**, 다른 본부(가짜 관리국·백일몽·협회) 직무 목록.
10. 키 배치 충돌(기본기획서 부록 A vs 기술안 Z/C/S) — 이 문서 범위 밖이지만 NPC 콤보 자료(`CombatKit`) 이름에 걸림.

## 11. NPC 대사 제작 계획 (2026-10-26 사용자 지시: 「대사는 짜는 걸로 계획」)

모델 호출 없이 쓰는 미리 쓴 대사. 제작은 Claude, 사용자는 표로 검토.

**범위**

| 대상 | 지금 | 만들 것 |
| --- | --- | --- |
| 몹 71종 | 없음 | 원형별 상황 태그 대사 |
| 이름 NPC 55명 | 말투 설명 + 2~4줄(`npc/roster.ts`), 플레이어블 8명만 상황 대사(`story/lines/agents.ts`) | 생태계 상황 태그로 확장 |

**생태계 상황 태그 (초안)**

- 평소: `idle`(혼잣말), `work`(근무 중 한마디, 직무별), `chat`(수다 말풍선, 짝 대사), `pass`(지나치며)
- 플레이어: `notice`(알아봄), `greet`, `bye`, `blocked`(길 막힘·자리 비켜 달라)
- 욕구: `tired`, `coffee`, `hungry`, `bored`
- 반응: `hit`, `scared`, `flee`, `angry`, `fight`, `win`, `down`, `witness`(남이 맞는 걸 봄)
- 소란: `crowd`(구경), `call`(경비·경찰 부름), `arrive`(진압 도착)
- 시간·장소: `night`, `rain`, `shift_start`, `shift_end`

**형식**: 태그마다 여러 줄, 무작위 하나. 줄마다 조건을 달 수 있다(성향 범위·기분·시간대·소속·관계). 같은 줄 연속 금지.

**근거**: 이름 NPC는 위키·로어북 시트·`roster.ts` 말투 설명. 몹은 `docs/동작표/NPC/`의 종류·설명과 장소 설정. 근거 없이 지어낸 줄은 표에 표시.

**순서**: 태그 목록 확정 → 첫 시연 범위(관리국 본부·정면 거리·종로 큰길)에 나오는 인물·원형부터 → 나머지.


## 12. 개발 도구 (2026-10-26 사용자: 개발하는 것으로 확정)

플레이어에게 숨긴 개발자 전용. 생태계 결과는 계산의 산물이라, 이것 없이는 「왜 저 NPC가 저기 있나」를 고칠 수 없다.

1. **세계 관찰 창** (단축키로 겹쳐 띄움): 장면별 인물 목록, 머리 위 지금 할 일, NPC를 누르면 욕구 수치와 할 일 점수표(왜 골랐나), 화면 밖 장면 인원·이름 NPC 위치, 직무 근무 상태, 소란도. 원하면 사용자도 열 수 있게.
2. **빨리 감기**: 게임 하루를 몇 초에 돌려 출근·점심·퇴근·밤 흐름 확인.
3. **씨앗 재현**: 무작위(몹 성향·할 일 고르기)를 씨앗 하나로 묶어 같은 번호면 같은 하루. 사용자가 본 이상한 장면을 번호로 재현.
4. **모바일 성능 측정**: 가상 브라우저에서 CPU를 늦춰 몸 14개 + 그림의 프레임 측정.
5. **자동 시험**: 고칠 때마다 하루를 빨리 돌려 확인 — 직무가 근무시간에 자리에 있음, 끼어 멈춘 몸 없음, 콘쥬스 목욕탕 일과 없음, 오류 없음.

## 13. 필드 → 본편 기록 (2026-10-26 사용자 확정)

- 기존 방식(막간이 기준 메시지 자리에 계속 남고, 확정 사실은 매 요청 들어감)은 유지할 수 있다. 단 **극도로 압축**한다.
- **대사 전문·서술형 문장 금지. 영어로만.** 지금 `interludeText`(대사 전부 + 한국어 서술)는 이 기준에 맞지 않아 새로 짠다.
- 형식 초안(확인 대기):

```
[FLD 10:42-11:30]
@HQ/2F-office Jaemtri: talk "overtime complaint" fav+1 promise=coffee
@HQ moved office>lounge>B1-gym
@HQ/B1-gym Gorgodio: spar, he down, fav-2
@Jongno-main brawl lv3, police came
[FACTS] loc=Jongno-main; follow=Eileen
```

- 대화 요지(`"overtime complaint"`)는 NPC 대화 응답을 받을 때 같은 호출에서 영어 요지 한 칸을 함께 받는다(추가 호출 없음). 6단어 이하.
- 몹과의 일상은 넘기지 않는다. 같은 종류 사건은 묶는다(「모브 5명 처치」 → `brawl lv3` 한 줄).
