## 최신 사용자 제약

현재 목적은 채팅 봇의 보조 체험 공간이다. 유저가 본인의 페르소나로 본부 요원을 만나 대화하고, 그 기록이 본편 컨텍스트에 이어져야 한다. 전투·로그라이크 확대 작업은 보류한다.

- 남성: 검정 바지정장·흰 셔츠·검정 구두·검정 짧은 머리.
- 여성: 검정 치마정장·흰 셔츠·검정 구두·검정 단발.
- 전신 대기 자세, 손은 주머니 밖, 투명 배경. 기존 요원 도트 재활용 금지.
- 원본은 둘 다 128×256px. 실제 인물은 남 241px·여 229px. **1배로 표시하며 세로 256px를 넘기도록 확대하지 않는다.**

## Claude가 이어갈 작업

1. 원본과 1배 비교 화면을 직접 검수한다. 선택 UI에서 두 페르소나를 보여주고 선택을 지속 저장한다. 기존 구현이 채팅별이므로 선택도 채팅별 레코드에 보존하는 방향을 권장한다. 대화 추가 시 선택이 지워지거나, 선택 저장 시 기존 대화가 지워지지 않도록 한다.
2. 본부 방문 모드에 선택된 원본을 적용한다. 알파 경계의 바닥을 발 위치에 맞추고 원본 픽셀 1:1로 표시한다. 불러오는 동안 기존 요원 그림을 사용자 페르소나로 대신 노출하지 않도록 한다. 승인되지 않은 다른 방향·동작 프레임을 새로 만들거나 기존 요원에서 가져오지 않는다.
3. 실제 Risu 소스를 구동하고 플러그인 시험판을 설치하여 화면과 입력을 검증한다. 사용자가 기존 Risu 탭이나 접속 주소를 제공해야만 시작할 수 있다고 가정하지 않는다. Risu는 공개 소스이며 로컬 실행이 가능하다. 실제 모델 자격 증명 필요 여부는 실행 환경 확인 후 구분한다.
4. 실제 모델 대화 성공 후 원래 채팅의 `goeiHqVisitV1`과 `localLore`의 「본부 방문 대화 기록」을 확인한다. 본부를 닫고 본편 프롬프트 구성에서 해당 기록이 포함되는지도 검증한다. 채팅 변경·재입장·새로고침 후 선택과 대화의 격리·지속성을 확인한다.
5. 반영된 실행 화면의 스크린샷과 플레이 가능한 시험판을 제공한다. 정적 합성 이미지나 모의 모델 테스트를 실제 Risu 종단 검증으로 표현하지 않는다.

## Risu 조사 중 확인한 문제

Risu 공식 저장소 `kwaroran/Risuai`, 확인 커밋 `02a83695d81eb4e083453c4524b8c7d463df95aa`에서 플러그인 iframe sandbox는 `allow-scripts allow-modals allow-downloads`이며 `allow-forms`가 없다. [sandbox 생성 코드](https://github.com/kwaroran/Risuai/blob/02a83695d81eb4e083453c4524b8c7d463df95aa/src/ts/plugins/apiV3/factory.ts#L786-L788).

기반 브랜치의 `src/game/visit.ts`는 form submit에 대화 전송을 연결한다. 실제 sandbox에서는 submit이 막히므로 **버튼 type=button의 click 핸들러와 입력의 Enter 핸들러**로 전송 경로를 수정하고 검증해야 한다. 한글 입력 중 Enter는 `isComposing`으로 제외한다. 저장소의 `tests/browser.mjs`에도 sandbox의 form 제한을 다루는 코드가 있다. 이 수정은 이번 자산 인계 커밋에 포함하지 않았다.

`src/ts/plugins/apiV3/v3.svelte.ts`의 getChatFromIndex/setChatToIndex, getCurrentLorebookEntries, runLLMModel 및 `src/ts/process/lorebook.svelte.ts`의 chat.localLore/alwaysActive 처리 경로는 소스로 확인했다. 실제 모델 요청과 최종 본편 컨텍스트 반영을 실행으로 검증한 상태는 아니다.
