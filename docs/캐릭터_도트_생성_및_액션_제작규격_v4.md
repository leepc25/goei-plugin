# 캐릭터 도트 생성 및 액션 제작규격 v4

작성: 2026-10-20. 상태: **재제작 설계안 / 시각 검증 전**.

## 1. 목적과 적용 순서

본 문서는 쟈알디를 시험 캐릭터로 삼는 캐릭터 제작 절차와 품질 기준이다. 12명에게 공통 적용할 기술 규격과 쟈알디 고유 외형·공격을 구분한다. 기존 결과를 합격 샘플로 간주하지 않는다. 사용자가 지적한 문워크, 작은 팔다리 움직임, 균일한 속도, 춤처럼 보이는 공격, 점프 체격 변화, 부족한 행동 종류를 해결하는 것이 목적이다.

동작과 시각 품질에 관한 신규 제작 지침은 본 문서가 v3보다 우선한다. v3의 601장·필수 326장과 공격별 10·12·16장은 과거 예산이며 신규 제작의 최소 장수나 완료 조건으로 사용하지 않는다. v3 JSON과 현재 실행 파일은 현행 구현 기록으로 보존한다. 본 문서 작성만으로 게임에 변경이 적용된 것은 아니다.

핵심 순서: **설정 확인 → 참고 동작 분석 → 체형 기준화 → 핵심 자세 → 타이밍·접지 시험 → 명암 정리 → 인게임 타격 시험 → 필요한 중간 그림 추가 → 패킹**. 전체 동작을 한 번에 생성하지 않는다.

## 2. 자료를 확보하고 분석하는 방법

### 자료별 역할

| 자료 | 얻을 것 | 가져오지 않을 것 |
| --- | --- | --- |
| 저장소 괴이봇 설정 | 성별·성격·복식·능력·조직 역할·인물 관계 | 게임 편의를 위한 창작을 원작 확정 설정으로 서술 |
| 사용자가 준 Jyaldi_default.png | 검은 긴 머리, 붉은 눈, 정장·셔츠·넥타이·장갑, 얼굴 인상과 태도 | 상반신 원화에서 보이지 않는 다리 길이 추정, 원화 비율의 무조건 복제 |
| 던전앤파이터의 관찰 가능한 플레이 자료 | 준비/접촉/회수, 약약강 리듬, 피격 반응, 이동·정지 연결 | 실제 확인하지 않은 원본 프레임 수 단정, 스프라이트 복제 |
| 던전앤드래곤 섀도 오버 미스타라 등 고전 벨트스크롤 자료 | 적은 자세로 실루엣·접지·집단 전투를 읽히게 하는 방법 | 저해상도나 적은 장수 자체를 품질 공식으로 취급 |
| 현재 시연판 | 실패 재현, 크기·시간·접점 측정 | 이미 생성했다는 이유로 그림 유지 |

참고작 이름을 적은 것과 분석 완료를 구분한다. 현재 이 문서에 외부 영상의 실측 결과는 없다. 제작 착수 시 동작별로 접근 가능한 출처 URL/파일, 작품·캐릭터·동작, 영상 시각 구간, 재생 속도, 관찰 내용을 기록한다. 녹화 60fps는 그림 60장을 뜻하지 않는다. 보간·중복·히트스톱·영상 드롭 여부를 구분하고 불명확하면 미상으로 남긴다. 자료에 접근할 수 없으면 실측했다고 주장하지 않고 자체 타이밍 가설로 시험한다.

각 대표 동작은 다음을 분석한다.

1. 시작 자세와 종료 자세, 지지발, 중심 이동, 팔·다리의 반대 움직임.
2. 준비·가속·접촉·후속·회수의 순서와 관찰 가능한 시간 비중.
3. 헛침과 명중의 시간 차이, 적의 반응, 소리·섬광의 동시성.
4. 1배속에서 읽히는 핵심 자세와 생략 가능한 중간 자세.
5. 우리 캐릭터의 체격·복식·능력에 맞게 바꿀 부분.

### 제작 전 근거 카드

동작 ID / 참고 출처와 구간 / 관찰 사실 / 자체 설계 가설 / 핵심 자세 스케치 / 예상 시간표 / 이동·공격 이벤트 / 검증 결과를 한 카드에 기록한다. 제작 시작 시 근거 카드가 없는 동작은 대량 생성하지 않는다.

## 3. 고정할 외형과 픽셀 규격

| 항목 | 기준 | 수정 방법 |
| --- | --- | --- |
| 원본 정자세 키 | 머리 꼭대기부터 신발 바닥까지 128px | 기준 포즈 검수 후 버전 단위로 변경 |
| 게임 표시 | 정수 2배, 정자세 256px | 프레임별·깊이별 확대 금지 |
| 체형 | 약 6등신의 성인 여성, 일반 체형과 충분한 매스 | SD·극단적인 장신으로 왕복하지 않음 |
| 머리 | 높이 21~22px, 얼굴 표현을 위해 소폭 과장 | 머리카락 외곽과 두개골을 구분 |
| 어깨 | 정면 가이드 32~35px | 넓은 어깨로 상체 볼륨을 대신하지 않음 |
| 흉곽 / 허리 / 골반 | 정면 가이드 27~31 / 23~27 / 26~29px | 포즈·원근에 따른 투영 폭은 별도 |
| 위팔 / 전완 | 두께 7~9 / 6~8px | 소매와 실제 관절을 함께 설계 |
| 허벅지 / 종아리 | 두께 9~11 / 7~9px | 하체에만 매스를 몰지 않음 |
| 손 / 신발 | 약 9×10 / 12×6px에서 시작 | 주먹·손바닥·총 쥐기 구별, 손목 연결 유지 |
| 일반 작업 셀 | 128×160px, 바닥 기준 (64,144) | 셀 크기로 몸을 정규화하지 않음 |
| 뻗는 동작 / 큰 동작 | 192×160 / 256×192px부터 | 잘림을 피하도록 여백만 확장 |
| 컷인 | 상반신 192×128px부터, 본체와 별도 | 눈·손·머리카락의 실제 변화 필요 |

정자세 가이드: 정수리 0, 턱 22, 어깨 28, 허리 48, 골반 63, 사타구니 69, 무릎 100, 발목 122, 발바닥 128. 숨겨진 관절의 실측값이나 모든 포즈에 강제할 화면 좌표가 아니다.

정면·측면·게임용 3/4 시점의 기준표를 먼저 만든다. 머리·흉곽·골반·위팔·전완·허벅지·종아리의 기준 길이를 기록하고 포즈마다 대조한다. 점프 중 무릎을 접어 그림 높이가 줄어드는 것은 자연스럽다. 이를 128px로 다시 키우거나 각 포즈의 바운딩박스를 동일 크기로 맞추면 체격이 변하므로 금지한다. 서로 다른 생성 시트도 동일한 인물 기준으로 맞추며, 시트마다 임의 확대하여 맞추지 않는다.

쟈알디의 인상은 침착하고 절제된 위압감에서 잡는다. 성인 여성의 얼굴·목·어깨 연결을 유지한다. 허리나 다리를 과도하게 가늘게 만드는 것으로 여성성을 표현하지 않는다. 붉은 눈은 보조 식별점이며 모바일에서 매번 보일 것을 전제로 하지 않는다.

## 4. 도트의 형태·명암·색 규격

- 먼저 검은 실루엣만으로 대기·걷기·달리기·공격·피격이 구별되어야 한다. 공격 팔과 몸통, 양다리 사이의 빈 공간을 설계한다.
- 광원은 장면 기본 좌상단으로 통일한다. 얼굴·흉곽·팔·골반·다리의 큰 면을 우선하고 주름은 관절과 당기는 방향에 배치한다.
- 검은 머리·재킷·장갑·바지가 한 덩어리로 붙지 않게 밝기 단계와 겹침 경계를 구분한다. 모든 외곽에 흰 테두리를 두르는 방식은 피한다.
- 재킷은 넓고 절제된 면, 머리카락은 큰 머리 다발, 장갑·구두는 제한된 날카로운 반사, 셔츠는 밝은 면으로 재질을 구분한다.
- 색 수는 투명 포함 48~64색을 출발 예산으로 잡고 필요하면 96색까지 검토한다. 숫자를 채우지 않는다. 피부·정장·머리 각각 약 3~5단계의 주요 명암으로 시작하고 팔레트의 공용 중간색을 활용한다.
- 자동 축소·감색 결과는 초안이다. 고립된 점, 얼룩, 프레임마다 튀는 색, 불필요한 계단을 최종 크기에서 정리한다. 물리적으로 접한 작은 눈·장식과 형태를 설명하지 않는 잡음을 구분한다.
- 부드러운 반투명 가장자리와 블러 대신 명확한 픽셀 덩어리를 사용한다. 본체 가장자리는 원칙적으로 불투명/투명으로 정리하고, 능력 효과의 반투명은 별도 레이어로 제한한다.
- 손·얼굴·공격 말단에 시선을 모으고 바지 주름 등에 같은 밀도의 디테일을 넣지 않는다. 흰 셔츠 면적과 넥타이의 방향도 몸통 회전을 설명해야 한다.

원본 1배·정수 2배·실제 패널 크기, 흑백·실루엣, 밝고 어두운 배경에서 검수한다. 큰 확대 이미지에서만 예쁜 상태는 합격시키지 않는다. 배경과 캐릭터는 같은 2배 픽셀 밀도를 사용하고 발바닥 접촉 그림자로 바닥과 연결한다. 그림자는 점프 높이에 따라 달라져야 하며 발에 붙여 공중으로 같이 띄우지 않는다.

## 5. 프레임·틱·장수의 구분

그림 수는 서로 다른 자세의 수, 유지 시간은 한 자세가 화면에 남는 시간이다. 한 그림을 5틱 유지해도 한 장이다. 엔진 갱신률·화면 주사율·애니메이션 그림 교체율을 분리한다. 아래 1틱은 **설계상 1/60초(약 16.67ms)**이며 엔진을 고정 60fps라고 가정하는 표현이 아니다.

다음 표는 핵심 자세 초안을 만들기 위한 **고유 그림 수 범위**다. 최소 합격 장수나 고정 발주량이 아니다. 자세가 불명확하면 장수를 줄여 해결했다고 하지 않고, 중요한 변화가 빠졌으면 추가한다. 완료율은 행동별 품질 통과 여부로 계산하며 총 장수로 계산하지 않는다. 유지·체공·상태 지속 시간은 별도다.

| knockdown / down_hold | 넘어짐 / 다운 유지 | 4~6 / 1~2 | 250~450ms / 유지 | 회전·바닥 충돌·몸 접점 |
| getup / getup_quick | 기상 / 빠른 탈출 | 4~6 / 3~5 | 350~600 / 220~350ms | 손→무릎→발로 지지 |

| item_use | 아이템 | 3~4 | 200~400ms | 사용 이벤트·손동작 |

왼오왼은 배우의 해부학적 왼쪽·오른쪽을 기준으로 기록한다. 화면상의 왼쪽 이동과 혼동하지 않는다. 3/4 시점에서 손이 숨으면 팔꿈치·어깨·몸통으로도 교대를 읽히게 한다. 장타→팔꿈치→파괴 장타라는 기존 기술안은 원작 고정 설정이 아니다. 새 핵심 자세에서 왼오왼·약약강을 먼저 검증한 뒤 확정한다.

본부·탐색도 제외하지 않는다. 문/패널 조작 3~4, 줍기 4~5, 조사 2~3, 대화 2~4, 장갑 정리 4~5, 귀환 이완 3~4, 운반 보행 6~8, 의자 앉기/일어서기 각 4~6, 앉은 대기 2~3, 서류 업무 3~5, 음료 4~5, 투입 5~7, 철수 4~6, 후송 상호작용 5~7장을 초기 범위로 둔다. 잡기 진입 3~4·유지 1~2·투척 5~7은 해당 캐릭터에게 기능을 지급할 때만 제작한다. 각 역할에 필요한 NPC도 전용 행동을 선정한다.

## 6. 약약강 타이밍의 첫 실험안

아래 수치는 참고작의 실측값이 아니라 **우리 게임의 검증용 가설**이다. 개별 자세 유지 시간을 정한 뒤 시험한다. 우선 그림 수는 5 / 5 / 7장이다.

| 타격 | 자세별 유지 틱 | 합계 | 접촉 이벤트 | 별도 명중 정지 |
| --- | --- | --- | --- | --- |
| 약 1타 | 준비 4 → 뻗기 1 → 접촉 2 → 후속 3 → 회수 6 | 16틱 ≈267ms | 시작 후 5틱 | 2~3틱 ≈33~50ms |
| 약 2타 | 준비 4 → 뻗기 1 → 접촉 2 → 후속 4 → 회수 7 | 18틱 =300ms | 시작 후 5틱 | 2~3틱 ≈33~50ms |
| 강 3타 | 준비 5 → 모으기 3 → 뻗기 1 → 접촉 3 → 후속 4 → 반동 5 → 회수 7 | 28틱 ≈467ms | 시작 후 9틱 | 4~5틱 ≈67~83ms |

히트스톱은 기본 재생 시간과 별도다. 명중하면 공격자와 대상의 로컬 동작 시계를 멈추고 접촉 자세를 유지한다. 헛치면 멈추지 않는다. 여러 적에게 같은 일격이 맞아도 정지 시간을 계속 합산하지 않는다. UI·입력 수신·짧은 섬광까지 모두 정지시키지 않는다. 배경과 다른 적까지 멈추는 범위는 성능과 가독성을 시험해 결정한다.

접촉 프레임 시작에 피해 판정을 평가하고, 실제 명중이 확인된 그 지점에서 자세를 고정한다. 큰 delta로 이벤트를 넘어가도 피해를 누락하지 않게 구간 횡단으로 처리하며, 같은 공격 ID·대상에는 한 번만 적용한다. 이벤트를 처리한 뒤 이미 회수 자세까지 진행해서 정지하는 구현을 피한다. 30fps에서는 1틱짜리 자세가 화면에 나타나지 않을 수 있으므로 핵심은 2틱 이상의 접촉 자세에 두고, 시각적으로 반드시 필요한 순간은 실제 저프레임 시험에서 유지 정책을 조정한다. 모든 중간 그림을 강제로 한 번씩 보여주느라 전체 동작이 늘어지지 않게 한다.

강타는 접촉 전 가속, 접촉 순간 정지, 정지 해제 후 밀림과 반동으로 대비를 만든다. 궤적·섬광·효과음은 같은 이벤트에 맞춘다. 이펙트는 몸의 동작을 가리지 않을 크기로 제작한다. 카메라 흔들림은 약타 0~1 / 강타 2~3 원본 픽셀 범위부터 시험하고 필수 효과로 간주하지 않는다. 정수 픽셀로 이동하고 움직임 감소 옵션을 고려한다.

입력 버퍼는 약 100~140ms부터 시험한다. 연계 입력 창, 다음 타 시작, 회피·가드 취소 가능 시점을 별도로 기록한다. 연계를 받으면 허용된 회수 구간에서 다음 준비 자세로 연결하고, 입력이 없으면 해당 타의 복귀를 재생한다. 모든 회수를 끝까지 강제하거나 모든 공격을 즉시 취소하는 양극단을 피한다. 기존 Z 유지 연계는 접근성 선택지로 시험하되 연속 입력과 같은 상태 규칙을 사용한다.

## 7. 접지와 이동의 구현 기준

걷기와 달리기는 시간만 흘려 루프를 돌리지 않는다. 실제 바닥 이동 거리에서 주기를 계산하되, 각 자세별 지지발 위치와 구간별 이동량을 함께 설계한다. 거리 위상만 추가한다고 발 미끄러짐이 자동으로 사라지지 않는다.

첫 시험 보폭은 원본 기준 걷기 좌우 한 주기 96~112px, 달리기 144~176px 범위로 잡는다. 기존 이동 속도는 답으로 고정하지 않는다. 자세에서 가능한 보폭과 게임의 회피·접근 시간을 함께 맞춘다. 예를 들어 표시 2배, 걷기 주기 104px, 실제 속도 200 화면px/s라면 한 주기는 1.04초다. 그 값이 느리면 그림만 빠르게 넘기지 말고 보폭·이동 속도를 함께 수정한다.

각 지지 구간에서 바닥에 닿은 발의 월드 위치를 추적한다. 의도한 발 구르기를 제외한 누적 미끄러짐은 원본 1~2px 이내를 1차 목표로 두고 초과하면 자세 또는 이동 곡선을 재설계한다. 출발·멈춤·벽에 막힘·대각선 이동에서도 확인한다. 걷기는 최소 한 발 지지, 달리기는 추진과 짧은 체공을 명확히 한다. 몸통의 작은 상하 변화는 지지와 압축의 결과여야 한다.

점프는 바닥 위치 (x,y), 공중 높이 z, 몸의 로컬 자세를 분리한다. 그리기 기준은 바닥 앵커에서 z를 뺀 위치이며, 접은 발끝을 임의로 바닥 앵커에 붙이지 않는다. 그림자와 착지점은 바닥에 남는다. 상승·정점·낙하·공중 공격·착지로 상태가 연결되고, 공중 근접과 공중 사격은 서로 다른 자세다. 애니메이션에 맞춘다고 공중에서 시간을 무한 정지시키지 않는다.

## 8. 판정·상태·입력 연결

한 동작의 납품 단위는 그림과 시간표, 이동 곡선, 공격·피격 판정, 전환 규칙, 소리·이펙트 이벤트다. 이미지 파일만으로 완료 처리하지 않는다.

- 타격별 공격 영역과 유효 구간을 분리하고 손끝·발끝·능력 범위에 맞춘다. 모든 행동에 동일 직사각형을 붙이지 않는다.
- 슈퍼아머는 일반 경직을 버티는 상태이며 무적과 구분한다. 가드·가드 붕괴·스턴·공중 피격·다운·후송의 진입 조건과 우선순위를 정의한다. 해당 상태별 자세를 제공한다.
- 약타는 짧은 경직과 작은 밀림, 강타는 큰 경직·밀림 또는 다운으로 구분한다. 숫자와 반응은 적의 체격·아머에 따라 달라진다. 화면 효과만 같게 붙이지 않는다.
- 앉기·앉아 이동·하단 공격은 실제 상태와 낮은 피격 범위를 가진다. 벨트스크롤의 아래 방향은 깊이 이동이므로 아래키 단독을 앉기로 바꾸지 않는다.
- 현재 방향키/Z/X/C/A/S/Shift/QWE 체계를 출발점으로 둔다. A+아래 앉기, 앉은 상태 좌우 이동·Z 하단차기, 달리기 중 Z 대시공격, 공중 Z 근접/사격 선택 규칙을 작은 시험에서 검증한다. A+아래는 가드와 충돌하므로 상태 우선순위·진입/유지/해제·위아래 이동 복귀를 확정하기 전 최종 키 규격으로 부르지 않는다.
- 키보드·마우스·터치·자동 진행 모두 같은 행동 요청과 상태 머신을 사용한다. 자동 진행만 공격 그림을 건너뛰거나 다른 속도로 때리지 않는다.
- 캐릭터별 근거리·원거리 방식은 설정에 맞춰 구별한다. 12명 전부에게 같은 주먹·권총 모션을 복사하지 않는다. NPC와 임시 지원 캐릭터는 실제 역할에 필요한 범위만 제작한다.

## 9. 생성 작업의 세부 절차

1. **설정표와 근거 카드:** 출처, 확정 설정, 게임용 창작안을 구분한다. 사용자 원화와 승인된 체형 기준을 함께 지정한다.
2. **기준 포즈:** 전투 대기·편한 대기·측면/3/4 기준을 소수 제작한다. 머리·손·상하체 매스와 명암을 확인하고 기준 이미지 버전을 고정한다.
3. **동작 설계:** 발 지지·중심·관절·힘의 방향을 표시한 핵심 자세부터 만든다. 세부 주름과 머리카락 장식은 후순위다.
4. **소량 생성:** 1개 동작 또는 같은 체격의 소수 핵심 자세씩 생성한다. 시트 전체에 균등한 변화·균등한 포즈 간격을 요구하지 않는다. 기존 불량 그림을 반드시 유지하도록 지시하지 않는다.
5. **시트 검수:** 손·발 개수, 좌우, 총과 손의 접점, 체격 변화, 빈 칸·겹침·셀 순서를 확인한다. 모든 칸을 정확한 동작 ID와 자세 ID로 대응시킨다.
6. **최종 크기 정리:** 전체에 일관된 변환만 적용하고 도트 덩어리·명암·외곽을 정리한다. 부위 늘이기, 프레임별 높이 맞추기, 감색만으로 완성 처리하지 않는다.
7. **회색 배경 시험:** 바닥 격자·지지발 표시·판정·시간표를 켜고 이동과 핵심 공격을 재생한다. 1배속과 느린 재생을 모두 확인한다.
8. **전투 시험:** 한 적을 대상으로 헛침·명중·가드·아머·다운을 시험한다. 적의 반응과 본체 접촉 자세를 동시에 검수한다.
9. **수정:** 불필요한 중간 그림을 빼거나 핵심 자세를 다시 생성한다. 이유 없이 장수를 늘리지 않는다. 외형 기준을 바꿨으면 관련 동작 전체를 재검수한다.
10. **배포:** 비교 가능한 실제 적용 HTML, 변경 요약, 알려진 미완성 행동, 실제 용량을 함께 전달한다. 이전 HTML을 새 결과로 제시하지 않는다.

생성 지시서에는 캐릭터 기준 이미지 버전, 시점·광원·원본 키·체형, 동작 ID와 자세별 지지발·팔 방향·시선, 동일 신체 크기, 명확한 실루엣, 투명 여백, 금지 변형을 적는다. “자연스럽게 12프레임” 같은 지시만으로 제작하지 않는다. 생성 도구가 낮은 해상도의 도트 규칙을 지켰는지는 별도로 확인한다.

## 11. 용량과 공용화

현행 비교 기준: 캐릭터 PNG 372,298바이트(약 363.6KiB), 1024×1879 RGBA 전개 약 7.34MiB. 배경·적 포함 normal 팩 575,155바이트, 단일 플레이 HTML 809,080바이트. 이는 측정 시점의 기존 구현이며 신규 목표 달성 기록이 아니다. 163개 패킹 프레임은 행동 163종이나 품질 163점을 의미하지 않는다.

초기 런타임 예산은 캐릭터당 압축 이미지 400KiB 안팎, 전개 텍스처 8MiB 안팎을 유지하는 방향으로 잡되 필요한 행동을 삭제해서 맞추지 않는다. 기준 동작 통과 뒤 필수 세트의 실제 면적과 색 수로 예산을 다시 산정한다. 현행과 같은 모션 범위에서 비교하고 범위가 늘면 증가 사유를 분리한다. 12명 전체 상주 시 단순 합산 약 88MiB가 될 수 있으므로 선택 캐릭터·현장 NPC·지원자에 맞춘 로딩/해제 정책이 필요하다. PNG 파일 크기가 GPU 실제 점유량과 같다고 보고하지 않는다.

- 동일 자세는 한 이미지로 저장하고 유지 시간으로 표현한다. 완전히 같은 픽셀·앵커인지 확인한 뒤 중복 제거한다.
- 시간표·상태 처리·판정 형식·일반 효과는 공용화한다. 캐릭터 실루엣·무기·중심 이동·핵심 타격 자세는 개별화한다.
- 팔·다리의 단순 회전 조립으로 모든 동작을 대체하지 않는다. 접점과 옷 주름이 깨지면 전용 그림을 사용한다.
- 본체와 큰 컷인·시네마틱은 분리해 필요 시 로드한다. 원본 생성물과 제작 참고 시트는 실행 HTML에 넣지 않는다.
- 여백 자르기 뒤 앵커를 보존하고 정수 좌표로 패킹한다. 감색 전후 형태·색 튐을 비교한다.

## 13. 공개 자료 조사 결과

2026-10-20 웹 검색 도구의 올바른 인자(`system2_search_query`)로 검색 및 원문 열기에 성공했다. 앞선 검색 오류는 잘못된 호출 때문이었다. 직접 HTTP 접속의 프록시 403과 웹 검색 가능 여부를 혼동하지 않는다.

확인한 원문, 적용할 항목, 샘플 에셋의 제작자 고지 조건은 [캐릭터 액션 공개 레퍼런스 조사](캐릭터_액션_공개레퍼런스_조사.md)를 참조한다. 신규 생성 전에 해당 자료로 근거 카드를 채운다. 페이지 본문 확인과 이미지 직접 분석·다운로드·재생 시간 실측은 별도 단계로 기록한다.
