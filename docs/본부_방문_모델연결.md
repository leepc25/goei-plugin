## 구현

- 플러그인 게임 버튼 → 본부 들어가기 → 기존 본부 장면. `makeBridge()`가 방문별 `GameVisit` 인스턴스를 생성한다.
- `bridge.visit`가 있으면 본부로 바로 시작한다. 출동 및 이전 전투 저장 복원은 방문 모드에서 실행하지 않는다. 독립 액션 데모는 기존 모드를 유지한다.
- 「본부 인물 · 대화」 또는 기존 인물 상호작용으로 방문 대화창을 연다.
- 본편 명부와 상태를 읽어 내근→사무실, 휴게→휴게실, 부상→의무실로 분류한다. 외근·비번·격리·작전투입·실종·사망·미정은 방문 대화 대상에서 제외한다. 상태를 추측해 생성하지 않는다.
- 전송 버튼을 눌렀을 때만 Risu `runLLMModel`을 호출한다. 메인/보조 모델 선택 및 `allowPlugins` 지원은 기존 `runModel`을 사용한다. 자동 재시도나 입장 시 모델 호출은 없다.
- 요청에는 해당 요원 로어북(CBS 평가), 상태·상황, 유저 이름·페르소나, 본편 최근 6마디, 해당 요원과 최근 8회 대화, 최근 본부 대화 발췌를 넣는다. 유저를 기존 조작 요원으로 간주하지 않는다.
- 성공한 대화마다 방문을 시작한 채팅의 `goeiHqVisitV1`에 최근 100회 원문을 저장한다. 최근 8회 발췌는 항상 활성인 로컬 로어북 「본부 방문 대화 기록」에 남긴다. 종료 시점의 비동기 저장에 의존하지 않으므로 이미 저장된 답변은 창을 닫아도 본편 컨텍스트에 남는다.
- 모델의 상태 태그나 보상 명령을 실행하지 않는다. 본편 메시지와 요원 상태는 직접 변경하지 않는다. 기록의 CBS 구분자는 비활성화한다.
- 중복 전송, 본편 응답 대기 중 전송, 부재 요원 전송을 차단한다. 도중 채팅을 바꾸면 진행 중 답변은 원래 채팅에만 저장하고 이후 전송은 본부 재입장을 요구한다.

## 검증과 미완료

- 타입 검사, 빌드, 전체 테스트 58개 파일 통과(첫 통합 기준).
- 별도 호스트 테스트: 실제 Risu 인터페이스를 모사하여 모델 선택, 중복 차단, 채팅 전환 시 저장 대상, 실패 응답 미기록 확인.
- Chromium: 본부 직접 입장, 대화창, 부재 인물 비활성, 전송, 저장 상태 표시 확인. 테스트 모델만 사용했으며 유료 모델 호출은 하지 않았다.
- 실제 사용자의 Risu 모델 계정으로 종단 호출은 아직 검증하지 않았다.
- 방 분류는 현재 명부/대화 데이터다. 실제 NPC 스프라이트를 해당 방에 배치하는 렌더링, 유저 페르소나 선택·그림 교체는 별도 후속 작업이다. 기존 요원 그림을 새 페르소나 완성품으로 취급하지 않는다.
