## 0. 사용자 결정·전제 (2026-10-29, 그대로 옮김 — 바꾸지 말 것)

- 새 왼쪽 메뉴 **「기록」**: 지금 「가계부」 자리에 들어간다(메뉴 수 그대로). 하위 탭 = [일지 | 보고서 | 인물 | 세력]. 위키에 있던 「이 채팅의 인물」·개인 기록·「세력」 화면은 기록 탭으로 **옮긴다**(위키는 문서만). 요원 격자에서 요원을 누르면 그 사람 기록으로 가는 지름길은 유지. 탭 셋·넷은 같은 너비.
- **가계부**는 메뉴에서 빠지고 사원증(왼쪽 위 세로 카드)의 「잔고」 줄을 누르면 지금 가계부 화면이 열린다. 폰은 지금처럼 머리의 잔고 칩으로도.
- **사원증은 세로 카드 구조 유지**. 안만 정리: 사진 → 「이름 + 소속 칩」 한 줄 → 잔고 줄(누르면 가계부, › 표시) → 「위치 시각 · 날씨」 한 줄 → 「목표」 한 줄. 시안 `Main.dc.html` 의 사원증 블록.
- **일지**: 종료된 괴이·사건·특수 **전부**가 한 줄씩(종료 시각·등급·이름·장소·투입 요원·결과). 내가 출동한 줄은 표시(노란 왼쪽 선). 요약 타일(이번 달 종료·내가 출동·백그라운드·오늘) + 필터 칩(전체·내가 출동·백그라운드·괴이·사건) + 찾기 + 날짜별 묶음. 「오늘 일지 이미지로」 단추는 **넣지 않는다**.
- **보고서**: 사건이 「종료」가 되는 순간 재료를 잘라 저장한다(그 뒤 상태가 바뀌어도 보고서는 종료 시점 그대로): 머리(이름·등급·종류·장소·발생/투입/종료 시각·소요), 경과(그 사건의 상황 글이 바뀐 시점 목록 — 턴마다 바뀐 상황 글을 모아 둬야 한다), 투입 요원과 상태, 결과(마지막 상황 글, 없으면 「처리 완료」), 그 기간의 인물 기록 변화(호감이 움직인 사람·근거 인용), 그 기간의 가계부 거래. **내가 출동한 사건**(출동·동행·방문 기록이 있는 것)은 전체 보고서, **백그라운드 사건**도 간이 보고서(머리·경과·투입 요원·결과만)를 자동으로 만든다. 보고서 탭 = 카드 목록(「내가 출동」/「요원 처리」 칩), 카드를 누르면 보고서 페이지(창이 아니라 기록 안의 페이지, 뒤로 단추). 페이지 위에 「이미지로 저장」(PNG 세로 900×1200 한 장, 시안 `Card.dc.html`)·「소감 쓰기」. **「채팅에 넣기」 수동 단추는 없다.**
- **채팅 본문 자동 표시(설정)**: 사용자 2026-10-29 「설정에서 정하도록」. 설정 「기록」 묶음에 「채팅에 보고서 표시」 = 안 띄움 / 내가 출동한 사건만(기본) / 전부. 켜져 있으면 사건이 종료된 그 응답 아래에 보고서 카드를 **display 처리기가 그린다**(상황판 기록·이미지 태그처럼 채팅 변수를 읽어 그릴 뿐, 메시지 본문에 글을 넣지 않고 모델 요청에도 가지 않는다). 카드에는 「기록에서 보기」 링크. 설정을 끄면 이미 그려진 카드도 사라진다(본문이 아니므로).
- **설정 「기록」 묶음의 항목(반드시 전부)**: 채팅에 보고서 표시(위 3단계) · 일지를 본편 요청에 참고로 넣기(끔/최근 N건, 기본 끔) · 소감 자동(갱신기 호출에 얹기, 기본 켬) · 일지 상한(기본 500) · 보고서 상한(기본 100). 「기본값으로 저장」 범위에 포함.
- **모델 호출 없음**이 기본. 예외 = 소감: (1) 인물 기록 갱신기가 켜져 있으면 종료 턴의 그 호출에 「이번 턴 종료 사건의 담당 요원 소감 2~3줄」 칸을 얹는다(호출 수 그대로). (2) 인물 기록 「보충」이 읽는 턴 범위에 종료 사건이 있으면 같은 호출에 얹어 채운다. (3) 보고서 페이지 「소감 쓰기」 단추 = 그 보고서 하나만 보조 모델 1회(단추 옆에 「보조 모델 1회」). 갱신기가 꺼져 있으면 (1)은 생략, 보고서는 「소감 없음」.
- **종료 알림**: 내가 출동한 사건이 종료되면 상황판 위에 한 줄 「보고서가 기록에 저장됐어요 · 보기」.
- 상황판 오른쪽 목록의 종료 줄에 보고서 아이콘(지름길)과 「기록에서 전부 보기 ›」. 전환 칩은 CCTV/지도 그대로.
- **필드 출동**이 끝나 본부로 돌아오면 같은 보고서를 만들고 바로 보여 준다(시안 `Field.dc.html`).
- 저장: 채팅 변수(채팅마다, 지금 `$goei_world` 처럼 JSON). 상한 **일지 500줄 · 보고서 100건**, 넘치면 오래된 것부터(고정한 보고서 제외). 상한은 설정(기록 설정 묶음). 모델 컨텍스트에는 **기본 안 넣음**, 설정 「최근 N건 일지 한 줄씩을 본편 요청에 참고로」(기본 끔, 방문 기록 막간처럼 요청에 끼움·채팅 메시지엔 안 넣음).
- 글꼴·배색은 플러그인 창 그대로(도트풍 아님). 라이트·페이퍼 테마도 같은 틀.
- 시안 전체: `scratchpad/design/project/*.dc.html` (Main·Journal·Reports·Report·MainPhone·Card·Field). 시안은 참고이고 실제 CSS 변수·컴포넌트(`src/ui/style.css` 의 .gx-*)를 쓴다.
- 사용자가 정한 다른 수치·방식(인물 기록 상한·세력 구간 등)은 건드리지 않는다. 시키지 않은 기능 금지.

```ts
interface TrailStep { m: number | null; /* 세계 분 */ e: number; /* epoch */ text: string; /* ≤160자 */ }

interface AnEntry { …기존…; trail?: TrailStep[]; touched?: boolean; startKey?: string }
interface InEntry { …기존…; trail?: TrailStep[]; touched?: boolean; startKey?: string }
interface MsEntry { …기존…; trail?: TrailStep[]; touched?: boolean; startKey?: string }

/** 응답 한 번 동안만 (applyOutput 첫머리에서 비우고, worldVars 가 저장할 때 뺀다) */
interface ClosedEvent { kind: 'an' | 'in' | 'ms'; entry: AnEntry | InEntry | MsEntry; cause: 'model' | 'ttl' | 'manual'; minute: number | null; epoch: number; cleared?: boolean }
interface WorldState { …기존…; closed?: ClosedEvent[] }
```

| 칸 | 누가 채우나 | 규칙 |
| --- | --- | --- |
| `trail` | `applyAnomalies`·`applyIncidents`·`applyMysticSites` 에서 `e.situation` 을 쓰는 줄 | 새 글이 마지막 `trail` 글과 다르면 `{m: w.minute, e: w.epoch, text}` 를 뒤에 붙인다. **최대 24개**, 넘치면 **둘째 것부터** 지운다(첫 발견 글은 남김). 글은 160자에서 자른다 |

### 1-3. 일지 줄 `JournalRow`

```ts
interface JournalRow {
  id: string;            // `j` + hash(kind|name|loc|born|closeEpoch)
  kind: 'an' | 'in' | 'ms' | 'fd';   // fd = 필드 출동 (5-10절)
  name: string; loc: string;          // loc = 지역 코드 (locName 으로 표시)
  grade?: string;
  at: number | null;     // 종료 세계 분 (분 모르면 null → 「시각 없음」 묶음)
  since: number | null;  // 활성 시작 분
  born: number | null;
  idx: number;           // 종료를 반영한 메시지 번호 (리롤 되감기 열쇠). 수동·필드는 그때 마지막 메시지 번호
  anchor: string;        // messageKey (지워진 메시지 뒤 정리용은 아님 — 일지는 영구)
  mine: boolean;         // 내가 출동
  cause: 'model' | 'ttl' | 'manual' | 'field';
  agents: { id: string; name: string; st: string }[];   // 투입 요원과 종료 시점 상태 (이름만 있는 외부인은 id '')
  result: string;        // 마지막 상황 글 ≤120자, 없으면 '처리 완료'
  rpt?: string;          // 보고서 id (상한에 밀려 지워지면 undefined 로)
  cleared?: boolean;     // 괴이 「클리어」 태그로 끝남
}
```

크기: 한 줄 **약 260~380바이트**(요원 2~3명 기준). 500줄 ≈ **130~190KB**. `$goei_world`(수 KB~30KB)보다 크지만 `goeiPeopleV1`(수백 KB 가능)보다 작다. **[내가 정한 것]** 결과 글 120자·요원 상태는 짧은 상태명만 저장해 상한을 맞춘다.

### 1-4. 보고서 `Report`

```ts
interface Report {
  id: string;            // `r` + 같은 hash (일지 줄과 1:1)
  no: string;            // 표시용 번호 「RPT-MMDD-NN」 (그 날짜 안 순번)

  trail: TrailStep[];                       // ≤24
  agents: { id: string; name: string; st: string; situation?: string /* ≤80 */ }[];
  result: string;                           // ≤400자
  people?: { who: string; delta: number; cue?: string; quote?: string /* ≤60 */; stage?: string }[];   // full 만, ≤12
  wallet?: { memo: string; amount: number; quote?: string }[];   // full 만, ≤12
  balance?: number;                         // 종료 시점 잔고 (full 만)
  debrief?: { who: string; text: string; src: 'turn' | 'backfill' | 'manual'; at: string };
  pin?: boolean;
  idx: number; anchor: string; statusKey?: string;   // statusKey = 종료 응답의 상태창 원문(trim) → 채팅 카드 자리표
  savedAt: string;                          // ISO
}
```

크기: 간이 **1~2KB**, 전체 **2.5~6KB**(경과 24줄 가득 찼을 때 상단). 100건이면 **보통 150~250KB, 최악 500KB**. **[내가 정한 것]** 전체 보고서라도 경과는 24줄·결과 400자·인물 12명·거래 12건에서 자른다. 상한 설정(보고서 20~300)을 올리는 쪽은 사용자 책임으로 두고 설정 설명에 「채팅이 무거워질 수 있어요」 한 줄.

### 1-5. 상한·정리·고정

| 규칙 | 내용 |
| --- | --- |

## 3. 경과 수집

### 3-1. 지금 상태

- `AnEntry.situation`·`InEntry.situation`·`MsEntry.situation` 은 **현재 값 하나**뿐. 모델이 태그를 적을 때마다 덮어쓴다(`e.situation = codesToNames(...)`). 사건은 태그에 상황 칸이 없으면 `''` 으로 지운다.
- 상황판 종료 카드(`endedShown`)는 이름·장소·등급만 남긴다.

### 3-2. 누적 방식 **[내가 정한 것]**

| 항목 | 내용 |
| --- | --- |
| 어디 | 항목 안 `trail: TrailStep[]` (1-2절). 엔진이 상황 글을 쓰는 세 자리에서 `pushTrail(e, w, text)` 한 줄 |
| 언제 | 글이 바뀌었을 때만(마지막 trail 글과 다를 때). 같은 글 반복은 안 쌓는다. 사건 태그가 상황 칸을 비우면(`''`) 쌓지 않는다(글 없음은 변화가 아님) |
| 발생 글 | 활성이 되는 첫 턴의 글이 첫 줄(「발생」 표시는 화면이 `trail[0]` 을 그렇게 그린다) |
| 상한 | 24개 × 160자 = 항목당 ≤ 4KB. 넘치면 `trail.splice(1, 1)`(첫 줄 보존) |
| 리롤 | `$goei_prev` 의 세계로 되돌아가 다시 반영하므로 trail 도 같이 되돌아간다. 따로 할 일 없음 |
| 비용 | 진행 중 항목은 상한(기본 preset 2 + random 1 + 추가 3 + 사건 1+3 + 특수 1+3 ≈ 14)까지라 `$goei_world` 최악 +56KB, 보통 +수 KB. 매 응답 `structuredClone`·`JSON.stringify` 가 그만큼 커진다(ms 단위, 무시) |

### 3-3. 종료 순간 자르기 — `core/journal/build.ts buildClosures(...)`

입력: `chat`(종료를 반영한 메시지가 들어 있는 채팅), `index`, 종료 뒤 세계 `w`, `closed[]`, `catalog`, `faction`, `settings`(`$jr_*`).
출력: `{ journal, reports, mineIds: string[] }` → 호출한 쪽이 `journalVars`·`reportVars` 로 저장.

| 단계 | 내용 | 출처 |
| --- | --- | --- |
| ① 머리 | 이름(괴이는 `presetName || name`)·등급·종류·`loc`·`born`·`since`·`at = closed.minute`·`duration = at - since`(둘 다 있을 때)·`place`(종료 응답 상태창 위치 칸) | `closed.entry`, `findStatusTags(message[index].data)` |
| ② 경과 | `entry.trail` 그대로 (없으면 `situation` 한 줄) | 3-2절 |
| ③ 투입 요원 | `entry.deploy`(특수는 `visitors`) 를 `codesToNames` → 쉼표로 나눠 명부(`rosterFor` + `catalog.people`)에서 id 찾기 → `w.agents[id].st`·`situation` | `engine.ts codesToNames`·`rosterFor` |
| ④ 결과 | `trail` 마지막 글(= 마지막 `situation`), 없으면 `'처리 완료'`. `cleared` 면 앞에 「클리어 · 」 | |
| ⑤ 내가 출동 | 2-3절 `isMine` | |
| ⑥ 인물 변화 (전체만) | 4-1절 | `goeiPeopleV1` |
| ⑦ 가계부 (전체만) | 4-2절 | `$st_wallet` |
| ⑧ 소감 | 비움(`debrief` 없음). 6장이 나중에 채운다 | |
| ⑨ 저장 | 일지 줄 push → 상한 정리 / 보고서 push → 상한 정리(고정 제외) / `rpt` 연결 | 1-5절 |

### 4-3. 메시지 번호 ↔ 열쇠

- 같은 턴에서 쓰는 열쇠가 세 가지다: 세계(`index`), 인물 기록·가계부(`messageKey(m, i)` = chatId 또는 `#i`), 방문·필드(`anchorOf` = 마지막 chatId 또는 `#length`). `anchorPositions(chat)` 가 셋 다 번호로 바꿔 준다(없는 열쇠는 무시). 기간 비교는 **번호**로만 한다.
- 메시지가 지워져 번호가 당겨져도 보고서는 이미 잘라 둔 스냅숏이라 영향 없다. 기간 계산은 종료 순간 한 번뿐.

### 6-2. 「보충」(backfill·지난 응답 읽기) 범위

- `backfillPeople(turns)` → `requestPeopleUpdate('backfill', {scope:{indexes}})` → `planBatches` 묶음마다 `buildUpdate(batch)`. 6-1절의 `ended = items.filter(idx ∈ batch && !debrief)` 가 **그 묶음의 종료 사건**을 자연히 포함한다. 따로 할 일 없음.
- `rereadPerson`(`only`)은 소감을 만들지 않는다(그 인물 기록만 고치는 호출).
