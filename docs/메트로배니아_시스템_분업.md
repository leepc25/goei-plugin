# 메트로배니아 로그라이트 시스템 작업 기준

2026-10-22. 통합 브랜치: `codex/metroidvania-run-system`.

## 이번 사용자 지시

캐릭터를 더 손대지 않고 시스템을 먼저 완성한다. 기존 쟈알디 한 명으로 검증한다. 캐릭터 그림·체형·동작·컷인 신규 제작과 다른 플레이어블 추가는 이번 범위가 아니다. 과거 문서의 캐릭터 전면 재제작 작업은 재개하지 않는다.

## 공통 구조

출동 → 깊이별 세계 → 방. 같은 출동에서는 방 배치, 열린 잠금, 주운 열쇠, 전투 승리, 배낭 보상, 바닥 아이템 상태를 보존한다. 새 출동에서는 이 상태와 강화가 초기화되고 규칙서·총애·본부 성장만 남는다.

각 깊이는 가로 일자 진행이 아니라 가지·루프·막다른 곳·열쇠 잠금이 있는 방 격자다. 일반 방의 전투와 해당 유형의 목표를 해결하면 다음 깊이로 내려가는 패널이 열린다. 숨은 방은 선택 탐색이다. 깊은 층의 추격·생존 방은 통과가 목표이며, 특수 수호자는 규칙으로 통과할 수도 있다. 정비 구역은 다락방 휴식·정보 송신·로프 귀환과 아래 점검문을 연결한다.

일반 전투는 네 방향에서 들어오는 방 전체를 기준으로 한다. 전투 중 출입으로 적을 지우지 못하게 한다. 이미 이긴 방은 적과 아이템을 다시 생성하지 않는다.

저장은 안전 지점 단위다. 진행 중인 전투를 중단하면 마지막 안전 지점의 방·HP·탄약·물품·강화를 함께 복원한다. 보상만 유지하고 소모품만 되돌리는 부분 복원은 금지한다. `goei-session/1` 봉투에 본부 원문, 영구 진행, 출동 체크포인트를 같은 슬롯으로 보관한다. 정산은 귀환 영상보다 먼저 한다.

## 사용자 검수 후 수정 — 첫 방 출구·컷씬·이동 표시 (2026-10-22)

`f67d0a7b` 검수에서 사용자가 “첫 방 E 무반응, 컷씬 버벅임, 걷기 이상”을 보고했다.
본부 문 열기 종료 처리에서 `opening.t`를 매번 마지막 프레임으로 되돌려 다음 틱에도 이동 예약을 반복했다. 그때마다 암전 카운터가 초기화되어 방 전환이 끝나지 않았다. 종료 콜백이 정확히 한 번만 실행되도록 수정했다. 앞선 본부 브라우저 검사는 `goto()`로 목적지에 이동했으므로 실제 문 통과 결함을 검증하지 못했다.

- 새 `hub-doors.test.mjs`: 실제 World의 E 입력과 틱으로 본부 열린 문 28개 전환 확인.
- 새 `door-video-browser.mjs`: 새로 시작 → 첫 사무실의 가구를 돌아 키보드로 이동 → 문 앞 E → 2층 복도. 위치 주입이나 goto 없이 통과.
- 캐릭터와 달리 30Hz 위치를 그대로 쓰던 카메라에 같은 렌더 보간을 적용했다. 방 진입/복원 시 이전 카메라 위치도 초기화한다. 대화/지도 등으로 멈춘 세계는 현재 위치로 고정해서 이전 틱과 현재 틱 사이를 오가지 않는다.
- 컷씬은 다음 컷 로딩 중 재생 시간·자막·음성을 대기하고, 로딩 표시와 건너뛰기를 제공한다. PNG 디코딩 동시 작업을 4개로 제한하고 다음 컷부터 순서대로 준비한다. 같은 이미지/자막은 반복 갱신하지 않고, 전체 화면 컷씬에 가려진 월드 렌더링을 중단한다.
- 컷 로딩을 의도적으로 지연한 Chromium 검사에서 3컷 순서 보존, 자막 선행 방지, 중복 draw 제거, 로딩 중 건너뛰기 콜백 1회를 확인했다.
- 타입 검사, 빌드, 전체 38개 테스트 파일 통과.

캐릭터 그림·컷씬 원본은 변경하지 않았다. 첫 출근 컷씬 c2/c3 원본은 초당 약 6장이고 c1/c4에는 1.625초 정지 프레임이 있으므로, 원본 자체의 동작 간격까지 매끄러워졌다고 주장하지 않는다. 이번 수정 범위는 문 전환·재생 지연·카메라 떨림이다.

## 현재 통합 상태 — 세 작업 통합 완료 (2026-10-22)

통합 기준 `ce0f4428`(본부 출동 및 구형 저장 복원 수정)에 다음 세 브랜치를 병합했다.

- 방 생성·퍼즐·진행: `codex/room-progression` / `6db4fd3c`.
- 탐사 지도·모바일 화면: `codex/exploration-ui` / `2a238350`.
- 본부·정산: `codex/hq-settlement` / `c55589a2`.

통합 담당이 `module-progression.patch`와 `map-provider.patch`의 연결 내용을 적용했다. 추격 방을 통과한 뒤에는 되돌아갈 수 있고, 오른쪽 절반의 계단 진입은 벽에 갇히지 않는다. 지도는 실제 남은 정비 입구와 층 클리어에 따른 패널 상태를 표시한다. 개별 담당 문서의 “패치 미적용 / 통합 담당 요청”은 당시 인계 기록이며 현재 상태는 이 절이 우선한다.

추가로 해결한 연결 오류:

- 점검표는 아이템 모듈의 회수품 가방 6칸을 사용한다. 가방이 차면 획득하지 않고, 획득하면 해당 소품을 제거해 저장·재방문 시 다시 생기지 않는다. 인터폰 거래도 같은 가방에서 소비한다. 본부 회수 임무는 귀환 시 실제 소지품으로 판단한다.
- 종료 이벤트에서 마지막 가방·보급품·현금·파편·부채를 복사한다. 회수품의 감정값(value/research)이 결과 변환에서 사라지지 않는다. 점검표 감정값은 기존 사진과 같은 예산 40/연구 8로 설정했으며 밸런스 검수 대상이다.
- 실제 출동 ID를 결과에 전달하고, 어댑터가 불일치한 결과 ID를 올바른 ID로 덮어쓰지 않는다. 구형 체크포인트의 notes.runId가 시드여도 출동 계약의 ID를 사용한다.
- 노부부 두 개체(할머니/할아버지)를 모두 처치하면 방 정리와 진압 임무가 성립한다. 규칙으로 통과한 경우에는 방 진행만 열린다. 체력이 남은 채 사라진 수호자는 처치로 기록하지 않는다.
- 시험 실패 시 계획 이름 conductor와 실제 적 proctor의 불일치를 공용 별칭 표로 해결했다. 감독관 처치 후 진행은 열리지만 실패한 시험을 성공으로 바꾸지 않는다.
- 기존 floorfit 실패도 수정했다. 사다리는 잠긴 셔터 앞 열쇠 경로를 유지하면서 벽 그림을 피하고, 같은 쪽에 입구가 이미 있으면 겹치는 추가 사다리만 생략한다. 320개 층의 배치 검사에서 사다리·벽·소품 간격과 셔터 앞 진입로 보존을 확인했다.

검증:

- 타입 검사, 빌드, 전체 `npm test`: 37개 테스트 파일 통과. 이전 stage/floorfit 실패 해소.
- `tests/run-system.test.mjs`: 8개 통합 회귀 검사 통과. 가방 용량·복원·거래·감정, 노부부 두 개체/규칙 통과, 시험 실패 수호자 처치를 포함한다.
- 스테이지 검사: 300시드 × 8유형의 58,950개 방 배치, 26개 출동의 필수 방 → 다음 깊이 → 정비 → 로프 진행. 보행 검사는 전투 밸런스 검증을 대체하지 않는다.
- Chromium 본부: 출동 → 실제 로프 귀환 → 정산 → 재출동, 새로고침 이어하기, 메뉴 철수, 사망 후송 → 치료 → 재출동, 중복/불일치 결과 거부. 테스트용 stageId 보정 없이 통과.
- Chromium 탐사: PC 1280×720, 가로 모바일 844×390/667×375에서 지도 열기/닫기·일시정지·정비 진입·터치 입력. 밀집 지도와 로프 표시는 상태를 주입한 화면 검증이다.
- Chromium 저장: PC/모바일 화면에서 시드·출동 ID·방·HP·탄약·출동 횟수 보존, 실제 이동 재개, 구형 stageId 없는 저장 복원, 철수 후 재접속 시 중복 정산 없음. 이 스크립트의 이동 입력은 키보드다.
- Chromium 장치: 실제 World 입력으로 퍼즐 오답 → 1·3·2 정답, 계단 옆 열쇠 선택.

`release/demo/goei-action-game.html`에 통합 코드를 반영했다. 플러그인 정식 릴리스와 main 병합은 하지 않았다. 캐릭터 자산은 변경하지 않았다. 시스템 연결과 위 회귀 검사 완료이며, 모든 임무/모든 깊이의 수동 완주, 전투 난이도와 보상 수치, 캐릭터 시각 품질을 최종 승인한 것은 아니다.

## 분업과 파일 소유권

1. **통합 담당(원래 대화)**: `engine/game.ts`, `world.ts`, `itemsLink.ts`, `contract.ts`, `checkpoint.ts`, `sessionStore.ts`, `engine/modules.ts`, `stage/module.ts`, `state.ts`. 저장/복원, 진행 상태, 공용 계약, 최종 통합.
2. **지도·탐색 UI**: `stage/runmap.ts`, `ui/`의 지도·HUD 관련 표시. PC/가로 모바일에서 현재 방·미탐색·정리·잠금·열쇠·패널·귀환 경로를 읽기 쉽게 한다. `engine/modules.ts` 연결이 필요하면 변경 제안만 남긴다.
3. **방 생성·퍼즐·진행 검증**: `stage/gen/`, `stage/plan.ts`, `stage/testing/`, `tests/stage.test.mjs`. 현재 보행 봇 실패를 재현하고 실제 막힘과 봇 결함을 구분해 수정한다. `stage/module.ts` 변경이 필요하면 재현 조건과 패치를 통합 담당에게 전달한다.
4. **본부·정산**: `hq/`와 본부 테스트. 로프 귀환/긴급 철수/사망, 임무 판정, 규칙서, 보급품 반환, 중복 정산 방지, 이어하기 시 active 출동 보존을 검증한다. 엔진 어댑터와 저장 봉투는 통합 담당에게 연결 요구를 전달한다.

다른 담당 파일이 필요하면 임의로 고치지 말고 재현과 최소 수정 제안을 남긴다. 각 담당은 기준 커밋에서 별도 브랜치를 만들고 커밋/푸시한다. main 병합, 공용 브랜치 덮어쓰기, 플러그인 릴리스는 하지 않는다. 기준 이후 다른 브랜치의 작업을 임의로 가져오지 않는다. 통합 담당이 모아 반영한다.

## 검증/전달

`npm run typecheck` → `npm run build` → 관련 테스트. 전체 `npm test`는 빌드 이후 실행한다. `node --test --test-isolation=none`은 기존 테스트 간 전역 상태 간섭이 있으므로 사용하지 않는다.

보행 봇 통과는 실제 Chromium 검증을 대체하지 않는다. 브라우저에서 단일 HTML(`dist/goei-action-game.html`)을 로컬 HTTP로 열고 확인한다. 테스트의 `file://` 경로를 환경에서 차단하면 HTTP 주소를 설정 가능하게 만든다. 본부 잼트리 이동은 `world.stage.goto('jaemtri')` 후 해당 소품을 기다린다. 시작 장면에 항상 `spot:jaemtri`가 있다고 가정하지 않는다.

전달할 내용: 브랜치·커밋, 변경 파일, 재현 조건과 결과, 실행한 검증, 남은 문제, 통합 담당이 반영할 연결 사항. 화면 담당은 PC/모바일 스크린샷과 실제 반영한 HTML 검수 링크도 제공한다. 빌드 결과 전체를 무조건 커밋하지 말고 필요한 시연 HTML만 포함한다.
