2026-10-22. 통합 브랜치: `codex/metroidvania-run-system`.

## 이번 사용자 지시

캐릭터를 더 손대지 않고 시스템을 먼저 완성한다. 기존 쟈알디 한 명으로 검증한다. 캐릭터 그림·체형·동작·컷인 신규 제작과 다른 플레이어블 추가는 이번 범위가 아니다. 과거 문서의 캐릭터 전면 재제작 작업은 재개하지 않는다.

## 공통 구조

출동 → 깊이별 세계 → 방. 같은 출동에서는 방 배치, 열린 잠금, 주운 열쇠, 전투 승리, 배낭 보상, 바닥 아이템 상태를 보존한다. 새 출동에서는 이 상태와 강화가 초기화되고 규칙서·총애·본부 성장만 남는다.

각 깊이는 가로 일자 진행이 아니라 가지·루프·막다른 곳·열쇠 잠금이 있는 방 격자다. 일반 방의 전투와 해당 유형의 목표를 해결하면 다음 깊이로 내려가는 패널이 열린다. 숨은 방은 선택 탐색이다. 깊은 층의 추격·생존 방은 통과가 목표이며, 특수 수호자는 규칙으로 통과할 수도 있다. 정비 구역은 다락방 휴식·정보 송신·로프 귀환과 아래 점검문을 연결한다.

일반 전투는 네 방향에서 들어오는 방 전체를 기준으로 한다. 전투 중 출입으로 적을 지우지 못하게 한다. 이미 이긴 방은 적과 아이템을 다시 생성하지 않는다.

저장은 안전 지점 단위다. 진행 중인 전투를 중단하면 마지막 안전 지점의 방·HP·탄약·물품·강화를 함께 복원한다. 보상만 유지하고 소모품만 되돌리는 부분 복원은 금지한다. `goei-session/1` 봉투에 본부 원문, 영구 진행, 출동 체크포인트를 같은 슬롯으로 보관한다. 정산은 귀환 영상보다 먼저 한다.

## 현재 통합 상태 — 완료 판정 아님

`origin/claude/project-thread-gozk76`의 방 격자 WIP를 최신 main에 합쳤다. 방 상태 직렬화/복원, 방별 아이템 보존, 직접 문 상호작용의 잠금 검사, 네 방향 전투, 안전 귀환과 긴급 철수 구분, 슬롯 저장 연결을 추가했다.

새 `tests/run-system.test.mjs` 5개 통과: 짧은 방 생성/진입, 왕복 아이템 보존, 출동 상태 저장 왕복, 역방향 전투/잠금, 슬롯 이관/저널 복구. 타입 검사 통과. 브라우저 본부 → 임무 → 출동 및 출동 저널 생성 확인. 브라우저 새로고침 이어하기·전체 정산·재출동 검증은 아직 진행 중이다.

### 2026-10-22 이어하기 수정

본부 `MissionLaunch`는 `stageId`를 생략한다. 출동은 기본 무대로 시작했으나 복원은 ID 일치를 요구해 정상 저장을 거부했다. `engine/game.ts`에서 실제 선택한 무대 ID를 출동 기록에 남기고, 초기 v1의 ID 없는 저장도 기존 기본 무대로 이관하도록 수정했다. 명시된 알 수 없는 ID는 계속 거부한다.

`tests/run-resume-browser.mjs` 추가. Chromium PC(1280×720)와 모바일 화면(844×390)에서 실제 본부 임무 출동 → 새로고침 → 타이틀 이어하기 → 시드·출동 ID·방·HP·탄약·출동 횟수 보존 → 영상 종료 후 키 입력 이동 → ID 없는 구형 저장 복원 → 철수 정산 → 재실행 시 본부 복원을 통과했다. 모바일 화면에서도 입력은 키보드로 자동화했으므로 터치 조작 검증으로 간주하지 않는다.

타입 검사·빌드 및 저장 관련 단위 시험 5개 통과. 전체 `npm test`는 파일 단위 37개 중 35개 통과, `stage.test.mjs`와 `floorfit.test.mjs` 실패가 남아 있다. 후자는 `lobby 2 1: 사다리@1520 문 앞 [1496, 1704]` 재현이다. 두 실패는 방 생성·퍼즐 담당에게 넘길 확인 사항이며 이 수정에서 해당 담당 파일은 변경하지 않았다. 로프 귀환/사망/재출동의 전체 검증 및 다른 담당 브랜치 통합은 별도로 남아 있다.

기존 `tests/stage.test.mjs`는 12개 중 11개 통과. 보행 봇 완주 시험은 현재 퍼즐 스위치에서 `스위치 1,3,2 n=3`으로 실패한다. 이전 단계에서 발견한 짧은 방 승객 인덱스 오류, 진입 지형, 문 주변 소품 충돌, 정비 구역 전투 시작점 문제를 수정한 뒤 더 깊이 진행하며 드러난 실패다. 봇 문제인지 실제 퍼즐 진행 문제인지 분리해서 확인해야 한다.

캐릭터 품질·모든 깊이 완주·모바일 조작 완성·플러그인 배포를 완료했다고 주장하지 않는다. 생성된 HTML은 작업 중 검수판이다.

## 분업과 파일 소유권

1. **통합 담당(원래 대화)**: `engine/game.ts`, `world.ts`, `itemsLink.ts`, `contract.ts`, `checkpoint.ts`, `sessionStore.ts`, `engine/modules.ts`, `stage/module.ts`, `state.ts`. 저장/복원, 진행 상태, 공용 계약, 최종 통합.
2. **지도·탐색 UI**: `stage/runmap.ts`, `ui/`의 지도·HUD 관련 표시. PC/가로 모바일에서 현재 방·미탐색·정리·잠금·열쇠·패널·귀환 경로를 읽기 쉽게 한다. `engine/modules.ts` 연결이 필요하면 변경 제안만 남긴다.
3. **방 생성·퍼즐·진행 검증**: `stage/gen/`, `stage/plan.ts`, `stage/testing/`, `tests/stage.test.mjs`. 현재 보행 봇 실패를 재현하고 실제 막힘과 봇 결함을 구분해 수정한다. `stage/module.ts` 변경이 필요하면 재현 조건과 패치를 통합 담당에게 전달한다.
4. **본부·정산**: `hq/`와 본부 테스트. 로프 귀환/긴급 철수/사망, 임무 판정, 규칙서, 보급품 반환, 중복 정산 방지, 이어하기 시 active 출동 보존을 검증한다. 엔진 어댑터와 저장 봉투는 통합 담당에게 연결 요구를 전달한다.

다른 담당 파일이 필요하면 임의로 고치지 말고 재현과 최소 수정 제안을 남긴다. 각 담당은 기준 커밋에서 별도 브랜치를 만들고 커밋/푸시한다. main 병합, 공용 브랜치 덮어쓰기, 플러그인 릴리스는 하지 않는다. 기준 이후 다른 브랜치의 작업을 임의로 가져오지 않는다. 통합 담당이 모아 반영한다.

## 검증/전달

`npm run typecheck` → `npm run build` → 관련 테스트. 전체 `npm test`는 빌드 이후 실행한다. `node --test --test-isolation=none`은 기존 테스트 간 전역 상태 간섭이 있으므로 사용하지 않는다.

보행 봇 통과는 실제 Chromium 검증을 대체하지 않는다. 브라우저에서 단일 HTML(`dist/goei-action-game.html`)을 로컬 HTTP로 열고 확인한다. 테스트의 `file://` 경로를 환경에서 차단하면 HTTP 주소를 설정 가능하게 만든다. 본부 잼트리 이동은 `world.stage.goto('jaemtri')` 후 해당 소품을 기다린다. 시작 장면에 항상 `spot:jaemtri`가 있다고 가정하지 않는다.

전달할 내용: 브랜치·커밋, 변경 파일, 재현 조건과 결과, 실행한 검증, 남은 문제, 통합 담당이 반영할 연결 사항. 화면 담당은 PC/모바일 스크린샷과 실제 반영한 HTML 검수 링크도 제공한다. 빌드 결과 전체를 무조건 커밋하지 말고 필요한 시연 HTML만 포함한다.
