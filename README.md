# 괴이: 이면세계 (goei-plugin)

RisuAI용 괴담 시뮬레이션 「괴이: 이면세계」의 전용 플러그인과 카드입니다. 괴이봇 2탄(Anomaly Sim 2.4)의 Lua 기능을 Risu 플러그인 API v3로 옮겼습니다.

## 설치

1. [Releases](https://github.com/leepc25/goei-plugin/releases)에서 최신 버전의 zip을 받습니다.
2. Risu 설정 → 플러그인 → 가져오기에서 `goei-plugin.js`를 추가합니다. 확인 창 두 개를 허용해 주세요.
   - 메인 화면 접근: 이 카드 채팅에서만 보이는 유령 버튼과 접속 효과를 그립니다. 거부하면 채팅 입력창 옆 메뉴에 항목이 대신 생깁니다.
   - 리플레이서: 시작 자료(시드)를 첫 응답에만 넣고, 응답마다 상황판 태그를 읽는 데 씁니다.
3. `괴이_이면세계.charx`를 캐릭터로 가져옵니다. 원래 쓰던 에셋 모듈(캐릭터 표정 이미지)은 그대로 켜 둡니다.
4. 채팅 화면 구석의 유령 버튼 → 세력, 첫 장면, 언어 → **출발**. 다른 봇에서는 아무것도 나오지 않습니다.

## 업데이트

- 플러그인: Risu 설정 → 플러그인 탭에서 업데이트(`release/goei-plugin.js`).
- 카드: 창의 설정 → 업데이트 → 「카드 업데이트 준비」 → 「카드에 적용」(`release/card-update.json`). 채팅·사진·에셋·카드 명부는 그대로입니다.
- 사진·에셋이 바뀐 버전은 Releases의 카드 파일을 다시 가져오세요.

## 개발

- `npm ci && npm run build && npm test` (브라우저 테스트: `python3 tests/make_fixture.py <카드.charx> <fixture.json>` 뒤 `node tests/browser.mjs <fixture.json>`)
- 카드 빌드: `python3 tools/build_lite_card.py card/원본_봇카드.jpeg release/괴이_이면세계.charx` (먼저 `npm run build`). `release/card-update.json`·`version.json`도 함께 만들어집니다.
- 릴리스: `package.json` 버전을 올리고 `dist/goei-plugin.js`와 위 파일들을 `release/`에 넣어 main에 커밋하면, `release/version.json`이 바뀐 것을 보고 GitHub Actions가 `v버전` 릴리스를 만들어 zip·카드·플러그인을 붙입니다.

### v0.15.0: 지도 확대, 바깥 눌러 닫기, 테마 따라가는 버튼, 간이 상태창

- 지도: 지도 칸은 그대로 두고 안쪽 지도만 확대·이동합니다. 휴대폰은 두 손가락으로 벌리고 한 손가락으로 옮기며, PC는 Ctrl+휠(트랙패드 오므리기)과 끌기, 어디서나 오른쪽 아래 +/−/원래 크기 버튼을 씁니다. 핀은 지도와 함께 자리를 옮기고 조금만 커집니다. 지역마다 보던 배율을 기억합니다.
- 창 바깥(어두운 막)을 누르면 창이 닫힙니다. 창 안에서 끌다가 바깥에서 놓은 건 닫지 않습니다.
- 채팅 화면의 여는 버튼은 창 제목 옆 아이콘과 같은 모양으로 바꾸고, 접속 효과(ANOMALY SIMULATION)와 채팅 속 이동·전화 기록 카드까지 그 채팅의 테마(다크·라이트·페이퍼)를 따릅니다.
- 왼쪽 위 소속 카드는 간이 상태창이 됩니다: 소속 사진·이름 아래에 마지막 상태창의 시각·위치·날씨·목표. 시작 뒤에는 쓸모없는 첫 장면(「05. 검사부대」 등)은 뺐습니다.
- 가짜 관리국(B00)을 고르면 본인 화면에서는 「관리국」으로 보입니다(설정상 본인에게는 진짜 관리국). 명부에서 이름을 직접 바꿨으면 그 이름을 씁니다.
- 「새 작전 준비」처럼 고정폭 글꼴에 한글이 섞인 곳이 굴림체로 보이던 문제: 한글은 본문 글꼴로 이어지게 했습니다.
- 화면에 보이는 봇 이름은 `src/ui/brand.ts` 한 곳에서 바꿉니다.

### v0.13.0: 새 플레이 세력 (F00~), 기본 세력 편집·숨기기

- 설정 → 카드 명부 → 조직에서 아무 조직이나 **플레이 세력**으로 켜면 F00, G00 … 코드를 받고 시작 화면에 나옵니다. 한 번 준 코드는 조직을 지워도 다시 쓰지 않습니다(`codes_used`).
- 새 세력마다 유형(조직형·민간형·프리랜서형), 시작 화면 이름·설명·사진 에셋, 모델용 영어 이름·세력 설명, 시작 때 함께 넣을 로어북, 괴담톡 전용 탭 이름을 정합니다. 켜면 그 조직과 소속 요원의 요원 목록 공개 대상·괴담톡 탭에 새 코드와 전용 탭(T105 등)이 들어갑니다.
- 새 세력의 첫 장면은 **직접 입력**과 **커스텀 임무** 두 가지입니다. 카드에 이미 있는 공용 빈 첫 장면을 써서 인사말을 더 넣지 않습니다.
- 모델에게는 로어북 자리표시자로 알립니다. 🏷️Tag의 `[AC]` 코드 목록·이름 줄·배치 세력 목록 뒤와 📜Faction 끝에 `{{getvar::fac_codes}}`·`fac_ac`·`fac_pool`·`fac_extra`가 있고, 플러그인이 시작·응답·명부 저장 때 이 변수를 채웁니다. 새 세력이 없으면 모두 빈 값이라 원래 글과 같습니다. 새 Lite 카드에는 자리표시자가 들어 있고, 예전 카드는 명부 화면의 「로어북에 자리 넣기」 버튼으로 넣습니다(넣기 전에는 새 세력이 시작 화면에 안 나옵니다).
- `[AC|F00]`도 소속 변경으로 받고, 괴담넷·위키·괴담톡 요청에서 F00 같은 코드도 이름으로 바꿉니다. 기본 다섯 세력 모두에게 열린 괴담톡 탭(중립·기타·괴이)은 새 세력에도 열립니다.
- 기본 다섯 세력은 시작 화면 이름·설명·사진을 고치거나 시작 화면에서 숨길 수 있습니다(모델용 글은 로어북 그대로).
- 설정의 「캐릭터당 이미지 수」는 이미지 출력 모델이 보조모델일 때만 보입니다(메인모델에는 해당 없음).
- 설계: `docs/조직코드_확장_설계.md`.

### v0.12.0: 괴담톡 메신저 화면, 설정 정리, 명부 후보 추가

- 괴담톡을 메신저처럼 바꿨습니다. PC는 왼쪽 목록(연락처·대화·공지)과 오른쪽 대화방 두 칸이고, 모바일은 목록과 대화방을 한 칸씩 보여 줍니다. 말풍선은 이어 보낸 것끼리 묶고 날짜가 바뀌면 가운데 줄을 넣습니다. 내 말풍선은 강조색, 시각은 말풍선 옆, 답장을 기다릴 때는 점 세 개가 움직입니다. 대화를 열면 맨 아래로 가고, 맨 아래를 보던 중이면 새 말풍선이 와도 따라갑니다.
- 입력창은 늘 대화방 맨 아래에 있습니다. 「＋」로 사진·파일·선물 첨부를 열고, 입력창은 글이 길어지면 늘어납니다. PC는 Enter로 보내고 Shift+Enter로 줄을 바꿉니다(모바일 자판의 Enter는 줄바꿈).
- 고정 높이 상자(대화 기록 최소 높이, 목록 최대 46vh 등)를 없애고, 창 높이를 나눠 씁니다. 목록·대화만 안에서 스크롤됩니다.
- 괴담톡 설정은 목록 아래 접는 칸 대신 톱니 버튼으로 여는 화면이 되었고, 답장·새 메시지·연락처·보관 묶음으로 나눴습니다. 설정 탭도 같은 모양(묶음 카드, 줄마다 왼쪽 이름·설명, 오른쪽 조작)으로 정리했고, 괴이 발생 수치는 종류별 카드로 나눴습니다.
- 좁은 화면에서 버튼 글자가 두 줄로 쪼개지던 것(「라이/트」, 「OF/F」)을 고쳤습니다. 모바일 편성 요원 카드는 두 줄로 촘촘하게 보입니다.
- 카드 명부: 괴이·미스틱 사이트 탭에서 폴더 안 항목과 「다른 폴더에서 온 후보」를 나눠 보여 줍니다. 원본 World catalog가 괴이 후보에 넣어 둔 조직(발푸르기스 협회 등)·개체(세크리엠 등)가 여기에 출처 폴더(예: 🙂요원 · 개체)와 함께 보입니다. 「다른 폴더에서 후보 추가」로 아무 폴더의 로어북이나 발생 후보로 넣고, 「후보 목록에서 빼기」로 뺄 수 있습니다.
- 괴담넷은 넓은 화면에서 글 목록이 너무 퍼지지 않게 가운데 1000px로 맞췄습니다.

### v0.10.0: 괴담톡·괴담넷 빠진 기능 복원 (첨부·보관·자동 새로고침)

- **첨부 보내기** (원본 첨부 기능). 작성칸 아래 버튼으로 사진·영상·파일·링크를 붙이고, 각 첨부에 내용을 적습니다(한 번에 3개까지, 글 없이 첨부만도 됨).
  - 괴담톡: 1:1 대화는 선물까지 보낼 수 있고, 단톡방에서는 선물 버튼이 막혀 있습니다. 첨부는 원본처럼 하나씩 따로 말풍선이 되고, 함께 쓴 글은 그 뒤에 한 말풍선으로 갑니다.
  - 괴담넷: 글·댓글·쪽지에 붙일 수 있습니다(원본처럼 선물 없음). 글은 AI가 제목·본문을 다듬어도 사용자가 붙인 첨부는 그대로 남고, 파일·링크는 글 아래 문서 목록으로 보입니다. 링크 내용이 주소 하나면 눌러서 열 수 있습니다.
  - AI에게는 원본과 같은 방식으로 보냅니다: 본문의 첨부 자리는 `[ATTACHMENT A1]`, 내용은 끝의 `ATTACHMENT DATA`에. NPC가 보낸 첨부와 원본 봇에서 넘어온 채팅의 첨부 기록(`%%ATTACHMENT%%`)도 같은 카드로 보입니다. 본편 반영 기록에는 「[사진 첨부 내용: …]」처럼 풀어 씁니다.
  - 실제 사진 파일 올리기(원본 「사진 직접 첨부」)는 플러그인이 Risu 인레이를 저장할 수 없어서 못 합니다. 원본 채팅에 있던 실제 사진은 「원본 채팅에서 보낸 이미지」로만 표시합니다.
- **괴담넷 사용 켜기/끄기**: 끄면 탭에는 안내와 설정만 남고, 게시판 생성과 본편 반영이 멈춥니다. 저장된 글·쪽지는 그대로이고, 다시 켜면 끄기 전 모델(메인/보조)로 돌아옵니다.
- **괴담넷 새로고침: 수동 / 본편 응답마다** (원본 「메인 채팅 응답마다 자동」). 본편 응답이 끝날 때마다 게시판을 한 번 새로 불러옵니다. 괴담톡 자동 확인도 켜져 있으면 괴담톡 → 괴담넷 순서로 차례로 부릅니다. 생성 중에 본편이 이어지면 그 결과는 버립니다.
- **보관 한도** (원본 자동 정리 설정): 괴담넷 상대별 쪽지(기본 40통), 괴담톡 1:1 대화(40개)·단톡방(100개)·공지(20개). 자동 정리를 끄면 지우지 않고, 켜면 개수를 바꿀 수 있습니다.
- **괴담톡 공지**: 페이지당 공지 수(20~60)와 페이지 넘기기, 「모두 읽음」, 새 공지 후 대기 턴 수(기본 3), 공지 작성에 참고할 이전 공지 수(기본 10).
- 괴담넷·괴담톡 설정 칸이 값을 하나 바꿀 때마다 닫히던 것을 고쳤습니다.
- 원본의 괴담넷 「검토 방식(thoughts)」은 2탄 괴담넷 요청에서 실제로 쓰이지 않던 값이라 옮기지 않았습니다.

## 5단계: 설정 · 캐릭터 이미지 (v0.7.0)

원본 설정 창의 동작·요원창·캐릭터 이미지 항목을 플러그인 창의 「설정」 탭으로 옮겼습니다. 값은 채팅마다 따로 저장되고(원본과 같은 `st_*` 변수), 새 채팅의 처음 값은 카드의 `Settings` 로어북 「기본설정」에서 가져옵니다.

- 괴이 발생 · 요원 시스템: OFF로 바꾸면 확인을 받은 뒤 지금 상황판(괴이·사건·미스틱 사이트·요원 상태)을 비웁니다. 다시 켜면 새로 발생을 뽑습니다(이전 상태는 복원하지 않음, 원본과 같음). `Settings`의 「상황판」(옛 이름 통합관제)을 false로 두면 새 채팅을 상황판 없이 시작합니다.

## 4단계-3: 괴담톡·폰 (v0.6.0)

원본 괴담톡(폰)을 옮겼습니다. 플러그인 창의 「괴담톡」 탭이며, 연락처·대화·공지 세 칸이 있습니다.

- 연락처: `Phone tabs`·`Agent roster` 로어북대로 내 소속에 공개된 탭(관리국이면 관리·중립·기타)과 인물을 보여 줍니다. 가짜 관리국에서는 탭 이름과 순서가 원본처럼 바뀝니다. 설정에서 「모든 연락처 공개」「괴이 연락처 공개」를 켤 수 있습니다. 「＋ 연락처」로 이름과 메모를 적어 직접 추가하면 「기타」에 들어가고, 명부에 있는 이름이면 그 인물로 추가됩니다.
- 1:1 대화: 이름을 누르면 방이 열립니다. 내 말은 먼저 저장하고, 답장은 원본과 같은 미니톡 패치(`<lb-minitalk-patch>`)로 받습니다. 모델은 새 말풍선·대기 표시(단톡은 퇴장도)만 덧붙일 수 있고, 저장된 기록은 고치지 못합니다. 답장을 못 받으면 「다시 시도」 또는 「건너뛰기」를 고릅니다. 실패한 응답 원문은 창 아래에 남습니다.
- 단톡: 「👥 단톡 만들기」로 여러 명을 고르고 주제를 적으면(선택) 방을 열고 첫 반응을 받습니다. 모델이 방 이름을 붙일 수 있습니다. 방 안의 「초대」로 사람을 더 부를 수 있고, 1:1 방에서 초대하면 단톡으로 바뀝니다. 상대는 최대 9명입니다.
- 새 메시지 확인(「↻」): 대화 중인 방과 공개된 연락처 전체를 한 번에 보내, 선톡·단톡 초대·소속 공지를 한 응답으로 받습니다. 받은 뒤에는 원본 설정처럼 선톡 1턴, 단톡 초대 3턴, 공지 3턴 동안 쉽니다(본편 응답 수 기준). 답장을 기다리는 1:1 방에는 후속 메시지 한 번까지만 옵니다. 형식이 틀리면 같은 자료로 한 번 더 묻습니다.
- 자동 확인(기본 켬, 원본과 같음): 본편 응답이 끝날 때마다 위 확인을 한 번 합니다. 같은 응답에는 다시 하지 않고, 확인하는 사이 본편이 이어졌으면 결과를 저장하지 않습니다. 모델 호출이 매 턴 한 번 늘어나므로, 원하지 않으면 설정에서 끄세요.
- 읽음: 보고 있는 방에 온 말풍선은 바로 읽음이 되고, 상대에게도 원본처럼 읽음 여부(`lastMessageRead`)가 전달됩니다. 안 읽은 수는 「대화」 칸과 탭의 빨간 점으로 보입니다. 공지는 펼치면 읽음입니다.
- 전화(「📞」): 상대와 용건(선택)을 적고 「전화 걸기」를 누르면 채팅 끝에 전화 기록을 남기고 창을 닫습니다. 채팅 화면에는 "OO에게 전화를 걸었다" 카드만 보이고, 전송을 누르면 본편이 통화 장면으로 이어집니다(빈 전송도 됨). 입력창에 덧붙여 보낸 글은 통화 내용으로 합쳐집니다.
- 기억: 같은 사람이 다른 방에서 보내거나 받은 말은 원본처럼 그 사람의 기억으로 함께 보냅니다(다른 참여자에게는 공개되지 않음). 괴담넷 공개 글도 참고로 붙습니다.
- 본편 반영(기본 포함): 모든 방의 말풍선(최대 200개)과 최근 공지 1개를 본편 요청 끝에 참고 기록으로 붙입니다(원본 MODULE_CONTEXT 형식, 2만 토큰 상한).
- 보관: 1:1 방마다 기록 40개, 단톡방마다 100개, 공지 20개를 넘으면 오래된 것부터 정리하고, 지운 기록의 대화 상태는 요약으로 남깁니다.
- 프롬프트는 카드의 `Phone` 로어북 섹션을 요청 조건에 맞는 것만 원본 순서대로 씁니다. 참고 자료는 봇 설명, 작가 노트, 📜Faction·🙂Roster, 최근 8턴, 요원 상태(상황판)입니다. 원본 기본값처럼 인물 로어북은 보내지 않으며, 설정 「인물 로어북 참고」를 켜면 함께 보냅니다.
- 저장은 원본과 같은 채팅 변수 `ph_state`·`ph_contacts`·`ph_bulletins`와 `ph_*` 설정입니다.
- 원본에서 뺀 것: 내가 사진·선물을 직접 첨부하기, 괴담넷과 한 번에 묶는 자동 요청, 요청 토큰 예산에 맞춰 자료를 줄이는 기능(카드 설정의 상한이 99999라 사실상 쓰이지 않음), 공지 페이지 크기 설정. NPC가 보낸 가상 첨부(사진·영상·파일·링크·선물)는 카드로 보여 줍니다.

## 4단계-2: 괴담넷 (v0.5.0)

원본 괴담넷을 옮겼습니다. 플러그인 창의 「괴담넷」 탭이며, 게시판과 쪽지함이 있습니다.

- 원본은 채팅 입력창을 빌려 글을 받았지만, 여기서는 창 안의 입력칸에 바로 씁니다. 채팅에 작성용 메시지가 생기지 않습니다.
- 사용자 기록은 앱이 소유합니다. 모델은 내 글·댓글·쪽지를 만들거나 바꿀 수 없고, 저장된 글의 제목·본문·작성자·날짜도 바꾸지 못합니다. 모델이 내 닉네임으로 쓴 새 글·댓글과 그 답글은 버립니다. 글 번호는 1846000부터 계속 올라가기만 합니다.
- 새로고침: 게시글 수(4~6 / 5~7 / 6~8 / 7~9)에 맞춰 새 게시판을 받습니다. 「새로고침 시 내 글: 유지」면 내 글은 남고, 「내 댓글 있는 글: 유지」를 켜면 그 글도 남습니다. 저장된 글은 조회·추천이 줄지 않고 새 댓글만 붙습니다.
- 글쓰기: 올릴 글이나 쓰고 싶은 내용을 적으면 제목과 본문을 다듬어 올리고, 같은 응답으로 첫 댓글, 선쪽지, 다른 글의 조회·댓글 변화까지 받습니다.
- 댓글·답글: 내 댓글은 먼저 저장하고, 반응은 원본처럼 내 댓글 아래로만 받습니다. 생성 중 글이 바뀌었으면 반응은 적용하지 않습니다.
- 쪽지: 닉네임을 누르거나 「✉ 쪽지」로 보냅니다. 상대와 처음 이어진 공개 글은 저장해 두었다가 매번 함께 보냅니다. 답장 형식이 틀리면 원본처럼 한 번만 다시 묻습니다.
- 선쪽지: 내 글이나 내 댓글을 보고 NPC가 먼저 쪽지를 보낼 수 있습니다. 받은 뒤에는 본편 응답 2번이 지나야 다시 받습니다. 설정에서 끌 수 있습니다.
- 내 글에 달린 댓글, 내 댓글에 달린 답글, 받은 쪽지에는 빨간 점이 붙고 펼치면 읽음이 됩니다. 내 글·댓글·쪽지 대화는 두 번 눌러 지웁니다. 지운 댓글의 답글은 윗 댓글로 올라갑니다.
- 본편 반영(기본 포함): 최근 글 5개(글마다 최근 댓글 10개)와 쪽지 30개를 본편 요청 끝에 참고 기록으로 붙입니다(원본 MODULE_CONTEXT 형식). 쪽지는 "당사자만 아는 내용"으로 표시됩니다. 보조 모델 요청과 플러그인 자체 생성에는 붙이지 않습니다.
- 프롬프트는 카드의 `GNet`·`LB Backend` 로어북 섹션을 원본 순서대로 씁니다. 사생활 단계, 주제, 분위기·말투, 보호 대상 같은 조건문은 플러그인이 풀어서 보냅니다. 참고 자료는 봇 설명, 작가 노트, "현재 발생 상황"(괴이·사건·장소 보고), 📜Faction·🙂Roster와 최근 8턴입니다(원본 기본값처럼 관련 로어북 추가 조회와 2차 참조는 끔).

- 원본에서 뺀 것: 사진 직접 첨부, 표시 방식(팝업·채팅 메시지), 본편 응답마다 자동 새로고침, 괴담톡과 한 번에 묶는 요청. NPC가 쓴 가상 첨부(사진·영상·파일·링크 설명)는 카드로 보여 줍니다.

- 문서 안의 링크를 누르면 그 문서를 열거나(있으면 파란색) 작성 화면으로 갑니다(빨간색). 로어북이 없는 하위 주제는 부모 문서의 원본 자료를 물려받습니다.
- 저장은 원본과 같은 형식입니다: 채팅 로어북 `WIKI｜제목` 항목(키 없음, 비활성)에 meta와 본문. 본편 요청에는 끼어들지 않습니다(원본 기본값처럼 위키를 본편 컨텍스트에 넣는 기능은 꺼 둠).
- 목록 위에서 분량(짧게·보통·상세, 기본 상세), 작성 모드(확장·원본 충실), 모델(메인·보조)과 작성 지침을 바꿀 수 있습니다. 작성 지침은 비우기 전까지 이후 모든 문서에 쓰입니다.
- 지도 상황 목록과 커스텀 임무 목록의 「위키」 버튼으로 그 이름의 문서로 바로 갈 수 있습니다.
- 원본과 다른 점: 플러그인은 지금 쓰는 페르소나를 읽을 수 없어 참고 자료에서 페르소나가 빠지고, 로어북의 `{{user}}`는 "주인공"으로 바뀝니다. 토큰 수 대신 자료 개수(20)와 최근 턴 수(8)로 길이를 제한합니다.

## 3단계: 지도 · 요원 이동 · 커스텀 임무 (v0.3.0)

원본 Lua의 지도 작업 공간과 커스텀 임무(수동 프리셋) 창을 옮겼습니다. 플로팅 버튼 창에 「지도」, 「커스텀 임무」 탭이 생겼습니다.

- 「지도」: 전국 지도(시도 17개)와 시도 지도(시군구, 랜드마크 시설)를 카드 안의 map01~map18 이미지 위에 핀으로 보여 줍니다. 상황이 있는 곳은 핀이 빛나고(괴이 빨강, 사건 주황, 미스틱 사이트 보라), 옆 목록에서 상황을 고르거나 종류로 거를 수 있습니다.
- 목표는 진행 중인 상황, 시군구, 랜드마크 시설 중 하나입니다. 상황이 없는 핀을 누르면 그 장소가 바로 목표가 되고, 상황이 있는 핀은 그곳 상황만 목록에 보여 주며 「이 장소 자체를 목표로」를 고를 수 있습니다.
- 편성: 요원과 지원 인원 합쳐 최대 3명(나 포함 4명). 원본과 같이 모델 태그로 작전투입·실종·사망 상태가 된 요원은 고를 수 없습니다.
- 「출발」을 누르면 원본과 같은 지시문(Directive 로어북의 COMMON + CONTINUATION + CONTEXT)이 `%%SCENE_CARD%%`로 감싼 유저 메시지로 채팅에 놓이고 창이 닫힙니다. 채팅 화면에는 "목표 | 투입" 카드만 보입니다. 그대로 전송하거나, 하고 싶은 말을 적어 보내면 요청 때 원본처럼 `Situation:`으로 지시문 뒤에 합쳐집니다. 보내기 전에 다시 출발하면 이전 카드를 바꿔 끼웁니다.
- 「상황 종료」는 두 번 눌러 확인하고, 그 상황을 끝내고 브리핑에서 뺍니다(원본의 휴지통 버튼).
- 「커스텀 임무」: 괴이·미스틱 사이트·랜드마크 목록에서 고르고 편성한 뒤 「요청」. 지시문 카드가 놓이고, 상황판이 켜져 있으면 다음 응답 브리핑에 `NEW [AN|<발생 지역: 시도와 시군구>|이름|...]` 줄을 넣어 모델이 발생시키게 합니다. 모델이 태그를 적으면 커스텀 임무(수동) 항목으로 등록되고, 안 적으면 다음 응답에서 다시 안내합니다. 대기 중인 요청은 탭에서 취소할 수 있습니다.
- 시작 화면의 「커스텀 임무」 상황이 열렸습니다. 시작을 누르면 직접 입력과 같은 빈 첫 장면으로 시작하고, 창이 그대로 커스텀 임무 고르기로 넘어갑니다. 여기서 보내는 지시문은 OPENING(첫 장면) 문구를 씁니다. 「시작 설정 다시 고르기」로 돌아갈 수 있습니다.
- 지시문 카드와 덧붙인 글은 한 번의 전송으로 셉니다(시작 자료는 첫 전송 동안 유지).

## 2단계: 상황판 (v0.2.0)

괴이·사건·미스틱 사이트·요원 현황입니다. 원본 Lua의 editInput/editOutput/editRequest를 대신합니다.

- START를 누르면 `st_anomaly_on=1`로 로어북 🏷️Tag 지침을 켜고, 첫 발생(프리셋 괴이, 랜덤 괴이, 사건, 미스틱 사이트)을 미리 뽑아 첫 응답부터 `NEW [...]` 줄이 모델에 갑니다.
- 응답이 채팅에 들어온 뒤 한 번(`addRisuChatListener('output')`): [AN]/[IN]/[MS]/[AG]/[AC] 태그와 상태창 시각을 읽어 상태를 갱신하고, 저장 본문에서 태그를 지우고, 다음 턴 브리핑(`an_report`, `in_report`, `ms_report`, `ag_report`)을 다시 만듭니다. 상태는 채팅 변수 `goei_world`(JSON) 하나에 있습니다.
- 규칙은 원본과 같습니다: 그룹별 상한·확률, 지역 대조(모델이 다른 지역을 적으면 무시), 모델이 스스로 낸 괴이는 추가 여유분 3개까지, 끝난 항목은 바로 다시 뽑지 않음, RP 유지 시간이 지나면 자동 종료(탐사 중인 괴이는 제외), 요원 사망 후 5번 응답이 지나면 결번 처리하고 예비 인원 충원, [AC]로 소속 변경.
- 원본보다 너그러운 점 하나: "서울 종로구"처럼 시도를 줄여 쓴 지역도 받습니다.
- 응답이 막 들어와 정리되기 전에도 Lite 채팅에서는 태그가 화면에 보이지 않습니다. 다른 봇에서는 표시·요청·응답 처리 모두 그대로 둡니다.
- 플로팅 버튼 창의 「상황판」 탭에서 현재 상태를 봅니다. 이전 버전으로 시작한 채팅은 탭에서 「상황판 켜기」를 누르면 됩니다.
- 설정값(상한, 확률, 유지 시간, 요원 수 12명)은 지금은 원본 기본값으로 고정이고, 5단계 설정 화면에서 바꿀 수 있게 합니다.

## 1단계에 들어간 것 (v0.1.4)

| 항목 | 원본 | Lite + 플러그인 |
|---|---|---|
| Lua 트리거 | 1,003KB, 상시 리스너 다수 | 없음 |
| 첫 메시지 | 285KB CBS (매번 해석) | 0.4KB 안내문, 첫 장면은 CBS 없는 추가 인사말 57개 중 하나만 표시 |
| 시작 패널 | 59KB CBS 정규식 (CBS 1,412개) | 플러그인 전용 창 |
| 배경 HTML | 684KB | 6.6KB (상태창·에셋 표시 CSS만) |
| 정규식 | 11개 | 4개 (에셋 3개 + 상태창, 원본과 동일) |
| 로어북 | 166개 | 같은 166개 + 매니페스트 1개 |

- 시작 화면: 소속 5개, 한국어/English, 상황(세력별 첫 장면, 직접 입력).
- 플로팅 버튼: 1초마다 현재 캐릭터·채팅 번호와 채팅 화면 여부만 확인하고, 캐릭터가 바뀔 때만 Lite 여부를 확인합니다. Lite 채팅 화면에 들어올 때마다(다른 봇이나 설정 화면에서 돌아올 때 포함) "ANOMALY SIMULATION" 접속 효과(2.4초)가 나옵니다. 동작 줄이기 설정이 켜져 있으면 짧게 페이드만 합니다.
- Risu는 플러그인의 클릭 리스너를 버튼이 아니라 문서 전체에 붙입니다. 그래서 클릭·끌기는 모두 좌표로 버튼 영역인지 확인한 뒤에만 반응합니다. 이벤트가 비동기로 오기 때문에 선택지 용사와 같은 방식으로, 리스너는 처음에 한 번만 걸고 누를 때마다 이전 끌기 상태를 버립니다. 손을 떼는 이벤트를 놓쳐도 버튼이 굳지 않고, 끌고 놓은 뒤의 클릭은 무시합니다.
- START를 누르면 원본 Lua의 `setup-start`와 같은 채팅 변수(`st_faction`, `st_lang`, `st_fm`, `ib_affiliation`, `seed_lore` 등)를 저장합니다. 로어북의 세력별 분기는 그대로 동작합니다.
- 시작 자료(Start trigger 목록의 로어북)는 첫 전송과 그 리롤에만 들어가고, 두 번째 전송부터 빠집니다 (원본과 같은 규칙).

## 원본에서 옮기지 않은 것

- 원본의 버튼 위치·크기·접기, 모바일 지도 표시 설정 (플러그인은 끌어서 옮기는 유령 버튼과 자체 창을 씀).
- 괴담넷·괴담톡·위키의 처음 값을 `Settings` 로어북에서 읽는 것 (각 탭의 설정이 채팅별로 저장됨).
- 괴담톡: 내 사진·선물 첨부 보내기, 괴담넷과 묶은 자동 요청, 토큰 예산에 맞춘 기록 자르기, 페이지당 공지 수.

## 알려진 한계

- 설정·보조모델 이미지 태그(v0.7.0), 괴담톡(v0.6.0), 괴담넷(v0.5.0), 위키(v0.4.x)는 아직 실제 Risu와 실제 모델에서 확인하지 않았습니다. 1~3단계는 실제 Risu에서 확인했습니다.
- 지도 이미지는 카드 에셋을 `readImage`로 읽습니다. 못 읽으면 이미지 없이 핀만 보입니다.
- 괴담넷·괴담톡 요청의 주인공 이름은 "주인공"으로 보내고, 페르소나 설명은 보내지 않습니다(플러그인이 현재 페르소나를 읽을 수 없음). 전화 기록의 `{{user}}`는 Risu가 본편 요청에서 페르소나 이름으로 바꿉니다.
- 지시문 카드의 투입 칸에는 페르소나 이름 대신 "나"로 표시합니다(플러그인이 현재 페르소나 이름을 읽을 수 없음). 모델에 가는 지시문에는 영향이 없습니다.
- 빈 채팅에서 Risu 기본 인사말 넘기기(화살표)로 추가 인사말을 직접 넘기면, 소속 변수와 화면의 첫 장면이 어긋날 수 있습니다. 시작은 괴이봇 버튼으로 해 주세요.

## 개발

```bash
npm install
npm run typecheck
npm run build            # dist/goei-plugin.js
npm test                 # 순수 로직 단위 검사

# 경량 카드 만들기 (원본은 읽기만 함)
python3 tools/build_lite_card.py <원본.charx|봇카드.jpeg> release/괴이봇_Lite.charx
python3 tests/verify_lite_card.py <원본> release/괴이봇_Lite.charx

# 실제 Chromium에서 가짜 risuai API로 시작 화면 검사
python3 tests/make_fixture.py release/괴이봇_Lite.charx /tmp/fixture.json
node tests/browser.mjs /tmp/fixture.json [스크린샷 폴더]   # 지도·세력·인물 사진은 fixture 옆 assets/
```

구조:

- `src/core/` 순수 로직 (시나리오 데이터, 시작 계획, 시드, 요청 처리). Risu API를 부르지 않아 단위 검사 가능.
- `src/core/cbs.ts` 로어북 조건문(CBS) 해석, `src/core/refs.ts` 참고 자료 모으기(원본 REFERENCE_CORE), `src/core/wiki.ts` 위키 저장·프롬프트·검사·렌더링, `src/core/gnet.ts` 괴담넷 저장·규칙·응답 검사, `src/core/gnetPrompt.ts` 괴담넷 요청문, `src/core/phone.ts` 괴담톡 저장·연락처·대화 규칙·응답 검사, `src/core/phonePrompt.ts` 괴담톡 요청문, `src/core/settings.ts` 기본 설정·괴이 생성 수치(채팅 변수 > 플러그인 저장소 기본값 > 옛 Settings 로어북), `src/host/prefs.ts` 새 채팅 기본값 저장(pluginStorage `goei:prefs`), `src/ui/images.ts` 카드 에셋 사진 캐시, `src/core/asset.ts` 이미지 태그 보충(자료 검사·요청문·삽입).
- `src/core/factions.ts` 플레이 세력 목록(기본 다섯 + 명부의 새 세력), 태그·세력 로어북 자리표시자 변수와 넣기.
- `src/core/world/directory.ts` 카드 명부(로어북 폴더 + 괴이봇 명부 + 옛 목록 합치기, 조직, 명부로 옮기기), `src/ui/directory.ts` 카드 명부 편집 화면, `scripts/migrate-lore.mjs` 경량 카드 만들 때 명부로 옮기기·원본과 비교.
- `src/core/dispatch.ts` 이동·커스텀 임무 지시문 조립, SCENE_CARD 기록 읽기·풀기.
- `src/core/world/` 상황판 엔진 (지역 표 `src/data/geo.json`, 로어북 목록 읽기, 태그 읽기/지우기, 발생·반영·브리핑).
- `src/host/` Risu API 래퍼. 저장 직전에 최신 채팅을 다시 읽어 변경을 덮어쓰지 않습니다.
- `src/ui/` 플러그인 전용 창 (iframe 안의 일반 DOM). `field.ts`가 지도·커스텀 임무 탭, `wiki.ts`가 위키 탭, `gnet.ts`가 괴담넷 탭, `phone.ts`가 괴담톡 탭, `settings.ts`가 설정 탭. `src/host/asset.ts`가 응답 뒤 보조모델 이미지 태그 보충.
- `tools/` 경량 카드 빌더. `rpack_map.bin`은 Risu 저장소의 rpack 치환표(MIT, `RPACK-LICENSE_MIT.txt`).

원칙: 채팅 렌더링 경로에는 무거운 일을 붙이지 않습니다. 요청 리플레이서는 시드 표식이 있는 요청과(Lite 채팅에서) 괴담넷 본편 반영에만 채팅을 읽고, 요청 도중에는 채팅을 저장하지 않습니다.
