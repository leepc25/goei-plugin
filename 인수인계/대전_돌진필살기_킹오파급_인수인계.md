# 대전 돌진 필살기를 킹오파98급으로 · 인수인계 (2026-11-09 21:10 KST 기준)

이 문서 하나와 폴더 `인수인계/대전_돌진필살기/`(아래 `보기/`·도구는 모두 이 폴더 안)만 보면 이어서 할 수 있게 정리했다. 다른 인계서·공유 폴더는 안 봐도 된다.

## 1. 하려는 일
조성춘의 돌진 난무 필살기를 킹오파98 필살기처럼 만든다. 시작 연출, 연타, 띄우기, 공중 연타, 내려찍기, 마무리 폭발까지 한 벌. 사용자 말: 「일단 1명이라도 킹오파 필살기처럼」, 마지막 「뭐가 됐든 완성을 해봐 하나라도」.

## 2. 지금 상태 (한 벌 완성, 사용자 답 기다리는 중)
- 처음부터 끝까지 이어 붙였고, 킹오파와 같은 장 번호로 나란히 도는 영상을 사용자에게 보냈다. 사용자 답은 아직 없다.
  - `보기/완성_킹오파_나란히_60장.mp4` (실제 속도), `보기/완성_킹오파_나란히_4배느리게.mp4`. 왼쪽 킹오파 롬, 오른쪽 우리.
- 시연판(웹에서 바로 해 봄): https://claude.ai/artifact/XexDGtsuQJK9PJVQ4MuNei (19판). 새 계정에서 안 열리면 아래 3의 방법으로 빌드해서 다시 올린다.
- 흐름(60장 = 1초):
  1. 시작: 배경만 흰색 4장(캐릭터는 그대로) → 검은 배경. 둘 다 28장 멈춤. 뒤에 둥근 빛이 바깥 띠부터 꺼지며 줄고, 가슴 앞 빛덩이 8장 → 빛살 8장. 멈춤이 풀리면 검은 배경 바로 걷힘.
  2. 돌진 → 연타 12대. 한 대 약 9장. 첫 대·4대마다·강타는 큰 한 방(바늘 다발 불꽃), 흰 배경은 첫 대만 2장.
  3. 띄우기(상대 발밑 불기둥) → 점프 → 공중 4대 → 내려찍기(배경만 흰 2장).
  4. 마무리: 배경 흰 4장, 불기둥, 큰 한 방 두 번.
  5. 흔들림은 화면이 위아래 4점, 두 장마다 번갈아.

## 3. 코드와 도구 (저장소 leepc25/goei-plugin)
- 작업 브랜치 `claude/project-thread-oke0n4`, 마지막 커밋 `6e809280ff`. main에는 아직 안 들어감(릴리스는 사용자가 「릴리스해」라고 할 때만).
- `src/game/versus/fight/fighter.ts`의 `rushSuper()`: 필살기 전체 흐름. 한 대 박자는 `beat()`, 맞는 자리 효과는 `bigFx()`.
- `src/game/versus/fight/match.ts`의 `superFlash()`: 시작 연출(멈춤 28/60초, 흰 배경, 검은 배경, 둥근 빛·빛덩이·빛살). `bgWhite`(배경만 흰색), 흔들림은 `draw()`의 `shY`.
- 효과 그림은 PixelLab 없이 손으로 찍는다. `tools/dotfx/`:
  - `hand/*.txt`: 글자 격자로 점 하나씩(예: `hand/ball.txt` 빛덩이 8장).
  - `hand_dot.py`: 색 글자표(PAL, 9단 '1'~'9'·'K').
  - `hand_mass.py`: 큰 한 방 `dot-hand-big3`(64×64, 10장, 바늘 36개를 손으로 정함).
  - `hand_start.py`: 둥근 빛 `dot-hand-orb`(띠 번호 그림 한 장 + 색표를 한 칸씩 민 13장), `dot-hand-rise`(빛덩이 + 빛살).
  - 굽고 나면 `add_to_pack.py`로 game-pack/action-fx에 넣는다.
- 빌드: `GOEI_GAME=1 node scripts/build.mjs` 뒤 `git checkout release`(빌드가 release 폴더를 건드림). 결과 `dist/goei-waitfight.html`. 로컬 보기는 저장소 맨 위에서 `python3 -m http.server 8765` → `http://localhost:8765/dist/goei-waitfight.html?pick=조성춘,스팡달&bg=street`.
- 시연판 다시 올리기: `dist/goei-waitfight.html`을 Artifact로 올리고, 팩이 바뀌었으면 `vs-src/vs-common.wasm`도 함께 올린다(`dist/vs-src/vs-common` 묶음: 4바이트 LE 머리 길이 + JSON [[이름, 위치, 길이]] + 데이터, contentType application/wasm).

## 4. 롬에서 잰 것 (자세히는 `롬_구조_뜯어보기.md`)
- 시작: 둥근 빛은 160×160 그림 한 장(15단 띠), 팔레트를 한 장마다 한 칸 밀어 줄어 보이게 함. 빛덩이 4×4→1×1타일 8장, 빛살 9장(장마다 새 그림).
- 큰 한 방: 64×64 스프라이트 하나, 16색 중 10색, 확대 없음, 장 길이 6,4,4,4,4,3,2,1,1,2(약 31장), 캐릭터 앞.
- 흰 화면은 배경색만 바꾼 것(캐릭터 그대로). 흔들림은 화면 전체 Y 4점.
- 참고 그림: `보기/큰한방_확대_매장.png`, `보기/테리_버스터울프_매장_80장.png`, `보기/돌진필살기_맞힘_80장.png`.

## 5. 롬 보는 법 (이 폴더의 도구)
- 롬 파일(kof98k.zip, neogeo.zip)은 저장소에 없다. 사용자에게 받는다.
- MAME 0.264: `SDL_VIDEODRIVER=dummy mame kof98k -rompath roms -video none -sound none -nothrottle -seconds_to_run N -snapshot_directory D -autoboot_script X.lua -skip_gameinfo`.
- `vs6.lua` 등: 2인 대전으로 들어가(코인 300·320장, 시작 400·420장) 상대를 세워 두고 필살기를 넣는다. 파워 칸 0x1083ef·0x108408에 3, 0x108292에 1을 매 장 써 넣는다. 테리는 앞으로 90장 걷고 ↓↘→↘↓↙←+A(한 칸 3장)로 맞는다.
- `vsv.lua`: 매 장 화면 메모리(SCB2~4, SCB1)·팔레트 RAM을 덤프. `vr.py`로 스프라이트 묶음을 찾고 `rend.py`로 그린다.
- `rushcap9.js`: 우리 게임을 한 장씩 찍는다(`node rushcap9.js 조성춘 스팡달 1 290`). 찍은 장과 롬 캡처를 같은 장 번호로 붙여 ffmpeg로 나란히 영상을 만든다.

## 6. 사용자 규칙 (이 일에서 들은 것)
- 효과는 손으로 한 점씩. 원·선 몇 개로 때우는 「도형놀이」 금지. 크게만 키우지 말 것, 캐릭터를 가리지 말 것.
- 「이펙트의 매스가 다르다」: 가는 선·고른 가시가 아니라 바늘 다발과 9단 색 덩어리.
- 롬은 분석·참고만. 킹오파 그림을 그대로 넣지 않는다. 롬 쓰기를 거부하지도 않는다.
- 캡처를 펼쳐 놓고 보고 따라 그리지 말고, 롬 구조(화면 메모리·팔레트·타일)를 뜯어서 표로 만들고 그대로 짓는다.
- 보여 주기 전에 킹오파와 캐릭터 키를 맞춰 나란히 비교한다. 정지 그림 몇 장으로는 「뭐가 바뀐 건지 모르겠다」고 했다. 바꿀 때마다 나란히 도는 영상으로 보여 준다.
- 번쩍임 제한은 대전에서 풀렸다. 그림은 파일 경로 링크로 보내고, 일을 멈춰 두지 말고 진행을 알린다.

## 7. 남은 일
1. 사용자가 영상을 보고 하는 말대로 고친다.
2. 빛덩이·빛살의 장수·크기를 롬 표에 더 맞춘다.
3. 시작 때 캐릭터가 기를 모으는 자세로 바뀌는 것(킹오파처럼). 조성춘 그림에서 맞는 장을 찾는다.
4. 다른 캐릭터로 넓히는 건 사용자가 말할 때.
5. 사용자에게 물어 둔 것(답 없음): 롬처럼 데이터 묶기. 캐릭터별 팔레트 번호, 16×16 타일 중복 없애기, 2P·맞음·기운은 팔레트만 바꾸기. 지금 139MB → 15~30MB 예상. 「해」 전에 시작하지 않는다.
