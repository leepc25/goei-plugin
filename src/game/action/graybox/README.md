# 회색 상자 시험판 · 차원 승강기

작성일: 2026-10-20 / 상태: 그림 없는 규칙 시험판. 시각 품질·캐릭터 통일성과는 무관하다.

`docs/게임_기본기획서.md` 23장 5단계("회색 상자 + 가짜 팩 부하 시험 + 크기 비교")를 구현한 것이다. 그림은 한 장도 쓰지 않고 상자와 글자만으로 전투·층 생성·정비 구역·승강기·규칙·드랍·강화·본부 순환을 돌려 본다. 시연판은 `release/demo/goei-graybox.html` 하나이며, 코드·CSS를 전부 내장해 파일을 열기만 하면 된다(약 100KB).

## 1. 들어 있는 것

| 영역 | 구현 | 출처 |
| --- | --- | --- |
| 전투 | 30Hz 고정 틱, 근접 3연타·돌진·공중·하단, 원거리, 고유기(폭파/읽기), 필살(게이지 100, 컷인 자리), 가드, 회피(요원별 뒤로/옆으로), 앉기, 점프, 잡기·던지기(경직 중인 적에 닿으면), 히트스톱·경직·다운·무적, 슈퍼아머 0~3 | 기본기획서 6장, 부록 A·E |
| 요원 | 쟈알디·에일린 2명(체력·속도·고유기·회피 방향만 다름) | 캐릭터제작서 01·02 |
| 층 생성 | 반 화면(640px) 청크 조합 + 고정 방 5종, 시드 난수(mulberry32), 검증 3회 재시도 후 대체 | 스테이지설계서_차원승강기 7장 |
| 층 유형 | 침묵·어둠·추격·퍼즐과 선택·재현(아파트)·시험 6종 + 로비 L1~L3 | 같은 문서 4장 |
| 정비 구역 | 세로 미로, 다락방(휴식·송신·귀환 로프), 90초 뒤 포식자, 다시 뽑기 | 같은 문서 5장 |
| 승강기 | 매 층 끝에서 다음 층 유형 3택, 총애 −3~+3(인사/닫기 연타), 호명 줄 | 같은 문서 6·9장 |
| 위협 예산 | `budgetFor(depth, chunk, danger, variant, growth)`, 화면 상한 8, 초과분은 정예로, 2파 | 기본기획서 8.4 |
| 수호자 | 유형별 1종(원형 행동만) | 같은 문서 8장 |
| 규칙·드랍·강화 | 규칙서 줄 수집, 4재화, 가방 6칸, 출동 내 강화 | 기본기획서 7·10장 |
| 본부 | 임무 선택 → 브리핑 → 투입 → 정산(귀환/후송) 순환, 후송 손실 A4 | 기본기획서 3장 |
| 크기 비교 | 정자세 키 128/96/80px 상자 높이 전환(저장됨) | 결정 A20 |
| 부하 시험 | 가짜 도트 PNG(16색 덩어리)를 실제 장수·크기로 생성 → IndexedDB 저장 → 읽기 → 디코딩 → 층 교체 10회, 시간·바이트·힙 측정 | 구현가능성 검토 5.1 |

부하 시험 기본 규격(`DEFAULT_SPEC`): 요원 2명 × 190장, 적 8종 × 40장, 타일셋 5장. 크기 128/96/80 각각 눌러 비교한다. IndexedDB는 RisuAI `pluginStorage`의 대용이며 실제 Risu 안의 수치와 모바일 실기 수치는 따로 재야 한다.

## 2. 조작

방향키 이동(같은 방향 두 번 = 달리기) · A 근접 · S 원거리 · D 고유기 · Q 가드 · W 필살 · E 상호작용/승강기 인사 · Space 점프 · Shift 회피 · ↓ 앉기, 앉아 A 하단 · 달리며 A 돌진 · 공중 A · 1~4 아이템 · Z 지도 · Esc 메뉴 · 승강기·본부 선택은 숫자 키 또는 클릭. 모바일은 아래 버튼 줄과 왼쪽 스틱. X 자동 전환은 아직 없다.

## 3. 파일

| 파일 | 역할 |
| --- | --- |
| `data.ts` | 요원·적·수호자·규칙·임무·강화·아이템 표, `budgetFor`, `depthLabel` |
| `gen.ts` | `makeFloor`, `makeService`, `validate`, `pickType`, `rng` |
| `sim.ts` | 실행 상태(Run/Meta/Player/Ent), `step`, `interact`, `settle`, 직렬화 |
| `render.ts` | 캔버스 그리기(상자·글자·HUD·소지도·오버레이) |
| `loadtest.ts` | `runLoadTest`, `DEFAULT_SPEC` |
| `index.ts` | `mountGraybox(box, host)`: 패널·키·터치·자동 저장·`window.__gb` |
| `demo.ts` | 단독 HTML 진입점(저장소 `localStorage goei-graybox:v1`) |

빌드는 `npm run build`가 `dist/goei-graybox.html`과 `release/demo/goei-graybox.html`, 시험용 `dist-test/graybox-sim.mjs`를 함께 만든다. 시험은 `node --test tests/graybox.test.mjs`(생성·전투·정비 구역·직렬화 8건)와 `node tests/graybox-browser.mjs`(Playwright 연기 시험, PC·모바일 스크린샷).

## 4. 확인한 것과 못 한 것

- 확인: 타입 검사·빌드·단위 8건·브라우저 연기 시험 통과. 무작위 봇 12판이 전 층 유형을 거쳐 B-12까지 내려가 정산까지 끝남(예외 없음).
- 못 한 것: 실제 RisuAI pluginStorage 안의 부하 수치, 모바일 실기 체감, 플러그인 창 안에 넣기(지금은 단독 HTML), X 자동 전환, 승객 조우·난입·지원 호출·숙련 동작·NPC 대화, 수치 균형. 전부 다음 단계다.
- 이 시험판 통과는 기술 시험 통과이며 그림·동작의 시각 품질 합격이 아니다(AGENTS.md).
