## 현재 계정과 비용

- `get_balance`, `list_jobs`, `search_help`는 HTTP 200 안에 MCP `isError=true`, `401 Missing Authorization header`를 반환했다. HTTP 성공은 인증 성공이 아니다.
- 현재 잔액·실행 중 작업 수·계정 한도는 모두 미확인(`null`). 과거 Tier 3/20개/17,000회 기록을 현재 값으로 사용하지 않는다.
- 이번 총괄/큐라스 회수 담당의 신규 생성 호출·신규 생성 차감은 0. 계정 전체에서 다른 제작자가 쓴 비용은 미확인이다.
- `job-inventory.json`: 원장 16개에서 작업 ID 1,420개를 중복 제거하고 출처 줄·원장 해시·manifest 20개의 해시를 수집했다. 명시된 작업 ID만 인덱싱한 것이므로 계정 전체 작업 목록은 아니다.
- 개별 작업의 서버 실제 비용은 아직 확인하지 못했다. `actual_cost=null`. 과거 `charged` 등 비용 주장과 실패 문구는 별도 배열에 원문·줄번호를 보존한다. 공유 계정 잔액 차이를 한 작업의 비용으로 계산하지 않는다.
- 각 담당은 서버 usage/영수증의 단위와 원문을 함께 제출한다. USD와 구독 생성 횟수를 합산하지 않는다. 서버에 비용이 없으면 추정으로 채우지 않는다.

계정 조회 재개(환경 비밀 변수 `PIXELLAB_API_TOKEN` 또는 `PIXELLAB_API_KEY`, 또는 승인된 MCP 인증 연결 후):

```bash
python3 game-src/action/character-resume/control.py account
python3 game-src/action/character-resume/control.py inventory
```

인증값은 저장소·채팅·명령 인수에 기록하지 않는다. 이 도구는 무료 계정 조회만 하며 생성·취소 기능이 없다. 조회 성공 후 원문을 확인해 `queue.json`의 계정 수치와 관측 시각을 갱신해야 한다. 현재 큐의 제출 허가는 꺼져 있다.

## 준비 자료 선택 인계

`handoff-index.json`에 담당별 파일, 원격 고정 링크, SHA-256을 기록했다. 원본은 준비 브랜치에 보존돼 있다. 각 담당은 필요한 경로만 가져오고 최신 제작 원본을 덮어쓰지 않는다.

```bash
git fetch origin codex/character-production-resume
# 아래 <경로>는 handoff-index.json에서 선택한다.
git restore --source=087dec121b9d65ad1c91fd3b1d5b1d669ba70fe4 -- <경로>
```

- 큐라스: 기존 회수 도구·5개 오프라인 검사·프레임별 검수·원본 인덱스. 담당이 `tools/recover_kyuras_jobs.py`로 분리해 계정 조회 중복을 제거했다.
- 쟈알디: `game-src/action/jyaldi-v5/resume/`의 참조 좌표, 뼈대, 걷기/달리기 요청 초안, 검증 및 겹침 그림과 `jyaldi-audit.md`. 미제출 초안이다. 공개 견적 각 3회는 과거 관측이며 다음 호출 직전 다시 확인한다.
- 에일린·다른 요원: `other-agents-audit.md`의 장별 결함과 최신 납품 대조. 생활·사교 양산보다 전투·이동 결함 우선.
- 검수 담당: 납품 빌더/검사, 독립 검수 HTML 빌더/템플릿/브라우저 검사, 엔진 연결 계약. 기존 HTML은 기존 원본의 검수 도구이며 수정 그림 납품이 아니다.
- `engine-delivery-preparation.patch` 전체 적용은 하지 않는다. 엔진·본부·스테이지·공용 atlas·통합 HTML은 이 작업에서 수정하지 않는다.

쟈알디 grabknee/탈의/샤워, 큐라스 walk_shotgun/씻기, 에일린·고르고디오 씻기, 데드폴 씻기 후속 납품을 오래된 미완료 표만 보고 다시 생성하지 않는다. `source-comparison.json`은 준비 브랜치와 현재 시스템의 원본 차이가 없음을 확인한 기록이다. 담당의 새 제출이 오면 다시 fetch해서 해시 대조한다.

## 제출·검수 규칙

1. 캐릭터별 담당은 한 명만 배정한다. 별도 동일 캐릭터 담당이 확인되면 제출을 멈추고 소유권을 조율한다.
2. 총괄이 현재 계정 큐/한도와 담당당 제출 중 1건을 확인한다. 최초에는 전체 유료 제출도 한 건씩 조율한다. `queue.json`은 원장이며 분산 잠금 서비스가 아니다. 별도 환경에서 각자 제출하면 안 된다.
3. 호출 전에 클립·견적·도구·요청문 해시·입력 해시·승인 근거를 기록하고 사용자에게 실제 차감 견적을 알린다. 응답 직후 작업 ID를 보존한다. 전송 결과가 불명확하면 재제출하지 않고 기존 작업을 찾는다.
4. 원본/응답/usage/실패를 보존한다. 실패 시 같은 방식에 문구만 바꿔 반복하지 않는다. `submission-receipt.template.json`은 제출 형식이며 실제 작업이 아니다.
5. 장별 얼굴·체형·복식·손/파지·지지발·반복 경계 또는 공격 연결을 정지 장과 재생으로 검수한다. 다른 캐릭터 그림을 동작으로 쓰지 않는다.
6. 수정 그림을 실제 반영한 독립 HTML을 PC/모바일에서 검수하고 본인 브랜치 commit/push 및 고정 링크를 제출한다. 생성 완료, 내부 검수 통과, 사용자 시각 승인은 별도 상태다.

현재 새 그림과 새 그림 반영 HTML이 없으므로 최종 시각 검수·납품은 미완료다. 과거 HTML 링크로 이를 대신하지 않는다.
