## 첫 수정 2건 — 각각 8장·예상 3회, 합계 6회

현재 공개 MCP 요금 설명은 뼈대 v3의 4~14장에 3회다. 실제 비용은 제출/회수 후 서버 영수증으로 확인해야 한다.
기존 로제몬 승인 상한은 712회, 과거 약 330회 사용이라는 인계가 있으나 정확한 누적 실비는 미검증이다.

1. `down`: 뒷머리 경계와 마지막 장의 갑작스러운 기립을 고친다. 끝 3개 뼈대는 누운 자세 유지.
2. `man_throw`: 뒤로 젖힌 머리·팔에 여백을 확보한다. 먼저 다운 결과를 검수한 다음 제출한다.

`requests/`는 **미제출 초안**이다. `inputs/`는 새 그림이 아니라 기존 기준에 투명 여백을 더한 API 입력이다.
192×144 → 256×160, 이동 (48,8), 크기 변경 없음. 기준 그림과 모든 관절에 같은 변환을 적용했다.
기존 생성기가 생략한 `view`를 `side`로 명시했다. 공개 schema 검증·18관절·좌표 범위·입력 픽셀 보존 검사를 통과했다.
공식 `search_help` 답은 인증 때문에 받지 못했으므로 연결 후 여백 처리와 실제 비용 조회 방법을 확인한다.
요청 해시·기준 해시·입력 해시·앵커·바닥선은 `queue.json`에 있다.

새 원본은 256×160 그대로 보존한다. 예전 192×144로 무조건 잘라내면 다시 머리가 잘릴 수 있다.
독립 HTML은 새 크기, 기준점 x=105(본체)/104(마네킹), 바닥 y=144를 반영한 후 검수해야 한다.
현재 `gen.py`는 예전 192×144 요청을 만드는 도구이므로 **이 수정 초안 제출에 사용하지 않는다**.

## 프레임 검수 결과 (원본 번호 00부터)

`evidence/*-before.png`는 기존 원본을 최근접 확대해 본 검사 자료다. 생성 결과가 아니다.

- `down` 00~02: 뒤로 넘어가는 단계는 읽힘. 03은 불투명 영역 x=0에 닿고 머리카락이 경계와 겹친다. 04는 x=1, 05~06은 x=8로, 인계의 “03~06 모두 왼쪽 잘림”을 전부 확정하지 않는다. 05~06은 거의 같은 누운 자세. 07은 갑자기 서서 얼굴·체형·복식 연속성이 깨진다. 기존 final은 07을 이미 제외했으므로 새 결함으로 중복 집계하지 않는다.
- `man_throw` 00~02: 준비·팔 들기가 읽힘. 03의 불투명 영역은 x=6, 04는 x=0이며 팔/손이 경계에서 잘림. 05는 팔이 얼굴 앞에 겹쳐 손 형태가 불명확. 06~07은 회수. 얼굴 없는 나무 구체 관절 체형은 유지됨.
- `walk` 00~06: 얼굴·연보라 머리·검정 정장/치마는 유지. 07은 팔짱에서 손이 얼굴 앞으로 갑자기 올라가 07→00 경계가 튄다. 다리 교차가 작고 접지 궤적은 재생 확인 필요.
- `run` 00~07: 걷기와 속도 차이를 보여 줄 실루엣이 약함. 05~06 앞손이 펴져 보이고 07에 다시 내려가 손 모양 연속성 보완 필요. 공중기를 구분하지 않은 일괄 바닥 보정은 금지.
- 얼굴/손 세부와 접지·반복 경계의 최종 합격은 **새 결과 재생 검수 후** 판정한다. 생성 완료와 사용자 시각 승인은 둘 다 아직 아니다.

## 큐·중복·비용 관리

- 로제몬 담당은 이 브랜치, 제출 중인 작업은 최대 1건. 다른 담당의 로제몬 예약이 보이면 제출하지 않는다.
- 이 세션에서 발견한 해당 원격 브랜치는 기존 씻기 인계뿐이며, 새 담당의 서버 큐는 인증 후 확인해야 한다.
- `historical-job-index.json`은 각 캐릭터의 기존 spend.log에서 추출한 1,355개 고유 작업 ID와 근거 행이다. 로제몬의 변경 폴더 안에만 색인을 보존했다. 서버 영수증을 받지 못한 개별 `actual_cost`는 null이다. 잔액 차이는 동시 작업 때문에 개별 비용 증거가 아니다.
- `gen.py`의 유료 제출 자동 재시도와 한도 응답 재삽입을 제거하고 동시 제출을 1건으로 제한했다. 네트워크 전 요청·해시를 보존하고 응답/작업 ID를 기록한다. 같은 요청 해시는 자동 재제출되지 않는다.
- timeout/접수 불명은 `unknown`으로 기록한다. `resume/submissions/`의 미해결 작업을 서버와 대조하기 전 다음 실행은 차단된다. 수신 완료·실제 비용 확인 후에만 상태를 해소한다. 실패했다고 기록 파일을 지우거나 seed만 바꿔 반복하지 않는다.
- `mcp.py`는 환경 비밀 변수와 기본 CA 신뢰를 사용하도록 고쳤다. 토큰은 요청/로그에 저장하지 않는다.

## 인증 연결 후 실행 순서

1. `PIXELLAB_API_TOKEN`을 환경 비밀 변수로 연결한다. 값은 채팅·Git에 넣지 않는다.
2. 무료 `get_balance`, `list_jobs(include_recent=true)`, `search_help`를 다시 실행하고 관찰 시각·현재 한도를 기록한다.
3. 총괄과 계정 큐·로제몬 소유권을 대조한다. 기존 작업이 있다면 ID로 회수하며 중복 제출하지 않는다.
4. 예상 3회를 재고지하고 `requests/down.json` 한 건만 제출한다. 전송 전 예약/해시, 직후 응답/작업 ID를 보존한다. 모호한 응답이면 재전송하지 않는다.
5. 원본·작업별 실제 비용·실패 기록을 보존하고 전 장을 검수한다. 미흡하면 원인을 조사해 방식을 바꾼다.
6. 새 원본과 앵커를 로제몬 독립 HTML에 반영해 PC·844×390 모바일에서 검수하고 commit/push 후 커밋 고정 실행 링크를 전달한다.
7. 다운 통과 후 마네킹 던지기, 이후 손/걷기/달리기를 처리한다. 생활·씻기 양산은 뒤로 둔다.

오프라인 검사: `python3 game-src/action/rojemon/resume/prepare.py`와 `python3 game-src/action/rojemon/resume/test_safety.py`.
이 검사는 실계정 인증/생성 성공이나 사용자 시각 승인을 뜻하지 않는다.
