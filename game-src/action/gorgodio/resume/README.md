# 고르고디오 제작 재개 · 총괄 인계

2026-10-22(한국 시간). 브랜치 `codex/art-gorgodio-resume`.
**실제 신규 PixelLab 생성은 인증 차단으로 미완료.** 생성 완료·내부 검수·사용자 시각 승인은 별도 상태다.
몸과 갑옷은 이 브랜치의 단일 담당 범위이며 분리 발주하지 않는다.

## 실행 환경과 계정

- 현재 잔액·계정 동시 실행 한도·실행 중 작업: **미확인**. 과거 17,000회/Tier 3/20칸을 현재 값으로 쓰지 않는다.
- 사용자가 이 채팅의 클라우드 환경 비밀 변수에 인증을 등록했다고 알린 뒤에도 다시 확인했다.
  환경 관측 리비전 5, 비밀 변수/런타임 변수 목록 모두 비어 있음. 새 명령의 PixelLab 변수명도 없음.
  `get_balance`, `list_jobs`, `search_help`가 `401 Missing Authorization header`를 반환했다.
  HTTP 200 안의 MCP `isError`를 성공으로 취급하지 않았다. 시각이 기록된 원응답은 `evidence/`에 있다.
- 이 작업의 유료 생성 요청 **0건**, 신규 차감 **0회**, 작업 취소 **0건**.
- 최신 공개 도구 계약: skeleton v3 3장 2회, 4~14장 3회, 15장 4회. 이는 견적이며 실제 비용이 아니다.
  고르고디오 기존 상한 690회/사용 약355회는 과거 인계 추정치다. 정확한 잔여 승인량으로 확정하지 않는다.
- 인증 반영 뒤 무료 계정 조회와 실제 계정 한도를 확인하고, 계정 총괄 예약·다른 담당 작업을 대조한다.
  기존 승인 범위의 수정 한 건을 고르고디오 담당이 견적 고지한 뒤 제출한다. 생활·사교 양산은 보류한다.

  두 브랜치 모두 `167b76fe90ff7ba19a8e20eef52a45c77321cc2a`로 동일하다. 전체 브랜치 병합 없음.

  이는 전체 계정 거래 내역이 아니라 저장소 원장의 대조 목록이다.

## 몸·갑옷 장별 검수

직접 확인 범위는 `contact-00.png`~`contact-09.png`의 **20클립**이다.
103클립 전체를 시각 합격시킨 것이 아니다. 얼굴·체형·복식·손·접지·순환 경계를 같은 배율/기준점에서 비교했다.

| 원본 장 | 관찰과 후속 처리 |
|---|---|
| idle 0~3 / a_idle 0~3 | 민머리·수염·검은 재킷 / 헬멧·판금·등 부스터는 유지. 작은 호흡 반복. 두 모습의 기준 발바닥 불일치는 별도 확인 필요 |
| walk 0~7 / a_walk 0~7 | 양발 교차는 있으나 맨몸 팔 스윙이 작고 7→0 자세 변화가 남음. 몸의 최하단 y=169,169,169,170,170,168,168,168; 갑옷 187,187,187,187,186,187,187,187. 발 지지 구간 추적 후 수정해야 하며 전체 최하단만으로 자동 접지하지 않음 |
| run 0~7 / a_glide 0~5 | 맨몸 큰 보폭·팔 동작이 약함. 갑옷 활강은 무릎 굽힘과 발 높이가 거의 고정. 둘은 설계상 다른 이동이므로 같은 자세로 강제하지 않음. 활강 최하단 y183, manifest 기준184 |
| jump 0~7 / a_jump 0~7 | 준비·공중·착지 순서는 읽힘. 갑옷 1·6에 부스터 불꽃이 원본에 남음. 공중 장까지 바닥에 고정하면 안 됨 |
| land 0~2 / a_land 0~2 | 웅크림→일어남. 갑옷은 원래 그림의 밑면이 선언된 발 기준선보다 낮음. 맨몸/갑옷 전환 위치를 같은 기준으로 검증 필요 |
| guard 0~3 / a_guard 0~3 | 얼굴/헬멧과 팔 형태는 대체로 유지. 맨몸은 식칼 대기, 갑옷은 팔을 들어 막는 동작이며 서로 같은 포즈가 아님. 갑옷 끝→첫 장에서는 팔이 다시 내려감; 비반복 클립임을 유지 |
| chop1 0~4 / a_swat 0~5 | chop1 1에서 뒷머리와 치켜든 팔로 얼굴이 가려짐. 3 타격 뒤 4 칼끝 윤곽이 흐림. a_swat은 횡방향 팔 뻗기, 몸/헬멧 유지. 맨몸 1의 핵심 자세를 수정해야 함 |
| chop2 0~5 / a_hammer 0~5 | 맨몸 2→3 칼 모양·손 높이 변화가 커서 궤적 재검토. 갑옷 3은 의도된 중간 잔상처럼 보이지만 최종 시각 승인 없음. 4 내려친 뒤 5 회수 |
| cleave 0~6 / a_axe 0~7 | cleave 4 셔츠 흰 면적이 갑자기 늘고, 5 칼 궤적 잔상이 크게 나타남. a_axe 2~3 양손 높이→4~6 내려앉음→7 회수. 몸의 복식 연속성 수정 우선 |
| summon 0~7 / a_arrive 0~4 | **전환 자세 단절**: 맨몸 4~7 한 손을 머리 위로 뻗은 자세로 끝나지만 갑옷 0은 양손 아래·웅크림으로 시작. 크기 확대만으로 연결되지 않음. 동일 담당이 소환 끝/갑옷 시작의 손·골반·발 대응 핵심 자세를 먼저 설계해야 함 |

기준표 자체의 불투명 영역은 몸 `(70,59,109,170)`, 갑옷 `(54,66,142,188)`이다(오른쪽/아래 끝은 제외 좌표).
갑옷 값은 등 부스터를 포함하며 해부학적 신장으로 읽으면 안 된다.
설계서 x84/발168, 최신 인계 x86/발169, manifest x86/발168이 서로 다르다.
갑옷 manifest 발184와 실제 기준 그림 밑면187도 다르다. 비교판은 차이를 숨기지 않고 선언값을 그대로 표시한다.

## 제출 도구 수정

- `scripts/gen.py`: 기본 1건, `--par`는 1만 허용. 클립 하나를 반드시 명시한다.
  이름 없는 전체 양산·기준표 재생성·새 생성으로 넘어가던 `--resume`은 차단했다.
- 유료 제출의 예외/큐 포화 자동 재시도 제거. 보내기 전에 전체 입력과 SHA-256을 배타 생성으로 기록한다.
  같은 입력 재제출, 미회수/미확정 기록이 남은 상태의 다른 seed/몸·갑옷 추가 제출을 차단한다.
- 무료 잔액/작업 목록 오류가 있으면 생성 전 중단. `mcp.py`는 환경 토큰과 기본 CA 설정을 사용한다.
- 결과는 `resume/results/<job-id>/`에 원본/프레임 해시/ID를 보존하며 기존 clips/final을 덮어쓰지 않는다.
  서버 응답과 usage를 제출 기록에 남기되 구조를 확인하지 않은 비용을 숫자로 꾸미지 않는다.
- 프로세스 잠금/제출 기록은 이 worktree의 보호다. **다른 머신·다른 담당의 계정 큐 잠금을 대신하지 않는다.**
  인증·실제 한도·담당별 예약을 총괄이 확인한 뒤만 호출한다. 실행 중이거나 결과가 불명확하면 새 생성하지 않는다.
