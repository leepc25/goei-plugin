## 실제 무료 조회

`evidence/current-tool-contracts.json`은 이번 tools/list 결과다. 공개 명세상 skeleton v3 4~14장=3회. 따라서 걷기 8장 견적 3회; 달리기도 3회지만 아직 다음 큐다.

`balance-probe.txt`, `list_jobs.txt`, `search_help.txt`는 HTTP 200 안의 `isError: true`, **401 Missing Authorization header** 응답이다. 현재 잔액·실행 중 작업·동시 한도는 null이다. 과거 20칸·잔액 기록으로 대체하지 않았다. 환경 변수 연결과 설치된 PixelLab 도구가 없고, 플러그인 검색도 결과 없음. 큐라스 조회/회수와 취소는 실행하지 않았다.

환경 비밀 변수 `PIXELLAB_API_TOKEN` 연결 후:

```bash
python3 game-src/action/jyaldi-v5/resume/preflight.py
python3 game-src/action/jyaldi-v5/resume/audit_resume.py
```

첫 명령은 무료 잔액·활성/최근 작업·한도 도움말만 조회한다. 토큰은 출력/명령 인수/저장소에 넣지 않는다. MCP 오류를 성공으로 취급하지 않는다. 실제 계정 한도는 응답을 읽어 확정한다. 토큰 연결만으로 유료 제출하지 않으며 다른 담당의 큐 점유와 중복 요청을 먼저 대조한다.

## 이번 검수

걷기·달리기 원본 16장과 최종 스트립의 RGBA가 완전히 같다(`source-audit.json`). 최신 달리기 0장은 직립 결함이 이미 고쳐져 삭제 대상이 아니다. 기존 원본 연락표를 재열람했으며 걷기 0~7의 굽힌 무릎·작은 팔 흔들림, 달리기 4장의 펀치처럼 뻗는 팔과 접지 비대칭이 남아 있다. 장별 상세는 `prior-frame-audit.md`.

걷기 뼈대 8장은 원측/근측 팔·다리 교대, 23+23px 다리와 17+14px 팔 길이, 0~4 근측 지지발/4~다음0 원측 지지발 고정, 7→다음0 경계를 기하 검사했다. 이 검사는 새 픽셀 그림의 얼굴·몸·손·접지 합격을 의미하지 않는다. 참조 overlay의 근측 어깨·팔꿈치·손목과 다리 위치를 그림과 다시 대조했다. 가려진 왼팔·먼 눈/귀는 여전히 추정이므로 실제 좌표로 확정하지 않는다. 생성 전 첫 그림과 추정 관절 정합성 최종 검수가 남는다.

그림 안에서 전진하는 주기 48px 설계다. 현재 엔진에 스트립만 끼우면 이중 이동한다. 독립 시연판에서는 주기 중 루트를 고정하고 끝에서만 48px를 이동시켜야 한다. 엔진 담당의 연결 검토 없이 공용 atlas·엔진·통합 HTML에 적용하지 않는다.

## 원장과 다음 제출 절차

`job-index.json`은 요원 8명의 spend.log에서 제출 ID 1,023건을 중복 ID 없이 모은 **과거 기록 인덱스**다. 활성 계정 큐가 아니다. 각 ID에 파일/줄/원문 근거를 붙였으며 실제 비용은 서버 증빙이 없어 null이다. 배치 견적 또는 공유 잔액 차이를 임의로 나눠 실제 비용으로 기록하지 않았다. 회수 담당은 원래 job의 usage를 확보해 연결한다.

각 담당은 캐릭터/클립/입력 PNG SHA-256/정규화 요청 SHA-256/공개 견적/제출 시간/작업 ID/서버 usage 원문/실제 비용 및 단위/실패 사유/납품 커밋을 제출한다. 한 담당당 제출 중 생성은 1건. 계정 큐와 한도가 확인되지 않으면 제출하지 않는다. 응답을 잃으면 새로 제출하지 않고 서버 작업부터 찾는다. 실패하면 원인과 방식 변경을 기록한 뒤에만 다음 요청을 만든다.

`source-audit.json`은 현재 입력/원본/요청 해시를 보존한다. 생성 완료 뒤 새 8장을 별도 원본 폴더에 보존하고 프레임별 얼굴·머리/몸/사지 길이·재킷·손·발·7→0 경계를 A/A2와 대조한다. 그 후 새 그림을 내장한 단일 독립 HTML을 PC/모바일에서 검수하고 commit/push한다. 현재 인증 차단 상태에서는 이 납품 기준을 완료했다고 보고할 수 없다.
