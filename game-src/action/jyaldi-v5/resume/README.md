# 쟈알디 걷기·달리기 재개 설계

**현재 상태: 뼈대 설계만 완료, PixelLab 미제출·그림 미생성·사용자 시각 승인 전.**

`python3 game-src/action/jyaldi-v5/resume/build_drafts.py`는 이 폴더의 초안·도해·기하 검사 결과만 다시 만든다. 네트워크 호출, 원본 변경, 엔진 적용 기능은 없다.

- `reference.json` / `reference-overlay.png`: 최신 guard/00을 직접 보고 맞춘 첫 그림의 18관절. 근측 관절은 그림에 대조했으며, 가려진 원측 팔과 얼굴 뒤편은 추정 좌표다. 독립 검수 전에 바로 제출하지 않는다.
- `walk-request.draft.json` / `run-request.draft.json`: MCP 도구명·인수·견적·미생성 상태. 실제 제출할 인수는 `arguments`이며 바깥 상태 기록은 도구 인수가 아니다. job_id와 실제 비용은 null이다.
- `walk-motion.json` / `run-motion.json`: 192×144 픽셀 관절, 각 장의 지지발, 루트 전진량, 반복 경계, 예상 시간. 생성 결과의 실측 좌표가 아니다.
- `walk-skeleton.png` / `run-skeleton.png`: 각 8장의 뼈대 도해. 빨강은 가까운 RIGHT, 파랑은 먼 LEFT. 실제 캐릭터 그림이 아니다.
- `validation.json`: 18관절, 범위, 사지 길이, 무릎 굽힘 방향, 지지발 고정, 걷기 7→다음0 고정 검사를 통과한 기록. 그림 품질 합격은 아니다.

## 생성 전 조건

공개 MCP `tools/list`를 2026-10-22 이번 세션에서 조회한 가격은 skeleton v3 4~14장당 3회이므로 걷기 8장 3회 + 달리기 8장 3회다. 계정 연결·현재 잔액·실행 중 작업·한도 확인과 첫 그림의 가려진 관절 검수가 끝나야 한다. 걷기 결과를 먼저 A/A2와 비교하고, 그 결과를 봐야 달리기를 제출할 수 있다. 실패 시 같은 방식으로 문구만 바꿔 반복 호출하지 않는다.

기준 계보는 승인 A → 재킷 후속 수정 A2 → 기존 guard/00 옆모습이다. A2와 guard/00의 존재를 새 사용자 시각 승인으로 간주하지 않는다. v3/v4 반려 그림과 잘못 등록된 캐릭터 객체는 사용하지 않는다.

## 접지와 엔진 연결

요청 초안은 발을 딛는 동안 그 발의 그림 좌표를 고정하고, 몸통이 전진하는 root-motion 방식이다. 걷기 한 주기48px, 달리기80px. 현재 시스템의 제자리 클립을 교체하기만 하면 몸통 이동이 이중 적용되므로 **그대로 엔진 연결 금지**다.

원칙적인 연결은 주기 중 루트를 고정하고, 끝에서 주기 이동량만 적용해 다시 0장으로 돌아가는 것이다. 기존 시스템 담당이 제자리 방식을 유지해야 한다면 별도 파생 팩에서 frame별 root_x를 뺀 후 해당량과 세계 이동을 정확히 동기화해야 한다. 이 폴더는 접지 규약만 전달하며 엔진 코드를 변경하지 않는다. 같은 장을 보이는 동안 코드만 이동시키면 발 미끄럼이 생기므로 시연에서 실제 세계 좌표를 재검사해야 한다.
