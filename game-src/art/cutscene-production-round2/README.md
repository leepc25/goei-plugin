## 이번에 바로잡은 내용

- 본부 문 담당 원격 tip `09e955d21aa3de669ced4bced5200dc0ae9e34c5`와 해당 채팅
  「본부 출입구 제작 준비」의 최신 인계를 읽었다. 그 담당도 승인된 새 문 이미지는 없다.
  숯색 프레임·브러시 금속·청회색 유리·젖빛 띠·중앙 이음새의 **양쪽 미닫이문**으로 맞췄다.
  이전 계획의 왼쪽 경첩 여닫이문은 폐기했다. 근거 사본은 `resume-evidence/door-design.md`.
- 320×180 배경을 생성해 nearest-neighbor 정수 2배로 640×360에 배치한다.
  가로세로 비율이 같아 제작 여백은 0px이다. PC는 원본 2배, 모바일 세로는 원본
  1배 320×180을 가운데 놓고 남는 공간에 여백을 둔다. 비정수 확대·도트 보간은 쓰지 않는다.
- 문 개구부 목표 `(200,31,80,125)`, 문턱 y=156; 동작 crop `(192,20,96,144)`.
  생성 좌표는 보장되지 않으므로 첫 장의 실제 경계를 측정한 뒤 확정한다.
- 고정 배경과 동작 마스크를 분리한다. 문틀·벽·바닥은 원본 그대로 유지하고, 문 개구부
  마스크 안의 움직임만 합성한다. 원본 crop 프레임도 모두 남겨 흔들림을 숨기지 않는다.
  문짝·유리·내부의 깜빡임, 잘린 손잡이·경계 누출은 별도 불합격 조건이다.
- 현행 MCP는 `frame_count=16` 요청에 입력 index 0 + 신규 16장, 총 **17장**을 반환한다고
  명시한다. 첫 400ms + 중간 15×100ms + 끝 500ms = 2,400ms. 같은 프레임 복제로 채우지 않는다.
- `create_image_pixen` 320×180: 1 generation. `animate_image` 96×144×16:
  `ceil(221184/65536)=4`. **예상 유료 2호출·5 generation**이며 계정 견적 확인 전 미제출이다.
  끝 장 편집·추가 후보·재시도 비용은 예약하지 않았다. 캐릭터 제작·반려 그림 참조는 없다.

## 실제 연결 확인과 보존 기록

- 공식 MCP `tools/list`: HTTP 200, 도구 103개. 필요한 6개 계약은
  `resume-evidence/tool-contracts.json`에 보존했다. 공개 도구 목록은 인증 성공 증거가 아니다.
- 실제 `get_balance`, `list_jobs`: HTTP 200 내부의 `isError=true`,
  **401 Missing Authorization header**. 계정 연결 실패로 판정했다.
- 공개 MCP 문서·OpenAPI 해시, 담당별 브랜치 SHA는 `resume-evidence/sources.json`.
- 환경 readiness에 등록된 secret/runtime variable/outbound identity 없음.
  `PIXELLAB_API_TOKEN` 존재 여부만 검사했으며 값이나 비밀 파일을 탐색·출력하지 않았다.
- 계정 재검사와 무료 도움말은 `inspect-pixellab.py`로 실행한다. 생성·취소·자동 재시도 기능은 없다.
  응답별 시각·호출·HTTP/MCP 상태를 `resume-evidence/account-*/`에 보존한다.
- `spend.log`는 이전 기록 뒤에 이번 기록을 추가했다. `manifest.json`의 실제 frames/order/ms는
  비어 있고, 계획 시간표는 `plannedPlayback`에 분리했다. 존재하지 않는 PNG·job ID를 넣지 않았다.

## 인증 후 실행 순서

사용자가 환경 비밀 변수 `PIXELLAB_API_TOKEN`을 연결한다. 키는 채팅에 붙이지 않는다.

```sh
python3 game-src/art/cutscene-production-round2/inspect-pixellab.py
```

1. 잔액·활성 및 최근 작업·무료 도움말이 모두 실제 성공했는지 응답 내부까지 확인한다.
   기존 이 컷의 job이 있으면 새 제출 전에 `get_image`로 결과부터 회수한다.
   현재 이 브랜치에 기록된 환경 컷 job ID는 0개다. 서버 작업 없음으로 해석하지 않는다.
2. 캐릭터 총괄의 최신 큐와 잔액을 대조하고 생성 슬롯을 공유한다(`coordination.md`).
   다른 담당의 큐라스 작업을 취소·재발주하지 않는다.
3. 최신 계약으로 `background.request.json`을 검증하고 단 한 번 제출한다.
   제출 전 요청 해시·예정 차감, 제출 직후 job ID·응답을 원장에 적는다.
   전송 결과 불명 시 재전송하지 말고 작업 목록부터 확인한다.
4. 회수한 원본을 `raw/background/`에 보존하고 직접 첫 장을 검수한다.
   구도·정면 미닫이문·문턱·팔레트·무인 상태·crop 가능 범위를 통과하기 전 동작을 제출하지 않는다.
5. 새 배경의 검수된 crop만 동작 입력으로 쓴다. 16장 생성 결과와 입력 장을 전부 회수해
   `raw/animation/<job-id>/`에 보존한다. 서버 usage를 호출별로 남긴다.
   공유 계정 잔액 차이로 이 컷의 실제 비용을 추정하지 않는다.
6. 첫 배경과 검수된 마스크로 17장의 원본 크기 합성 및 정수 2배 최종 PNG를 만든다.
   RGBA 해시 중복, 마스크 밖 변경 0, 문틀·바닥선 고정, 열린 폭 진행을 검수한다.
   실패 시 원인을 기록하고 방식을 수정한 뒤 다음 호출을 결정한다.
7. 실제 PNG와 타이밍을 내장한 단일 HTML에 정상/0.25배/반복·일시정지·장 넘김을 제공한다.
   PC·모바일 가로/세로에서 재생 완료/반복 경계·터치 조작과 시각 일관성을 검수한다.
   이 단계는 현재 미실시다. 기존 `build-review.mjs`는 인증 차단 설계 화면만 만들며
   신규 컷 검수판이 아니다.

## 교체 대상과 통합 계약

원래 콘티에서 문이 열리는 컷은 **`first_day/c3` (8–14초, 6초)**다.
`first_day/c2`는 길을 걷는 캐릭터 컷이므로 이번 교체 대상이 아니다.
이 2.4초 환경 컷은 c3의 문 열림 구간 후보이며 나머지 3.6초의 잼트리 장면은
캐릭터 담당 범위다. 실제 6초 편집 및 t=8/10.5 자막과의 정합은 메인 통합 담당이 결정한다.
빈 복도만으로 6초 전체를 교체하면 인사 장면이 사라지므로 자동 대체하지 않는다.

납품 시 원본 320×180·최종 640×360 PNG, 재생 순서/장별 ms, job/usage/해시 manifest,
단일 HTML을 이 폴더에 보존한다. 통합 담당이 승인 후 필요한 환경 구간만 원본
`game-src/art/cutscene/frames/first_day/c3/`의 새 통합판에 결합하고 패킹한다.
공용 로더·오디오·`story/video.ts`·자막·기존 timing은 이 브랜치에서 수정하지 않았다.

현재 미완료: 인증/잔액/진행 작업 확인, 필요한 기존 결과 회수, 실시간 생성 예약 확인,
첫 프레임 생성·검수, 동작 제작, 실제 프레임 PC·모바일 검수, 재생 가능한 신규 HTML.
이전 원본 게임 검증 기록은 `resume-evidence/README-before-resume.md`에 보존했다.
그 검증을 이번 새 그림의 합격으로 주장하지 않는다.
