# 컷씬 프레임 제작

기준 요청서는 `docs/GPT요청_컷신영상.md`의 GitHub main 최신본이다.

## 작업 순서 (2026-10-22 사용자 지시)

1. `dinner/c4`부터 컷과 컷씬을 모두 역순으로 진행한다.
2. 매 컷 시작 전 `git fetch origin main`으로 새 main을 받고 합친다.
3. `tools/build_cutscene_frames.py --check <scene>/<cut> --ref origin/main`으로 원격 컷을 검사한다. 폴더만 있다고 완료로 판단하지 않는다.
4. `timing.json` 누락, PNG와 `ms` 개수 불일치, 번호 누락, 잘못된 PNG 크기, 잘못된 반복 구간이 있으면 해당 컷을 마저 완성한다.
5. 새 컷은 `--only <scene>/<cut>`로 분리한다. 640×360 PNG와 시간표를 확인하고 그 컷만 커밋·푸시한다. 기존 완료 컷을 일괄 재생성하지 않는다.
6. 한 컷씬의 다른 모든 컷도 원격에서 검사를 통과하면 `register(<scene>)`로 `frames/index.json`에 이름을 추가한다. 기존 이름은 보존한다.

## 그림과 패킹

- 그림 제작: 내장 image_gen. 신규 인물 기준은 `cast-reference.png`, 원작은 `assets/agents/`의 원화이다. 반려된 이전 게임 도트를 참조하지 않는다.
- `sheets/`는 생성 원본이다. 프레임은 `frames/<scene>/<cut>/0001.png`부터 둔다. 원본 시트가 있다고 납품 완료는 아니다.
- 패킹은 최근접 픽셀 샘플링만 쓰며 컷마다 공통 64색 팔레트, 디더링 없음, 투명하지 않은 PNG를 출력한다. 원본 시트의 해상도는 생성 도구가 정하므로 패킹에서 규격을 맞춘다.
- 기본 동작 간격은 125ms이며 준비·완료 자세를 더 오래 유지한다. 지속 동작에는 1부터 세는 `loop` 구간을 쓴다. 컷 전체 길이는 콘티를 따른다.
- `opening/c3`와 `first_entry/c3`는 버튼 누르기가 아니라 점검표의 빈 서명란을 가리키는 장면이다. 접촉 자세를 고정하고 오프닝의 흰 번쩍임은 125ms만 쓴다.
- `opening/c8`의 한 명씩 생겨나는 최초 후보는 사용자 반려다. 여덟 명이 처음부터 함께 존재하고 걸어 나와야 한다. `ensemble/`은 교체 제작 중간 자료이며 현재 완료 자산이 아니다.
- 기술 검사를 통과했다는 사실은 사용자 시각 품질 승인을 뜻하지 않는다. 오디오는 선택 사항이며 아직 제작하지 않았다.

## 시연

`production/player.html`은 단일 HTML 시연판 템플릿이다. 정수 배율 픽셀 표시를 위해 원본 캔버스는 640×360이며 보간을 끈다. 시연판은 `release/demo/goei-cutscenes-gpt.html`에 만든다.
